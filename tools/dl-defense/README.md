# 딥러닝 봇 탐지기 (오프라인 프로토타입)

작성자: 김성원 · 위치: `tools/dl-defense/` · Python + PyTorch · 서버(Spring)와 연결되어 있지 않음

> **한 줄 요약**: 행동 로그에서 한 대상(회원·기기)의 이벤트 순서(종류·간격·응답 상태)와 기기 공유 신호를 보고
> "사람 같은가 봇 같은가"를 0~100으로 매기는 신경망입니다. 규칙 엔진(`risk/`)을 대신하지 않고 **옆에서 비교·보강**합니다.

## 꼭 알아둘 것

- **학습은 가상 데이터로만 합니다.** 사람 5유형 + 봇 6유형을 시뮬레이션합니다(`jejari_dl/sim.py`). 대회 데이터·대회 봇 값(간격·UA·이메일)은 쓰지 않았고, 이 저장소에는 아직 없습니다.
- **가상 데이터 점수(탐지율 100%, AUC 1.0)는 실력이 아닙니다.** 시뮬레이터가 만든 봇이 사람과 너무 잘 갈려서 나온 값입니다. 실제 성능은 대회 로그에 `score.py`를 돌려 `eval_contest.sh` 결과와 비교해야 알 수 있습니다.
- **강동균의 `tools/ml/`(Isolation Forest 등)과 별개**입니다. 이 폴더는 건드리지 않고 따로 만들었습니다. 합칠지는 팀과 정합니다.
- 입력에 **이메일·태그·라벨·UA·IP 해시를 쓰지 않습니다.** 기기 해시만 씁니다 (같은 와이파이는 IP가 같아서 가짜 신호가 됩니다).
- 매수 제한(1회 4 · 열차당 4 · 1일 20 · 명절 8)과 무관합니다. 점수는 참고용입니다.

## 구성

```
jejari_dl/schema.py    이벤트 종류 8개·입력 약속 (BehaviorType.java와 같은 순서, 추가만 가능)
jejari_dl/sim.py       가상 데이터: 사람 5유형, 봇 6유형 (매개변수를 넓은 범위에서 뽑음)
jejari_dl/model.py     CNN → 양방향 GRU → 어텐션·최대 풀링 (+ 공유 신호) → 점수
jejari_dl/training.py  학습(간격 배율 증강)·문턱 고르기·저장·불러오기
jejari_dl/metrics.py   AUC·유형별 탐지율·규칙 기준선(근사)
jejari_dl/realdata.py  behavior_log JSON → 모델 입력 (창 64개, 기기 단위 공유 신호)
train.py / evaluate.py / score.py / tests/
```

## 사용법

```bash
cd tools/dl-defense
pip install -r requirements.txt
python train.py                              # 가상 데이터로 학습 → out/model.pt (CPU 1~2분)
python evaluate.py --loo                     # 처음 보는 봇 유형에도 통하는지 (몇 분)
python score.py --model out/model.pt --input events.jsonl --top 20
python -m unittest discover -s tests         # 14개, 몇 초
```

`events.jsonl`은 `behavior_log`를 한 줄에 이벤트 하나(JSON)로 내보낸 파일입니다 (`eventType`·`ts`·`memberId`·`deviceHash`·`responseStatus`. 스네이크 표기도 읽습니다). 출력은 대상마다 `key, score, flag, reasons, events`입니다.

## 어떻게 동작하나

1. 이벤트마다 종류(원핫 8) · 응답 상태(2xx/409/기타) · log 간격 · 200ms 미만 표시를 만들고, 대상마다 최대 64개를 봅니다. 더 길면 창을 밀며 보고 **가장 높은 점수**를 씁니다.
2. 기기 단위 신호 2개(연결 계정 수, 60초 안에 선점한 서로 다른 계정 수)를 따로 붙입니다.
3. 학습 때 간격 전체에 0.7~1.4배를 곱해, 절대 속도 하나에 외우지 않게 합니다.
4. 문턱은 **검증용 사람 점수에서 오탐률이 `--max-fpr`(기본 2%)가 되는 값**으로 고릅니다. 탐지율을 올리려고 문턱을 낮추지 않습니다.

## 왜 leave-one-family-out으로 평가하나

대회 봇은 우리가 모르는 수법일 수 있습니다. 봇 유형 하나를 빼고 학습한 뒤 **그 유형을 처음 보여 줘서** 탐지율을 봅니다.

| 처음 본 유형 | 딥러닝 | 규칙 기준선 | 사람 오탐(딥러닝) |
|---|---|---|---|
| fixed_interval | 100.0% | 2.1% | 1.4% |
| sniper | 100.0% | 100.0% | 1.8% |
| multi_account | **1.3%** | 100.0% | 1.6% |
| jitter_evader | 100.0% | 41.1% | 1.4% |
| cancel_cycler | 100.0% | 0.0% | 1.8% |
| waitlist_macro | 100.0% | 45.1% | 1.8% |
| 평균 | 83.6% | 48.0% | 1.6% |

(사람 2000·봇 1500·15 epoch로 잰 값. 기본 설정 `--loo` 결과는 `evaluate.py --loo`로 다시 확인하세요.)

- **multi_account**: 한 명의 행동은 사람과 같고 "기기 하나에 명의 여러 개"로만 구별되는 유형입니다. 이 신호가 봇이라고 한 번도 배우지 못하면 모델이 못 잡습니다. 그래서 `score.py`는 **모델과 별개로** 동시 선점 계정 ≥ 2이면 `shared_device` 사유로 표시합니다.
- **규칙 기준선은 근사**입니다 (`RiskPolicy.defaults()` 문턱을 가상 데이터에 옮김). 가상 시퀀스가 짧아 "간격 30개 이상" 조건을 못 채우는 등 시뮬레이터 한계가 섞여 있으므로 **"딥러닝이 규칙보다 낫다"는 근거로 쓰지 마세요.**
- 기본 학습 직후 시험(가상) 사람 오탐은 3.0%로, 목표 2%보다 높았습니다. 사람 점수가 0에 몰려 문턱이 매우 낮아진 탓에 표본 차이가 크게 보입니다.

## 한계와 다음 단계

- 시뮬레이터가 단순합니다. 대회 1차 로그가 나오면 ① `score.py`로 점수를 매기고 ② 봇마다 어떤 사유로 잡혔는지, 사람 오탐이 몇 건인지 `eval_contest.sh` 결과와 비교해 보세요. 그 로그로 이 모델을 **학습하지는 않습니다** (시험용 데이터).
- 좌석 번호가 모델 입력에 없어 "같은 좌석 연타"는 409 응답 횟수로만 봅니다.
- 서버 연동(`risk` 패키지 점수 반영)은 `app_policy`·ERD 패치가 필요해 하지 않았습니다. 필요하면 강동균에게 요청합니다.
- 모델 파일(`out/`, `*.pt`)은 커밋하지 않습니다. 같은 시드면 `train.py`로 다시 만들 수 있습니다.
