# 결제 · 결제 멱등 · Saga (PAY-01~04, EVT-04·05)

작성자: 길동현 · 코드 위치: `src/main/java/com/jejari/payment/` (절차: `concurrency.md` §1·§4~§6.2)

## 한 줄 요약

버튼을 여러 번 눌러도 **결제는 한 번만** 되고, 결제 결과에 따라 예약을 **확정하거나 원래대로 되돌립니다.**

## 어떻게 동작하나

```
결제 요청 → 멱등 키 확인 → [DB] 예약 결제 중으로 + 마감 연장 + 결제 행 → 커밋 → Mock PG 승인 요청
   승인 → 예약 확정, 좌석 SOLD               (Saga: PAYING → CONFIRMED)
   거절 → 예약 만료, 좌석·매수 한도 반환      (Saga: COMPENSATED)
   응답 없음 → 그대로 두고, 마감 뒤 스캐너가 PG에 다시 물어봄
```

- **중복 결제를 막는 세 겹**
  1. Redis 멱등 키 `idem:pay:{예약}:{키}`: 같은 키로 다시 오면 처음 결과를 돌려줌
  2. 예약 `HOLD → PAYMENT_PENDING` 조건부 UPDATE: 한 번만 바뀌므로 다른 키로 동시에 와도 결제는 1건
  3. DB `UNIQUE(reservation_id, idempotency_key)`, 예약당 승인 1건 인덱스
- **Saga**: 결제 결과로 예약을 앞으로 진행하거나 되돌림. 되돌리기(좌석 반환)는 강동균의 `SeatReleaseService`를 같은 트랜잭션에서 부름

## Mock PG (카드번호 끝자리)

| 끝자리 | 결과 |
|---|---|
| 0 | 거절 |
| 9 | 응답 없음 (계속 모름) |
| 8 | 응답 없음 → 조회하면 승인 (늦은 승인) |
| 나머지 | 승인 |

## 왜 이렇게 했나

- **PG 호출은 트랜잭션 밖에서**: DB 락을 쥔 채 외부 응답을 기다리지 않음 (§0.6)
- **결과를 모르면 만료시키지 않음**: 돈이 빠졌을 수도 있으므로, 다시 물어볼 때까지 미룸
- **승인·실패·스캐너 모두 예약 행을 먼저 잠금**: 같은 결제를 동시에 바꾸지 못하게 줄 세움
- **결제 ID = 예약 ID**: 결제 시작은 예약당 한 번(재시도 없음)이라 1:1. ERD에 결제 시퀀스가 아직 없음

## 확인한 것 (`PaymentInfraTest` 18개, 실제 Oracle·Redis)

| | 결과 |
|---|---|
| 같은 예약에 다른 키로 20개 동시 요청 | 결제 **1건**, PG 승인 **1번** |
| 같은 키로 20개 동시 요청 | 결제 1건, 나머지는 같은 결과·처리 중 |
| 승인과 실패가 동시에 옴 | 한쪽만 반영, 좌석·카운터 일치 |
| 거절 | 좌석·한도 반환, Saga 보상 |
| 일부러 넣은 버그 3종 (상태 조건·보상·락 제거) | 테스트가 모두 잡음 |

## 쓰는 법

```
POST /api/v1/reservations/{예약ID}/payments
Idempotency-Key: <버튼 누를 때 만든 UUID, 재시도는 같은 값>
{ "cardNumber": "4111111111111111" }
→ 201 새 결제 / 200 같은 키 재요청 / 202 처리 중 / 409 PAYMENT_DUPLICATED·SEAT_LOST / 410 기한 지남
```

## 주의할 점·남은 것

- 카드번호 원문은 저장하지 않음 (HMAC 해시 + 끝 4자리). HMAC 키가 없으면 해시 없이 저장하고 경고 로그
- 늦은 승인 환불(PAY-05, P2)은 아직 로그만 남김
- PG 콜백 API는 실제 PG로 바꿀 때 추가
