# 알림 (EVT-06 · WL-04)

> **열차 예매에서 어디?** 앱의 "알림함"입니다. "결제 기한이 2분 남았어요", "예매가 만료됐어요", "취소표가 생겼어요" 같은 안내가 여기에 쌓입니다.

작성자: 길동현 · 코드 위치: `src/main/java/com/jejari/notification/` (절차: `concurrency.md` §9.1-6·§12)

## 한 줄 요약

알림은 **두 단계**입니다. 먼저 `notification` 표에 행을 남기고(만들기), 발송기가 그 행을 "보내고" 발송 시각을 찍습니다(보내기). 실제 푸시·메일은 보내지 않고 로그와 알림함으로 대신합니다.

## 어떻게 동작하나

```
[만들기]                                                  [보내기]              [보기]
예약 만료 이벤트 ──▶ notification 소비자 ──┐
환불 완료 이벤트 ──▶ (Inbox로 1번만)       ├──▶ notification 행 ──▶ 발송기(1초) ──▶ 알림함 API
결제 기한 2분 전 ──▶ 기한 임박 스캐너(10초) ┤     (sent_at 없음)     로그 + sent_at   GET /notifications
취소표 제안·건너뜀 ─▶ 강동균 제안 트랜잭션 ──┘
```

| 알림 | 언제 | 누가 만듦 |
|---|---|---|
| `WAITLIST_OFFER` 취소표 제안 | 대기자에게 좌석이 넘어감 | 강동균 (제안과 같은 트랜잭션) |
| `WAITLIST_SKIPPED` 건너뜀 | 매수 한도 초과로 제안을 못 받음 | 강동균 |
| `PAY_REMINDER` 결제 기한 임박 | HOLD 예약의 기한 2분 전 (`notification.pay_reminder_sec`) | 기한 임박 스캐너 |
| `EXPIRED` 예약 만료 | 기한 초과·결제 실패 (`RESERVATION_EXPIRED`) | notification 소비자 |
| `REFUNDED` 환불 완료 | `REFUND_COMPLETED` 이벤트 | notification 소비자 (환불 성공 때 강다인 취소 코드가 이벤트를 남김, 길동현 추가) |

## 왜 이렇게 했나

- **만들기와 보내기를 나눔**: 누가 행을 남기든(나, 강동균) 보내는 곳은 발송기 하나. 강동균은 행만 남기면 된다.
- **소비자는 Inbox로 1번만**: 같은 이벤트가 두 번 와도 알림 1건 (`processed_event`와 알림 INSERT가 한 트랜잭션).
- **제안 알림은 소비자가 다시 만들지 않음**: 강동균이 제안과 같은 트랜잭션에 이미 남긴다 (겹치면 2건).
- **기한 임박은 이벤트가 아니라 스캐너**: "2분 전"은 무언가 일어난 게 아니라 시간이 지난 것이라서. HOLD 만료 스캐너와 같은 인덱스(`ix_resv_hold_due`)를 쓰고, 예약당 1번만.
- **실패해도 뒤 알림을 막지 않음**: 소비자는 1초 간격 3번 다시 시도한 뒤 로그를 남기고 넘어감.

## 확인한 것 (실제 Oracle)

| 테스트 | 결과 |
|---|---|
| 같은 만료 이벤트 2번 | 알림 1건 |
| 확정 예약 취소 → 환불 성공 | `RESERVATION_CANCELED` 뒤에 `REFUND_COMPLETED` 1건 (동시 취소 3번이어도 1건, 환불 실패면 0건) |
| 환불 완료 이벤트 | `REFUNDED` 알림 1건 |
| 처리 중 실패 | 알림·도장 둘 다 롤백, 다시 오면 처리 |
| 기한 임박 스캐너 2번 실행 | HOLD 예약만 1건 (결제 중·기한 먼 것·지난 것은 0건) |
| 발송 전·후 알림함 | 발송된 것만 보임, 남의 알림 읽음 표시는 404 |
| 일부러 넣은 버그 3종 (중복 방지·HOLD 조건·회원 확인 제거) | 테스트가 모두 잡음 |

## 쓰는 법

```
GET   /api/v1/notifications?size=20&before={nextBefore}   → { items[], unreadCount, nextBefore }
PATCH /api/v1/notifications/{id}/read                     → 204 (이미 읽었어도 204, 남의 것은 404)
```

## 주의할 점·남은 것

- 테스트 중에는 소비자·기한 임박 스캐너가 꺼져 있음 (`build.gradle`). 켜 두면 다른 테스트의 회원에 알림이 생겨 회원 삭제가 FK로 실패함
- `REFUNDED`: `ReservationCancelService.refund()`가 환불을 DONE으로 바꾼 순간에만 `REFUND_COMPLETED`를 남김 (한 번만). 돌려준 돈이 0원(수수료 100%)이면 남기지 않음
- 안 보낸 알림 찾기는 지금 표 전체를 읽음. 커지면 `ix_notif_unsent` 인덱스 추가 (강동균에게 요청)
- 앱 여러 대면 기한 임박 알림이 드물게 2건 생길 수 있음 (1차는 1대)
