# 실제 KTX 시간표 적재 (개발용 데이터)

작성자: 길동현 · 코드 위치: `tools/load-tago-schedule.js`

## 한 줄 요약

공공데이터포털 열차정보 API에서 서울↔부산 실제 KTX 시간표를 받아, 오늘 앞뒤 7일치 운행을 로컬 Oracle에 넣는다. 화면에서 실제 열차 번호·시각으로 검색·예매해 볼 수 있다.

## 쓰는 법

```bash
# 1) .env에 공공데이터포털 서비스키(디코딩 키)를 넣는다. 각자 발급 (data.go.kr → 국토교통부_(TAGO)_열차정보 활용 신청)
#    DATA_GO_KR_KEY_DEC=...

# 2) SQL 만들기 (기본 앞뒤 7일, --days 3 처럼 바꿀 수 있음)
node tools/load-tago-schedule.js

# 3) DB에 넣기
MSYS_NO_PATHCONV=1 docker exec -i jejari-oracle-1 bash -c 'sqlplus -s / as sysdba' < build/tago/schedule.sql
```

- 결과 SQL은 `build/tago/schedule.sql`, API 원본 응답은 `build/tago/raw/`에 캐시 (`build/`는 깃에 안 올라감)
- 모두 MERGE라 여러 번 돌려도 같은 결과. 날짜가 지나면 다시 돌리면 됨 (지난 날 운행은 DEPARTED로 바뀜)
- 키는 출력하지 않음. 스크립트는 `.env`에서 `DATA_GO_KR_KEY_DEC` 줄만 읽음
  - (2026-11-18 강동균) **`DATA_GO_KR_KEY`도 읽습니다.** 요즘 포털은 64자 키 하나만 줘서 팀이
    `DATA_GO_KR_KEY` 하나로 모으는 중입니다 (`.env.example`). 옛 이름 `_DEC`가 먼저이고,
    없으면 새 이름을 봅니다 — 기존 `.env`는 그대로 돌아갑니다

## 어떻게 동작하나

```
API: 서울→부산, 서울→광명, …, 동대구→부산 (구간별 · 날짜별)
  → KTX만 골라 열차번호별로 역마다 도착·출발 시각을 모음
  → train / train_run / train_stop MERGE SQL 생성
```

- 출발→도착 구간을 모두 조회해서, 중간역 도착 시각은 "출발역→그 역", 출발 시각은 "그 역→종착역" 결과에서 가져옴
- 역은 서울·광명·대전·동대구·부산 5개. 서지 않는 역은 행을 안 만들고 stop_order에 빈 번호가 생김 (구간 재고를 안 쓰므로 순서만 맞으면 됨)

## ID 범위 (다른 데이터와 안 겹치게)

| 테이블 | ID | 비고 |
|---|---|---|
| train | 10000 + 열차번호 | 번호는 시드와 같은 5자리(`00103`). 좌석 배치는 시드 열차 1을 복사. train_kind `KTX` |
| train_run | 400000 + 연중일 × 1000 + 열차번호 | 시드 1001~9003, 관리자 등록 1,000,000~ 와 안 겹침 |
| 판매 기간 | 운행일 2달 전 07:00 ~ 출발 시각 | 지난 날은 DEPARTED, 나머지 ON_SALE |

## 주의할 점

- **시드와 같은 편은 넣지 않음** (11-19): 시드 열차(`train_id < 10000`)에 같은 번호가 있으면 그 편은 시드가 매일 운행을 깔아 두므로 건너뜀. 예전에 넣어 둔 같은 편 운행은 예약·대기·좌석 행이 없으면 지움. 공용 서버에서 `00103`과 `103`이 같은 시각으로 두 번 나오던 것
- 운행 번호가 시드(700000번대)와 겹칠 수 있는 구간이 있어, 같은 run_id를 다른 열차가 쓰고 있으면 그 행은 건드리지 않음

- 4자리 열차번호(9021 등 임시 열차)는 ID 규칙에 안 맞아 건너뛰고 목록만 출력
- 운행이 많아지면(15일 ≈ 900개 ON_SALE) 대기열 입장 스케줄러가 매초 운행 수만큼 돈다. 부하 테스트 때는 이 점을 감안할 것
- 테스트는 시드 운행(9001 등)만 쓰므로 이 데이터가 있어도 통합 테스트 결과는 같음 (11-18 결제·취소·알림 42개 통과 확인)
- 데이터 적재 담당(DATA-01) 스크립트 `tools/load-public-data.js`와는 별개. 실제 시간표로 화면을 확인하고 싶을 때만 씀
