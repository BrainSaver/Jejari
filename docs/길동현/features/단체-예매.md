# 단체 예매 (여행사)

작성자: 길동현 · 코드 위치: `src/main/java/com/jejari/group/`, `src/main/resources/lua/group/`, 화면 `frontend` U-12·A-11 · 절차: `docs/concurrency.md` §18

> **열차 예매에서 어디?** 여행사가 10명 넘는 인원을 한 번에 신청하는 화면(U-12)과, 관리자가 신청을 보고 승인·거절하는 화면(A-11)입니다. 승인된 뒤의 결제·만료·취소는 일반 예약과 같습니다.

## 한 줄 요약

단체 신청을 받으면 운행마다 미리 묶어 둔 할당석(BLOCKED)에서 먼저 좌석을 주고, 모자라면 남은 일반 좌석에서 선착순으로 이어 주어 **예약 하나(`source = 'GROUP'`)**를 만든다.

## 어떻게 동작하나

```
신청 (POST /api/v1/groups)
  → 검사: 인원 11~200명, 대표자 = 본인인증 번호, 명단 안 번호 중복, 동의
  → 명단 암호화 저장 (group_booking REQUESTED + group_passenger)
  → 바로 자동 승인 시도 (GroupAllocator)
        좌석 고르기: 할당석 중 같은 객차 연속 → 모자라면 일반 좌석 (행·Redis 키 둘 다 없는 좌석만)
        Redis: group_claim.lua로 할당석(GROUP) + 일반 좌석(빈 키)을 한 번에 R로 바꿈 (전부 아니면 전무)
        DB 한 트랜잭션: group_booking FOR UPDATE → reservation HOLD → seat_inventory BLOCKED→HOLD (+ 일반 좌석 INSERT)
                        → reservation_seat → 명단에 좌석 → APPROVED → history·saga·outbox(SEAT_HELD)
        실패하면 group_return.lua로 Redis 되돌림
  → 이후 결제·만료·취소는 일반 예약과 같은 경로 (§4~§9)
```

- 위험 신호(휴대폰 없는 사람 30% 초과, 다른 단체와 번호 겹침, 위험 점수 높음)가 있으면 자동 승인하지 않고 관리자 확인(A-11)으로 넘긴다
- **미뤄진 승인:** 일반 좌석이 필요한데 그 운행 대기열에 사람이 있으면(줄 선 사람 또는 입장해 고르는 사람) 승인을 미룬다. `GroupRetryScanner`가 1분마다 신청 순서대로 다시 시도한다
- 할당석 반납 시각(출발 `group.quota_release_days`일 전)까지 승인되지 못하면 `REJECTED`
- 명단은 승인 뒤 7일 안에 한 번 바꿀 수 있다 (대표자는 못 바꿈, `PUT /api/v1/groups/{id}/passengers`)

## 왜 이렇게 했나

- **할당석 먼저, 모자라면 일반 좌석 선착순 (11-24 결정, §18.3a):** 할당석만 쓰면 큰 단체가 늘 거절되고, 일반 좌석을 무조건 주면 단체가 줄 선 사람보다 먼저 가져간다. 그래서 일반 좌석은 **대기열이 빈 뒤에만**, 개인 선점과 같은 Redis `SET NX` 경쟁으로 잡는다
- **예약 하나로 만듦:** 할당석 몫만 먼저 배정하면 예약이 두 건으로 쪼개져 결제·취소가 꼬인다. 모자라면 전부 미루거나 거절한다
- **Redis 스크립트 하나로 한 번에 잡기:** 할당석 키와 일반 좌석 키를 따로 잡으면 반쯤 잡힌 상태가 생긴다. `group_claim.lua`는 전부 맞을 때만 쓴다 (`hold.lua`와 같은 방식)
- **남의 만료된 HOLD는 건드리지 않음:** 단체 트랜잭션 안에서 남의 예약을 정리하면 락 순서가 꼬인다. 그런 좌석은 건너뛰고 스캐너(§6.1)에 맡긴다
- **매수 카운터 안 씀:** 시스템이 대표자 명의로 잡는 것이라 개인 20매 한도와 무관하다. 그래서 만료·취소·재선점 때도 `source = 'GROUP'`이면 카운터를 줄이지 않는다 (강동균 좌석 코드)

## 주의할 점

- 할당석 만들기·반납·BLOCKED 좌석 일반 선점 거절은 **강동균**(`58bcb50`, `docs/강동균/features/단체-할당석.md`), 단체 취소 위약금(`group_fee_policy`)은 **강다인**(`a109dae`) 코드다
- 대기자에게 제안 중인 좌석(`REOFFER:R`)은 DB 행이 없어 빈 좌석처럼 보인다. 반드시 Redis 키도 같이 본다 (G5c)
- 탑승자 정보는 `PiiCipher`로 암호화한다. 행 ID는 `그룹ID-순번` 형식 (`10f62a9`)
- 신청 번호는 `group_booking_seq` (ERD v38)
- 정책 값 (`app_policy`, 기본값): 인원 `group.min_size` 11 ~ `max_size` 200 · 할당석 비율 `group.quota_rate` 0.05 · 반납 `group.quota_release_days` 30일 전 · 결제 기한 `group.pay_deadline_days` 3일 · 명단 변경 `group.roster_change_days` 7일 · 할인 `group.discount_rate` 10% (출발 `discount_within_days` 30일 안) · 휴대폰 없음 경고 `group.no_phone_warn_rate` 30%
