## 한 일

- `com.jejari.notification` 패키지
  - notification 소비자: 예약 만료 → `EXPIRED`, 환불 완료 → `REFUNDED` (Inbox로 1번만)
  - 결제 기한 임박 스캐너: HOLD 예약 기한 2분 전 `PAY_REMINDER` (예약당 1번)
  - 발송기: 안 보낸 알림을 로그로 "보내고" `sent_at` 기록 (강동균 제안 알림 포함)
  - 알림함 API: `GET /api/v1/notifications`, `PATCH /api/v1/notifications/{id}/read`
- 강다인 환불 코드(`ReservationCancelService.refund()`)에 `REFUND_COMPLETED` outbox 추가: 환불을 DONE으로 바꾼 쪽만, 돌려준 돈이 있을 때만 → 환불 완료 알림이 실제로 생김. 취소 테스트 3개에 확인 추가, 일부러 지우면 2개 실패
- 취소표 결제 통합 테스트 3개: 결제 시작 때 대기 마감 연장, 승인 → `ACCEPTED`, 거절 → `EXPIRED`
- 테스트 11개 추가, 전체 단위 434 · 인프라 393 통과. 버그를 일부러 넣은 4종 모두 테스트가 잡음

## 왜 이렇게 했나

- 강동균 메시지 확인: 대기 마감 연장(WL-05)과 대기 `EXPIRED`는 **이미 코드에 있었음**. 그래서 새로 만들지 않고 실제 제안 예약으로 테스트만 붙임
- 알림은 "만들기"와 "보내기"를 나눔 → 누가 행을 남기든 보내는 곳은 하나
- 테스트 중에는 소비자·스캐너를 끔 (`build.gradle`). 다른 테스트 회원에 알림이 생기면 그 테스트의 회원 삭제가 FK로 실패하기 때문
