# 2026-11-17 (저녁) · 결제 수단 시퀀스 교체, 늦은 승인 환불 (PAY-05)

> **열차 예매에서 어디?** 결제를 실패로 정리했는데 나중에 카드사가 "사실 승인됐다"고 알려 온 경우입니다. 돈은 빠졌는데 좌석은 이미 풀렸으니 돈을 돌려줍니다.

## 한 일

- 결제 수단 ID를 `reservation_seq`에서 `payment_method_seq`로 교체 (PR #12). 옛 번호와 겹치면 다음 번호로
- `LateApprovalRefund`: 늦은 승인·확정 실패 때 전액 자동 환불
  - Saga가 결제를 APPROVED로 바꾸는 트랜잭션에서 `cancellation`(PAY_FAILED, 전액, 수수료 0, REQUESTED)을 같이 남김
  - 커밋 뒤 PG 환불(환불 키 `cancel:{cancel_id}`) → 성공하면 DONE·결제 REFUNDED·`REFUND_COMPLETED` → 알림 "환불 완료"
  - PG 환불 실패 → FAILED로 남김 (재시도 배치 대상)
- 테스트 3개 추가·2개 수정 (`PaymentInfraTest` 21개 통과). 버그 2종을 일부러 넣어 테스트가 잡는지 확인

## 왜 이렇게 했나

- **결제 APPROVED와 환불 기록을 한 트랜잭션에**: 커밋 직후 앱이 죽어도 `REQUESTED` 행이 남아 "돌려줘야 할 돈"을 잃지 않음
- **PG 환불은 커밋 뒤**: DB 락을 쥔 채 외부 응답을 기다리지 않음 (§0.6)
- **예약은 되살리지 않음**: 좌석이 이미 다른 사람에게 갔을 수 있음
- **환불 실패는 예외 대신 FAILED**: 승인 처리 자체는 끝났으므로. 같은 `refund(cancelId)`를 다시 부르면 되고, 환불 키가 같아 두 번 환불되지 않음

## 배운 점

- 결제 수단 PK 충돌이 그대로 밖으로 나가면 결제 서비스가 "같은 멱등 키 동시 요청"으로 읽는다. 예외 종류 하나로 의미를 판단하는 곳은 그 예외가 다른 이유로도 날 수 있는지 봐야 한다
