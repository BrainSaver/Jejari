## 한 일

- `com.jejari.payment` 패키지: Mock PG, 결제 시작, Saga(확정·보상), PG 결과 확인 스캐너, 결제 API
- `EventType`에 빠진 이벤트 3개 추가 (`REFUND_COMPLETED`, `WAITLIST_OFFERED`, `WAITLIST_SKIPPED`)
- 통합 테스트 18개 (실제 Oracle·Redis) 모두 통과, 버그를 일부러 넣어 테스트가 잡는지 확인
- 로컬 Oracle을 최신 DDL·시드로 다시 만들고, `.env`에 빠진 키 5개 추가 → 전체 인프라 테스트 310개 통과

## 어떻게 했나

- 흐름: `멱등 키 → DB(예약 결제 중 + 마감 연장 + 결제 행) → 커밋 → PG → 승인이면 확정 / 거절이면 되돌림 / 모르면 스캐너`
- 강동균이 미리 만들어 둔 좌석 함수(`SeatPaymentService`, `SeatReleaseService`)를 그대로 불러 씀. 좌석은 B, 예약·결제·Saga는 C

## 왜 이렇게 했나

- **결제 ID = 예약 ID**: ERD에 결제 시퀀스가 없고, 결제 시작은 예약당 한 번이라 1:1
- **결제 수단 ID는 `reservation_seq`에서**: 임시. 시퀀스가 생기면 교체
- **결과 모름은 자동 만료 안 함**: 돈이 빠졌을 수 있어서

## 막힌 점과 해결

- 로컬에서 다른 팀원 테스트가 실패 → DB가 오래됐고 `.env`에 키가 없었음: `troubleshooting/20261117-로컬-환경이-main보다-오래됨.md`

## 배운 점

- 테스트가 처음부터 다 통과해도 믿지 말고, 일부러 망가뜨려 실패하는지 본다 (이번에도 3종 모두 잡음)
- 팀원이 `.env.example`에 키를 추가해도 내 `.env`는 저절로 안 바뀐다
