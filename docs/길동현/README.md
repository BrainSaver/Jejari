# 길동현이 만든 것 한눈에 보기

> **열차 예매에서 "좌석을 고른 뒤 돈을 내는 단계(결제)"와, 예매 상태가 바뀔 때 다른 기능에 알려 주는 "연락망(이벤트)"이다.**

```
회원가입 → 열차 조회 → 대기열 → 좌석 고르기 → [ 결제 ] → 예매 확정 → 취소·환불
   E·D        B          A          B          ★ 길동현      ★          D
                                                  │
                      예매 상태가 바뀔 때마다 ──▶ [ 이벤트 연락망 ] ──▶ 알림 · 좌석 반환 · 위험 점수
                                                  ★ 길동현
```

## 1. 결제 (PAY-01~04)

**예매에서 어디?** 좌석을 잡은 뒤 "결제하기" 버튼을 누르는 순간부터 예매가 확정되거나 취소될 때까지.

| 상황 | 결과 |
|---|---|
| 카드 승인 | 예매 확정, 좌석은 내 것(SOLD) |
| 카드 거절 | 예매 취소, 좌석은 다시 판매 (대기자 먼저) |
| 카드사 응답 없음 | 확정도 취소도 안 하고 기다림 → 나중에 카드사에 다시 물어봄 |

- 카드사는 가짜(Mock PG)다. 카드번호 끝자리로 결과를 정한다: `0` 거절 · `9` 응답 없음 · `8` 늦은 승인 · 나머지 승인
- 자세히: [features/결제-멱등-saga.md](features/결제-멱등-saga.md) · 직접 눌러 보기: [http/결제-흐름.http](http/결제-흐름.http)

## 2. 중복 결제 막기 (EVT-04)

**예매에서 어디?** 결제 버튼을 두 번 누르거나, 인터넷이 끊겨 다시 보내거나, 탭 두 개로 동시에 결제할 때.

- 결과: **아무리 여러 번 눌러도 돈은 한 번만 나간다.** (동시에 20번 보내도 결제 1건, 테스트로 확인)

## 3. Saga: 확정하거나 되돌리기 (EVT-05)

**예매에서 어디?** 결제 결과가 나온 직후.

- 예매는 여러 단계(좌석 잡기 → 결제 중 → 확정)를 거친다. 중간에 실패하면 앞 단계에서 한 일(좌석·매수 한도)을 **되돌린다.**
- 좌석을 되돌리는 실제 일은 강동균(좌석 담당)의 코드를 부른다.

## 4. 이벤트 연락망: Outbox · 릴레이 · Inbox (EVT-01~03)

**예매에서 어디?** 화면에는 안 보인다. 예매 상태가 바뀔 때마다 뒤에서 돈다.

- 예: "예매 확정됨" → 알림 보내기, "예매 취소됨" → 대기자에게 좌석 넘기기, 위험 점수 다시 계산
- 결과: 알림이 **빠지지 않고, 순서대로, 한 번만** 간다.
- 자세히: [features/outbox-릴레이-inbox.md](features/outbox-릴레이-inbox.md)

## 5. 알림 (EVT-06 · WL-04)

**예매에서 어디?** 앱의 알림함. "결제 기한 2분 남음", "예매 만료", "취소표가 생겼어요".

- 알림 행을 남기면 발송기가 1초 안에 "보내고"(로그) 알림함에 보인다. 실제 푸시·메일은 없음
- 취소표 제안 알림은 강동균이 남기고, 보내는 것은 내 발송기가 한다
- 환불 완료 알림을 위해 강다인의 환불 코드에 `REFUND_COMPLETED` 이벤트 한 줄을 추가했다
- 자세히: [features/알림.md](features/알림.md)
