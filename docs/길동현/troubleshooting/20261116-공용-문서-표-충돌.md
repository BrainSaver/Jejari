# [docs] 문서 사이트 저장 때 "main과 충돌" (기능설계서 11장 표)

## 1. 문제

- 현상: 문서 사이트에서 저장하자 "main과 충돌 — main과 내 브랜치가 둘 다 바꾼 파일: `docs/기능설계서.md`" 창이 뜨고 저장이 멈춤
- 재현 조건: 내 브랜치에서 11장 미정 사항 #4·#8을 고침, 그 사이 다른 팀원이 main에서 바로 옆 줄 #3·#7을 고침
- 영향: 내 브랜치의 문서를 사이트에서 저장할 수 없음

## 2. 원인

- 문서 사이트는 저장할 때 main을 내 브랜치에 합친다. 이때 Git이 자동으로 못 합치면 멈춘다.
- 최종 원인: Git은 **붙어 있는 줄**을 양쪽이 고치면, 서로 다른 줄이어도 한 덩어리로 보고 충돌로 처리한다. 표의 행은 줄이 붙어 있어서 특히 잘 걸린다.

```
<<<<<<< HEAD          (내 브랜치: #4·#8 해결)
| 4 | ~~좌석 일부 취소 지원 여부~~ | 해결: … |
=======
| 3 | ~~RESTRICTED 회원은 …~~ | 해결: … |     (main: #3·#7 해결)
>>>>>>> origin/main
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 한쪽 내용으로 덮기 | 빠름 | 다른 사람 결정이 사라짐 | |
| 행 번호별로 고친 쪽을 골라 합치기 | 양쪽 결정 모두 유지 | 손이 감 | ✓ |

```bash
git fetch origin
git merge origin/main                 # 충돌 발생
# 충돌 구간에서 행마다 바뀐 쪽을 선택: #3·#7은 main, #4·#8은 내 것
git add docs/기능설계서.md && git commit --no-edit
git push origin DongHyeon
git merge-tree --write-tree origin/main DongHyeon   # 충돌 없으면 성공 출력
```

- 선택한 이유: 미정 사항 표는 사람마다 맡은 행이 달라, 행 단위로 고르면 의미 손실이 없다.

## 4. 수치

## 5. 정리

- 한 줄 요약: "여러 명이 같은 표를 고쳐 충돌이 났고, 행마다 고친 쪽을 골라 양쪽 결정을 모두 살렸다."
- 다음에 비슷한 상황이면: 공용 문서(`기능설계서.md`, `concurrency.md`, `README.md`)는 **고치기 전에 `git pull origin main`**. Claude에게는 "main과 충돌난 거 양쪽 다 살려서 풀어줘"라고 하면 된다.
