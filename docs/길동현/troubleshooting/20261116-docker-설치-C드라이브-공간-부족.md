# [infra] Docker Desktop 설치가 C: 공간 부족으로 실패 (F:에 설치해도 C:를 검사)

| 항목 | 내용 |
|---|---|

| 날짜 | 2026-11-16 |
| 상태 | 해결 |
| 관련 커밋·이슈 | 없음 (PC 환경 문제) |

> 파일 이름: `docs/길동현/troubleshooting/20261116-docker-설치-C드라이브-공간-부족.md`

## 1. 문제

- 현상: `winget install Docker.DockerDesktop`이 `설치 관리자가 종료 코드로 인해 실패함: 1`로 끝남. 화면에는 이유가 안 나옴
- 재현 조건: Windows 10, C: 여유 공간 3.3GB 미만, WSL 2 미설치(기본 내장 WSL)
- 영향: `docker` 명령이 없어 `docker compose up -d` 불가 → 로컬 인프라를 못 띄움

## 2. 원인

- 설치 로그 `%LOCALAPPDATA%\Docker\log\host\*Installer*.log`에 원인이 두 개 있었다.

```
installing: not enough disk space to install: need 3272 MiB, only 2709 MiB available
c:\windows\system32\wsl.exe --version failed: exit status 1
```

- 최종 원인: ① C: 공간 부족 ② WSL 2가 설치돼 있지 않음 (`wsl --version`이 도움말만 출력)
- 함정: `--installation-dir=F:\...`로 설치 경로를 바꾸거나 `TEMP`를 F:로 바꿔도 **설치 프로그램은 항상 C:의 `AppData\Local\Temp`에 풀고 C: 공간 3.3GB를 검사**한다. 설치 단계만큼은 C: 공간이 꼭 필요하다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 설치 경로·TEMP를 F:로만 돌림 | C:를 안 비워도 될 것 같음 | 설치 프로그램이 C:를 검사해 실패 | |
| C:를 비우고 설치, 이미지·데이터는 F:에 | 설치 후 C:를 거의 안 씀 (이미지 약 10GB 이상이 F:로) | 설치 순간 C: 여유 3.3GB 이상 필요 | ✓ |

순서 (관리자 권한 창이 뜨면 "예"):

```powershell
# 1. WSL 2 (재부팅 필요)
wsl --install --no-distribution

# 2. C: 정리 후, 설치 파일을 받아 F:에 설치 (데이터 경로까지 F:)
"Docker Desktop Installer.exe" install --quiet --accept-license --backend=wsl-2 `
  --installation-dir=F:\Docker\Docker --wsl-default-data-root=F:\Docker\wsl

# 3. 재부팅 → Docker Desktop 실행 → 터미널(Claude Code 포함)을 새로 열기
docker version
```

- 선택한 이유: 공간을 많이 먹는 건 설치 파일이 아니라 이미지와 컨테이너 데이터라서, 데이터 경로만 F:로 보내면 된다.
- C:에서 비우기 좋았던 곳: `%LOCALAPPDATA%\Temp`, `npm-cache`, Android 에뮬레이터 이미지(`.android\avd`, `Android\Sdk\system-images`), 디스크 정리의 "시스템 파일 정리"
- 설치 직후 `docker: command not found`면 셸이 설치 전 PATH를 들고 있는 것. 터미널을 새로 연다.

## 4. 수치

| 지표 | 해결 전 | 해결 후 |
|---|---|---|
| C: 사용 (이미지·데이터) | 설치 불가 | 0GB (F:\Docker\wsl에 약 14GB) |

- 측정 환경: Windows 10 Pro 19045, Docker Desktop 4.99, 이미지 9.8GB (Oracle Free·Kafka·Mongo·Redis·Prometheus·Grafana)
- 측정 방법: `docker system df`, `du -sh /f/Docker/wsl`

## 5. 정리

- 한 줄 요약: "Docker 설치가 이유 없이 실패해 설치 로그를 보니 C: 공간과 WSL이 원인이었고, 설치만 C:에서 하고 데이터는 F:로 보내 C: 사용을 0으로 만들었다."
- 다음에 비슷한 상황이면: 설치 실패는 화면 메시지 말고 **설치 로그**부터 본다. Claude에게 시킬 땐 "Docker 설치 로그 확인해줘"라고 하면 된다.
