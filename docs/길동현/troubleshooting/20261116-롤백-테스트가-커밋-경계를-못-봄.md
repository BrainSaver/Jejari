# [event] 롤백되는 테스트로는 Outbox의 커밋 경계를 검증할 수 없음

> 파일 이름: `docs/길동현/troubleshooting/20261116-롤백-테스트가-커밋-경계를-못-봄.md`

## 1. 문제

- 현상: Outbox·릴레이·Inbox 테스트 9개가 모두 통과했지만, Outbox의 핵심인 "업무와 같이 커밋/롤백되는가", "커밋 전 행을 릴레이가 보내지 않는가", "릴레이 두 개가 동시에 돌아도 한 번만 보내는가"는 **한 번도 실제로 실행되지 않았음**
- 재현 조건: `@JdbcTest` 기본 설정 (테스트마다 트랜잭션 하나, 끝나면 롤백)
- 영향: 이 부분에 버그가 있어도 테스트는 초록색 → 중복 발행·이벤트 유실을 놓칠 수 있음

## 2. 원인

- `@JdbcTest`는 테스트 메서드 전체를 트랜잭션 하나로 감싸고 끝에 롤백합니다. 그래서
  - 커밋이 한 번도 일어나지 않고
  - 모든 쿼리가 같은 연결이라 "다른 연결에서는 커밋 전 행이 안 보인다"를 확인할 수 없고
  - 동시에 두 트랜잭션이 행 잠금을 다투는 상황을 만들 수 없습니다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 기존 롤백 테스트만 유지 | 정리 불필요, 빠름 | 커밋 경계·동시성 검증 불가 | |
| 실제로 커밋하는 테스트 클래스 추가 (`NOT_SUPPORTED` + 끝에 직접 삭제) | 실제 운영과 같은 조건 | 정리 코드 필요, 실행 중인 앱과 행을 다툼 | ✓ |

- `OutboxCommitInfraTest` 10개 추가: 롤백/커밋 원자성, 커밋 전 비가시성, 부분 실패 커밋, 릴레이 2개 동시 40건, 잠금 대기 초과, 발행 후 중단 → 재발송 → Inbox 1회 처리, 샤드 격리, 배치 크기, 정리 배치
- 추가로 **뮤테이션 테스트**: 릴레이에 일부러 버그를 넣고 테스트가 실패하는지 확인

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 이벤트 테스트 수 | 11 | 27 |
| 일부러 넣은 순서 버그 검출 (발행 실패 후 계속 / FAILED 무시) | 확인 안 함 | 2 / 2 검출 (각각 3개·2개 테스트 실패) |
| 릴레이 2개 동시 40건 | 확인 안 함 | 중복 0, 순서 어긋남 0 |

- 못 잡은 변형 1개: 바깥 `status IN ('PENDING','FAILED')` 조건 삭제. Oracle이 잠금 대기 뒤 쿼리를 다시 실행할 때 안쪽 쿼리의 같은 조건이 걸러 주므로 결과가 같습니다. §11.3의 안전장치로 남겼습니다 (동작으로 추론, Oracle 내부는 직접 확인 안 함).
- 측정 방법: `.\gradlew infraTest --tests "com.jejari.event.*"` (Docker 필요, 앱은 끄고)

## 5. 정리

- 한 줄 요약: "Outbox 테스트가 모두 통과했지만 롤백되는 테스트라 커밋 경계를 전혀 검증하지 못한다는 걸 알고, 실제로 커밋하는 테스트 10개와 뮤테이션 테스트를 추가해 일부러 넣은 순서 버그 2종을 모두 잡는 것을 확인했다."
- 다음에 비슷한 상황이면: "이 테스트가 실패할 수 있는가?"를 먼저 묻는다. 코드를 일부러 망가뜨려 봐서 안 깨지면 그 테스트는 아무것도 지키지 않는 것이다.
