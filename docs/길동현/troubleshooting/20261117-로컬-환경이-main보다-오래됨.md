# [infra] main을 받았는데 다른 팀원의 통합 테스트가 47개 실패

> **열차 예매에서 어디?** 예매 기능이 아니라 내 PC의 개발 환경(DB·`.env`)이 팀 코드보다 오래돼 생긴 문제입니다.

## 1. 문제

- main을 합친 뒤 `./gradlew infraTest`에서 회원·좌석·행동 로그 테스트 47개 실패 (내 이벤트 테스트는 통과)

## 2. 원인

코드는 main과 같은데 **내 PC의 DB와 `.env`가 옛날 상태**였다.

| 증상 | 원인 |
|---|---|
| `ORA-02289: 시퀀스가 존재하지 않습니다` (member_seq) | Oracle 초기화 스크립트는 빈 볼륨에서 한 번만 돈다. 그 뒤 바뀐 ERD가 반영 안 됨 |
| 좌석 조회 결과 0건 | 시드 데이터도 같은 이유로 없음 |
| `No qualifying bean of type 'PiiCipher'`·`'Pseudonymizer'` | `.env`를 만든 뒤 팀원이 `.env.example`에 키 5개를 추가함. `.env`는 git에 없어 저절로 안 바뀜 |

## 3. 해결

```powershell
# 1. Oracle을 최신 DDL·시드로 다시 만들기 (로컬 DB 데이터 삭제됨)
docker compose rm -sf oracle; docker volume rm jejari_oracle-data; docker compose up -d oracle
docker compose logs oracle | Select-String "seed loaded"     # 약 5분

# 2. .env에 빠진 키 확인 (값은 안 보이고 이름만)
#    .env.example에는 있는데 .env에 없는 키를 찾아 채운다
```

- 빠진 키: `JEJARI_HMAC_KEY`, `JEJARI_ENC_KEYS`, `JEJARI_ENC_ACTIVE`, `JEJARI_PEPPER_KEYS`, `JEJARI_PEPPER_ACTIVE`
- 지금은 내 PC에서 새로 만든 값. 로컬 개발은 팀원마다 달라도 되고, **클라우드에 서버를 올릴 때 팀 공용 값으로 통일**하기로 함

## 5. 정리

- 한 줄 요약: "main을 받았는데 다른 팀 테스트가 47개 실패해서 보니 내 DB와 .env가 옛날 상태였고, DB를 최신 DDL로 다시 만들고 빠진 키를 채워 310개 모두 통과시켰다."
- 다음에 비슷한 상황이면: ERD가 바뀌었거나 `.env.example`이 바뀐 커밋을 받았으면 DB 재생성과 `.env` 키 비교부터 한다.
