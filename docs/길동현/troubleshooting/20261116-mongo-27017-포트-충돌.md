# [infra] docker compose up 때 Mongo가 27017 포트 충돌로 안 뜸

| 항목 | 내용 |

> 파일 이름: `docs/길동현/troubleshooting/20261116-mongo-27017-포트-충돌.md`

## 1. 문제

- 현상: `docker compose up -d`에서 mongo가 실패하고, mongo를 기다리던 kafka·grafana·kafka-init까지 같이 멈춤

```
Error response from daemon: ports are not available: exposing port TCP 127.0.0.1:27017
 -> 127.0.0.1:0: listen tcp4 127.0.0.1:27017: bind: Only one usage of each socket address
 (protocol/network address/port) is normally permitted.
```

- 재현 조건: 예전에 MongoDB를 Windows에 직접 설치해 서비스(`MongoDB`)가 자동 실행 중인 PC
- 영향: 로컬 인프라 전체가 안 뜸 (Oracle·Redis만 뜨고 Kafka는 안 뜸)

## 2. 원인

- 가설: 다른 프로그램이 27017을 쓰고 있다 → 포트 주인 확인

```bash
netstat -ano | grep ":27017 " | grep LISTEN     # PID 확인
tasklist //FI "PID eq <PID>"                    # → mongod.exe (Services)
sc query MongoDB                                # → RUNNING
```

- 최종 원인: PC에 설치된 MongoDB 서비스가 27017을 먼저 잡고 있었다. `compose.yaml`은 `127.0.0.1:27017:27017`로 고정이라 겹친다.
- 같은 방식으로 1521(Oracle), 6379(Redis), 9092(Kafka), 9090(Prometheus), 3000(Grafana)도 겹칠 수 있다. 3000은 프런트 개발 서버, 6379는 직접 설치한 Redis가 흔한 범인이다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| PC MongoDB 서비스를 멈추고 시작 유형 "수동" | 팀 파일 그대로, 재부팅해도 다시 안 겹침 | 그 MongoDB가 필요할 땐 직접 켜야 함 (동시 사용 불가) | ✓ |
| 이번만 서비스 멈춤 | 간단 | 재부팅하면 다시 충돌 | |
| `compose.yaml` 포트를 27018로 | PC MongoDB와 같이 씀 | 팀 공용 파일과 달라지고 `.env`의 `MONGO_PORT`도 바꿔야 함 | |

```powershell
# 관리자 PowerShell
Stop-Service MongoDB -Force
Set-Service MongoDB -StartupType Manual
```

그 뒤 `docker compose up -d` → `docker compose ps`에서 oracle·mongo·redis·kafka가 `healthy`, kafka-init이 `Exited (0)`.

- 선택한 이유: 팀 공용 설정을 개인 PC 사정으로 바꾸지 않는다.
- 꼭 포트를 바꿔야 하면 `compose.yaml` 말고 개인용 `compose.override.yml`(`.gitignore`에 있음)에서 바꾼다.

## 4. 수치

- 해당 없음 (환경 문제)

## 5. 정리

- 한 줄 요약: "compose가 포트 충돌로 실패해 포트 주인을 찾아보니 PC에 따로 설치된 MongoDB였고, 서비스를 수동 시작으로 바꿔 팀 설정을 건드리지 않고 해결했다."
- 다음에 비슷한 상황이면: `ports are not available` 메시지의 포트 번호로 `netstat -ano`를 보고 PID → 프로그램을 찾는다. Claude에게는 "몇 번 포트 누가 쓰는지 찾아줘"라고 하면 된다.
