# [admin] 봇 대회 결과 화면이 항상 500 — formatted() SQL 안의 `%'`

| 항목 | 내용 |
|---|---|
| 작성자 | 길동현 |
| 날짜 | 2026-11-27 |
| 상태 | 해결 (2026-11-27 4a1bae7 배포 후 화면 확인) |
| 관련 커밋·이슈 | 83190a5 (원인 코드 7ec2ccd) |

> 파일 이름: `docs/길동현/troubleshooting/20261127-봇대회-목록-500-formatted-퍼센트.md`

## 1. 문제

- 현상: 관리자 화면 "봇 대회 결과"를 열면 대회 선택 칸이 "대회 기록 없음"이고, 오류 상자가 뜬다.
  - 처음 부르는 대회 목록 API `GET /api/v1/admin/contests`가 `HTTP 500 INTERNAL_ERROR`를 돌려준다.
  - 응답이 0.8초 만에 와서 시간 초과는 아니었다.
- 재현 조건: 항상. 대회 데이터가 있든 없든, 누가 열든 같다.
- 영향: 봇 대회 결과를 화면에서 전혀 볼 수 없다. 데이터는 손상되지 않는다 (읽기 전용 API).

## 2. 원인

- 가설 1: 목록 SQL이 Oracle에서 실패한다 (정규식·`FETCH FIRST` 등).
  - 확인: 서버와 같은 이미지(`gvenzl/oracle-free:23-slim-faststart`)를 띄워 SQL을 예시 데이터로 그대로 실행했다.
  - 결과: 정상이었다. 다만 이건 자바가 문자열을 만든 **뒤의** SQL을 손으로 옮긴 것이라 아래 원인을 거치지 않았다.
- 가설 2: 자바 쪽 예외. 서버 로그에서 확인했다.
  - 앱은 `jejari`가 아니라 `jejari@8080` 이름으로 돈다.
  - 서버 시계가 UTC라 `--since "13:30"`처럼 시각을 주면 잡히지 않는다. `--since "2 hours ago"`로 찾았다.
- 최종 원인: `ContestResultService.list()`가 SQL을 `"""…""".formatted(KIND, IS_PARTICIPANT)`로 만든다. 그 안의 `LIKE 'bot%'`, `LIKE 'human%'`에서 `%'`를 `String.format`이 채울 자리로 읽어 `UnknownFormatConversionException`이 났다. 같은 문장의 `'lt%%'`는 이스케이프돼 있었는데 이 두 줄만 빠졌다.

```
sudo journalctl -u 'jejari@*' --since "2 hours ago" --no-pager | grep -A40 "unexpected error"

ERROR ... c.j.common.error.GlobalExceptionHandler : unexpected error
java.util.UnknownFormatConversionException: Conversion = '''
    at java.base/java.lang.String.formatted(String.java:4441)
    at com.jejari.admin.contest.ContestResultService.list(ContestResultService.java:76)
    at com.jejari.admin.contest.web.ContestAdminController.list(ContestAdminController.java:40)
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| `%` → `%%`로 이스케이프 | 두 글자 수정, 동작 그대로 | 다음에 `%`를 쓸 때 또 빠뜨릴 수 있음 | ✓ |
| `formatted()` 대신 문자열 이어 붙이기 (`" + KIND + "`) | `%`를 신경 쓰지 않아도 됨 | 같은 파일의 다른 쿼리와 모양이 달라지고 수정 범위가 커짐 | |
| `LIKE` 패턴을 `?` 바인드 값으로 넘기기 | SQL 문자열에 `%`가 아예 없음 | 쿼리 모양이 바뀌어 다시 검증이 필요 | |

- 선택한 이유: 원인이 정확히 두 글자이고, 같은 문장이 이미 `'lt%%'`로 같은 방식을 쓰고 있다.
- 바뀐 코드 위치: `src/main/java/com/jejari/admin/contest/ContestResultService.java` 72~73줄 (83190a5)
- 같은 파일의 다른 `formatted()`(`runsOf`)에는 `%`가 없어 문제없다.

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| `formatted()` 결과 | `UnknownFormatConversionException` | `LIKE 'bot%'`, `LIKE 'human%'`가 든 정상 SQL |
| `GET /api/v1/admin/contests` | 500 (매번) | 200, 대회 목록 표시 |

- 측정 환경: 로컬 JDK 21에서 같은 텍스트 블록을 `formatted()`로 실행해 출력 확인. Oracle 쿼리는 `oracle-free:23` 컨테이너에서 확인.
- 측정 방법: 4a1bae7 배포 후 관리자 화면 "봇 대회 결과"를 열어 대회 목록이 뜨는 것을 확인했다.

## 5. 정리

- 면접용 한 줄 요약: "`String.formatted()`로 만든 SQL 안의 `LIKE 'bot%'`가 서식 지정자로 읽혀 목록 API가 항상 500이었고, 서버 스택 트레이스로 원인을 찾아 `%%`로 이스케이프해 고쳤다."
- 다음에 비슷한 상황이면:
  - `formatted()`/`String.format()`로 SQL을 만들 땐 문자열 안의 `%`를 모두 `%%`로 쓴다. 가능하면 `LIKE` 값은 `?` 바인드로 넘긴다.
  - SQL만 따로 돌려 정상이어도 자바가 문자열을 만드는 단계에서 터질 수 있다. 500이면 먼저 서버 로그의 `unexpected error` 스택을 본다 (`journalctl -u 'jejari@*'`, 시각 대신 `--since "N hours ago"`).
