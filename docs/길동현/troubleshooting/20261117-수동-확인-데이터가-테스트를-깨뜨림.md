## 1. 문제

- 알림 기능을 넣고 전체 `infraTest`를 돌리니 관리자 현황·좌석 선점·좌석 배치도·취소표 테스트 7개 실패
- 숫자가 1~2씩 어긋남 (`expected: 522 but was: 521`, `expected: 0 but was: 1`)

## 2. 원인

- 가설: 내 코드가 좌석을 건드렸나? → 실패한 테스트는 알림과 상관없는 좌석 수 세기
- 확인: 회원 범위 밖의 `seat_inventory` 행 조회 → **운행 9001 좌석 1개가 SOLD**, 오전에 curl로 결제를 확인할 때 만든 예약(회원 82)
- 최종 원인: 테스트는 자기 회원 범위만 지우므로, 손으로 만든 예약은 아무도 안 지움. 공용 운행 좌석이 하나 팔린 상태라 남은 좌석 수가 하나씩 어긋남

## 3. 해결

- 회원 82·83의 예약 관련 행(예약·좌석·결제·이력·outbox·매수 카운터)과 Redis 좌석 키 1개 삭제 (회원 계정은 유지)
- 다시 돌리니 393개 모두 통과

## 4. 수치

| 지표 | 전 | 후 |
|---|---|---|
| 인프라 테스트 실패 | 7 / 393 | 0 / 393 |

## 5. 정리

- 한 줄 요약: "다른 팀 테스트 7개가 숫자 1 차이로 실패해서 보니 내가 손으로 결제해 본 좌석이 남아 있었고, 그 예약을 지우니 모두 통과했다."
- 다음에 비슷한 상황이면: 손으로 확인한 뒤에는 그 예약을 취소하거나 지운다. 숫자가 1씩 어긋나는 실패는 코드보다 남은 데이터부터 본다.
