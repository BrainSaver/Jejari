# [infra] Oracle 컨테이너 재시작 직후 DB 테스트가 대부분 실패 (ORA-01109)

| 항목 | 내용 |
|---|---|
| 작성자 | 길동현 |
| 날짜 | 2026-11-16 |
| 상태 | 해결 |
| 관련 커밋·이슈 | `0f9f181` (테스트 대상), 코드 변경 없음 |

> 파일 이름: `docs/길동현/troubleshooting/20261116-oracle-재시작-직후-테스트-실패.md`

## 1. 문제

- 현상: IntelliJ에서 `OutboxInboxInfraTest`를 돌리니 **1개 통과, 8개 실패**. 방금 전 명령줄에서는 9개 모두 통과했던 테스트

```
ORA-01109: database not open
ORA-12514: Cannot connect to database. Service FREEPDB1 is not registered with the listener
```

- 재현 조건: Oracle 컨테이너가 재시작된 직후 몇 분 안에 테스트 실행 (`docker compose ps`는 `healthy`)
- 영향: 코드가 맞는데도 테스트가 깨져 보임. 유일하게 통과한 1개는 DB 연결 전에 예외가 나는 테스트였음

## 2. 원인

- 가설: 코드가 아니라 DB 상태 문제 (에러가 전부 접속 단계의 `ORA-`) → 컨테이너 로그 확인

```
docker logs jejari-oracle-1 2>&1 | Select-String "FREEPDB1"
# 14:38 컨테이너 재시작 … 14:42:14 FREEPDB1 opened
```

- 최종 원인: Oracle Free는 컨테이너(CDB)가 뜬 뒤 **실제 앱이 쓰는 PDB(FREEPDB1)를 몇 분 늦게 엽니다.** healthcheck는 그 전에 `healthy`가 될 수 있어서, 그 사이에 접속하면 실패합니다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 로그에서 `FREEPDB1 opened`를 확인한 뒤 실행 | 바로 가능, 팀 파일 그대로 | 매번 사람이 확인 | ✓ |
| compose healthcheck를 PDB 접속 확인으로 변경 | `healthy` = 쓸 수 있음 | 공용 파일(조영준 담당) 수정 필요 | 제안 |

```powershell
docker logs jejari-oracle-1 2>&1 | Select-String "FREEPDB1 opened"
```

- 위 줄이 나온 뒤 다시 돌리니 9/9 통과.

## 4. 수치

| 지표 | 열리기 전 | 열린 뒤 |
|---|---|---|
| `OutboxInboxInfraTest` 통과 | 1 / 9 | 9 / 9 |

- 측정 환경: 로컬 Docker Compose (Oracle Free 23ai)

## 5. 정리

- 한 줄 요약: "Oracle 재시작 직후 DB 테스트가 대부분 실패해서 로그를 보니 healthy와 별개로 PDB가 4분 뒤에야 열렸고, PDB 열림을 확인한 뒤 실행하니 모두 통과했다."
- 다음에 비슷한 상황이면: 갑자기 여러 DB 테스트가 같이 깨지면 코드보다 먼저 `ORA-` 번호와 컨테이너 로그를 본다.
