# A-08 배포 (공용 서버)

- 기능: INF-03 (공용 서버 운영)
- 담당: 조영준
- 시안: 없음 (운영 도구, 프로젝트가 끝나면 지움)
- 구현: `frontend/src/admin/Deploy.jsx` (+ 서버 `DeployAdminController`·`DeployAdminService`) (2026-11-19)

## 목적

팀원이 main에 올린 변경을 자동 배포 주기(20분)를 기다리지 않고 바로 공용 서버에 반영합니다. 버튼은 서버의 자동 배포 장치(`jejari-autodeploy`)를 지금 한 번 실행시킬 뿐이라, "CI를 통과한 main만", "ERD·DB 패치가 있으면 멈춤(BLOCKED)"이 그대로 적용됩니다.

## 화면 구성

- 지금 서버: 배포된 커밋(번호·제목), 마지막 판단(정상 / CI 기다림 / CI 실패 / 멈춤 / 실패)과 시각·내용, 마지막 수동 요청
- 판단별 할 일 안내 (멈춤이면 "버튼으로 못 풂 → 운영자가 DB 패치")
- "지금 배포" 두 단계 버튼, 진행 중 표시 (5초마다 다시 읽음)

## 동작

1. `GET /api/v1/admin/deploy` (VIEWER): 서버 파일 `~/jejari-app/deployed-sha`·`autodeploy.state`·`deploy-requests.log`와 `systemctl is-active`로 상태
2. `POST /api/v1/admin/deploy` (SUPERVISOR 중 서버 `.env` `JEJARI_OPS_DEPLOY_ADMIN_IDS`에 적힌 관리자): `sudo systemctl start --no-block jejari-autodeploy.service`로 시작만 걸고 바로 응답. 진행 중이면 409, 1분 안에 다시 누르면 429, 서버에서 꺼져 있으면 404
3. 배포 중에는 앱이 한 대씩 재시작돼 이 화면의 요청이 잠깐 실패할 수 있음 → 화면은 오류를 숨기고 다시 읽음
