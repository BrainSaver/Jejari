# U-06 결제 (기한 카운트다운)

- 기능: PAY-01, RSV-05, WL-05
- 담당: 길동현 · 강동균
- 시안: `docs/ui/U-06.html`

## 목적

선점한 예약을 결제 기한 안에 결제합니다. 취소표 제안을 받은 예약도 이 화면에서 결제하면 수락입니다.

## 화면 구성

- 결제 기한 카운트다운 (서버의 `pay_deadline_at` 기준)
- 예약 요약: 운행, 좌석, 승객, 금액
- 결제 수단: 등록한 가상 카드 선택, 없으면 이 화면에서 가상 카드번호 입력 (1차는 U-09 없이 여기서 등록, 기능설계서 1.1)
- 결제하기 버튼, 선점 취소 버튼
- 취소표 제안이면 "취소표 제안 · 10분 안에 결제하면 확정" 띠

## 동작

1. 결제하기를 누르면 멱등 키를 만들고 `POST /reservations/{id}/payments`. 버튼은 응답까지 잠급니다.
2. 결제를 시작하면 서버가 기한을 한 번 연장합니다. 응답의 새 기한으로 카운트다운을 다시 맞춥니다.
3. 결과가 오면 U-07로 갑니다. PG 응답이 늦으면 U-07에서 "확인 중"으로 기다립니다.
4. 선점 취소를 누르면 `POST /reservations/{id}/cancel` (HOLD만 가능, 수수료 없음) 후 U-03.
5. 기한이 지나면 버튼을 막고 "결제 기한이 지났어요"를 보여줍니다.

## 연결 API

| 메서드 | 경로 | 언제 |
|---|---|---|
| GET | `/api/v1/reservations/{id}` | 화면 열 때 |
| GET | `/api/v1/me/payment-methods` | 결제 수단 목록 |
| POST | `/api/v1/reservations/{id}/payments` | 결제하기 (Idempotency-Key) |
| POST | `/api/v1/reservations/{id}/cancel` | 선점 취소 |

## 오류·예외 표시

| 코드 | 화면에 보이는 것 |
|---|---|
| `RESERVATION_EXPIRED` | "결제 기한이 지나 좌석이 풀렸어요" 후 U-03 |
| `SEAT_LOST` | "좌석을 잃었어요. 다시 예매해 주세요" |
| `PAYMENT_DUPLICATED` | 이미 시작된 결제로 U-07 이동 |
| `RESERVATION_NOT_HOLD` | 현재 상태를 다시 읽어 맞는 화면으로 |
| `PAYMENT_IN_PROGRESS` | 선점 취소 시 "결제 중이라 취소할 수 없어요" |

## 메모

- 결제 실패 후 재시도는 없습니다 (다시 예매). 1차 PG는 직접 만든 Mock PG입니다.
