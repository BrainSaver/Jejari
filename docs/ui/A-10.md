## 목적

명절 예매가 열리는 순간 **지금 얼마나 몰리고, 어디가 느리거나 깨지는지**를 관리자 로그인만으로 한 화면에서 봅니다.
Grafana "제자리 · 앱 개요"와 같은 지표(127.0.0.1에만 열려 있어 서버 접속이 필요)를 관리자 화면 안으로 가져온 것입니다.
큰 회사 관제 화면의 흔한 순서를 따릅니다: ① 지금 괜찮은가 → ② 얼마나 몰리나 → ③ 어디가 병목인가.

## 화면 구성 (위에서 아래로)

| 영역 | 내용 | 갱신 |
|---|---|---|
| 상태 띠 | 정상 · 주의 · 위험 + 이유 (아래 문턱) | 10초 |
| **실시간 흐름도** | 사용자 → 업무 영역 6개 → 앱 서버 → Redis·Oracle·MongoDB·Kafka. **동그란 점이 요청**이고 실제 초당 값만큼 흐른다 | 2초 |
| KPI | 초당 요청(평소의 N배·최고) · 응답 p95(p50·p99) · 5xx 비율(429 비율) · 대기열(입장) · 예약·결제 성공/초(409) · 앱 서버 응답 대수 | 10초 |
| 자원 | CPU · 힙 · DB 커넥션(대기 수) · Tomcat 스레드 · Redis 메모리. 막대 + 주의·위험 눈금 | 10초 |
| 그래프 6개 | 영역별 초당 요청 · 응답 시간 · 실패·거절 비율 · 업무 처리량 · 대기열 · 자원 사용률. 기간 30분·1시간·6시간·24시간, 마우스를 올리면 그 시각 값 | 10초 |
| 많이 불린 API | 최근 1분 위 10개: 초당 · 비중 · p95 · 5xx 비율 | 10초 |

### 흐름도 읽는 법

- **파란 점** = 정상 요청, **빨간 큰 점** = 5xx (영역 노드에서 터짐), **노란 빈 점** = 429 요청 제한 (노드 앞에서 되돌아감)
- 점 수는 꾸민 움직임이 아니라 **실제 비율** 그대로: 가장 바쁜 선이 초당 점 25개를 넘지 않게 "점 1개 = N건"을 1·2·5 단위로 고르고 범례에 적는다. 요청과 저장소 작업은 단위를 따로 쓴다 (요청 1건이 Redis 명령 여러 개라)
- 선 굵기 = 초당 값 (로그). 노드 테두리 초록 정상 · 노랑 주의(오류 1%↑ 또는 평균 1초↑) · 빨강 위험(오류 5%↑)
- 노드에 마우스를 올리면 자세한 값, "표로 보기"는 같은 값을 표로 (색을 못 쓰는 경우)
- 움직임 줄이기 설정(prefers-reduced-motion)이면 점 없이 선 굵기·숫자만

### 업무 영역 (URI 템플릿으로 나눔, `TrafficService.group`)

대기열 `/api/v1/runs/*/queue*` · 좌석 조회 `/api/v1/runs/*/seats*` · 예약·결제 `/api/v1/reservations*`·`/api/v1/waitlists*` · 로그인·내 정보 `/api/v1/auth*`·`/api/v1/me*` · 관리자 `/api/v1/admin*` · 기타 (actuator 제외)

## 상태 문턱 (`TrafficService.health`, 바꾸면 이 표도)

| 지표 | 주의 | 위험 |
|---|---|---|
| 5xx 비율 | 1% | 5% |
| 응답 p95 | 1초 | 3초 |
| DB 커넥션 풀 | 80% (또는 대기 1개↑) | 95% |
| Tomcat 스레드 | 80% | 95% |
| CPU | 80% | 95% |
| 힙 | 85% | 95% |
| Redis 메모리 | 80% | 90% (noeviction이라 다 차면 쓰기 실패) |
| 앱 응답 | 일부 안 됨 | 전부 안 됨 · 수집 안 됨 |

**알림**(장애 아님): 트래픽 급증(직전 1시간 평균의 3배↑, 초당 5건↑), 429 요청 제한 5%↑. 명절 예매 시작에는 당연히 몰리므로 급증 자체는 빨간색이 아니다 — 그때 함께 볼 것은 응답 시간과 오류율.

## API

| 메서드 | 경로 | 권한 | 설명 |
|---|---|---|---|
| GET | `/api/v1/admin/traffic?range=30m\|1h\|6h\|24h` | VIEWER | 상태·KPI·그래프(공통 시각 `t` + 선별 값)·API 표. 4초 캐시 |
| GET | `/api/v1/admin/traffic/flow` | VIEWER | 흐름도 값 (최근 30초 초당). 1.5초 캐시 |

- 서버가 Prometheus(`jejari.ops.prometheus-url`, 기본 `http://127.0.0.1:9090`, 환경변수 `JEJARI_PROMETHEUS_URL`)에 **고정 쿼리**만 보낸다. 화면은 기간만 고르므로 관리자 화면을 통해 아무 PromQL이나 보내는 통로가 없다
- Prometheus가 꺼져 있으면 `available: false` + 이유 → 화면은 "확인 불가" 띠. 앱 나머지는 영향 없음 (3초 시간 초과)
- 대기열 인원 지표 `jejari_queue_waiting`·`jejari_queue_active`는 이번에 새로 내보낸다 (`QueueMetrics`, 대기열 Redis 키를 읽기만). 배포 직후에는 그래프 앞부분이 비어 있다
- 개인정보 없음 (요청 수·응답 시간·자원)
