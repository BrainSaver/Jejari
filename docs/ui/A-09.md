# A-09 모델 관리

- 기능: RISK-05 (위험 점수 모델 보조 의견) 이어서
- 담당: 강동균
- 시안: 없음 (운영 도구)
- 구현: `frontend/src/admin/Models.jsx` (+ 서버 `ModelAdminController`·`ModelAdminService`) (2026-11-19)

## 목적

합성 모델 버전(`model_run`, algorithm = ENSEMBLE)을 **실데이터 점수로 비교**하고, 케이스 화면(A-06) "모델 보조 의견" 카드에 보여 줄 버전을 고릅니다.
모델 점수는 보조 의견뿐이라 대기열 순번·이용 제한·케이스 열기에는 영향이 없습니다.

**학습은 이 화면에서 하지 않습니다.** 공용 서버 CPU가 이미 바빠(PERF-01) 화면 요청으로 학습을 돌리지 않고, 점수는 서버의 매시간 작업(`deploy/model-refresh.sh`)이 등록된 모든 버전으로 매겨 둡니다. 새 버전은 집계자 PC 등에서 학습(`tools/ml/train_next.py`)해 `data/ml/model-*`에 올리고, `model_run` 행(ERD 패치)과 `MODELS` 목록에 더하면 다음 시간부터 여기 나타납니다.

## 사용자가 많아질수록 똑똑해지는 순환

1. **무작위 점검 표본** (이 화면): 최근 7일 활동 계정을 무작위로 골라 케이스(trigger ADMIN, "무작위 점검 표본 …")로 연다 → 관리자가 평소처럼 판정. 규칙·모델이 연 케이스의 판정만 쓰면 이미 잡던 봇만 더 잘 잡게 되는 것을 막는 치우침 없는 정답
2. **주간 재학습** (서버, 일요일 새벽 `deploy/model-retrain.sh`): 실데이터로 사람 기준 갱신 + 판정이 충분하면 다시 학습 → 지금 모델과 자동 시험 → 통과한 것만 꺼진 후보(`ens-w…`)로 등록
3. **사람이 켬** (이 화면): 후보는 매시간 지금 모델과 나란히 채점된다. 버전 표의 "자동 시험" 결과와 두 버전 비교를 보고 켠다

## 화면 구성

- 무작위 점검 표본: 판정 대기·끝(봇·사람) 수, 계정 수(1~20) + "표본 뽑기" 두 단계 버튼 (REVIEWER), 열린 케이스 링크
- 버전 표: 버전 · 상태(사용 중/꺼짐, "사용 중으로" 두 단계 버튼) · 학습 시각·데이터 · 문턱 · 점수 계정 수 · 봇 쪽으로 본 수(%) · 닮은 유형별 수 · 관리자 판정과 맞은 수 · 마지막 점수 시각
- 두 버전 비교: 둘 다 봇 쪽 / 한쪽만 봇 쪽 수, 한쪽만 봇 쪽으로 본 계정 위 50개 (두 점수 · 닮은 유형 · 관리자 판정)
- 이 화면이 보낸 요청 (traceId)

## 읽는 법

- **"관리자 판정과"는 판정이 있는 계정만** 셉니다. 케이스 판정(verdict)이 RESELLER·MACRO·CANCEL_ABUSE면 봇, NORMAL이면 사람. 규칙이 연 케이스에만 판정이 있어 **규칙 쪽으로 치우친 숫자**입니다. "사람 판정 중 봇 쪽으로 봄"이 실제 오탐 사례라 가장 중요합니다
- 실데이터에는 정답이 없어 탐지율을 낼 수 없습니다. 두 버전이 **다르게 본 계정**을 열어 보는 것이 이 화면의 핵심입니다 (계정 번호로 케이스·재생을 찾아 확인)

## 동작

1. `GET /api/v1/admin/models` (VIEWER): `model_run`의 ENSEMBLE 버전 + MongoDB `model_score`에서 버전별 집계
2. `GET /api/v1/admin/models/compare?a=&b=` (VIEWER): 두 버전의 문턱 이상 계정 비교
3. `POST /api/v1/admin/models/{version}/activate` (SUPERVISOR): `UPDATE model_run SET is_active = CASE …` 한 문장으로 ENSEMBLE 하나만 Y. 점수가 없는 버전은 409 `MODEL_NOT_SCORED`, 없는 버전은 404
