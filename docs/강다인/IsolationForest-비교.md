# Isolation Forest 비교 — 규칙 엔진·합성 모델과 같은 대회 계정으로 (RISK-05)

> 작성: 강다인 · 2026-11-26 · 상태: **완료** · 모델·특징·학습: 강동균 [`tools/ml/`](../../tools/ml/README.md) · 규칙 엔진: 강다인 [위험점수-규칙](features/위험점수-규칙.md)

## 한 줄 결론

**Isolation Forest(IF)는 규칙 엔진이 이미 잡는 "튀는" 봇만 잡고, 규칙이 놓친 사람 같은 봇(botc)은 하나도 못 잡는다.**
실제 사람 점수가 봇 바로 아래(0.9점 차)까지 붙어 있어 문턱을 조금만 내려도 오탐이 쏟아진다.
→ 지금 결정(규칙이 판정, 모델은 관리자 보조 의견, IF는 그 안의 안전망)을 그대로 둔다.

## 무엇을 비교했나

| 이름 | 무엇 | 판정 기준 |
|---|---|---|
| 규칙 엔진 | 다인 담당. 점수 + 마커 규칙 → 의심 케이스 | **케이스가 열린 계정** (`eval_contest.sh`, 대회 날 실제 서버) |
| IF 혼자 | 라벨 없이 "생성 데이터 사람과 다른 계정" | 사람 기준 백분위 **95 이상** (= 생성 데이터 사람 오탐 5%, 팀 목표) |
| 합성 모델 | 부스팅 + IF (GRU 없이) 중 큰 값 | 학습 때 정한 문턱 96.4 (`threshold_base`) |

- 모델: `data/ml/model/model.pkl` (2026-11-18 학습, 생성 데이터 18,000명). **대회 데이터로는 학습하지 않음** (적용만)
- 데이터: 대회 실제 서버 기록 `data/ml/contest-*`. 사람·봇 라벨은 대회 참가 기록
- 규칙 결과가 같이 남아 있는 대회는 **c1124d**(사람 27 · botb 6 · botc 6)뿐이라 이 대회가 본 비교. 나머지는 봇 쪽 참고

## 결과 — c1124d (2026-11-24 대회, 사람 27명)

| | botb 6 (브라우저 자동화, 빠름) | botc 6 (규칙을 아는 사람 같은 봇) | 사람 오탐 (27명) |
|---|---|---|---|
| 규칙 엔진 | **6/6** (HEADLESS_HOLD · LINEAR_MOUSE) | 0/6 | **0/27** |
| IF 혼자 | 5/6 | **0/6** | 0/27 |
| 합성 모델 (부스팅 + IF) | 6/6 | **6/6** | **4/27 (14.8%)** |
| 규칙 OR IF | 6/6 | 0/6 | 0/27 |

- **IF를 규칙에 더해도 새로 잡는 봇이 0**이다 (규칙 OR IF = 규칙 혼자)
- botc는 IF 점수 중앙값 52.6 — 사람(89.6)보다도 **덜 튀어** 보인다. 사람처럼 움직이도록 만든 봇은 "평소와 다름"으로는 안 잡힌다
- botc를 잡는 건 라벨로 배운 **부스팅**인데, 대신 진짜 사람 4명을 같이 잡는다 (팀 목표 오탐 5% 초과) → 보조 의견에만

### IF 점수 분포 — 사람과 봇 사이 여유가 거의 없다

| | IF 점수 (사람 기준 백분위) |
|---|---|
| 사람 27명 | 77.5 ~ **93.6** (중앙값 89.6) |
| botb 6 | **94.5** ~ 97.8 |
| botc 6 | 중앙값 52.6 |

| IF 문턱 | botb | botc | 사람 오탐 |
|---|---|---|---|
| 95 (지금) | 5/6 | 0/6 | 0/27 |
| 90 | 6/6 | 0/6 | **13/27** |
| 85 | 6/6 | 0/6 | **25/27** |

- 생성 데이터의 사람 기준으로 백분위 95를 문턱으로 잡았는데, **실제 사람은 생성 데이터 사람보다 훨씬 튄다** (중앙값 89.6 = 생성 사람 상위 10% 수준)
- 그래서 오탐 0은 운이 좋은 쪽에 가깝다. 사람 최고 93.6과 botb 최저 94.5가 **0.9점 차**. 실제 서비스처럼 사람이 수천 명이면 문턱 95 위로 넘어오는 사람이 생긴다

- 1차 대회(c1119) 때 규칙 엔진은 케이스 0건이었고, 그 뒤 LINEAR_MOUSE · HEADLESS_HOLD · INHUMAN_STEP을 넣어 11-24 대회에서 botb 6/6이 됐다 ([봇-탐지-보강](features/봇-탐지-보강.md))

## 생성 데이터에서는 (강동균, 2026-11-18, `compare.py`)

| | IF | 부스팅 |
|---|---|---|
| 섞어서 나누기 — 탐지 / 오탐 | 28.7% / 6.8% | 100% / 3.8% |
| 계열 하나 빼기 (처음 보는 수법) — 탐지 / 오탐 | 36.1% / 6.8% | 78.9% / 4.1% |

실제 대회 결과와 같은 방향: IF는 혼자 쓰기에 약하고, 부스팅과 합쳤을 때 "속도형"(29 → 89%) 같은 튀는 계열을 보태는 안전망 역할.

## 그래서

| 결정 | 이유 |
|---|---|
| IF를 판정(케이스·순번)에 쓰지 않는다 | 규칙이 잡는 봇과 겹치고, 사람과의 여유가 0.9점이라 문턱을 못 내린다 |
| IF는 합성 모델 안 안전망으로 유지 | 생성 데이터 "처음 보는 계열"에서 부스팅 74% → 합쳐서 87% (강동균) |
| botc 같은 봇은 규칙으로 | 모델이 잡는 근거가 "새 계정 + 둘러보지 않음 + 이벤트 수" 같은 약한 신호라 사람도 같이 잡힌다. 규칙 쪽 후보는 [대회-보강-후보](대회-보강-후보.md) |
| 오탐 판단은 사람 수를 늘려서 | 사람 27명으로는 1명 = 3.7%p. 2차 대회 판정 기준도 "30명 미만이면 보류" |

## 다시 돌리는 법

```bash
pip install scikit-learn numpy          # torch 없어도 됨 (GRU 없이 부스팅 + IF)
python -I - <<'EOF'
import sys, pickle, numpy as np
sys.path.insert(0, 'tools/ml')
from score import parts, apply_exon
from compare import load
m = pickle.load(open('data/ml/model/model.pkl', 'rb'))
rows, _ = load('data/ml/contest-c1124d/features.csv')
X = np.array([[float(r[k]) if r[k] not in ('', 'nan') else np.nan for k in m['features']] for r in rows])
P = parts(m, X, None)                                    # 모델별 백분위 {'부스팅': …, 'IF': …}
comb = apply_exon(m, X, np.maximum.reduce(list(P.values())))
for kind in ('botb', 'botc', 'human'):
    i = [j for j, r in enumerate(rows) if r['strategy'] == kind]
    print(kind, len(i), 'IF>=95', int((P['IF'][i] >= 95).sum()), '합성', int((comb[i] >= m['threshold_base']).sum()))
EOF
# 규칙 엔진 결과: data/ml/contest-c1124d/eval.txt (대회 날 loadtest/tools/eval_contest.sh 출력)
```

`data/`는 git에 없다 (대회 기록이라). 대회 집계자 PC에서 받은 `data/ml/contest-*`, `data/ml/model`이 필요하다.
