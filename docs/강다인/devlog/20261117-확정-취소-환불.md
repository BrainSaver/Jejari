## 어떻게 했나

```
POST /cancel → 상태 읽기 → HOLD·PAYMENT_PENDING → SeatReleaseService.cancelBeforePay (B)
                        → CONFIRMED → [tx] 예약 FOR UPDATE → 수수료 재계산 → CANCELED → returnSoldSeatsInCurrentTx (B)
                                         → cancellation(cancellation_seq) → outbox RESERVATION_CANCELED → history
                                     [커밋 뒤] PgClient.refund → cancellation DONE + payment REFUNDED / FAILED
```

## 왜 이렇게 했나

- **수수료는 서버가 잠근 뒤 다시 계산**: 미리보기 값을 받아 쓰면 클라이언트가 0원으로 바꿔 보낼 수 있다. 잠근 뒤라 계산하는 사이 상태가 바뀌지 않는다.
- **예약 행 먼저 잠금 (§0.4)**: 같은 예약의 취소·결제 처리가 줄을 선다. 동시에 세 번 눌러도 한 번만 취소되고 카운터도 한 번만 준다.
- **환불은 커밋 뒤, 트랜잭션 밖 (§0.6)**: PG가 느릴 때 DB 락을 오래 잡으면 그 예약의 다른 처리와 좌석 반환이 막힌다.
- **환불 실패해도 취소는 유지**: 취소를 되돌리면 이미 돌려준 좌석·카운터가 꼬인다. 돈은 FAILED로 남겨 재시도(CNL-03)로 돌려준다.
- **환불 키 `cancel:<id>`**: 재시도로 두 번 환불되는 일을 PG 쪽에서 막는다.
- **좌석 반환은 B 메서드 그대로**: SOLD 삭제·카운터 감소·REOFFER 순서와 보상 경로를 B가 이미 맞춰 둠. 같은 일을 다시 만들면 두 곳이 어긋난다.

## 막힌 점과 해결

- **PG에 환불 기능이 없었음**: `PgClient`(C)는 승인·조회·주문 막기만 있었다 → 환불 메서드를 추가하고 가짜 PG는 바로 성공. 실제 PG로 바꿀 때 구현해야 해서 길동현 님께 알림.
- **cancellation에 정책 ID가 필요**: 예매 내역 상세의 취소 정보에 정책 ID가 없었다 → 응답에는 숨기고(`@JsonIgnore`) 내부에서만 쓰도록 추가.
- **테스트 기대값 키 이름**: 이벤트의 좌석 키는 `seats`인데 `seatIds`로 적어 실패 → 테스트 수정 (코드는 맞음).

## 배운 점

- 돈이 걸린 값은 화면에서 보여 준 값을 받아 쓰지 말고 **처리 시점에 서버가 다시 계산**한다. 미리보기와 실제가 같은 함수를 쓰면 결과도 같다.
- 외부 호출(PG)은 DB 트랜잭션과 분리하고, 실패하면 "되돌리기"가 아니라 **"재시도할 수 있게 남기기"**를 기본으로 한다.
- 다른 사람 코드는 이미 비워 둔 자리(주석)에 최소한으로만 끼운다. 기존 테스트가 그대로 통과하는지 같이 돌린다.
