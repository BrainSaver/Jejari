### 5. 로그인 503 안내 (조영준 님 요청)

- 조영준 님이 PERF-01 개선 1로 동시 비밀번호 해시 수를 32 → 4로 줄이면 로그인이 몰릴 때 503이 날 수 있다며, 가입·로그인 화면 안내 확인을 요청
- 확인: 앱이 준 503은 서버 문구("잠시 후 다시")가 나오지만 ① 앞단(Caddy)·재시작 중 503은 본문이 없어 "요청이 실패했어요 (503)"만 뜸 ② 로그인 실패 때 **비밀번호 칸을 무조건 비움** → 사용자 잘못이 아닌데 다시 입력하게 함
- 고침: `lib/busy.js`(SERVICE_UNAVAILABLE·HTTP 502/503/504 = 바쁨) → 회원 로그인·가입·관리자 로그인이 같은 문구 "입력한 내용은 그대로 두었으니 몇 초 뒤 다시". 바쁠 때는 비밀번호를 지우지 않음
- 가입 중 503이어도 본인인증 토큰은 그대로 (해시 → 토큰 소비 순서라 해시에서 실패하면 토큰을 안 씀) → 다시 누르면 됨

### 10. 예매 완료 알림 (다인 님 요청)

- 예매해도 알림함에 아무것도 안 뜸 → 알림 종류에 "예매 완료"가 없었음 (만료·환불·취소표·결제 임박만)
- `RESERVATION_CONFIRMED` → 알림 `CONFIRMED`, 알림 목록에 표 요약(열차·날짜·출발·구간·좌석, **내 예약일 때만**), 화면 "예매가 완료됐어요 · 00049 열차 · 11월 19일(목) 15:45 · 서울 → 부산 · 2호차 7A" + [예매 내역 보기 →], 예매 내역은 `?open=`으로 그 표를 펼치고 스크롤
- **ERD 필요**: `notification.type` CHECK에 CONFIRMED → 강동균 님께 요청. 패치 전에 넣다가 CHECK에 걸리면 알림 처리기가 그 이벤트를 끝없이 재시도하며 다른 알림까지 멈춤 → **넣기 전에 DB 제약을 확인하고 없으면 그 한 건만 건너뜀**(5분마다 다시 확인, 패치하면 재시작 없이 켜짐). 처음엔 저장 실패를 잡으려 했는데, 저장 메서드가 `@Transactional`이라 안에서 실패하면 바깥 트랜잭션이 롤백 예정이 돼서 안 됨 → 미리 확인으로 바꿈. 그래서 main에도 바로 합침
- 막힌 것: 전체 테스트가 메모리 부족으로 강제 종료 → Docker Desktop이 멈춰 Oracle·Mongo·Kafka unhealthy → 다인 님이 Docker 재시작, 필요한 컨테이너 4개만 다시 켬. 알림 테스트 8개가 "다른 사람이 먼저 선택한 좌석"으로 실패 → 11-17 로컬 예약이 테스트 좌석을 쓰고 있었음. 테스트가 빈 좌석만 고르게 고침 (길동현 님 테스트)
- 테스트: 알림 통합 10 (CONFIRMED·표 요약·남의 예약은 요약 없음 포함)
- 강동균 님이 ERD v30으로 CHECK에 CONFIRMED 추가 → 로컬에 v28~v30 적용. 이제 공용 서버에서도 예매 완료 알림이 뜬다 (재시작 없이 5분 안)
