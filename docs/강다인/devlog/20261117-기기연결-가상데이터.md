# 2026-11-17 · 회원↔기기 연결 기록 (DATA-02 준비) · 봇 탐지 평가

> 작성: 강다인 · 관련: DATA-02(E·D), DATA-03(조영준), RISK-02, QUE-01 · 같은 날: [위험 점수 배치](20261117-위험점수-1분-배치.md)
> 커밋: `fix(behavior): 행동 로그 적재 때 회원↔기기 연결(member_device) 기록`

## 한 일

- 조영준 님 k6 시나리오 12로 봇 탐지 평가 직접 실행: **탐지율 100% (24/24), 오탐률 0% (0/40)**
- 조영준 님이 시나리오 12·`eval_risk.sh`를 넘겨줌 → DATA-02(가상 회원·예매 데이터)를 D가 진행하기로 하고, 첫 단계로 `member_device` 기록
- **`member_device`를 쓰는 코드가 레포 전체에 없던 문제** 해결 (팀원·조영준 님 지적): 행동 로그 적재(`BehaviorSink`)가 (회원, 기기) 쌍을 MERGE

## 왜 중요했나

- `member_device`를 읽는 곳은 두 군데: 대기열의 회원 조회(`OracleMemberIdentityPort`)와 위험 점수 배치(`RiskInputReader`).
- 비어 있으면 **기기 점수가 대기열 패널티에 전혀 반영되지 않는다**. 한 기기로 여러 계정을 돌리는 봇(MULTI_ACCOUNT_SYNC)이 기기 점수를 받아도 대기열에서 뒤로 밀리지 않던 상태.
- 관리자 화면에서 기기 케이스의 연결 계정도 비어 있었다.

## 어떻게 했나

```
행동 로그 묶음 → (회원, 기기) 쌍별 처음·마지막 시각 → MERGE member_device → Mongo insertMany → risk:dirty
```

| 규칙 | 이유 |
|---|---|
| 없는 회원 ID는 원천 쿼리가 비어 아무 일도 안 함 | 토픽은 누구나 쓸 수 있다고 봄. FK 오류로 적재 전체가 멈추지 않게 |
| 회원당 기기 20개까지만 새로 기록 (아는 기기는 시각만 갱신) | 기기 ID를 바꿔 가며 표를 부풀리거나 그 회원의 대기열 조회를 무겁게 만드는 것 방지 (대기열 상한 100보다 아래) |
| 마지막 시각은 GREATEST로만 늘림 | 늦게 도착한 옛 이벤트가 되돌리지 않게 |
| Mongo 저장보다 먼저 기록 | 이벤트가 보일 때 연결도 이미 있게 (테스트 뒷정리 경합 제거). MERGE라 재시도해도 같음 |

## 막힌 점과 해결

- k6 미설치(`exec: k6: not found`) → winget 설치 안내. 실행 태그가 요약표 위 INFO 줄에 있어 못 찾음 → DB에서 이메일(`lt{tag}.`)로 찾음, 다음부터 `-e RUN_TAG=`.
- **기존 `BehaviorLogInfraTest` 실패** (`ORA-02292` FK_MEMBER_DEVICE_MEMBER_ID): 이제 적재가 기기 연결을 남겨서 테스트 뒷정리의 회원 삭제가 막힘 → 뒷정리에 `member_device` 삭제 추가 + 기록 순서를 Mongo 저장 앞으로.

## 배운 점

- "읽는 곳은 있는데 쓰는 곳이 없는" 테이블은 에러 없이 **조용히 기능을 끈다**. 새 테이블을 읽을 때 누가 채우는지 같이 확인한다.
- 평가 결과 100%는 "연결됐다"는 뜻이지 "영리한 봇도 잡는다"는 뜻은 아니다. 문턱 근처 봇으로 경계를 재야 한다.

## 추가: 1,000명 평가와 "탐지율 0%" 해프닝

- 처음 1,000명 평가에서 **탐지율 0%**: 생성은 16:32에 끝났는데 앱이 평소 모드로 켜지지 않아 1분 배치가 한 번도 돌지 않음 (`risk:dirty` 2,980건 그대로, 가상 회원 점수 0건, 재동기화 표시 시각도 15:05에 멈춤). 평가 스크립트는 기다리다 그대로 계산해 0%를 냄.
- 해결: **생성기가 끝날 때 위험 점수 배치를 직접 돌리게** 바꿈 (+ `score-only` 모드). 앱을 켜고 기다리는 단계 자체를 없앰.
- 다시 계산: 2,980개 대상 5회, 실패 0, 케이스 130 → 평가 **탐지율 100% (90/90), 오탐률 0% (0/910)**
- 배운 점: "0%"처럼 극단적인 결과는 탐지 규칙보다 **파이프라인이 실제로 돌았는지**부터 본다 (대기 목록, 점수 행 수, 마지막 계산 시각). 사람이 순서를 지켜야 하는 단계는 없앨 수 있으면 없앤다.
