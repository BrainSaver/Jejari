### 2. 찾은 문제와 보완

| 문제 | 보완 |
|---|---|
| 없는 주소·`/guest`·`/guest/lookup` 새로고침·`/favicon.ico`가 401 JSON | `/api`·`/actuator`가 아닌 GET·HEAD는 화면으로 열고, 없는 주소는 404 + "없는 페이지예요" 화면. [트러블슈팅](../troubleshooting/20261125-화면-목록에-없는-주소가-로그인-필요-JSON.md) |
| 폰에서 예매 도우미(마스코트)가 좌석 종류·열차 찾기 버튼을 가림 | 960px 미만에서 72px → 52px, 본문 아래 여백 84px로 버튼을 마스코트 위로 올릴 수 있게 |
| 비회원 조회: 예약 번호에 글자를 치면 말없이 지워짐, 휴대폰 "123"도 조회됨 | "숫자만 넣을 수 있어요" 안내, 휴대폰 10~11자리가 아니면 안내 + 조회 버튼 잠금 |
| "전화 도움 1588-0000"이 `tel:` 링크라 누르면 실제로 전화가 걸림 (시연용 번호) | 버튼으로 바꾸고 "시연용 사이트라 상담 전화는 없어요. 예매 도우미에게 물어보세요" 안내. 로그인·검색 오류 문구의 번호도 뺌 |

**왜 이렇게 했나**

- 401 문제는 목록에 `/guest`만 넣어도 되지만, 화면을 추가할 때마다 세 곳을 같이 고쳐야 해서 이미 한 번 빠졌다. 데이터는 전부 `/api`라 "API가 아니면 화면"이라는 규칙으로 바꿔 목록 관리를 없앰
- 없는 주소를 404 상태 그대로 화면으로 돌려주면 사람은 안내를 보고, 검색 엔진·점검 도구는 404를 본다
- 마스코트는 떠 있는 버튼이라 완전히 안 겹칠 수는 없음 → 작게 + 아래 여백으로 "스크롤하면 비켜 가게"

### 3. 확인

- `SpaPagesWebTest` 6개 새로: 비회원 화면 새로고침 200, 없는 화면 404(GET·HEAD), 없는 정적 파일 JSON 404, API·actuator는 여전히 401, 화면 주소라도 POST는 401, 브라우저 화면 판정
- 기존 보안·오류 테스트 `ErrorResponseTest` 7 · `AuthWebTest` 14 · `AdminAuthWebTest` 8 · `DevSecurityConfigTest` 6 → **41개 모두 통과**
- 프론트엔드 빌드 통과, 폭 400px로 없는 페이지·비회원 조회 안내·전화 도움 안내 화면 확인 (마스코트는 로컬에 백엔드가 없어 숨김 상태라 배포 뒤 확인)

### 4. 모바일 레이아웃 다듬기 (오후)

다인 제보: 첫 화면 [열차 찾기] 버튼이 인원·좌석 종류 칸에 겹쳐 보임. 로컬 화면을 공용 서버 공개 API에 붙여 360·390·412px × 보통·아주 크게로 찍고, 겹침·가로 넘침·잘림을 자동으로 찾는 스크립트로 확인

| 문제 | 원인 | 보완 |
|---|---|---|
| [열차 찾기]가 조건 칸에 붙음 | 모바일에서 검색판이 그냥 블록이라 칸 묶음(아래 끝 719px)과 버튼(위 끝 719px) 사이가 0 | 960px 미만에서 검색판을 세로 flex + 간격 14px, 버튼 높이 56px |
| 열차 카드의 작은 기차가 출발·도착 시각("14:58", "17:47")을 덮음 | 기차(30px)가 `margin-left:-15px`로 선의 0%~100%를 달려 양 끝에서 반이 선 밖으로 나감 | 15px ~ `100% - 15px`만 달리게 |
| 첫 화면 위쪽에 로고 없이 "제자리" 글자만 | 모바일 머리에 PC 메뉴의 인장 로고가 빠져 있었음 | 인장 로고 + 누르면 첫 화면 |
| 예매 도우미가 도착역 선택·예매하기 버튼 모서리를 가림 | 떠 있는 버튼이 52px | 46px, 오른쪽 여백 10px |

- 확인: 7개 화면(첫 화면·검색 결과, 로그인, 가입, 비회원, 비회원 조회, 없는 페이지, 관리자 로그인) × 3폭 × 글자 2단계 자동 검사 겹침 0 (아래 탭바·떠 있는 도우미처럼 원래 위에 뜨는 것은 뺌)
- 로그인 뒤 화면(대기열·좌석·결제·예매 내역 등)은 이번에도 못 봄

### 5. 일부 폰에서 화면 위쪽이 잘림 (팀원 제보) · 마스코트 크기

- 재현 시도: 7개 화면 × 폭·높이 8가지(280×653 ~ 412×915) × 글자 보통·아주 크게 → 시작 스크롤 0, 화면 위로 나간 요소 0, 가로 넘침 0. **헤드리스 브라우저에서는 재현 안 됨** (주소창·앱 안 브라우저 막대는 흉내 못 냄)
- 같은 계열 원인 두 곳
  - 예매 도우미 창: `100vh`(주소창을 뺀 높이보다 큼)로 높이를 잡아 위가 잘림 → 길동현 님이 같은 날 `100dvh` + 안전 영역으로 고침 (`3bf6337`)
  - 달력·시각·인원 선택 창(`.dlg`): `max-height:calc(100dvh - 32px)`만 있어 dvh를 모르는 브라우저(예전 iOS·삼성 인터넷)는 높이 제한이 통째로 무시 → 화면보다 큰 창이 가운데 정렬돼 위가 잘리고 스크롤도 안 됨. 또 글자 "아주 크게"(zoom 1.3)에서는 dvh를 알아도 창이 화면의 1.3배 (360×560: 위 21 ~ 아래 628)
- 보완: `100vh` 먼저 + `100dvh`로 덮기, 높이를 글자 배율로 나눔, 바깥을 스크롤 가능 + `place-items:safe center` → 같은 화면에서 위 21 ~ 아래 549
- 마스코트: 다인 의견으로 폰에서 46px → 58px
- 남은 것: 제보한 폰의 기종·브라우저(카카오톡 안 브라우저인지)와 잘린 화면 사진을 받아 진짜 원인이 이것인지 확인
