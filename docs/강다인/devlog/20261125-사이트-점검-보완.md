- 잘 되던 것: 검색 29개, 로그인 없이 예매하기 → 로그인 → 원래 대기열로 돌아오는 연결, 비회원 조회 실패 메시지가 한 가지(존재 여부 안 알려 줌)
- 로그인 뒤 화면은 못 봄 (공용 서버라 가입·로그인은 직접 해야 함)

### 2. 찾은 문제와 보완

| 문제 | 보완 |
|---|---|
| 없는 주소·`/guest`·`/guest/lookup` 새로고침·`/favicon.ico`가 401 JSON | `/api`·`/actuator`가 아닌 GET·HEAD는 화면으로 열고, 없는 주소는 404 + "없는 페이지예요" 화면. [트러블슈팅](../troubleshooting/20261125-화면-목록에-없는-주소가-로그인-필요-JSON.md) |
| 폰에서 예매 도우미(마스코트)가 좌석 종류·열차 찾기 버튼을 가림 | 960px 미만에서 72px → 52px, 본문 아래 여백 84px로 버튼을 마스코트 위로 올릴 수 있게 |
| 비회원 조회: 예약 번호에 글자를 치면 말없이 지워짐, 휴대폰 "123"도 조회됨 | "숫자만 넣을 수 있어요" 안내, 휴대폰 10~11자리가 아니면 안내 + 조회 버튼 잠금 |
| "전화 도움 1588-0000"이 `tel:` 링크라 누르면 실제로 전화가 걸림 (시연용 번호) | 버튼으로 바꾸고 "시연용 사이트라 상담 전화는 없어요. 예매 도우미에게 물어보세요" 안내. 로그인·검색 오류 문구의 번호도 뺌 |

**왜 이렇게 했나**

- 401 문제는 목록에 `/guest`만 넣어도 되지만, 화면을 추가할 때마다 세 곳을 같이 고쳐야 해서 이미 한 번 빠졌다. 데이터는 전부 `/api`라 "API가 아니면 화면"이라는 규칙으로 바꿔 목록 관리를 없앰
- 없는 주소를 404 상태 그대로 화면으로 돌려주면 사람은 안내를 보고, 검색 엔진·점검 도구는 404를 본다
- 마스코트는 떠 있는 버튼이라 완전히 안 겹칠 수는 없음 → 작게 + 아래 여백으로 "스크롤하면 비켜 가게"

### 3. 확인

- `SpaPagesWebTest` 6개 새로: 비회원 화면 새로고침 200, 없는 화면 404(GET·HEAD), 없는 정적 파일 JSON 404, API·actuator는 여전히 401, 화면 주소라도 POST는 401, 브라우저 화면 판정
- 기존 보안·오류 테스트 `ErrorResponseTest` 7 · `AuthWebTest` 14 · `AdminAuthWebTest` 8 · `DevSecurityConfigTest` 6 → **41개 모두 통과**
- 프론트엔드 빌드 통과, 폭 400px로 없는 페이지·비회원 조회 안내·전화 도움 안내 화면 확인 (마스코트는 로컬에 백엔드가 없어 숨김 상태라 배포 뒤 확인)

## 직접 확인하는 법 (배포 뒤, main은 10분마다 자동 재배포)

```bash
for p in /guest/lookup /this-page-does-not-exist /favicon.ico /api/v1/reservations; do
  printf "%s -> " $p; curl -s -o /dev/null -w "%{http_code}\n" "https://jejari.duckdns.org$p"; done
# 기대: 200, 404, 200, 401
```

- 브라우저: 휴대폰 폭으로 첫 화면 아래까지 내려서 열차 찾기 버튼이 마스코트 위로 올라오는지
