## 어떻게 했나

```
POST /admin/reservations/{R}/cancel (SUPERVISOR)
  → 사유 검사 → 예약 주인 찾기(없으면 404)
  → [tx] 예약 FOR UPDATE(CONFIRMED만, 아니면 409) → 수수료 0·전액 → CANCELED → 좌석 반환(B)
         → admin_action → cancellation(ADMIN) → outbox RESERVATION_CANCELED(reason ADMIN) → history(ADMIN)
  [커밋 뒤] 환불 (사용자 취소와 같은 refund() → DONE이면 REFUND_COMPLETED)
```

## 왜 이렇게 했나

- **취소 코드를 새로 짜지 않고 같은 트랜잭션에 actor만 넘김**: §8.1이 "USER·ADMIN 같은 절차"라고 정해 둠. 좌석 반환·카운터·REOFFER·환불을 두 벌로 두면 한쪽만 고쳐지는 일이 생긴다
- **위험 점수는 손대지 않아도 빠진다**: `RiskInputReader`·`SuspiciousCaseOpener`가 이미 `cancel_type = 'USER'`만 센다. 관리자가 취소한 것을 회원의 "결제 후 취소" 신호로 세면 안 된다
- **감사 기록을 같은 트랜잭션에**: 취소만 되고 "누가 왜"가 빠지는 일이 없다. 사유가 짧으면 아무것도 바꾸지 않고 400
- **확정 예약만**: 결제 전 예약은 기한이 지나면 스스로 풀린다. 강제로 풀 일이 없고, 경로를 늘리면 시험할 것도 는다
- **두 번 눌러도 한 번**: 예약 행 잠금 + `status = 'CONFIRMED'` 조건이라 두 번째는 409. 취소·환불·감사 기록 모두 1건

## CNL-03 환불 재시도 배치

- `RefundRetryBatch`: 5분마다 REQUESTED·FAILED 취소를 다시 환불 요청. 1분 유예(커밋 뒤 환불 진행 중인 건 제외), 72시간 지나면 멈추고 ERROR 로그
- 사용자·관리자 취소는 `ReservationCancelService.retryRefund` → 처음과 같은 `refund()`, 늦은 승인은 길동현 님 `LateApprovalRefund.refund`
- **왜 같은 코드를 다시 부르나**: 환불 키 `cancel:<cancel_id>`가 같아 PG가 한 번만 환불하고, DONE 조건부 UPDATE라 `REFUND_COMPLETED`도 한 번(길동현 님 메모). 재시도용 DONE 처리를 따로 짜면 이 조건을 또 맞춰야 한다
- 길동현 님 `MockPgClient`가 실패도 기억해서 재시도가 영원히 실패하던 것 → 성공만 기억 (실제 PG처럼)
- 테스트 중엔 `build.gradle`에서 배치를 끔 (다른 테스트의 일부러 만든 FAILED를 바꾸지 않게)
- 막힌 것: 테스트 좌석 34번을 로컬 시연 예약(회원 555)이 쓰고 있어 "다른 사람이 먼저 선택한 좌석" → 37번으로
