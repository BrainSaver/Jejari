# 2026-11-17 · 의심 케이스 목록·상세·타임라인 (ADM-05)

> 작성: 강다인 · 관련: ADM-05, A-06, 기능설계서 4.10 · 같은 날: [위험 사용자 목록](20261117-위험사용자-목록.md), [의심 케이스 자동 생성](20261117-위험점수-1분-배치.md)
> 커밋: `feat(risk): 의심 케이스 목록·상세·타임라인 (ADM-05)`

## 한 일

- `GET /api/v1/admin/cases` 목록, `/{id}` 상세, `/{id}/timeline` 타임라인 (VIEWER 이상)
- 타임라인: 케이스 대상에 연결된 **모든 계정의 행동 로그를 시간순 한 줄로**, 의심 구간 안 이벤트 표시(`inWindow`), 발동 마커
- 상세: 연결 계정(계정 1·2…, 가린 이름), 현재 점수 근거, **점수 변화 이력**(그래프용, risk_score_history)
- 케이스 오류 코드 `RiskAdminErrorCode` (`CASE_NOT_FOUND`, ADM-06용 3개 미리)

## 어떻게 했나

```
suspicious_case (+ risk_score 현재 점수) → 대상의 연결 회원 (RiskInputReader.membersOf, 가입 순 → 계정 1, 2…)
 → behavior_log { member_id IN 회원들, ts 범위 }  ({member_id, ts} 인덱스, 시간순, 최대 2000건)
 → 이벤트마다 계정 라벨·의심 구간 안 여부 + case_marker
```

## 왜 이렇게 했나

- **모든 계정을 한 줄로**: 봇은 계정을 바꿔 가며 같은 좌석을 노린다. 계정별로 따로 보면 각자는 평범해 보인다.
- **연결 기준을 배치와 공유**: 점수를 계산한 "연결 계정"과 화면의 계정이 다르면 관리자가 근거를 확인할 수 없다.
- **24시간·2000건 제한**: 화면 하나가 Mongo 전체를 훑으면 적재(insertMany)까지 느려진다. 잘렸는지는 `truncated`로 알린다.
- **실명 대신 계정 번호**: 판정에는 "어떤 계정이 언제 무엇을"만 필요하다. 실명은 SUPERVISOR 해제(ADM-06)로.

## 막힌 점과 해결

- 처음엔 없는 케이스에 공용 `NOT_FOUND`("요청한 경로를 찾을 수 없습니다")를 쓰려 했는데, 화면이 경로 오류와 구분하지 못함 → 전용 `CASE_NOT_FOUND`.
- 테스트 4개 한 번에 통과. 작업 중 main에 조영준 님 문서 커밋이 들어와 리베이스.

## 배운 점

- "보여 주는 기준"과 "판정한 기준"을 같은 코드로 묶어 두면, 나중에 연결 규칙을 바꿔도 화면과 점수가 같이 바뀐다.
- 관리자 화면도 사용자 트래픽과 같은 DB를 쓴다. 조회 범위·건수 상한을 처음부터 둔다.
