## 3. 설계 결정

결정 하나당 한 칸. "왜 이렇게 했는가"를 면접에서 그대로 말할 수 있게 적습니다.

### 결정 1. RESTRICTED 회원은 취소표 대기 신청 불가

- 상황: 이용 제한 회원도 예매는 가능하고 대기열 패널티(최대 100초)만 받는 가정이었음. 그런데 취소표 대기는 대기열 입장 토큰 없이 신청하고, 순서도 위험 점수와 무관한 신청 순서라 패널티를 우회하는 길이 됨
- 고려한 대안: 취소표 대기 순서에 위험 점수 반영 / 제한 회원 예매 자체 차단
- 선택과 이유: 대기 신청만 막음. WL-01에서 상태 확인 한 줄이라 구현 비용이 작고, 대기 순서는 신청 순서 그대로라 설명이 단순함
- 감수한 단점: 오탐으로 제한된 정상 사용자는 취소표 기회를 잃음 → 케이스 판정(ADM-06)에서 DISMISSED 시 ACTIVE로 복구
- 관련 코드·커밋: 기능설계서 2장·WL-01·9장, U-10
