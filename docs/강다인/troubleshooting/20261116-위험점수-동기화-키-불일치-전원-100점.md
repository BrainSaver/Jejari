# [risk] 동기화 표시 키 이름이 대기열과 달라 모든 회원이 위험 점수 100점

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-16 |
| 상태 | 해결 (main 병합 전, 대기열과 맞물려 확인하다 발견) |
| 관련 커밋·이슈 | `cd7f653` (수정), `6d4dac2` (원인), 김성원 `aff413e` |

## 1. 문제

- 현상: 대기열이 위험 점수 캐시(Redis `risk:*`)를 믿지 않고 매번 Oracle 조회로 빠졌고, 그 조회 구현이 없어 **모든 회원이 100점**(최대 패널티)으로 처리될 상태였다.
- 재현 조건: 내 재동기화(`RiskCacheResync`)가 정상으로 돈 뒤에도 대기열 진입 → 패널티 최대.
- 영향: 깨끗한 사용자까지 전부 순번이 뒤로 밀림. 오류 로그 없이 조용히 일어나서 눈에 잘 안 띔.

## 2. 원인

- 대기열(김성원 `aff413e`)은 "재동기화가 끝났다"는 표시 키가 있어야 캐시를 믿고, 없으면 Oracle 조회 → 실패하면 100점(fail-closed)으로 바뀌었다.
- 그런데 표시 키 이름이 서로 달랐다.

```
쓰는 쪽(나, RiskCacheResync)   : riskcache:synced_at
읽는 쪽(대기열, QueueKeys)     : risk:meta:synced_at
```

- 대기열 눈에는 표시 키가 영원히 없음 → 항상 Oracle 조회 → `RiskScoreFallbackPort` 구현 없음 → 100점.
- 최종 원인: 두 파트가 같은 키 이름을 **문자열로 따로 적어** 두었다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 내 문자열을 `risk:meta:synced_at`로 고치기 | 한 줄 | 나중에 한쪽이 바뀌면 또 어긋남 | |
| 대기열 상수 `QueueKeys.RISK_SYNCED_AT`를 그대로 가져다 쓰기 | 이름이 한 곳에서만 정해짐 | 대기열 패키지에 의존 | ✓ |

- 함께 고친 것
  - `OracleRiskScoreFallback`: 대기열의 `RiskScoreFallbackPort` 구현. 회원의 CI·결제·기기 점수 최댓값을 `risk_score`에서 읽고, 해시 형식이 틀리면 예외 → 대기열이 100점.
  - 표시 키 감시: 30초마다 확인해 없으면(Redis 재시작·초기화) 10분 주기를 기다리지 않고 바로 재동기화. 표시 키가 없는 동안은 진입마다 Oracle을 읽으므로 그 시간을 짧게.
  - 개발 모드에서는 재동기화·Oracle 조회를 끔 (부하 테스트가 Redis에 직접 넣은 점수를 지우지 않게).
- 바뀐 코드: `risk/cache/RiskScoreCache.java`, `risk/cache/RiskCacheResync.java`, `risk/store/OracleRiskScoreFallback.java`

## 4. 수치

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 깨끗한 회원의 대기열 패널티 | 100점 처리 | 0점 (저장된 점수대로) |
| 대기열 실제 `RiskPenaltyService`와 맞물린 통합 테스트 | 없음 | 6개 추가, 옛 키로 되돌리면 3개 실패 |

- 측정 방법: `docker compose up -d` 뒤 `./gradlew infraTest --tests 'com.jejari.risk.*'`. `bootRun` 후 Redis에 `risk:meta:synced_at`가 생기는지 확인.

## 5. 정리

- 면접용 한 줄 요약: "대기열과 위험 점수 캐시가 '동기화 완료' 키 이름을 서로 다르게 적어 전원이 최대 패널티를 받을 상황이었고, 상대 파트의 상수를 직접 쓰게 바꾸고 실제 대기열 코드와 맞물리는 통합 테스트를 넣어 다시 어긋나면 테스트가 깨지게 했다."
- 다음에 비슷한 상황이면: 다른 파트와 공유하는 키·토픽·헤더 이름은 **상대 코드의 상수를 가져다 쓰고**, 내 테스트 안에서 상대의 실제 코드를 한 번 돌려 본다.
