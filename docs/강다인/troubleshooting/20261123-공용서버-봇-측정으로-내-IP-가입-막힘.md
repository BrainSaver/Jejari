# [ops] 공용 서버에서 봇 측정을 돌린 뒤 내 IP의 회원가입이 1시간 막힘

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-23 |
| 상태 | 해결 (1시간 뒤 자동 해제) · 재발 방지 규칙 정함 |
| 관련 커밋·이슈 | `39a768f`, `6617d81` (측정 기록) |

## 1. 문제

- 현상: 공용 서버(https://jejari.duckdns.org)에서 봇 대회 보강 전 측정을 돌린 뒤, 같은 PC에서 회원가입을 하니 "요청이 많다"(429)로 막힘
- 재현 조건: 한 IP에서 1시간 안에 가입 10번 넘게 (봇 명의 12개 + k6 정상 사용자 20명 = 32번)
- 영향: 다인 님 본인 가입이 최대 1시간 막힘. 같은 와이파이를 쓰는 사람도 같이 막힘

## 2. 원인

- 측정 동안 가입 제한(`auth.signup_rate_per_hour`)을 10 → 100으로 올렸다가 끝나고 10으로 되돌렸다
- 최종 원인: **되돌린 건 한도이고, 이미 센 횟수(Redis `rate:signup:*`)는 1시간 동안 남는다.** 한도가 10으로 돌아오자 32번 센 내 IP가 바로 막혔다

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 기다리기 (1시간 뒤 자동 해제) | 서버를 건드리지 않음 | 그동안 가입 못 함 | ✓ (그날) |
| 다른 네트워크(휴대폰 데이터)로 가입 | 바로 됨 | 임시방편 | |
| 공용 서버 한도를 잠깐 다시 올림 | 바로 됨 | 다른 팀원도 쓰는 서버의 정책 변경 | |
| **재발 방지**: 공용 서버에서 계정을 대량으로 만드는 측정은 미리 영향을 알리고, 로컬로 충분하면 로컬에서 | — | — | ✓ |

- 선택한 이유: 측정 결과는 로컬과 공용 서버가 같았다 (botb·botc 모두 24석, 케이스 0). 공용 서버에서 꼭 해야 할 이유가 약했다

## 4. 수치

| 지표 | 값 |
|---|---|
| 측정 중 내 IP 가입 횟수 | 32 (한도 10) |
| 막힌 시간 | 최대 1시간 |
| 로컬 vs 공용 결과 | 같음 (봇 24석·케이스 0) |

## 5. 정리

- 면접용 한 줄 요약: "공용 서버에서 부하 측정 후 한도만 되돌리고 이미 쌓인 레이트 리밋 카운터를 놓쳐 내 IP가 막혔고, 이후 공용 환경 측정 전엔 남는 부작용(카운터·데이터)을 먼저 공유하도록 절차를 바꿨다."
- 다음에 비슷한 상황이면: 레이트 리밋을 잠깐 푼 측정이 끝나면 한도와 **카운터 둘 다** 본다. 공용 환경은 "끝나고 남는 것"(카운터, 계정, 운행)을 먼저 적고 시작한다
