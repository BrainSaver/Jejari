# [web] 화면 목록에 없는 주소가 "로그인이 필요합니다" JSON(401)으로 보임

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-25 |
| 상태 | 해결 |
| 관련 커밋·이슈 | `7d99f55` (`SecurityConfig`, `GlobalExceptionHandler`, `SpaForwardController`) |

## 1. 문제

- 현상: 공용 서버를 사람처럼 둘러보다 발견. 주소를 잘못 치면 화면 대신 `{"code":"AUTH_REQUIRED","message":"로그인이 필요합니다."}`가 그대로 보임
- 같은 원인으로 깨진 곳
  - **비회원 예매·조회** `/guest`, `/guest/lookup`: 화면 안에서 눌러 들어가면 되지만, 새로고침하거나 링크로 바로 열면 401 JSON
  - `/favicon.ico`: 브라우저가 들어올 때마다 401 → 탭 아이콘 실패 + 서버 401 기록
- 영향: 비회원이 조회 화면을 북마크·공유하면 못 씀. 오타 주소에 "로그인하라"고 해서 로그인해도 안 됨

## 2. 원인

- 보안 설정이 화면 경로를 **목록**(`SPA_PAGES`)으로만 열고 나머지는 `anyRequest().authenticated()`
- 프론트엔드에 `/guest`가 생겼을 때 `App.jsx`에만 넣고 서버 목록 두 곳(`SecurityConfig`, `SpaForwardController`)에는 빠짐
- 없는 주소는 MVC까지 가기 전에 인증 필터가 401로 끊어서 404가 될 기회가 없었음

```
GET /this-page-does-not-exist → 401 application/json {"code":"AUTH_REQUIRED",...}
GET /guest/lookup              → 401
GET /favicon.ico               → 401
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 목록에 `/guest/**`·`/favicon.ico`만 추가 | 변경 최소 | 다음 화면을 추가할 때 또 빠짐, 오타 주소는 여전히 401 | |
| `/api`·`/actuator`가 아닌 GET·HEAD는 모두 열기 + 없는 주소는 404 | 화면 추가와 무관, 오타 주소도 바르게 404 | 열리는 범위가 넓어 보임 | ✓ |

- 선택한 이유: 데이터는 전부 `/api` 아래라 화면 쪽 GET을 열어도 새는 것이 없다. 목록 방식은 사람이 세 곳을 함께 고쳐야 해서 이미 한 번 빠졌다
- 없는 주소: 브라우저 화면 요청(GET·HEAD, `Accept: text/html`, 확장자 없음, API 아님)이면 **404 상태로 index.html**을 돌려줘 새 "없는 페이지예요" 화면이 뜬다. API·없는 정적 파일은 JSON 404
- 함께 고친 것: `favicon.ico` 추가, 비회원 경로를 `SpaForwardController`에 추가, 프론트 `*` 경로를 홈으로 말없이 보내던 것 → 안내 화면(`NotFound.jsx`)
- 바뀐 코드 위치: `common/security/SecurityConfig.isPageRequest`, `common/error/GlobalExceptionHandler.handleNotFound`, `common/web/SpaForwardController`, `frontend/src/user/NotFound.jsx`

## 4. 수치

| 주소 | 개선 전 | 개선 후 |
|---|---|---|
| `/guest/lookup` (새로고침) | 401 JSON | 200 화면 |
| `/this-page-does-not-exist` | 401 JSON | 404 + "없는 페이지예요" 화면 |
| `/favicon.ico` | 401 | 200 아이콘 |
| `/api/v1/reservations` (로그인 없이) | 401 | 401 (그대로) |
| `/actuator/env` | 401 | 401 (그대로) |

- 측정 방법: `./gradlew test --tests 'com.jejari.common.web.SpaPagesWebTest'` (6개). 보안 관련 기존 테스트 `ErrorResponseTest`·`AuthWebTest`·`AdminAuthWebTest`·`DevSecurityConfigTest` 35개도 통과
- 배포 뒤 확인: `curl -s -o /dev/null -w "%{http_code}" https://jejari.duckdns.org/guest/lookup` → 200

## 5. 정리

- 면접용 한 줄 요약: "화면 경로를 허용 목록으로만 열어 새 화면이 빠지면 새로고침 때 401이 났는데, 'API가 아닌 GET은 화면'으로 규칙을 바꾸고 없는 주소는 404 화면으로 답해 목록 관리 자체를 없앴다."
- 다음에 비슷한 상황이면: 사람이 여러 곳을 같이 고쳐야 하는 목록은 규칙으로 바꿀 수 있는지 먼저 본다. 화면 추가 PR에는 "주소창에 직접 쳐서 새로고침" 확인을 넣는다
