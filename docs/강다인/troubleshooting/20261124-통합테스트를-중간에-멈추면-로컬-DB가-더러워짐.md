# [test] 통합 테스트를 중간에 멈추면 로컬 DB에 제약·행이 남아 다음 실행이 엉뚱하게 실패함

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-24 |
| 상태 | 해결 (로컬 정리) |
| 관련 커밋·이슈 | 강동균 님 `253cf16` (알림 제약 테스트를 NOVALIDATE로) |

## 1. 문제

- 현상: 대회 전 전체 테스트에서 통합 527개 중 15개 실패. 좌석 수가 41~45개씩 모자라고, "다른 사람이 먼저 선택한 좌석", `ORA-02443`(없는 제약 삭제), `ORA-00001`(열린 케이스 중복)
- 재현 조건: ① 로컬 DB에 ERD 패치(v36~v38)가 빠진 걸 알고 전체 테스트를 **중간에 멈춤**(Gradle 중지 + 테스트 JVM 강제 종료) ② 테스트 전용 운행 9001에 11-17 부하 시험 데이터가 남아 있음
- 영향: 코드는 멀쩡한데 테스트가 깨져서, 진짜 회귀(내 변경 탓 2건)를 찾기 어려워짐

## 2. 원인

- 실패를 모아 보니 셋으로 나뉨
  1. **내 변경 탓** (2건): 새 기준에 맞지 않던 합성 데이터·테스트 녹화
  2. **오래된 데이터**: 운행 9001에 `ltwh7w…@loadtest.example.com` 예약 70건·판매 좌석 45개 (11-17 부하 시험). 테스트는 자기 데이터만 지워서 남아 있었음
  3. **멈춘 테스트의 흔적**: 알림 테스트는 `ck_notification_type`을 지웠다가 `finally`에서 되살리는데, JVM을 죽이면 `finally`가 안 돈다 → **CHECK 제약이 빠진 DB**. 다른 테스트의 열린 케이스 1건·녹화 세션 2개도 `@AfterEach`가 못 돌아서 남음

```
ORA-02443: 존재하지 않는 제약 - 삭제할 수 없습니다        ← 이미 지워진 채로 남은 ck_notification_type
ORA-00001: 고유한 제약 조건(JEJARI.UX_CASE_OPEN_SUBJECT) ← 11:20에 열려 남은 테스트 케이스
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 로컬 DB를 지우고 새로 만들기 | 깨끗함 | 오래 걸리고 다른 작업 데이터도 사라짐 | |
| 실패를 원인별로 나누고, 남은 것만 골라 지우기 | 다른 데이터는 그대로 | 손이 감 | ✓ |

- 제약은 원래 정의(`db/patch/v30.sql`, 다시 돌려도 안전)로 복구
- 운행 9001의 부하 시험 예약 70건과 딸린 행(좌석·결제·취소·이력·사가), 11:20 테스트 케이스 1건, 녹화 세션 2개만 지움
- 남는 위험(알림 테스트가 `CONFIRMED` 알림이 있는 DB에서 실패)은 강동균 님이 `NOVALIDATE`로 고침

## 5. 정리

- 면접용 한 줄 요약: "전체 테스트 15개 실패를 원인별로 나눠 코드 회귀 2건과 환경 문제 13건을 가렸고, 멈춘 테스트가 남긴 제약 삭제를 찾아 복구했다."
- 다음에 비슷한 상황이면:
  - 긴 테스트는 **패치를 먼저 맞추고** 시작한다 (`ls db/patch`와 로컬 DB 비교)
  - 어쩔 수 없이 멈췄다면 남은 테스트 JVM(`jps -l`)을 끄고, **DB를 바꾸는 테스트(제약 삭제 등)의 흔적부터** 확인한다
  - 실패가 많으면 숫자 차이(41~45)부터 본다 — 같은 크기로 어긋나면 남은 데이터일 가능성이 크다
