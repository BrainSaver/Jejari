# [payment] Mock PG가 환불 실패까지 기억해서 재시도 배치가 영원히 실패

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-18 |
| 상태 | 해결 |
| 관련 커밋·이슈 | `4505277` (CNL-03) |

## 1. 문제

- 현상: 환불 재시도 배치(CNL-03)를 만들면서, 처음 환불이 실패(FAILED)한 취소를 원인을 고친 뒤 다시 요청해도 계속 실패했다.
- 재현 조건: 승인 거래 ID가 없는 결제로 확정 취소 → 환불 FAILED → 결제에 거래 ID를 채움 → 같은 환불 키로 재요청
- 영향: 테스트에서 재시도 경로를 확인할 수 없음. 실제 PG가 이렇게 동작했다면 일시 장애 한 번으로 환불이 영구히 막힌다

## 2. 원인

- 가설: 배치가 대상을 못 고르나? → 대상 조회는 맞았고, PG 호출 결과가 매번 `NO_APPROVED_TX`였다.
- 최종 원인: `MockPgClient.refund`가 `computeIfAbsent(refundKey, …)`로 **실패 결과까지** 환불 키에 저장했다. 같은 키(`cancel:<cancel_id>`)로 다시 오면 처음 실패를 그대로 돌려줬다.

```java
refunds.computeIfAbsent(refundKey, k -> pgTxId == null ? 실패 : 성공)   // 실패도 영구 저장
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 재시도 때 환불 키를 바꾸기 (`cancel:<id>:2`) | Mock 수정 없음 | 실제 PG에서 **두 번 환불**될 수 있음 (멱등성 깨짐) | |
| **Mock이 성공만 기억** | 실제 PG와 같은 동작, 키는 그대로 | 다른 파트(길동현) 코드 수정 | ✓ |

- 선택한 이유: 멱등 키의 목적은 "성공한 환불을 두 번 하지 않기"다. 실패는 다시 시도할 수 있어야 한다. 길동현 님 결제 테스트 24개가 그대로 통과하는 것도 확인.
- 바뀐 코드 위치: `src/main/java/com/jejari/payment/pg/MockPgClient.java`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 원인 해소 뒤 재시도 결과 | FAILED (영구) | DONE, payment REFUNDED, 알림 1번 |

- 측정 방법: `./gradlew infraTest --tests "com.jejari.reservation.ReservationCancelInfraTest"` → `환불_실패는_재시도_배치가_다시_요청해_DONE으로_바꾸고_알림은_한_번`

## 5. 정리

- 면접용 한 줄 요약: "Mock PG가 멱등 키에 실패 결과까지 저장해 환불 재시도가 영구 실패했고, 실제 PG처럼 성공만 기억하게 바꿔 재시도는 가능하면서 이중 환불은 막았다."
- 다음에 비슷한 상황이면: 멱등 캐시에는 **확정된 성공 결과만** 넣는다. 가짜 외부 시스템(Mock)도 실제 시스템의 재시도 의미를 그대로 따라야 테스트가 의미 있다.
