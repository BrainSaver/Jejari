# [auth] 설정 레코드에 생성자를 하나 더 만들었더니 웹 테스트 44개가 기동 실패

| 상태 | 해결 |
| 관련 커밋·이슈 | `22bec4b` |

## 1. 문제

- 현상: 자동 로그인 보안 작업에서 `JwtProperties`에 관리자·비유지 세션 시간 2개를 추가하고, 기존 테스트 도우미가 그대로 쓰도록 **예전 모양의 생성자를 하나 더** 만들었다. 그러자 단위 테스트 465개 중 44개가 `Failed to load ApplicationContext`로 실패
- 영향: 웹 계층 테스트(`@WebMvcTest`) 전부. 실제 앱도 기동하지 못했을 것

## 2. 원인

- 실패한 테스트가 모두 Spring 컨텍스트를 띄우는 것이라 설정 바인딩을 의심 → 바뀐 것은 `JwtProperties`뿐
- 최종 원인: `@ConfigurationProperties` **레코드는 생성자로 값을 채우는데, 생성자가 둘이면 어느 쪽인지 고르지 못해** 바인딩이 실패한다 (`@ConstructorBinding`으로 하나를 지정하지 않는 한)

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 정식 생성자에 `@ConstructorBinding` | 예전 생성자 유지 | 레코드 compact 생성자에 붙여야 해 헷갈림 | |
| **보조 생성자를 없애고 테스트 도우미(`TestJwt`) 한 곳을 고침** | 단순, 생성자 하나 | 테스트 한 줄 수정 | ✓ |

- 새 값은 compact 생성자에서 null이면 기본값(8시간·12시간)으로 채운다 → 설정 파일에 없어도 동작

## 4. 수치

| 지표 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 단위 테스트 실패 | 44 / 465 | 0 / 465 |

## 5. 정리

- 면접용 한 줄 요약: "설정 레코드에 편의 생성자를 추가했다가 Spring이 바인딩 생성자를 고르지 못해 컨텍스트가 뜨지 않았고, 생성자를 하나로 두고 기본값은 compact 생성자에서 채워 해결했다."
- 다음에 비슷한 상황이면: 설정 레코드는 생성자를 하나만. 호환이 필요하면 테스트 도우미를 고친다.
