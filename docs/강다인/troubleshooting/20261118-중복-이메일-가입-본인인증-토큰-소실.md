# [member] 이미 가입된 이메일로 가입하면 본인인증 토큰이 사라져 처음부터 다시 해야 함

## 1. 문제

- 현상: 회원가입 2단계에서 이미 가입된 이메일을 넣으면 "이미 가입된 이메일이에요"가 뜬다. 이메일만 바꿔 다시 누르면 **"본인인증 시간이 지났어요"** 가 뜨고 1단계(본인인증)로 돌아간다.
- 재현 조건: 가입된 이메일 A가 있을 때, 새로 본인인증 → 이메일 A로 가입 → 409 → 이메일 B로 가입
- 영향: 사용자는 본인인증을 다시 해야 하고, 안내가 실제 원인(이메일 중복)과 달라 헷갈린다. 가입 이탈

## 2. 원인

- 화면 검토(강동균 님이 만든 U-02) 중 발견. 서버 `SignupService.signup` 순서를 봤다.
- 최종 원인: 1회용 인증 토큰을 **이메일 중복 판정보다 먼저 소비**했다. 중복은 INSERT의 UNIQUE 위반으로만 판정하는데, 그때는 이미 토큰이 지워진 뒤다.

```
signup: IP 제한 → 이메일·비밀번호 규칙 → 토큰 peek → Argon2id 해싱 → 토큰 consume(GETDEL) → INSERT
                                                                       ↑ 여기서 사라짐      ↑ 여기서 중복 발견 (409)
```

비밀번호 규칙 위반은 consume 전에 검사해서 토큰을 잃지 않았는데(기존 테스트 `비밀번호_규칙_위반이면_토큰을_잃지_않는다`), 이메일 중복만 그 뒤에 있었다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 화면에서 409를 받으면 1단계로 보내며 "다시 인증" 안내 | 서버 수정 없음 | 사용자는 여전히 본인인증을 다시 해야 함 | |
| 토큰을 INSERT 실패 시 되살리기 | 정확 | 토큰 재발급 로직이 복잡, 동시 가입과 섞이면 위험 | |
| **consume 전에 이메일 중복을 먼저 조회** | 한 줄, 토큰을 안 잃음 | 조회와 INSERT 사이 틈 → UNIQUE가 최종 판정으로 남아 있어 안전 | ✓ |

- 선택한 이유: 비밀번호 규칙과 같은 원칙("입력 실수로 토큰을 잃지 않게")을 이메일에도 적용. 동시 가입 두 건은 여전히 UNIQUE 위반으로 하나만 성공한다.
- 계정 존재 여부 노출: 원래도 409로 알려 주던 정보라 새로 드러나는 것은 없다. 본인인증을 통과한 요청(토큰 peek 뒤)만 조회하고, 가입 IP 제한(`rate:signup`)도 그대로다.
- 바뀐 코드 위치: `src/main/java/com/jejari/member/signup/SignupService.java`

| 중복 이메일 뒤 다른 이메일로 가입 | 400 AUTH_VERIFY_FAILED (본인인증 다시) | 201 (이어서 가입) |

## 5. 정리

- 면접용 한 줄 요약: "1회용 인증 토큰을 이메일 중복 판정보다 먼저 소비해 사용자가 본인인증을 다시 해야 했고, 소비 전에 중복을 먼저 확인하되 최종 판정은 DB UNIQUE에 남겨 동시성 안전성을 유지했다."
- 다음에 비슷한 상황이면: 되돌릴 수 없는 일(토큰 소비, 결제, 메일 발송)은 **실패할 수 있는 검사를 모두 끝낸 뒤**에 한다. 순서를 그림으로 그려 보면 바로 보인다.
