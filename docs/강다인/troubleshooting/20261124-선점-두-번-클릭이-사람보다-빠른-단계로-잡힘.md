# [risk] 선점 버튼을 두 번 누른 사람이 "사람 손으로 불가능한 속도"(INHUMAN_STEP)로 잡힘

| 항목 | 내용 |
|---|---|
| 작성자 | 강다인 |
| 날짜 | 2026-11-24 |
| 상태 | 해결 (2차 대회 진짜 사람으로 확인) |
| 관련 커밋·이슈 | `69f399d` (같은 좌석 두 번 누름 빼기), 강동균 님 [오탐 시험](../../강동균/features/오탐-시험-사람-변형.md) 4절 |

## 1. 문제

- 현상: 강동균 님 오탐 시험에서 사람 변형 `humandouble`(선점 버튼을 0.06~0.14초 간격으로 두 번 누름) 3명 중 1명이 `INHUMAN_STEP`에 걸림
- 재현 조건: 첫 선점 요청이 다른 사람에게 밀려(409) 화면이 좌석표를 새로 받는 순간, 늦게 나간 두 번째 클릭이 서버에 닿음
- 영향: 버튼을 두 번 누르는 흔한 사람이 케이스 규칙에 걸림 (INHUMAN_STEP은 마커 규칙)

## 2. 원인

- 가설 1: 두 번째 선점이 "선점 → 결제" 단계를 짧게 만든다 → 연습 봇은 결제 전에 사람 속도로 쉬어서 아님
- 가설 2: 첫 선점이 밀리면 좌석표가 새로 그려진다 → 맞음. 늦게 나간 두 번째 클릭이 **새 좌석표 바로 뒤**에 닿아 "좌석표 → 선점 0.1초"가 됨
- 최종 원인: 단계 속도를 "같은 세션의 마지막 좌석표 → 다음 선점"으로 재는데, 두 번째 클릭은 새 좌석표를 보고 누른 게 아니라 **그 전에 누른 클릭이 늦게 도착한 것**

```
t+0.000  SEAT_HOLD  좌석 [10]  409 (다른 사람이 먼저)
t+0.060  VIEW_SEAT  화면이 좌석표를 새로 받음
t+0.100  SEAT_HOLD  좌석 [10]  ← 두 번째 클릭. 좌석표에서 0.04초 → "사람 손으로 불가능"
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 화면에서 응답이 올 때까지 버튼 막기 (이중 클릭 방지) | 근본적 | 서버 규칙은 그대로라 옛 화면·다른 클라이언트에서 여전히 오탐 | |
| INHUMAN_STEP 문턱을 2번 → 3번 | 간단 | 봇도 덜 잡음 | |
| 같은 세션이 **바로 전 선점과 같은 좌석**을 문턱 안에 다시 보낸 요청은 단계에서 뺌 | 첫 요청은 그대로 재서 숨는 길이 아님. 연타는 FAST_CLICK·SAME_SEAT_RETRY가 따로 봄 | 행동 로그의 좌석 목록(`meta.seatIds`)이 필요 | ✓ |

- 바뀐 코드 위치: `SignalCollector.holdStep(…, seatKey)`, `RiskInputReader.apply` (좌석 목록을 넘김)
- 두 번째 요청은 "좌석표 → 선점"도, "선점 → 결제"의 기준 시각도 건드리지 않음 (결제 단계는 첫 응답부터 잼)

## 5. 정리

- 면접용 한 줄 요약: "선점 버튼을 두 번 누른 사람이 '좌석표 0.04초 뒤 선점'으로 봇 판정을 받았는데, 늦게 도착한 같은 좌석 요청을 단계 속도에서 빼서 2차 대회 진짜 사람 오탐을 0으로 만들었다."
