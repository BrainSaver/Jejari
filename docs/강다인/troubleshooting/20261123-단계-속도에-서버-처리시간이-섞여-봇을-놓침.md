# [risk] "사람 손으로 불가능한 속도" 규칙이 서버가 바쁠 때 봇을 놓침 (처리 시간이 간격에 섞임)

## 1. 문제

- 현상: `INHUMAN_STEP`(좌석표 → 선점, 선점 → 결제가 0.5초 미만 2번)을 넣고 강동균 님 연습 봇 30종을 돌렸는데 **9종만** 걸렸다. 강동균 님 측정으로는 25종이 0.5초 미만이었다
- 재현 조건: 로컬 PC에서 앱·Docker·연습 봇 90계정·합성 사람을 한꺼번에 (같은 시각 Kafka 연결이 끊겼다 붙고 Redis 시간 초과)
- 영향: 서버가 바쁠수록 봇을 덜 잡는다. 대회처럼 몰리는 순간에 규칙이 약해진다 (사람을 더 잡는 쪽은 아니라 오탐은 없음)

## 2. 원인

- 가설: 봇이 실제로 느렸나? → 한 계정(botnodev)의 행동 로그를 보니 좌석표 → 선점 1.06초, 선점 → 결제 2.0초. 강동균 님 PC에서는 0.35초·0.42초
- 행동 로그 시각(`ts`)이 어디서 찍히나 → `BehaviorInterceptor`가 **요청을 받은 시각**을 남긴다
- 최종 원인: "다음 요청 시각 − 앞 요청 시각"에는 **앞 요청을 서버가 처리한 시간**이 들어간다. 봇은 응답을 받자마자 다음 요청을 보내도, 서버가 좌석표를 1초 걸려 만들면 간격이 1초가 된다

```
07:19:57.073 VIEW_SEAT   (서버가 ~1초 처리)
07:19:58.129 SEAT_HOLD   ← 받은 시각끼리 1.06초. 실제로 봇이 쉰 시간은 0.1초 안팎
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 문턱을 1.5초로 올림 | 코드 한 줄 | 사람(최소 0.6초대)까지 잡을 위험. 서버 속도에 따라 또 흔들림 | |
| 행동 로그에 처리 시간을 남기고 "응답이 나간 시각 → 다음 요청"으로 잼 | 서버 속도와 상관없이 사람이 보고 누른 시간만 남음. 위조 불가(서버 값) | 행동 로그 칸 하나 추가 (ERD 요청) | ✓ |

- 선택한 이유: 재고 싶은 것은 "사람이 화면을 보고 누르는 시간"이다. 서버가 쓴 시간은 빼야 맞다
- 바뀐 코드 위치: `behavior/BehaviorInterceptor.java`(응답 뒤 `elapsed`), `behavior/BehaviorEvent.java`(`elapsedMs`, 예전 메시지는 null), `behavior/sink/BehaviorDocuments.java`(`elapsed_ms`, 음수·하루 넘는 값 버림), `risk/batch/RiskInputReader.java`, `risk/SignalCollector.java`

## 5. 정리

- 면접용 한 줄 요약: "요청 간격으로 봇 속도를 쟀더니 서버가 바쁠 때 처리 시간이 섞여 봇을 놓쳤고, 행동 로그에 처리 시간을 남겨 '응답을 받은 뒤부터' 재도록 바꿔 연습 봇 탐지를 9종에서 25종으로 늘렸다."
