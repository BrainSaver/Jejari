# 봇 탐지 보강 (봇 대회 1차 뒤, 2026-11-23)

작성자: 강다인 · 코드: `src/main/java/com/jejari/risk/` (`MouseMotion`, `RiskGrade`, `batch/MarkerCodes`, `batch/RiskInputReader`) · 자세한 판정·테스트: [위험점수-규칙](위험점수-규칙.md) 아래쪽 절들

## 한 줄 요약

1차 대회에서 봇 두 개 모두 규칙 케이스가 0건이었다. 봇이 사람과 **다를 수밖에 없는 성질** 네 가지를 규칙으로 더하고, 점수를 **정상·경고·위험** 세 등급으로 묶었다.

## 새 규칙 4개

| 규칙 | 잡는 봇 | 한 줄 판정 | 점수 | 케이스 |
|---|---|---|---|---|
| `INHUMAN_STEP` | 필요한 요청만 아주 빨리 하는 매크로 (연습 봇 25/30) | 좌석표 응답 → 선점, 선점 응답 → 결제가 0.5초 미만 2번 | 30 / 40 | ERD v34 뒤 |
| `HEADLESS_HOLD` | 브라우저 없이 HTTP만 쓰는 봇 | 좌석을 잡은 로그인 세션에 화면 녹화가 0건 | 30 / 45 | ERD v34 뒤 |
| `LINEAR_MOUSE` | 브라우저 자동화 기본 클릭 (botb 6/6) | 녹화된 마우스가 클릭 자리끼리 순간이동하거나 직선·등속 | 25 / 40 | ✅ |
| `NO_SEARCH_ENTRY` | 운행 번호를 알고 대기열로 바로 오는 봇 | 하루 동안 사람이 직접 한 열차 조회 0건 + 대기열 진입 | 10 (LOW) | 점수만 |

## 등급

| 등급 | 점수 | 하는 일 |
|---|---|---|
| 정상 | 0~29 | 순번만 점수만큼(초) 뒤로 |
| 경고 | 30~79 | + A-05 "경고", 70부터 녹화 자세히 |
| 위험 | 80~ | + 케이스 · 결제 차단 (케이스·결제 차단과 같은 기준 80) |

## 왜 이렇게 했나 (핵심 원리)

- **개수로 센다, 비율이 아니다**: 정상 행동을 섞어도 점수가 내려가지 않게 (무작위 2만 개 단조성 시험)
- **사람을 지키는 장치를 먼저**: 휴대폰 탭(마우스 흉내)·키보드 클릭은 마우스 규칙에서 뺌, 녹화가 고장 나면 "녹화 없음"을 세지 않음, 자동 새로고침은 "빠른 단계"로 안 셈, 한 번은 우연일 수 있어 2번부터
- **응답을 받은 뒤부터 잰다**: 서버가 바쁘면 요청 시각끼리의 간격이 늘어 봇도 느려 보였다 → 행동 로그에 처리 시간(`elapsed_ms`)을 남김
- **ERD보다 코드가 먼저 나가도 안전**: DB CHECK가 받아 주는 규칙 코드만 케이스 마커로 넣고, 나머지는 점수만 (롤백 없음). 패치가 들어오면 5분 안에 저절로 켜짐

## 2차 대회 전 보강 (2026-11-24)

새 규칙 없이 이미 케이스 마커인 규칙의 판정을 넓혔다 (ERD 패치 없음).

| 무엇 | 바꾼 판정 | 잡는 봇 (연습 봇) |
|---|---|---|
| HEADLESS_HOLD | 녹화가 있어도 **손이 움직인 흔적이 없으면** 같게 봄: 클릭 0건, 또는 마우스 클릭뿐이고 궤적 점이 없거나 클릭 자리에만 (터치·키보드만이면 제외) | botrecone · botrecclick · botrecjump |
| LINEAR_MOUSE | 직선·등속을 **입력 장치와 상관없이** 셈, 최소 거리 100을 점 5개 구간마다가 아니라 **이어진 직선 전체**로 | botrectouch · botreclinear |
| INHUMAN_STEP | 같은 세션이 바로 전과 **같은 좌석**을 문턱 안에 다시 보낸 요청은 뺌 (선점 버튼 두 번) | 오탐 수정 |
| MULTI_ACCOUNT_SYNC (기기) | 그 기기에서 직전 다른 계정의 마지막 행동 뒤 `risk.rule.account_switch_sec` 안에 행동한 계정만 셈 | 오탐 수정 (가족 한 컴퓨터) |

- 로컬 연습 봇: 3단계 9종 중 **5종 3/3 케이스**(전엔 1종 1/3), 합성 사람·사람 변형 10종 오탐 0
- 남은 4종(휜 곡선·같은 궤적 재사용·휴대폰인 척·사람과 같은 녹화)은 손 모양(겨냥 동작)을 봐야 함
- 트러블슈팅: [선점 두 번 클릭](../troubleshooting/20261124-선점-두-번-클릭이-사람보다-빠른-단계로-잡힘.md)

## 2차 대회 결과 (2026-11-24, 강동균 님 [분석](../../강동균/features/2차-대회-결과-분석.md))

- **botb 6/6 케이스** (HEADLESS_HOLD·LINEAR_MOUSE), **진짜 사람 27계정 오탐 0** (최고 45점) — 1차 0/12에서
- 진짜 사람으로 잰 기준값 → ERD v40: `inhuman_step_ms` 500 → **1000**(사람 최소 2.74초), `account_switch_sec` 3 → **15**(가족 전환 최소 31.7초), `no_search_entry_points` 10 → **30**
- botc(진짜 브라우저 + 곡선 마우스 + 사람 속도)는 규칙으로 못 잡음 → 모델이 6/6. 규칙과 모델이 서로 다른 봇을 잡는다

## 아직 모르는 것

- 진짜 사람은 5명·27계정뿐 — 트랙패드·터치 노트북·광고 차단기로 녹화가 막힌 사람은 아직 못 봄
- 마우스 규칙 문턱은 botb 녹화를 보고 정했다 (botb가 LINEAR_MOUSE에 걸린 건 처음 보는 시험이 아님)
- 손 모양: 평소 녹화(SAMPLED 0.15초)는 이동 하나에 점 4~5개라 곡선·손떨림이 안 보임 → 녹화 해상도를 먼저 정해야 함 (강동균 님 분석 5절)
