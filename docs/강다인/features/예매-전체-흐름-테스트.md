# 예매 전체 흐름 통합 테스트 (TEST-02)

작성자: 강다인 · 코드: `src/test/java/com/jejari/flow/BookingFlowE2EInfraTest.java`

## 한 줄 요약

사용자가 화면에서 하는 순서 그대로 **HTTP API만** 불러, 다섯 파트가 이어 붙었을 때 끊기는 곳이 없는지 한 번에 본다.

## 흐름

```
본인인증 → 가입 → 로그인                         (D 강다인)
  → 대기열 진입 → 입장 → 입장 토큰               (A 김성원)  ※ 입장 스케줄러는 테스트에서 꺼져 있어 admit()을 한 번 직접 부름
  → 좌석 배치도(토큰 없으면 403) → 좌석 선점     (B 강동균)
  → 결제(Mock PG 승인 카드) → 확정               (C 길동현)
  → 예매 내역 → 수수료 미리보기 → 취소 → 환불     (D 강다인)
```

## 마지막에 확인하는 DB 흔적

| 무엇 | 기대값 |
|---|---|
| 상태 이력 | HOLD → PAYMENT_PENDING → CONFIRMED → CANCELED |
| outbox 이벤트 순서 | SEAT_HELD → PAYMENT_STARTED → RESERVATION_CONFIRMED → RESERVATION_CANCELED → REFUND_COMPLETED |
| 결제 | REFUNDED, 취소 응답 환불액 = 미리보기 환불액 |
| 매수 카운터 | 0 (샀다가 취소) |
| 좌석 | 재고 행 0, Redis 좌석 키는 REOFFER(대기자 먼저) 또는 이미 풀림 |
| 행동 로그 (Kafka → MongoDB) | 이 회원으로 SEAT_HOLD·CANCEL (최대 15초 기다림) |

## 왜 이렇게

- **API만 부른다**: 서비스 메서드를 바로 부르면 인증·입장 토큰·멱등 키·컨트롤러의 행동 로그 같은 "연결 부분"을 건너뛴다. 파트 경계에서 깨지는 걸 보려면 사용자와 같은 입구로 들어가야 한다.
- **세부 규칙은 파트 테스트에 맡김**: 동시성·실패 경로는 TEST-01과 파트별 테스트가 본다. 여기는 정상 흐름 하나를 끝까지.
- **좌석은 DB에서 빈 것을 고른다**: 로컬 시연 데이터가 쓰는 좌석과 겹치면 "다른 사람이 먼저 선택한 좌석"으로 실패한다 (오늘 CNL-03 테스트에서 겪음).

