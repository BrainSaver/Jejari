# 예매 내역 목록·상세 (RSV-04)

작성자: 강다인 · 코드: `src/main/java/com/jejari/reservation/` (`ReservationQueryService`, `CancelFeeCalculator`, `web/ReservationQueryController`) · 화면: U-08

## 한 줄 요약

내 예약을 최근 것부터 상태별로 보여 주고, 상세에서 좌석·승차권 번호(확정일 때만)·결제 상태·결제 기한·**취소 가능 여부와 예상 수수료**를 보여 준다. 읽기만 한다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/reservations?status=CONFIRMED,CANCELED&before=1024&size=20` | 내 예약 목록. `status`는 HOLD·PAYMENT_PENDING·CONFIRMED·CANCELED·EXPIRED를 쉼표로(없으면 전체), `before`는 다음 페이지 커서(`nextBefore`), `size` 1~50(기본 20) |
| GET | `/api/v1/reservations/{id}` | 상세 |

같은 경로의 POST(좌석 선점, 결제 전 취소)는 강동균 님 `seat.web.ReservationController`가 맡고, 이 컨트롤러는 GET만 맡는다.

상세 응답 예 (확정 예약):


## 규칙

| 규칙 | 이유 |
|---|---|
| 모든 조회에 `member_id = 나` | 남의 예약은 "없음"(404 `RESERVATION_NOT_FOUND`)과 똑같이 답해 예약 ID가 있는지조차 모르게 함 |
| 승차권 번호는 CONFIRMED일 때만 | 선점 때 발급되지만 확정 전에는 효력이 없음 (기능설계서 RSV-04) |
| 결제 기한은 HOLD·PAYMENT_PENDING일 때만 | 다른 상태에선 의미 없음 |
| 취소 가능: HOLD → 무료, PAYMENT_PENDING → 불가(`PAYMENT_IN_PROGRESS`), CONFIRMED → 수수료 계산, 나머지 → 불가(`ALREADY_CLOSED`) | U-08 버튼 표시 |
| 모르는 상태 값·크기는 400 | 조용히 무시하면 "전체"처럼 보여 혼동 |
| `Cache-Control: no-store` | 승차권 번호·결제 상태가 브라우저·프록시 캐시에 남지 않게 |

## 수수료 계산 `CancelFeeCalculator` (공용)

확정 취소(CNL-01 수수료 미리보기·CNL-02 확정 취소, 다음 작업)도 이 계산을 그대로 써서 상세 화면의 예상 수수료와 실제 수수료가 항상 같게 한다. 상태 없는 순수 함수다.

```
출발 전: 남은 분 = 출발 − 지금 (분 단위 내림), cancel_fee_policy 구간 [min, max) 중 하나 (출발 후 행 제외)
출발 후: after_departure = 'Y' 행. 출발 후 cancel.after_departure_limit_min(20분)이 지나면 취소 불가
수수료 = Σ 좌석별 금액 × 비율 (좌석마다 원 미만 버림), 환불액 = 결제 금액 − 수수료
정책 고르기: 운행의 행사 정책 → 없으면 상시 정책(sale_event_id NULL)
```

- **정책이 없거나, 구간이 겹치거나, 비율이 0~1 밖이면 취소 불가**(`FEE_POLICY_MISSING`)로 답한다. 수수료를 0원으로 잘못 계산하면 사자마자 취소하는 되팔이의 비용이 사라지기 때문이다 (fail-closed).
- 경계에서는 늘 더 불리한 쪽: 출발 10분 59초 전은 10분, 출발 30초 뒤는 −1분.
