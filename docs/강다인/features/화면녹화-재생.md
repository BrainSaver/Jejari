# 화면 녹화 재생 (ADM-11)

작성자: 강다인 · 2026-11-18 · 코드: `src/main/java/com/jejari/replay/`, `frontend/src/replay/recorder.js`, `frontend/src/admin/ReplayPlayer.jsx` · 화면: A-06 케이스 상세 아래 "화면 녹화 재생"

## 한 줄 요약

회원 화면에서 **어디를 언제 눌렀고 마우스가 어떻게 움직였는지**만 가볍게 기록해, 관리자가 의심 케이스에서 그 세션을 **영상처럼 다시 본다**. 옆에 같은 세션의 서버 결과(선점 409·결제·취소)가 같은 시간축으로 나와 "클릭 → 서버 결과"가 한 줄로 보인다.

## 흐름

```
[회원 브라우저] recorder.js
   PAGE_VIEW · CLICK(좌표 0~1000, 요소 ID) · MOUSE_PATH(FULL만) · SCROLL · VISIBILITY · INPUT(길이만)
   → 5초마다(replay.batch_sec) POST /api/v1/replay/events
[서버] ReplayController → ReplayService: 검사·모드 결정 → ReplayPublisher (요청 스레드는 기다리지 않음)
   → Kafka jejari.replay (키 = 로그인 세션 ID)
   → ReplaySink (그룹 replay-sink) → MongoDB replay_session (세션 1건) + replay_event (이벤트)
[관리자] A-06 → GET /api/v1/admin/cases/{id}/replays(/{sessionId}) → ReplayPlayer (SVG로 다시 그림)
```

## 규칙과 이유

| 규칙 | 이유 |
|---|---|
| **입력값은 절대 받지 않음**, 길이만 (`input_masked: "len:7"`) | 비밀번호·카드번호·이메일이 녹화에 남으면 안 된다. 서버 요청 모양에 값 칸이 아예 없음 |
| 요소 ID는 `영문·숫자·_:-./` 64자만 (`data-rec="seat-105007"`) | 화면 문구(이름 등)가 요소 ID로 섞여 들어오지 않게. 한글이면 버림 |
| 화면 ID는 주소의 숫자를 `:id`로 (`runs/:id/seats`) | 예약 번호 같은 ID를 녹화에 남기지 않음. 운행 번호만 `run_id`로 따로 (세션 검색용) |
| 좌표는 화면 비율 0~1000 | 녹화한 기기 해상도와 상관없이 재생 |
| **FULL / SAMPLED** 녹화: 위험 점수 70 이상(`replay.full_record_score`) 또는 세션 해시 표본 10%(`replay.full_record_ratio`)만 FULL. 나머지는 마우스 궤적을 버림 | 마우스 궤적이 저장량의 대부분. 정상 회원은 클릭·화면 이동만 남긴다. 같은 세션은 늘 같은 모드 |
| 궤적 점 50개(`replay.max_path_points`), 세션당 5,000건(`replay.max_events_per_session`), 요청당 500건 | 매크로가 이벤트를 쏟아부어도 저장량이 끝없이 늘지 않게 |
| 시각이 서버와 하루 넘게 다르면 버림 | 시계가 틀린 기기·위조 |
| `(session_id, seq)` 유니크, seq = "지금 ms × 1000"부터 | 네트워크 재전송·Kafka 재전달이 중복 저장되지 않음. 새로고침해도 seq가 겹치지 않음 |
| 90일 뒤 자동 삭제(`expire_at` TTL, `replay.retention_days`) | 개인정보 최소 보관 |
| **케이스가 열리면 삭제 보류**(`legal_hold`): 1분 배치가 케이스를 열 때 겹치는 세션의 `expire_at`을 지움. 적재기는 저장 뒤 보류 여부를 다시 확인해 그 사이 들어온 것도 뺌 | 조사 중인 증거가 90일 TTL로 지워지지 않게 |
| 관리자는 **케이스를 통해서만** 본다: 케이스 대상(CI·기기·결제수단)의 계정 세션 중 의심 구간과 겹치는 것만. 다른 세션 ID는 404 | 아무 회원의 녹화나 열어 볼 수 없게 (최소 열람) |
| 녹화가 꺼져 있거나 Kafka가 죽어도 회원 화면은 그대로 (녹화는 버림) | 녹화 몇 초 유실 < 예매 화면이 느려지는 것 |

## ERD와 다른 점 (강동균 님께 알림)

- ERD 비고는 `replay_event`를 **시계열 컬렉션**으로 적었지만, MongoDB 시계열 컬렉션은 **유니크 인덱스를 만들 수 없어** 재전달 중복을 막을 수 없다(DB설계서는 `{session_id, seq}` 유니크를 요구). 그래서 **일반 컬렉션 + `{session_id, seq}` 유니크 + `expire_at` TTL**로 만들었다. ERD 비고 수정이 필요하면 강동균 님께 요청.
- `api`·`domain_event` 칸은 쓰지 않고, 재생할 때 같은 세션의 `behavior_log`(서버 이벤트)를 함께 읽는다. 같은 것을 두 번 저장하지 않으려고.

## 직접 보기

1. 앱·프론트를 띄우고(`작업안내.md`), 회원으로 로그인해 열차 검색 → 좌석 화면에서 이것저것 누른다 (5초마다 전송)
2. 그 회원이 케이스에 걸려야 관리자 화면에 보인다. 화면만으로 확실한 방법은 **결제 직후 취소 2번**(CANCEL_AFTER_PAY): 같은 계정으로 좌석 결제(카드 `4111111111111111`) → 예매 내역에서 취소를 30분 안에 두 번 → 1~2분 뒤 케이스가 열린다
   - ⚠️ 좌석을 연타해도 케이스는 안 열린다. 좌석 선택은 브라우저 안에서만 바뀌고 서버 요청이 없어서, 행동 로그(=위험 점수 입력)에 남지 않는다
3. `/admin/cases` → 그 케이스 → 맨 아래 **화면 녹화 재생** → 세션 고르고 [재생] (1·4·16배, 빨간 눈금 = 탐지 마커)

Mongo에서 바로 보기: `db.replay_session.find().sort({started_at:-1}).limit(1)`, `db.replay_event.find({session_id: "…"}).sort({seq:1})`

## 개선 B: 화면 뼈대 배경 + "무엇을 했나" (2026-11-19)

처음 버전은 빈 화면 틀 위에 마우스·클릭만 그려 **무엇을 했는지 알 수 없었다** (다인 님 지적). 화면을 통째로 녹화(rrweb)하면 이름·연락처가 남으므로, 그 사이를 택했다.

| 추가 | 내용 | 개인정보 |
|---|---|---|
| `LAYOUT` 이벤트 | 화면이 뜨거나 바뀔 때(좌석 상태·목록 도착·스크롤·창 크기) 그 순간 **보이는 요소의 상자**: 종류(button·link·input·select·heading·tab·seat-free/hold/taken/mine/lost), 위치·크기(0~1000), `data-rec` ID, 누를 수 없음 여부. 1초에 한 번까지, 바뀐 게 없으면 안 보냄, 400개까지 | 화면 글자를 담지 않음 |
| 버튼 문구 `label` | 클릭한 버튼·탭·링크와 뼈대 상자의 문구 ("결제하기", "열차 찾기") | **숫자·@ 없는 한글·영문 20자**만 (서버가 다시 거름) → 전화·카드·이메일·좌석 번호 불가 |
| 좌석 이름 | 재생 응답에 `seats: {"seat-105007": "5호차 3A"}` (좌석 표에서) | 운영 데이터 |
| 재생기 | 그때 회원 화면의 실제 배치를 배경으로 그리고(좌석은 상태 색), 그 위에 궤적·클릭(이름표). 위 띠에 화면 이름 한글 | |
| "무엇을 했나" | 화면 이동·클릭(좌석 번호/버튼 문구)·입력(길이)·탭 이동 + 서버 결과(좌석 선점 → 실패 — 이미 다른 사람이 잡음)를 시간순 한 줄씩 | |

**미리 찍은 스크린숏을 배경으로 쓰지 않은 이유**: 회원마다 창 크기·스크롤이 달라 클릭 위치가 어긋나고, 그때 좌석이 비어 있었는지 판매됐는지를 보여 줄 수 없다. 뼈대는 그 사람 화면에서 그대로 재서 위치가 맞고 좌석 상태까지 남는다.

**ERD와 다른 점 추가** (강동균 님께): `replay_event.type`에 `LAYOUT`, 필드 `label`(문구)·`boxes`(뼈대 상자 배열)
