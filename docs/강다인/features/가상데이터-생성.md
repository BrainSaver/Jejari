# 가상 회원·예매·행동 데이터 생성 (DATA-02)

작성자: 강다인 · 코드: `src/main/java/com/jejari/synthetic/` (`SyntheticDataService`, `SyntheticDataRunner`) · 함께: 조영준 님 DATA-03 (`loadtest/scenarios/12_bot_detection.js`, `loadtest/tools/eval_risk.sh`)

## 한 줄 요약

정상 회원과 봇 4종을 수천 명 규모로 DB에 바로 만든다. 시나리오 12와 **같은 이메일 라벨 규칙**이라 `eval_risk.sh`로 그대로 탐지율·오탐률을 잰다. 시나리오 12는 "지금 들어오는 트래픽", 이건 "이미 쌓여 있는 데이터"를 맡는다.

## 실행 (PowerShell, 앱은 꺼 둔 상태에서)

```powershell
cd C:jjr
# 1) 생성 + 위험 점수 계산까지 (1,000명 약 5~7분, 끝나면 저절로 꺼짐. 앱을 따로 켤 필요 없음)
.gradlew.bat bootRun --args="--spring.profiles.active=synthetic --jejari.synthetic.tag=syn1 --jejari.synthetic.members=1000"
# 2) 평가 (점수는 이미 계산돼 있어 기다릴 필요 없음)
cd C:jjrloadtest
$env:WAIT_SEC = "5"
& "C:Program FilesGitinash.exe" tools/eval_risk.sh syn1
# 3) 지우기
cd C:jjr
.gradlew.bat bootRun --args="--spring.profiles.active=synthetic --jejari.synthetic.tag=syn1 --jejari.synthetic.cleanup=true"
# (점수만 다시 계산: --jejari.synthetic.score-only=true)
```

생성기가 끝날 때 위험 점수 배치를 그 자리에서 다 돌린다. 처음엔 "생성 → 앱 켜기 → 1분 기다리기 → 평가"였는데, 앱을 켜지 않고 평가해서 **탐지율 0%**(점수가 하나도 계산되지 않은 상태)가 나온 일이 있어 순서를 없앴다.

## 결과 (2026-11-17, 1,000명, 태그 syn1)

| 종류 | 인원 | 탐지 | 걸린 규칙 |
|---|---|---|---|
| normal | 910 | **0** (최고 10점) | - |
| cancel | 20 | 20 | CANCEL_AFTER_PAY (CI·결제 수단) |
| fast | 20 | 20 | FAST_CLICK (CI·기기) |
| multi | 30 | 30 | MULTI_ACCOUNT_SYNC (기기) |
| retry | 20 | 20 | SAME_SEAT_RETRY (CI·기기) |

**탐지율 100% (90/90), 오탐률 0% (0/910).** 가족 기기 공유 정상 회원도 오탐 없음. 다계정은 member_device 기록(같은 날 추가) 덕분에 기기 단위로 잡힘. 한계: 봇이 문턱을 확실히 넘게 만든 데이터라, 문턱 근처 봇의 경계는 따로 재야 함.

태그는 영문 소문자·숫자 8자 이내, 같은 태그로 두 번 만들 수 없음. `--jejari.synthetic.seed=…`로 같은 모양을 다시 만들 수 있음.

## 만드는 것

| 종류 (이메일) | 비율 | 정답 | 데이터 | 걸려야 할 규칙 |
|---|---|---|---|---|
| normal | 나머지(약 91%) | NORMAL | 사람 속도 클릭 8~22번, 과거 구매 0~2건, 10%는 한참 뒤 1건 취소, **5%는 가족과 기기 공유(4시간 차)** | 없음 (오탐 함정 포함) |
| fast | 2% | MACRO | 20~60ms 간격 50번 | FAST_CLICK |
| retry | 2% | MACRO | 같은 좌석 409 8번 | SAME_SEAT_RETRY |
| multi | 3% (3명 묶음) | RESELLER | 한 기기로 몇 초 안에 각자 선점 | MULTI_ACCOUNT_SYNC |
| cancel | 2% | CANCEL_ABUSER | 결제 1~3분 뒤 취소 3번 | CANCEL_AFTER_PAY |

- 회원·카드·기기·`member_device`·행동 로그(최근 3시간)·과거 예약·결제·취소(최근 20일)를 만들고 `risk:dirty`에 표시.
- CI(`mockCiHash`)·전화 암호화(`PiiCipher`)·카드·기기 해시(`Pseudonymizer`)가 **실제 가입과 같은 함수**라 대기열·위험 점수·관리자 화면이 똑같이 읽는다. 카드번호는 `9`로 시작하는 가짜 16자리.
- 과거 이력은 **태그 전용 "출발한 운행"**(run_id 880001~)에 쌓는다. 판매 중 운행·테스트용 9001·9002의 좌석 재고는 건드리지 않는다.
- 비밀번호는 만들지 않음 (로그인 안 함, Argon2 1,000번은 느림).
