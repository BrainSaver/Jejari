# 위험 점수·의심 케이스 직접 확인하기

작성자: 강다인 · 스크립트: `tools/risk-demo.sh` · 관련: RISK-02(1분 배치), RISK-04(의심 케이스)

가짜 회원 하나로 "봇처럼" 또는 "사람처럼" 요청을 보내고, 1분 배치가 점수·케이스를 만드는지 Oracle·Redis에서 바로 확인합니다. 2~3분이면 끝납니다.

## 준비 (처음 한 번)

1. `docker compose up -d` → `docker ps`에서 oracle·redis·mongo·kafka가 `healthy`인지 확인
2. `.env`가 있어야 합니다 (`.env.example` 복사 후 값 채움)
3. Oracle이 최신 DDL(ERD v19 이상: `suspicious_case_seq`·`case_marker_seq` 등)로 만들어져 있어야 합니다. 예전 DB면 `docs/erd/jejari-erd.ddl.sql`로 다시 만드세요.

## 실행

터미널 두 개를 씁니다.

**PowerShell** (Windows 기본 터미널)

```powershell
# 터미널 1: 앱 실행 (Started JejariApplication 이 보일 때까지 기다림, 이 창은 켜 둠)
cd C:\jjr
.\gradlew.bat bootRun

# 터미널 2
cd C:\jjr
$env:RESET_RATE = "1"                                              # 본인인증 횟수 제한 기록 지우기 (로컬 전용)
& "C:\Program Files\Git\bin\bash.exe" tools/risk-demo.sh bot      # 봇처럼: 쉬지 않고 좌석 배치도 30번
& "C:\Program Files\Git\bin\bash.exe" tools/risk-demo.sh normal   # 사람처럼: 3초 간격으로 3번
```

**Git Bash**

```bash
./gradlew bootRun                          # 터미널 1
RESET_RATE=1 bash tools/risk-demo.sh bot   # 터미널 2 (normal도 같은 방식)
```

다 보면 터미널 1에서 Ctrl+C로 앱을 끕니다.

스크립트가 하는 일: 가입·로그인 → 대기열 입장(입장 토큰) → 좌석 배치도 요청 → 최대 90초 동안 1분 배치를 기다림 → 결과 출력.

## 결과 읽는 법

| 항목 | 봇 (`bot`) | 사람 (`normal`) |
|---|---|---|
| `risk_score.final_score` | 30 이상 (빠른 클릭 25 + 신규 계정 5) | 5 (신규 계정만) |
| `reasons` | `FAST_CLICK` (+ 간격이 아주 고르면 `REGULAR_INTERVAL`) | `NEW_ACCOUNT` |
| `review_status` | `PENDING` (케이스가 열려 검토 대기) | `NONE` |
| 케이스·마커 | `RULE` · `OPEN`, 마커 `FAST_CLICK` "200ms 미만 간격 요청 N회" | 없음 |
| Redis `risk:CI:…` | final_score와 같은 값 (대기열이 이 값으로 순번을 미룸) | `5.00` |

실제 실행 예 (2026-11-17): 봇 → 30점, 케이스 `RULE`·`OPEN`, 마커 "200ms 미만 간격 요청 28회", Redis `30.00` / 사람 → 5점, 케이스 없음.

## 막힐 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `앱이 안 떠 있어요` | bootRun 전이거나 아직 시작 중 | 터미널 1에서 `Started JejariApplication`까지 기다림 |
| `HTTP 429 RATE_LIMITED` | 본인인증·가입은 IP당 시간당 10번 (보안 기능) | 로컬이면 PowerShell `$env:RESET_RATE = "1"` 후 다시 실행 (Git Bash는 `RESET_RATE=1 bash …`). 로컬 Redis의 제한 기록을 지움 |
| `HTTP 400` (가입) | Windows curl은 한글 인자를 UTF-8로 안 보냄 | 스크립트는 영문 이름 `Demo`를 씀. 직접 요청할 때도 영문으로 |
| `403 QUEUE_TOKEN_REQUIRED` | 좌석 배치도는 대기열 입장 토큰(`X-Queue-Token`) 필요 | 스크립트가 자동으로 받음 |
| 90초가 지나도 점수 행 없음 | 사람 모드에서 7일 넘은 계정이면 0점이라 정상. 봇인데 없으면 앱 로그의 `위험 점수 배치` 줄 확인 | |
| 점수는 있는데 케이스가 없음 / 앱 로그에 `suspicious_case_seq` 오류 | 로컬 DB가 v19 이전 DDL (준비 3번) | 최신 DDL로 DB를 다시 만든 뒤 다시 실행 |
| 테스트(`./gradlew infraTest`)가 안 끝남 | bootRun 앱이 아직 떠 있어 같은 Kafka 소비 그룹을 나눠 씀 | 앱을 끄고(Ctrl+C) 테스트. 꺼졌는지는 `netstat -ano \| grep :8080` |
