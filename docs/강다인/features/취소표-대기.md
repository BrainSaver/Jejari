# 취소표 대기 신청·목록·취소 (WL-01·02)

작성자: 강다인 · 코드: `src/main/java/com/jejari/waitlist/` (`WaitlistService`, `web/WaitlistController`) · 화면: U-10 · 절차: concurrency.md §9.3

## 한 줄 요약

매진된 등급에 취소표 대기를 걸고(같은 운행 1건, 전체 3건까지), 내 대기 목록을 보고 취소한다. 대기 순서는 **신청 시각 + 위험 점수 × 3분**이라 대기열에서 뒤로 밀린 봇이 취소표로 우회하지 못한다. 실제 제안(WL-03)은 `seat-release` 소비자가 한다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/waitlists` | 신청. 본문 `{"runId":9001,"fromStationId":"3900023","toStationId":"3900114","seatGrade":"GENERAL","seatCount":1}` → 201 `{waitlistId, status, requestedAt}` |
| GET | `/api/v1/waitlists` | 내 대기 목록 (최근 50건). 기다리는 중이면 `ahead`(같은 운행에서 내 앞 대기 수), 제안받았으면 `offerDeadlineAt`·`offeredReservationId` |
| DELETE | `/api/v1/waitlists/{id}` | 대기 취소 (WAITING만) → 204 |

대기열 입장 토큰은 필요 없다 (매진 화면에서 바로 신청).

## 신청 흐름

```
입력 검사 (등급 GENERAL·FIRST, 매수 1 이상)
 → 판매 중 운행·승하차역 순서 (TrainRunReader)           실패: RUN_NOT_ON_SALE 409 / 400
 → 1회 매수 한도 (PurchaseLimits)                        실패: LIMIT_PER_RESERVATION 422
 → 회원 상태 ACTIVE만 (MemberIdentityPort)               실패: WAITLIST_RESTRICTED 403
 → 그 등급 남은 좌석 < 매수 (SeatMapService)             실패: WAITLIST_NOT_SOLD_OUT 409
 → 위험 점수 (RiskPenaltyService, 대기열과 같은 규칙) × waitlist.penalty_ms_per_point
 → [트랜잭션] 회원 행 FOR UPDATE → 활성 대기 수 확인 → INSERT (priority_at = 신청 시각 + 패널티)
                                                        실패: WAITLIST_DUPLICATED 409 / WAITLIST_LIMIT 422
```

다른 파트 코드를 그대로 쓴다: 운행·구간(B `TrainRunReader`), 1회 한도(B `PurchaseLimits`), 남은 좌석(B `SeatMapService`), 회원 상태(D `OracleMemberIdentityPort`), 위험 점수(A `RiskPenaltyService`).

## 규칙

| 규칙 | 이유 |
|---|---|
| 순서 = `priority_at`, 신청 때 한 번만 계산 | 대기열 패널티 우회 방지 (§9.3). 점수 때문에 신청을 막지는 않음 |
| 1점 = 3분 (`waitlist.penalty_ms_per_point` 180000) | 80점이면 4시간 뒤. 봇은 판매 첫날 오전 신청자 뒤로, 오탐된 정상 사용자도 몇 시간 뒤면 차례 (미정 7 해결값) |
| RESTRICTED는 거절 | 최대 패널티(5시간)로 미뤄도 결국 표를 가져감 |
| 회원 행을 잠그고 한도 확인 | 따닥 두 번 눌러 두 요청이 동시에 "0건"을 보고 둘 다 들어가는 것 방지 (4개 동시 요청 → 1건만, 테스트로 확인) |
| 활성 대기 = WAITING·OFFERED | 끝난 대기(ACCEPTED·EXPIRED·CANCELED·SKIPPED)는 한도에 안 셈 |
| 점수·패널티·priority_at은 응답에 없음 | 왜 밀렸는지 알려 주면 봇이 점수 기준을 역산 |
| 대기 취소는 WAITING만, 다시 눌러도 204 | 제안받은 좌석(OFFERED)은 예약이 이미 있으니 예매 내역에서 취소 (`WAITLIST_NOT_WAITING`) |
| 남의 대기와 없는 대기는 같은 404 | ID로 남의 대기를 알아내지 못하게 |
| 한도·패널티 값은 `AppPolicy` (`waitlist.max_per_run` 1, `max_active` 3, `penalty_ms_per_point` 180000) | 코드에 박지 않음 |
