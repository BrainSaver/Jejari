# 회원가입 + 모의 본인인증 + 로그인 (AUTH-01·02·03)

작성자: 강다인 · 코드 위치: `src/main/java/com/jejari/member/` · 화면: U-01, U-02

> 상태: 구현 완료 (단위 테스트 45개, Oracle·Redis·MongoDB 통합 테스트 15개). 원천은 기능설계서 4.1, ERD `member`·`member_credential`·`identity_verification`·`login_attempt`.

## 한 줄 요약

이름 + 휴대폰으로 **항상 같은 가짜 CI**를 만들어 같은 사람의 여러 계정을 묶고, 비밀번호는 **pepper + Argon2id**로 저장하며, 로그인은 **계정이 있는지 없는지 응답으로 알 수 없게** 만든다.

## API

| 메서드·경로 | 본문 | 성공 | 실패 |
|---|---|---|---|
| `POST /api/v1/auth/verify` | `{name, phone, provider}` (MOCK_PASS / MOCK_PHONE) | 200 `{verificationToken, expiresIn}` | `AUTH_VERIFY_FAILED`, `RATE_LIMITED` |
| `POST /api/v1/auth/signup` | `{verificationToken, email, password}` | 201 `{email: "ho***@example.com"}` | `AUTH_VERIFY_FAILED`, `AUTH_PASSWORD_POLICY`, `AUTH_EMAIL_DUPLICATED`, `INVALID_REQUEST`, `RATE_LIMITED` |
| `POST /api/v1/auth/login` | `{email, password}` | 200 `{accessToken, tokenType, expiresIn}` + 리프레시 쿠키 | `AUTH_INVALID_CREDENTIALS`, `AUTH_LOCKED`, `AUTH_RATE_LIMITED`, `AUTH_BANNED`, 503 |

모든 응답에 `Cache-Control: no-store`. 가입은 로그인 세션을 주지 않는다 (로그인 화면으로 이동).

## 어떻게 동작하나

```
verify : IP 시간당 제한 → 이름·휴대폰 정규화 → 가짜 CI 해시 → 1회용 토큰(Redis, 10분)
signup : IP 시간당 제한 → 이메일·비밀번호 규칙 → 토큰 확인(읽기만) → Argon2id 해싱
         → 토큰 소비(GETDEL) → 한 트랜잭션: member + member_credential + identity_verification
login  : IP 분당 제한 → 이메일별 잠금 확인 → 계정 조회(없으면 더미 해시) → Argon2id 검증
         → 실패: 실패 수 +1 / 성공: 정지 확인 → 실패 수 초기화 → (필요하면 재해싱) → 세션 발급
         → 모든 시도를 MongoDB login_attempt에 기록
```

## 보안 설계 (왜 이렇게 했나)

| 위협 | 막는 방법 | 코드 |
|---|---|---|
| DB 유출 후 비밀번호 대입 | Argon2id(m=19MiB,t=2) **+ pepper**(DB 밖 비밀값, HMAC 먼저). DB만으로는 대입 불가 | `PasswordHasher` |
| 정책 캐시 조작으로 해시 약화 | Argon2 파라미터가 OWASP 최소보다 약하면 무시하고 기본값 | `AuthPolicy.Argon2Params` |
| 계정 존재 여부 알아내기 (열거) | 틀린 비밀번호·없는 계정·탈퇴 계정 → 같은 코드·같은 메시지, 없는 계정도 더미 해시로 **같은 시간**. 잠금도 **없는 이메일까지 똑같이** 세서 "잠김"이 존재 신호가 아님 | `LoginService` |
| 비밀번호 대입 (한 계정) | 연속 5회 실패 → 15분 잠금 (Redis `login:fail:{emailHash}` + DB `locked_until` 이중) | `AuthLimiter` |
| 크리덴셜 스터핑 (여러 계정) | IP당 분당 20회, 모든 시도 기록(email_hash·ip_hash·verify_ms) | `LoginAttemptLog` |
| 해시 연산으로 서버 마비 | Argon2 동시 32개 제한(자리 없으면 503), 128자 넘는 비밀번호는 해시하지 않고 실패 | `PasswordHasher` |
| IP 위조로 제한 회피 | `X-Forwarded-For`는 설정한 프록시에서 온 요청만, 오른쪽부터 읽음 | `ClientIpResolver` |
| 정지 계정 정보 노출 | 비밀번호가 맞을 때만 `AUTH_BANNED` | `LoginService` |
| 인증 토큰 위조·재사용 | 토큰은 무작위 256비트, 내용은 서버에만. Redis 키는 토큰의 SHA-256, 휴대폰은 Redis에서도 암호화, `GETDEL`로 1회만 | `VerificationTokens` |
| 동시 가입으로 중복 이메일 | 미리 조회하지 않고 UNIQUE 위반으로 판단 → 하나만 성공 | `SignupService` |
| 개인정보 평문 저장 | 휴대폰 = AES-256-GCM(`phone_enc`, AAD에 member_id) + HMAC(`phone_hash`), CI는 해시만 | `SignupService` |
| 로그·예외로 새는 비밀값 | 요청 객체 `toString`에서 비밀번호·이름·번호 가림, 오류 메시지에 입력값 안 넣음, User-Agent 제어 문자 제거 | `MemberAuthController` |
| 비밀값 없이 약하게 동작 | HMAC·암호화 키·pepper 중 하나라도 없으면 기능 자체가 꺼짐 (엔드포인트 없음). 키가 서로 같으면 기동 거부 | `MemberAuthEnabled` |

**비밀번호 규칙** (NIST SP 800-63B): 10~64자, 서로 다른 문자 4종 이상, 흔한 비밀번호·키보드/숫자 연속 패턴 금지, 이메일 아이디 포함 금지, 앞뒤 공백·제어 문자 금지. 문자 종류 조합(대문자+숫자+기호)은 강제하지 않는다.

**같은 CI로 여러 계정 가입은 허용** (다계정 실험 대상). 매수 제한·위험 점수가 CI 기준으로 합산하므로 막을 필요가 없다.

## 설정 (`.env`)

| 키 | 설명 |
|---|---|
| `JEJARI_ENC_KEYS`, `JEJARI_ENC_ACTIVE` | 개인정보 암호화 키 `k1:<base64 32바이트>` (팀 공용) |
| `JEJARI_PEPPER_KEYS`, `JEJARI_PEPPER_ACTIVE` | 비밀번호 pepper `p1:<base64 32바이트>` (팀 공용, 다른 키와 달라야 함) |
| `jejari.auth.trusted-proxies` | 배포 때 로드밸런서 주소. 로컬은 비워 둠 |

정책값(`app_policy`): `auth.argon2_params`, `auth.max_concurrent_hash`, `auth.lock_after_failures`, `auth.lock_minutes`, `login_attempt.retention_days` + **새로 제안** `auth.login_rate_per_min`(20), `auth.signup_rate_per_hour`(10), `auth.verify_token_ttl_sec`(600). 범위를 벗어난 값은 무시하고 기본값.

## 다른 파트와의 약속

| 상대 | 약속 |
|---|---|
| 조영준 (E) | 로그인 성공 후 세션은 `AuthTokenService.issue(MEMBER, memberId, client)`, 응답은 `TokenResponses.ok` 그대로 사용 |
| 전체 | `ci_hash`·`phone_hash`·`email_hash`·`ip_hash`는 `Pseudonymizer`로만 계산 |
| 조영준 (DATA-02 가상 데이터) | 봇·다계정 시드도 같은 정규화·같은 함수(`mockCiHash`)로 ci_hash를 만들어야 묶임. 비밀번호는 `PasswordHasher.hash`로 |

## 한계 (솔직하게)

- **인증 실패 기록**: `identity_verification.member_id`가 NOT NULL이라 실패(FAIL)는 회원이 없어 저장할 수 없다. 지금은 앱 로그(IP 해시만)로 남긴다.
- **이름 평문**: ERD의 `member.name`은 평문이다. 휴대폰·CI·카드·IP만 암호화·해시 대상.
- **Redis 재시작 직후**: Redis 잠금 카운터가 사라져도 DB `locked_until`로 잠금은 유지되지만, 이 짧은 시간에는 있는 계정만 "잠김"이 보일 수 있다 (없는 계정의 잠금 기록은 Redis에만 있음).
- **가입 이메일 중복**: `AUTH_EMAIL_DUPLICATED`는 가입된 이메일임을 알려 준다 (기능설계서 규칙). 본인인증 + IP 시간당 10회 제한으로 대량 조회를 막는다.
