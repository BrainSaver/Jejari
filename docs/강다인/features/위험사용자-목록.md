# 위험 사용자 목록 (ADM-04)

작성자: 강다인 · 코드: `src/main/java/com/jejari/risk/admin/` (`RiskAdminService`, `web/RiskAdminController`) · 화면: A-05

## 한 줄 요약

위험 점수가 높은 대상(CI·결제 수단·기기)을 점수 순으로 보여 준다. 이름·연락처·이메일은 **마스킹한 값만** 나가고, 해제는 케이스 상세(ADM-06, SUPERVISOR)에서만 한다.

## API

`GET /api/v1/admin/risks?minScore=80&maxScore=100&status=PENDING,CONFIRMED&type=CI&page=0&size=20` (관리자 VIEWER 이상)

| 필터 | 값 |
|---|---|
| `minScore`·`maxScore` | 0~100 (min ≤ max) |
| `status` | NONE·PENDING·CONFIRMED·CLEARED 쉼표 (`risk_score.review_status`) |
| `type` | CI·PAYMENT·DEVICE 쉼표 |
| `page`·`size` | 0부터, 1~100 (기본 20) |

한 줄 예:

```json
{ "subjectType": "CI", "subjectHash": "5936c6ee…", "finalScore": 91.50, "reviewStatus": "PENDING",
  "markers": ["FAST_CLICK"], "linkedAccounts": 3,
  "holder": { "name": "홍*동", "phone": "010-****-5678", "email": "g*****@example.com", "cardLast4": null },
  "latestCase": { "caseId": 47, "status": "OPEN", "triggerType": "RULE", "openedAt": "…" },
  "calculatedAt": "…" }
```

## 규칙

| 규칙 | 이유 |
|---|---|
| 전화번호는 복호화한 즉시 `PiiMasker`로 가림 | 원문이 변수 밖으로 나가지 않음. 테스트가 응답 전체에서 원문 이름·번호·이메일이 없는지 확인 |
| 복호화 실패(키 없음·변조)는 오류 대신 `***` | 한 행 때문에 목록 전체가 깨지지 않게. 원문·암호문은 로그에도 안 남김 |
| `markers`는 케이스를 여는 4개 규칙만 | 보조 신호(신규 계정 등)는 점수에는 들어가도 "왜 의심인가"의 핵심이 아님 |
| 대표 계정 = 연결된 가장 오래된 계정 | 다계정이면 처음 만든 계정이 원래 주인일 가능성이 큼 |
| 결제 수단은 카드 끝 4자리만 (`****4242`) | 카드 번호는 저장도 해시·끝 4자리만 |
| 모르는 필터 값은 400, 응답은 `no-store` | 조용히 무시하면 "전체"가 보임 / 마스킹이어도 개인정보 조각 |
