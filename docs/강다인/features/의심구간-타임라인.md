# 의심 케이스 목록·상세·타임라인 (ADM-05)

작성자: 강다인 · 코드: `src/main/java/com/jejari/risk/admin/` (`CaseAdminService`, `web/CaseAdminController`) · 화면: A-06

## 한 줄 요약

의심 케이스를 고르면 대상(CI·결제 수단·기기)에 연결된 **모든 계정의 행동 로그를 시간순 한 줄**로 보여 주고, 의심 구간 안 이벤트와 발동 마커를 표시한다. 점수 변화 이력(그래프용)과 연결 계정(마스킹)도 함께 준다. 기획서의 차별점 화면이다.

## API (관리자 VIEWER 이상)

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/admin/cases?status=OPEN,REVIEWING&page=0&size=20` | 목록 (최근 순). 열린 시점 점수와 현재 점수·검토 상태 |
| GET | `/api/v1/admin/cases/{id}` | 요약, 의심 구간, 현재 근거(reasons), 마커, 연결 계정(계정 1·2…, 가린 이름, 상태, 가입일), 점수 이력(최근 200점, 시간순) |
| GET | `/api/v1/admin/cases/{id}/timeline?from=…&to=…` | 연결 계정 전부의 행동 로그. 기본 범위 = 의심 구간, 최대 24시간·2000건. 이벤트마다 `account`, `eventType`, `responseStatus`, `intervalMs`, `inWindow`, `meta`(좌석 ID·오류 코드) |

`from`·`to`는 ISO-8601(`2026-11-17T01:00:00Z`). 없는 케이스는 404 `CASE_NOT_FOUND`.

## 규칙

| 규칙 | 이유 |
|---|---|
| 같은 대상의 **모든 계정** 이벤트를 합침 | 다계정 봇이 계정을 바꿔 가며 같은 좌석을 노리는 모습이 한 화면에 보여야 함 |
| 연결 기준은 위험 점수 배치와 같음 (`RiskInputReader.membersOf`) | 점수를 매긴 근거와 화면에 보이는 계정이 어긋나지 않게 |
| 계정은 "계정 1, 2…"(가입 순)와 가린 이름만 | 조사에 실명·연락처는 필요 없음. 해제는 ADM-06에서 SUPERVISOR만 |
| 범위 최대 24시간·2000건, 넘으면 `truncated: true` | 관리자 요청 하나가 MongoDB를 오래 붙잡지 않게 |
| 조회는 {member_id, ts} 인덱스 | ERD에 ADM-05용으로 잡혀 있는 인덱스 |
