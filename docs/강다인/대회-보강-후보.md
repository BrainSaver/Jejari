# 봇 대회 뒤 규칙 보강 후보 (수비: 강다인)

> 작성: 강다인 · 2026-11-19 · 대회 계획: [강동균 · 봇-대회-제안](../강동균/봇-대회-제안.md) · 규칙: [위험점수-규칙](features/위험점수-규칙.md)

## 원칙

- **11-23 1차 대회 전까지 위험 규칙 코드는 바꾸지 않는다.** 바꾸면 1차·2차의 "보강 전후" 비교가 깨진다. 이 문서는 코드가 아니라 **미리 생각해 둔 답안지**다.
- 11-23~25에 1차 결과(뚫린 봇·오탐된 사람)를 보고, 아래 후보 중 **실제로 뚫린 수법에 해당하는 것만** 고친다. 대회에서 안 나온 수법까지 미리 막으면 2차 수치가 부풀려진다.
- 보강마다 **사람 오탐 위험**을 같이 본다. 실제 근거: 호텔 예약 당일 취소 16.4%, 출장자 직전 취소 3배 ([DATA-04](features/외부데이터-호텔-취소-분석.md)), 정상 회원 노이즈(연타 1~4번 30%, 409 1~2번 15%).

## 대회 날 볼 것

1. `eval_contest.sh` 결과에서 **뚫린 봇마다 어느 수법인지** → 위 표 번호에 맞춰 보기. 표에 없는 수법이면 새 줄 추가
2. **오탐된 사람**이 있으면 근거(reasons)부터. 8번(자동 새로고침)인지 먼저 확인
3. 케이스가 열린 봇의 **화면 녹화 재생**(ADM-11)이 남았는지 — 화면 없이 API만 부른 봇이면 녹화가 비어 있다(3번 근거)
4. 블라인드(김성원·길동현) / 규칙 아는 쪽(강동균·조영준) 따로 센다

## 보강할 때 순서

1. 새 신호는 `RiskRule`에 **추가만** (이름 변경 금지, 저장된 reasons와 어긋남). 문턱·배점은 `app_policy risk.rule.*`
2. 케이스를 여는 마커 규칙이면 ERD `case_marker.rule_code` CHECK 패치를 **강동균 님께 요청** (v24 때처럼)
3. 단위 테스트(경계 한 칸 아래/위) + 정상 노이즈로 오탐 없는지
4. 조영준 님 경계 재측정(`./run.sh 12 -e BOUNDARY=1`) → 2차 대회(11-26)는 **같은 봇 그대로**
