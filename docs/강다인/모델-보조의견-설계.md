# 모델 점수를 관리자 화면에 보조 의견으로 (RISK-05 연결) — 설계안

> 작성: 강다인 · 2026-11-19 · 상태: **구현 완료** (ERD v25 강동균, 연결 강다인) · 모델 도구: [`tools/ml/`](../../tools/ml/README.md) (강동균)

## 지금 상황

- 모델 비교는 강동균 님이 끝냄 (`tools/ml/compare.py`). 처음 보는 봇 계열: Isolation Forest 36% · 부스팅 79% · 합치면 87%
  → 실제 모델은 **부스팅 + IF + GRU** 합성, 계정마다 점수 0~100 + **근거 3개**(`score.py` → `scores.csv`)
- 팀 결정: 모델 점수는 **관리자에게 보여 주는 보조 의견**. 대기열 순번·제한은 지금처럼 규칙 점수와 사람 판정으로 (봇 대회 제안서)
- 남은 일: 모델 점수를 관리자 화면(A-05·A-06)까지 가져오는 길

## ERD와 맞지 않는 점 (그래서 확정이 필요)

| ERD에 있는 것 | 문제 |
|---|---|
| `risk_score.iforest_score` · `model_version` | 대상이 **CI·기기·결제수단** 단위인데 모델은 **계정** 단위. 그리고 이름이 IF 전용인데 실제 점수는 세 모델 합성 |
| 근거 칸 | 모델 근거 3개를 넣을 곳이 없음 (`reasons`는 규칙 근거) |
| `model_run.algorithm` CHECK | `RULE / IFOREST`만. 합성 모델(부스팅+IF+GRU)을 기록할 값이 없음 |

## 제안

```
[오프라인, Python] score.py → scores.csv
   → tools/ml/load_scores.sh: MongoDB model_score 에 계정마다 1건 + Oracle model_run 1행 (모델 버전·문턱·성능)
[서버, Java] 케이스 상세·위험 사용자 조회 때 대상의 계정들 → model_score 중 가장 높은 것
[화면] A-06 케이스 상세에 "모델 보조 의견" 카드 (A-05 목록엔 칸 하나)
```

| 항목 | 제안 | 이유 |
|---|---|---|
| 실행 | **오프라인 배치** (대회 뒤·필요할 때 Python으로 매기고 적재) | 모델이 Python(scikit-learn·torch)이라 서버에서 실시간으로 부르면 서버가 무거워짐. 보조 의견이라 1분 지연도 필요 없음 |
| 저장 | **MongoDB `model_score`** (새 컬렉션): `member_id`, `ci_hash`, `score`, `by`(가장 높게 본 모델), `scores`{부스팅·IF·GRU}, `reasons`[3], `model_version`, `scored_at`, `source`(대회 태그) | 계정 단위·근거 배열을 그대로. Oracle `risk_score`는 규칙 점수 전용으로 둠 (대기열이 읽는 값이라 섞지 않음) |
| 모델 기록 | Oracle `model_run` 1행 (버전·파라미터·문턱·성능). `algorithm` CHECK에 **`ENSEMBLE`** 추가 | 발표 수치의 원천이 한 곳에 |
| 화면 | A-06: 점수·문턱·모델 버전·근거 3개 + **"판정 참고용, 순번·제한에는 안 씀"** 문구. 규칙 점수와 나란히 | 관리자가 규칙과 모델이 다르게 볼 때를 바로 봄 (발표 그림) |
| 권한 | 케이스와 같음 (VIEWER) | 근거는 특징 이름·숫자뿐, 개인정보 없음 |

**ERD 변경 (강동균 님께 요청)**: ① MongoDB `model_score` 컬렉션 추가 ② `model_run.algorithm` CHECK에 `ENSEMBLE`
③ (선택) `risk_score.iforest_score`는 쓰지 않는다고 비고에 적거나 지움

## 일정

- **봇 대회와 충돌 없음**: 규칙 점수는 그대로라 11-23 전에 만들어도 된다. 다만 대회 중 관리자 화면에 모델 점수가 보이면 수비(나)의 판정에 영향 → 1차 대회 동안은 화면에서 숨기는 설정(`jejari.model.show`) 또는 대회 뒤 적재
- 확정되면: 적재 스크립트·조회 API·A-06 카드 (약 반나절), 11-27 대회 데이터로 매긴 점수를 바로 올려 발표 그림으로

## 강동균 님께 확인할 것

1. 위 방식(오프라인 → Mongo `model_score` → 관리자 화면)으로 갈지, 아니면 `risk_score.iforest_score`에 대상 단위로 넣을지
2. ERD 변경 ①②③
3. `scores.csv` 컬럼이 고정인지 (적재 스크립트가 읽음): 지금 `member_id, label, strategy, score, flag, by, score_{모델}…, reasons`. `label`·`strategy`(정답)는 적재하지 않음 — 관리자 화면에 정답이 보이면 안 됨

## 구현 (2026-11-19)

| 부분 | 위치 | 내용 |
|---|---|---|
| 적재 | `tools/ml/load_scores.sh <scores.csv> <버전> [--source 태그] [--activate]` | 정답 라벨·표시 빼고, 모델 이름을 ERD 이름(부스팅→GBM/gbm…)으로, `(member_id, model_version)` 덮어쓰기. `model_run`에 그 ENSEMBLE 버전이 없으면 멈춤. `--activate`면 그 버전만 사용 중(Y) |
| 조회 | `GET /api/v1/admin/cases/{id}/model` (`ModelOpinionService`) | 케이스 연결 계정 → 사용 중인 합성 모델 버전 점수, 높은 순. 문턱 이상이면 `overThreshold`. 점수 없는 계정 수 |
| 숨김 | `jejari.model.show` (기본 true) | 봇 대회 1차 동안 `false` → "모델 점수를 보이지 않게 설정" 안내만 |
| 목록 | A-05 "모델 의견" 칸 (2026-11-23): `GET /admin/risks` 행마다 대상에 묶인 계정 중 최댓값·봇 쪽 여부·모델·점수 있는 계정 수, 머리에 버전·문턱 | 숨김·사용 중 모델 없음 규칙은 A-06과 같음 |
| 화면 | A-06 오른쪽 판정 위 "모델 보조 의견" | 계정별 점수·"봇 쪽/사람 쪽으로 봄"·가장 높게 본 모델·근거 3개. GRU면 "화면 녹화 재생으로 확인" 안내 |
| 테스트 | `ModelOpinionInfraTest` | 케이스 계정만·높은 순·문턱·남의 점수 안 섞임·정답 라벨 없음·사용 중 모델 없으면 숨김·없는 케이스 404 |

11-27 모델 비교 때: 대회 데이터로 `score.py` → `load_scores.sh … --source live:{태그} --activate` → 대회 케이스 화면에서 규칙과 모델을 나란히.
