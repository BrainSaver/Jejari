# 비회원(게스트) 예매

작성자: 김성원 · 코드 위치: `src/main/java/com/jejari/member/guest/`, `member/GuestGuard.java`, `frontend/src/user/Guest.jsx`, `GuestLookup.jsx`
설계·합의: `docs/김성원/팀-확인-요청-비회원-예매.md`, `docs/강동균/김성원-답장-비회원-예매-20261123.md` · ERD v33 (`db/patch/v33.sql`)

> 다른 팀원이 1~2분 안에 이해할 수 있게 짧게 씁니다.

## 한 줄 요약

가입(이메일·비밀번호) 없이 **본인인증만** 하면 예매할 수 있다. 서버에서는 비밀번호가 없는 회원(`member_type = 'GUEST'`)이라, 대기열·좌석 선점·결제·매수 제한·위험 점수가 회원과 똑같이 동작한다.

## 어떻게 동작하나

```
예매하기 → (로그인 안 됨) 로그인 화면 → [비회원으로 예매]
  → POST /api/v1/auth/verify   {name, phone, provider}      본인인증 → 1회용 verificationToken
  → POST /api/v1/auth/guest    {verificationToken}          게스트 행 + 세션 행 + 액세스 토큰 → 보던 열차로 복귀
조회  POST /api/v1/auth/guest/lookup {reservationId, phone}   로그인 없이 예약 한 건 (IP당 시간당 제한)
켜짐  GET  /api/v1/auth/guest/enabled                         화면이 비회원 버튼을 보일지
```

- **같은 CI는 행 하나**를 다시 쓴다 (예매마다 새로 만들면 위험 점수가 같은 CI의 계정 수를 세서 다계정으로 오탐). 이미 회원인 CI는 `GUEST_IS_MEMBER`(로그인 안내)로 거절하고 본인인증 토큰은 태우지 않는다.
- **세션 행을 만든다** (`auth_session`): 행동 로그·녹화가 이어지고, 관리자 정지로 쫓아낼 수 있다.
- **정지된 CI**(탈퇴한 정지 회원 포함)는 게스트로도 못 들어온다.
- **가입하면 그 행이 회원으로 바뀐다** (`SignupService.insert`): 예매 이력이 이어지고 계정 수가 늘지 않는다.
- **조회**는 예약 번호(PK) + 휴대폰 HMAC(`phone_hash`) 비교. 없는 번호·다른 휴대폰·회원 예약은 모두 같은 404라 예약 존재 여부를 알 수 없다. 시도 한도는 `guest.lookup_rate_per_hour`(기본 10), Redis 키 `rate:guest_lookup:{ipHash}`.
- **삭제**(`purgeExpired`, 매일 04:30): 마지막 예약 출발일 + `guest.retain_days_after_run`(기본 30일)이 지나고 진행 중 예약이 없으면 이름·연락처를 지운다. CI 해시는 남긴다. 같은 CI가 다시 오면 그 행을 되살린다.
- 게스트가 못 쓰는 것: 취소표 대기, 내 정보 변경·원본 보기·탈퇴 → `GuestGuard`가 403 `GUEST_NOT_ALLOWED`. 게스트 여부는 JWT가 아니라 DB(`member_type`)로 본다 (게스트가 가입해 회원이 되면 토큰이 남아 있어도 바로 회원).

## 왜 이렇게 했나

- **게스트 표시는 `status`가 아니라 `member_type`**: `status`는 관리자 조치 칸이다. `GUEST`를 넣으면 이용 제한이 안 걸리고(제한은 `ACTIVE`만 `RESTRICTED`로 바꿈), 정지를 풀면 일반 회원이 되고, 대기열이 `ACTIVE/RESTRICTED/BANNED`만 받아 예매도 못 한다.
- **선점 시간은 회원과 같다**: 게스트 전용 길이를 두면 결제 마감 시각을 복사하는 다섯 곳이 모두 회원 종류를 알아야 한다. 남용은 CI 기준 매수 제한·위험 점수가 막는다.
- **본인인증 없는 비회원은 만들지 않았다**: 매수 제한 PK와 위험 점수가 CI에 기대고 있다.

## 켜는 법과 주의할 점

- **기본은 꺼져 있다**: `app_policy`의 `guest.enabled = N`. 관리자 설정 화면에서 `Y`로 바꾸면 켜진다 (Redis `policy:cache`에 반영). 꺼져 있으면 비회원 버튼이 안 보이고 `POST /auth/guest`는 403 `GUEST_DISABLED`.
- **서버 DB에 `db/patch/v33.sql`을 먼저 적용해야 한다** (`member.member_type`, `guest_expires_at` 컬럼). 없으면 가입·내 정보 조회가 실패한다. DB가 바뀌는 배포라 자동 배포가 멈춘다.
- 비회원의 **예약 번호**는 결제 결과 화면에 크게 나온다 (조회에 필요). 결제·취소는 비회원 조회 화면이 아니라, 같은 본인인증으로 다시 입장한 뒤 예매 내역에서 한다.
- 켠 뒤 확인: 로컬은 `docker exec jejari-redis-1 redis-cli HSET policy:cache guest.enabled Y` 로 켠다. 통합 테스트는 `GuestInfraTest`(13개).
