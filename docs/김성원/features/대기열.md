# 대기열·번호표·입장 토큰 (QUE-01~05)

> 담당 김성원 · 코드 `queue/` · 설계 기능설계서 4.3 · 키 목록 DB설계서 6.2

## 한눈에

회원이 줄을 서면 **Redis 정렬 집합(ZSET)** 에 들어가고, 1초마다 맨 앞 N명이 **입장 토큰**을 받습니다. 좌석 API는 이 토큰이 없으면 컨트롤러에 닿기 전에 403으로 막습니다.

```
POST /runs/{id}/queue ──▶ queue:{runId} (score = 진입시각ms + 위험점수×1000ms)
                              │ 1초마다 맨 앞 queue.admit_per_sec명
                              ▼
                     queue:pass:{runId}:{memberId}  (토큰, 300초)
                              │
GET /runs/{id}/seats ◀── X-Queue-Token 검증 (QueueTokenFilter)
```

## 핵심 원리 3가지

1. **위험 사용자는 요청을 늦추지 않고 순번만 뒤로 보냅니다.** score에 `점수 × risk.penalty_ms_per_point`를 더할 뿐이라 서버 자원은 똑같이 쓰고, 정렬 결과만 뒤로 갑니다 (80점이면 80초 뒤).
2. **판단은 Lua 한 번으로 끝냅니다.** "이미 줄 섰나 → 같은 CI의 다른 계정이 있나 → 번호 발급 → ZADD"를 스크립트 하나로 하므로, 새로고침 연타나 다계정 동시 진입에도 줄에는 한 번만 섭니다.
3. **토큰은 (운행, 회원) 쌍마다 하나**이고 값은 256비트 무작위입니다. 남의 토큰·다른 운행의 토큰은 조회 단계에서 걸러지고, 이탈하거나 시간이 지나면 키가 지워져 재사용이 안 됩니다.

## 규칙 요약

| 상황 | 동작 |
|---|---|
| 같은 운행에 다시 진입 | 새 번호표 없이 기존 순번 그대로 (새로고침해도 안 밀림) |
| 다른 운행에 대기·입장 중 | `QUEUE_DUPLICATED` (회원당 1개) |
| 같은 CI의 다른 계정이 대기·입장 중 | `QUEUE_DUPLICATED` (`queue_log.left_reason = REJECTED_DUPLICATE`) |
| RESTRICTED 회원 | 최대 패널티 (100점 취급) |
| BANNED 회원 | `AUTH_BANNED` |
| 입장 뒤 토큰 만료 | 대기 기록도 같이 사라져 다시 줄 설 수 있음 |

패널티 점수는 회원의 CI·결제 수단·기기 해시로 `risk:{종류}:{해시}`를 읽어 **최댓값**을 씁니다 (캐시에 없으면 0점).

## 다른 파트와 맞닿는 곳 (`queue/.../port/`)

| 자리 | 누가 채우나 | 지금은 |
|---|---|---|
| `MemberIdentityPort` (member·결제 수단·기기 해시) | D·E | 개발용 가짜 |
| `OnSaleRunProvider` (train_run ON_SALE) | B | 개발용 가짜 |
| `QueueLogSink` (queue_log를 Kafka로) | C·D | 로그만 출력 |
| `MemberAuthenticator` (JWT에서 회원 ID) | E | `X-Member-Id` 헤더 (개발 모드만) |
| 예약 선점 API의 토큰 검증 | B | `QueuePassService.verify(runId, memberId, token)` 호출 |

## 실행·테스트

```bash
# Redis가 localhost:6379에 있어야 합니다 (테스트는 15번 DB만 씀)
cd queue && ./gradlew test
# 개발용 실행: 가짜 회원·운행 켜기
./gradlew bootRun --args='--jejari.dev-mode=true --jejari.queue.dev-on-sale-runs=1001'
```

## 확인한 것 (통합 테스트 38개, 실제 Redis)

- 500명 동시 진입: 번호표 중복 0, 순번 = 번호표 순서
- 같은 회원 50번 연타: 줄에 1번, 같은 CI 20계정 동시: 1계정만 성공
- 입장 처리와 진입이 동시에: 입장 200명 중복 0
- 토큰 없음·가짜·남의 것·다른 운행·이탈 후·만료 후: 좌석 API 전부 403
