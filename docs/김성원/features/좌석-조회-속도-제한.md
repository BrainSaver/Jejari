# 좌석 조회·선점 속도 제한 (새로고침 제한)

작성자: 김성원 · 코드 위치: `src/main/java/com/jejari/queue/domain/SeatRateLimiter.java`, `src/main/resources/lua/seat/seat_rate.lua`, `frontend/src/user/Seats.jsx`
요청·결정 사항: `docs/김성원/팀-확인-요청.md` 18~20번

> 다른 팀원이 1~2분 안에 이해할 수 있게 짧게 씁니다.

## 한 줄 요약

한 계정이 좌석 배치도를 새로고침하거나 선점을 반복하는 속도를 **사람은 거의 안 걸리게 유하게** 제한하고, 한도에 붙어서 계속 두드리는 계정만 **잠깐 쉬게** 한다. 봇이 빈자리를 찾으려고 계속 새로고침하는 것을 늦추려는 장치다.

## 어떻게 동작하나

```
GET  /runs/{id}/seats      ← 입장 토큰 검사(QueueSeatTokenInterceptor) 직후  ┐ 조회 버킷
POST /reservations         ← 대기열 토큰 검사 직후(ReservationController)    ┘ 선점 버킷 (따로)
  → Redis Lua seat_rate.lua → 허용 / 429 SEATMAP_RATE_LIMITED + Retry-After
```

- **1단계 (물통)**: (회원, 운행)마다 **처음 10번**은 그냥 지나가고, 그 뒤로는 **초당 1번**씩 채워진다. 호차를 바꾸고 새로고침을 몇 번 눌러 보는 사람은 거의 안 걸린다. 천천히 누르면 절대 안 걸린다.
- **2단계 (쉬게 하기)**: 물이 바닥난 채로 **60초 안에 20번** 넘게 거절당하면 그 계정을 **60초 동안** 막는다. 한도에 붙어 계속 두드리는 봇만 걸린다.
- 조회와 선점은 **따로 센다**: 배치도를 안 보고 선점만 반복해도 같은 한도가 걸린다.
- 기준은 IP가 아니라 **(회원, 운행)**: 공유기·회사망의 정상 사용자가 같이 막히지 않는다. 비회원(게스트)도 `member_id`가 있어 같은 규칙이다.
- **토큰이 맞는 요청만 센다**: 입장 토큰 없는 요청은 한도 이전에 403이다 (남의 한도를 쓰거나 키를 만들 수 없다).
- **화면**: 429를 받으면 "좌석을 너무 자주 불러서 N초 쉬어요" 안내와 카운트다운이 뜨고, [다시 불러오기]는 시간이 지나야 켜진다. **자동으로 다시 보내지 않는다** (바로 다시 부르면 제한이 의미 없다).

## 왜 이렇게 했나

- **IP 대신 계정+운행**: IP 기준은 공유 IP의 정상 사용자를 막는다.
- **한 번에 막지 않고 물통+잠금 2단**: 사람은 몰려서 누르기도 한다. 엄격한 고정 간격은 정상 사용자가 걸린다. 봇은 한도를 꽉 채워 두드리므로 2단계에 걸린다.
- **Redis가 안 되면 통과(fail-open)**: 이 제한이 정상 예매를 막으면 피해가 더 크다. 대신 경고 로그와 지표(`jejari.seat.rate_limit_error`)를 남기고, 거절은 `jejari.seat.rate_limited{kind, locked}`로 센다. 로그인 제한(fail-closed)과 다른 점이다.
- **정책 값**: `AppPolicy`의 코드 기본값(`seatmap.rate_burst`=10, `rate_per_sec`=1, `abuse_threshold`=20, `abuse_window_sec`=60, `cooldown_sec`=60)이고, ERD v34에 들어가면 관리자 화면에서 바꾼다 (요청 18번).

## 주의할 점

- **속도를 늦출 뿐 구멍을 닫지는 못한다.** 계정을 여러 개 쓰는 봇은 계정마다 따로 세므로 못 막는다 (본인인증·위험 점수의 몫). 결제 기한이 지나 풀린 좌석이 대기자보다 먼저 일반 사용자에게 열리는 구간(0.37~5.15초)도 이 제한만으로는 닫히지 않는다 (요청 19번).
- 거절 횟수를 위험 점수 입력으로 쓰는 것은 아직 하지 않았다 (지표만 남김). 강다인 님 확인이 필요하다.
- 수치(10회·초당 1·20번·60초)는 추정이다. `VIEW_SEAT` 간격 분포를 보고 조정한다.
- 테스트: `SeatRateLimiterTest`(응답 해석·Redis 장애 시 통과) · `SeatRateLimiterInfraTest`(실제 Redis: 버스트·충전·잠금·키 분리).
