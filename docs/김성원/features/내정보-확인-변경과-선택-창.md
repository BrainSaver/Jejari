# 내 정보 확인·변경, 헤더 이름, 검색 선택 창

작성자: 김성원 · 코드 위치: `frontend/src/user/Search.jsx`, `Me.jsx`, `myName.js`, `UserLayout.jsx` / `src/main/java/com/jejari/member/me/`

> 다른 팀원이 1~2분 안에 이해할 수 있게 짧게 씁니다.

## 한 줄 요약

검색 조건(운행일·시각·좌석 종류)을 인원처럼 **창으로 고르게** 했고, 내 정보에서 **비밀번호를 다시 확인해야** 가려진 이름·휴대폰을 보거나 이름·휴대폰·비밀번호를 바꿀 수 있게 했다. 오른쪽 위에는 `회원 #번호` 대신 가린 이름(`홍*동 님`)이 나온다.

## 어떻게 동작하나

```
GET   /api/v1/me             가린 이름·휴대폰 (기존)
POST  /api/v1/me/reveal      {password}                            → 가리지 않은 {name, phone}
PATCH /api/v1/me             {currentPassword, name?, phone?, newPassword?} → {me, reloginRequired}
```

- **원본 보기:** 비밀번호를 맞게 넣으면 30초 동안만 보여 주고 다시 가린다 (자리를 비워도 안전하게).
- **정보 변경:** 바꿀 칸만 채워 보낸다. 이름·휴대폰은 바로 반영, 비밀번호를 바꾸면 **모든 기기의 로그인 세션을 끊고** 로그인 화면으로 보낸다 (`/login?changed=1` 안내).
- **헤더 이름:** `myName.js`가 `/me`를 한 번만 받아 두고, 내 정보에서 이름을 바꾸면 바로 갱신한다.
- **검색 창:** `Dialog` 한 틀(`DateDialog`·`TimeDialog`·`GradeDialog`·`PeopleDialog`). [적용]을 눌러야 반영되고 취소·Esc·바깥 클릭은 버린다.
- **로고로 돌아오면:** 조건이 비었는데 이전 결과가 남아 "조건에 맞는 열차가 없어요"가 뜨던 것을, 조건이 없으면 결과를 비우도록 고쳤다.

## 왜 이렇게 했나

- 비밀번호 재확인은 탈퇴와 **같은 코드(`verifyPassword`)와 같은 실패 카운터**를 쓴다. 5번 틀리면 로그인도 잠기므로 이 API들로 비밀번호를 무차별 대입하는 우회가 안 된다.
- 이름·휴대폰을 바꿔도 `ci_hash`(본인인증 값)는 그대로다. 그래서 위험 점수·매수 제한이 따르는 "같은 사람"은 바뀌지 않는다. 다만 본인인증을 다시 받지는 않으므로, 연락처는 화면에 보이는 값일 뿐 인증된 값이 아니다.
- 선택 창은 `createPortal`로 `.user` 바로 아래에 그린다. 페이지 전환 애니메이션의 `transform`이 남으면 `position: fixed`가 그 요소 기준이 되어, 열차 목록이 길어진 뒤 창이 화면 아래로 밀리기 때문이다.
- 헤더 이름은 서버가 가린 값 그대로 쓴다 (개인정보 노출 최소). 원본은 비밀번호 확인 뒤에만 보인다.

## 주의할 점

- 로그인 없는 예매는 **구현하지 않았다.** 스키마 변경이 필요해 `팀-확인-요청-비회원-예매.md`에 변경안을 적어 두었다.
- 휴대폰 형식은 한국 휴대폰(010·011·016~019)만 받는다. 이름은 2~50자 글자.
- 비밀번호 변경 후에는 다른 기기도 로그아웃된다. 이 기기에서도 다시 로그인해야 한다.
