# 예매 안내 챗봇 (Groq)

> 담당 김성원 · 코드 `src/main/java/com/jejari/chat/`, `frontend/src/user/ChatWidget.jsx` · 단위 테스트 `ChatServiceTest`

## 한눈에

사용자 화면 오른쪽 아래의 마스코트 머리를 누르면 열리는 채팅창입니다. "11월 28일 서울에서 부산 열차 알려줘"처럼 물으면 **실제 DB의 시간표·운임·잔여석**으로 답합니다. **안내·조회만** 하고, 예매·결제·취소는 대신하지 않습니다.

```
브라우저 → POST /api/v1/chat → ChatService → Groq(gpt-oss-120b)
                                    ↑  "search_runs를 이 인자로 불러 줘"
                                    └─ TrainQueryService(열차 조회)를 직접 실행해 결과를 돌려줌 → 모델이 글로 정리
```

## 어떻게 동작하나

1. 화면이 대화(최근 12개)를 서버로 보냅니다. Groq 키는 서버에만 있고 화면에는 없습니다.
2. 서버가 시스템 프롬프트(오늘 날짜, 할 수 있는 일·없는 일)와 도구 두 개(`list_stations`, `search_runs`)를 붙여 Groq에 보냅니다.
3. 모델이 도구를 부르겠다고 하면(예: 서울→부산 2026-11-28) 서버가 `TrainQueryService`로 조회하고 결과를 모델에 넘깁니다. 도구는 **최대 3바퀴**까지만 이어지고, 마지막 바퀴는 도구 없이 글로 답하게 합니다.
4. 모델의 최종 답을 화면에 보여 줍니다. 마스코트 표정은 상황(인사·찾는 중·실패·속도 제한)에 따라 바뀝니다.
5. 답에 쓴 열차에는 버튼이 붙습니다. 판매 중이면 **[예매하러 가기]**(검색 화면의 [예매하기]와 같은 대기열 화면 `/queue/{운행}`으로 이동), 매진이면 **[취소표 대기]**. 버튼은 서버가 이번 질문에서 실제로 조회한 열차 중 답에 열차 번호나 "09:28 →" 출발 시각이 나온 것에만 붙여서, 모델이 지어낸 열차에는 붙지 않습니다 (최대 4개). 판매 전·판매 종료 열차는 갈 곳이 없어 버튼이 없습니다.
6. 처음 열면 자기소개 인사와 바로 누를 수 있는 질문 4개가 보이고, 서비스 이용 안내(예매 순서·취소표·비회원 등)는 프롬프트에 적은 범위 안에서만 답합니다.

## 왜 이렇게 했나

- **모델이 열차를 지어내지 못하게**: 열차 정보는 도구 결과만 근거로 말하게 했습니다. 모델은 DB를 직접 못 보니 "조회해 달라"고 요청하고 서버가 실행하는 구조(도구 호출)입니다.
- **조회만 하는 이유**: 대기열·좌석 선점·결제를 챗봇이 대신하면 공정 예매 흐름과 봇 탐지(위험 점수)가 무의미해집니다. 예매는 화면의 검색 → 대기열로 안내합니다.
- **버튼은 이동만**: 줄 서기·좌석 고르기·결제는 사용자가 직접 합니다. 버튼을 눌러도 대기열 화면에서 평소처럼 줄을 서므로 공정 흐름과 위험 점수가 그대로 적용되고, 로그인이 안 돼 있으면 로그인 뒤 그 화면으로 돌아옵니다.
- **매진은 실시간 잔여석으로**: 잔여석은 좌석 배치도와 같은 값(Redis 선점·판매 + DB 판매)이라 다른 사람이 잡은 좌석까지 빠져 있습니다. 서버가 검색 화면과 같은 규칙으로 `매진`·`판매 중 (특실 매진)`·`판매 전`·`판매 종료`를 정해 모델에 주고, 매진이면 반드시 매진이라고 말하게 했습니다.
- **컨트롤러를 거치지 않고 서비스를 직접 호출**: 챗봇 조회가 사용자 행동 로그(`VIEW_TRAIN`)에 섞여 위험 점수를 흐리지 않게 합니다.
- **개인정보는 모델에 보내지 않음**: 도구 결과는 시간표·운임·잔여석뿐이고, 프롬프트에서도 주민번호·카드번호·비밀번호는 받지 말라고 합니다.

## 주의할 점

| 항목 | 내용 |
|---|---|
| 키 | 환경변수 `GROQ_API_KEY`(`.env`)로만. 코드·설정 파일·로그에 두지 않음. 비어 있으면 챗봇이 꺼지고 화면 버튼도 안 뜸 (`GET /api/v1/chat/status`) |
| 모델 | 기본 `openai/gpt-oss-120b`, `GROQ_CHAT_MODEL`로 변경. **Groq가 모델을 자주 내립니다.** 기본이던 `llama-3.3-70b-versatile`이 내려가 404가 났었음. 안 되면 `GET https://api.groq.com/openai/v1/models`로 목록을 보고 바꾸세요 |
| 제한 | 한 번에 500자, 대화 12개. IP당 분당 10번 (앱 1대 기준 메모리 계수라 재시작하면 초기화) |
| 입력 검증 | `system`·`tool` 역할은 받지 않음 (지시문 끼워 넣기 방지). 마지막 메시지는 사용자 질문이어야 함 |
| 권한 | 비회원도 사용 (`SecurityConfig`에서 `GET /chat/status`, `POST /chat`만 허용) |
| 답 형식 | 화면이 평문으로 그리므로 프롬프트에서 마크다운을 쓰지 말라고 했음. 모델을 바꾸면 이 부분을 다시 확인 |
| 마스코트 | `frontend/src/user/bot/*.png` 6장 (기본·신남·윙크·놀람·화남·슬픔). 가슴에 KTX 로고가 있어 외부 공개 전에 확인 필요 |

- 대화가 많아지면 분당 제한을 Redis로 옮기기 (여러 대로 늘릴 때)
