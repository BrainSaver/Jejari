# 대기열 입장 처리: 활성 운행만 돌고, 앱이 여러 대여도 속도는 정책값

작성자: 김성원 · 코드 위치: `src/main/java/com/jejari/queue/domain/QueueAdmitter.java`, `QueueAdmitScheduler.java`, `src/main/resources/lua/queue/admit.lua`·`enter.lua`·`reconcile.lua` · 절차 원천 `docs/concurrency.md` §14.1

> 요청: 조영준 (공용 서버 실측: 판매 중 운행 971건, 사용자 없는데 Redis 초당 5,700회·VM CPU 73%). 대기열 기본 설명은 `대기열.md`.

## 한 줄 요약

1초마다 도는 입장 처리가 **줄 선 사람이 있는 운행만** 처리하고, 앱이 몇 대여도 **입장 속도가 `queue.admit_per_sec` 그대로**가 되게 했다.

## 어떻게 동작하나

```
줄 서기(enter.lua) ──▶ queue:runs(SET)에 운행 ID 추가
                              │ 1초마다 SMEMBERS 한 번
                              ▼
        운행마다 admit.lua 한 번 (왕복 1번)
        ├ 만료된 입장자 정리, 처리량 기록(바뀔 때만)
        ├ 이번 1초에 이미 입장시킨 수(queue:adm:{운행}:{초}) 확인 → 남은 만큼만 입장
        └ 줄도 입장자도 모두 비면 queue:runs에서 뺌
```

- **고친 점 1: 빈 운행 건너뛰기.** 전에는 판매 중인 모든 운행(971건)을 매초 돌며 Redis를 4~5번씩 불렀다. 이제는 `queue:runs`에 있는 운행만 돌고, 아무도 없으면 Redis 명령은 1초에 `SMEMBERS` 한 번뿐이다.
- **고친 점 2: 앱 2대면 입장이 2배가 되던 문제.** 앱마다 매초 정책값만큼 꺼내서 2대면 실제로 2배였다. 이제 `admit.lua`가 "이번 1초에 입장시킨 수"를 Redis에서 같이 세서, 두 대가 같은 초에 불러도 합쳐서 정책값을 넘지 않는다.
- **고친 점 3: 안 바뀌는 값을 매초 쓰지 않기.** `queue:throughput`은 값이 바뀔 때만 쓴다. 정책값은 운행마다가 아니라 한 번만 읽는다.

## 왜 이렇게 했나

- **Set을 쓴 이유**: 판매 중 운행 목록은 DB에서 오는데, 줄이 있는 운행은 Redis가 제일 잘 안다. 진입과 정리를 Lua로 해서 "넣기"와 "빼기" 사이에 다른 요청이 끼어들 수 없다.
- **잠금 대신 초당 카운터**: 한 대만 처리하게 잠그면 그 대가 느려지거나 멈출 때 입장이 끊긴다. 카운터는 어느 대가 먼저 부르든 결과가 같고, tick이 1초를 넘겨도 안전하다.
- **입장 중인 사람이 있는 운행도 목록에 남긴다**: 입장자(`queue:active`)의 만료 정리가 필요해서, 토큰이 끝나 둘 다 빌 때까지 남긴다.
- **목록 맞추기(`reconcile.lua`)**: 앱이 뜰 때와 5분마다 판매 중 운행 중 줄이 있는데 목록에 없는 운행을 다시 넣는다. 이 기능이 들어오기 전에 줄 선 사람이나 Redis 키 유실에 대비한 안전장치다. 한 번 호출에 판매 중 운행 전체를 확인한다.

## 주의할 점

- 테스트에서 `admitter.admit(runId)`를 직접 부르면 **초당 상한이 없다** (정책값만큼 매번 입장). 상한은 스케줄러가 쓰는 `admitActiveRuns()`에만 걸린다. 상한을 시험하려면 `admit(runId, perSec, ttl, true)`를 쓴다.
- 판매가 끝난 운행도 줄이 남아 있으면 `queue:runs`에 있는 동안은 처리한다. 대기열은 판매 마감 시각에 만료되도록 이미 설정되어 있어 실제 차이는 거의 없다.
- 개발용 `/api/v1/dev/reset`은 `queue:*`를 지우므로 `queue:runs`도 같이 지워진다.
- 로컬 실측(판매 중 운행 1,000건): 사용자 없을 때 tick 평균 1.4ms·Redis 호출 1번, 운행 1건 활성일 때 11ms. 공용 서버(앱 2대)에서의 값은 조영준 님이 확인한다.
- 새 키: `queue:runs`, `queue:adm:{runId}:{초}` (3초 뒤 만료). `docs/concurrency.md` §14.1 키 표에 적혀 있다.
- 테스트: `QueueServiceTest`의 "활성 운행 목록과 입장 처리" 5건 (목록 관리, 토큰 만료 후 정리, 목록 맞추기, 같은 초 상한, 앱 여러 대 동시 처리).
