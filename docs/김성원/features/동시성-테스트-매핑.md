## 한 줄 요약

§16의 T1·T2·T3·T5·T6·T10·T15·T16·T18·T21은 모두 통합 테스트로 옮겨져 있습니다. 9개는 main에 이미 있거나 같은 시점에 main에 올라와 있고, **T6만 새로 추가했습니다.** (T16도 같은 시나리오를 먼저 만들었지만 main에 같은 시나리오가 따로 올라와 있어서 main 쪽 테스트를 씁니다.)

## 새로 추가한 테스트(T6)와 T16의 원리

- **T6**: 결제를 시작하면 마감을 `GREATEST(기존 마감, 지금+180초+60초)`로 바꿉니다. 선점 마감(지금+10분)이 후보(약 4분)보다 길면 마감이 그대로여야 합니다. 마감이 줄면 결제 중인 좌석이 일찍 풀리기 때문입니다. 예약·좌석·Saga·결제 확인 시각·Redis TTL이 모두 같은 값으로 유지되는지 봅니다.
- **T16**: 앞 대기자가 이미 열차당 한도(10매)를 채웠으면, 제안 트랜잭션이 그 대기자를 SKIPPED로 바꾸고(알림 포함) 같은 좌석을 다음 대기자에게 줍니다. 걸린 대기자의 카운터는 늘지 않아야 합니다.

## 실행

```bash
./gradlew infraTest
./gradlew test --tests '*PaymentInfraTest' --tests '*WaitlistOfferInfraTest'   # T6·T16만
```

Oracle·Redis 컨테이너가 떠 있어야 합니다(`docker compose up -d`).

## 주의할 점

- T6은 작성 환경에 Docker·Oracle·Redis가 없어 **아직 실행해 보지 못했습니다.** 처음 돌릴 때 실패하면 테스트 쪽 전제(예: 선점 마감 10분, 열차당 한도 10매 정책값)부터 확인하세요.
- 나머지 §16 시나리오(T4·T7~T9·T11~T14 등)는 이 문서의 범위가 아닙니다.
