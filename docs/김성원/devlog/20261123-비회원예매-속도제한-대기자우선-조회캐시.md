## 어떻게 했나

- **속도 제한**: `GET /runs/{id}/seats`·`POST /reservations`가 입장 토큰 검사를 통과한 뒤 `seat_rate.lua`가 한 번에 판정 (토큰 버킷 + 거절 횟수 창 + 잠금). 조회 버킷과 선점 버킷은 따로 센다
- **대기자 우선**: 키 만료를 `PXAT 마감`에서 `PXAT 마감 + 유예`로 바꿨다. 마감 직후에도 키 값이 `R`이라 일반 사용자의 `hold.lua`는 실패하고, 스캐너가 만료 처리하면 기존 `reoffer.lua`가 키를 `REOFFER:R`로 바꿔 대기자에게 넘긴다. **Lua 스크립트는 고치지 않았다**
- **비회원**: 비밀번호 없는 회원 행(`member_type = 'GUEST'`)이라 대기열·선점·결제·매수 제한·위험 점수 코드를 그대로 쓴다

## 왜 이렇게 했나

- **속도 제한 기준을 IP가 아니라 (회원, 운행)으로**: 공유기·회사망을 같이 쓰는 정상 사용자가 함께 막히지 않게
- **유예 A안**: 측정해 보니 키가 사라진 순간부터 대기자 제안이 좌석을 다시 잡을 때까지 **0.37~5.15초 동안 좌석이 일반 사용자에게 열려** 있었다 (8회). 0.5초마다 새로고침하는 봇이 대기자보다 먼저 가져갈 수 있는 구멍이다
  - 감수한 단점: 대기자가 없는 좌석도 몇 초 늦게 열린다. 명절 판매는 몇 분 안에 매진돼 받아들였다 (강동균 님 결정). `0`으로 두면 예전 동작
- **캐시를 30초로 짧게**: DB 커넥션 풀을 20에서 40으로 늘려도 처리량이 그대로였다(221 → 206 req/s). DB 자체가 병목이라 풀을 키우기보다 DB를 부르는 횟수를 줄였다
- **비회원도 회원 행으로**: 따로 테이블을 두면 대기열·결제·위험 점수를 모두 두 갈래로 짜야 한다. 같은 CI를 한 행으로 묶어서 다계정으로 오탐하는 것도 막는다
