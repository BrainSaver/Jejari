## 어떻게 했나

- **챗봇**: `화면 → POST /api/v1/chat → ChatService → Groq(gpt-oss-120b)`. 모델은 DB를 못 보니 도구(`list_stations`, `search_runs`)를 불러 달라고 하고, 서버가 `TrainQueryService`로 조회해 결과를 넘긴다. 도구 호출은 최대 3바퀴까지
- 예약 버튼은 **서버가 이번 질문에서 실제로 조회한 열차** 중 답에 나온 것에만 붙인다 (모델이 지어낸 열차에는 버튼이 붙지 않음)
- **재입장 버그**: 좌석 화면을 떠날 때 `leave`를 불러 대기 기록을 지우고, `leave.lua`가 `queue:passext:{운행}:{회원}`도 함께 지우게 했다

## 왜 이렇게 했나

- **챗봇은 조회만**: 챗봇이 줄 서기·선점·결제를 대신하면 대기열과 위험 점수가 의미 없어진다. 버튼도 화면 이동만 하고, 사용자는 평소처럼 줄을 선다
- **서비스를 직접 호출**: 컨트롤러를 거치면 챗봇 조회가 사용자 행동 로그(`VIEW_TRAIN`)에 섞여 위험 점수를 흐린다
- **차단을 프롬프트에만 맡기지 않음**: 프롬프트에 "무관한 요청 거절"만 있었더니, 실제 서버에서 잔여석을 조회하는 파이썬 코드와 내부 도구 이름을 알려 줬다. 서버가 질문과 답을 모두 검사하는 단계를 넣었다
- **키는 서버에만**: `GROQ_API_KEY` 환경변수. 화면 번들에는 없다 (11-25 보안 점검 3번에서 확인)

## 배운 점

- LLM에게 "하지 마"라고 하는 것만으로는 막을 수 없다. 모델이 보는 입력(도구 이름·설명)은 그대로 답에 나올 수 있다고 보고 서버에서 검사한다
- 대기열 상태는 화면을 **들어갈 때**만이 아니라 **나갈 때**도 정리해야 한다. "나가면 기록이 사라진다"는 사용자 기대와 서버 상태를 맞춰야 한다
