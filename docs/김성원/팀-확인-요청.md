# 대기열·HMAC 작업 팀 확인 요청

> 작성 김성원 · 2026-11-16 · 브랜치 `SeongWon` · 코드 `queue/`, `hmac/`, `k6/queue/` · 기능 문서 `docs/김성원/features/`

대기열(QUE-01~05)과 HMAC 모듈을 구현하면서 **다른 파트의 결정이나 작업이 필요한 것**을 사람별로 모았습니다. 각 항목은 "무엇을 / 왜 / 제안"이고, 답을 받으면 이 문서의 체크박스를 지웁니다. 모두 **제안**이며 합의된 것이 아닙니다.

> **2026-11-27 정리**: 항목마다 main 코드를 확인해 닫았습니다. 남은 것은 **5·7번(기능설계서 오류 코드·응답 필드, 길동현 님 문서)** 과, 발표 뒤로 미룬 6번(`queue_log` 적재)·20번(스캐너 주기)·17번의 Oracle 동시 조회 제한입니다.

(처음 작성 때) 현재 상태 요약: main의 새 구조(루트 Gradle 프로젝트, `com.jejari`, JWT 인증)에 맞춰 옮겼고, 인프라 없이 도는 테스트 39개(HMAC 19개 포함)와 Redis 통합 테스트 57개가 통과, 진입 처리량은 한 PC 기준 초당 약 3,000건(내 PC) ~ 4,700건(4코어 컨테이너)에서 정체. 회원·운행 연동·로그 적재는 아직 없어서 `queue/port/`의 인터페이스로 막아 두었습니다 (구현이 없어도 앱은 뜨고 대기열만 "준비 중"으로 동작).

## 전원에게 (공지)

- `git pull origin main`(내 브랜치에서) 뒤 **`.env`에 `JEJARI_HMAC_KEY=`가 새로 필요합니다.** `.env.example`을 다시 보고 같은 줄을 추가하세요. `.env`는 저장소에 올라가지 않아서 팀원마다 직접 만들어야 합니다. 값은 `openssl rand -base64 32`로 만들되, **팀 전원이 같은 값**을 써야 같은 사람의 해시(CI·전화번호·카드)가 같아집니다 (팀장이 정해 공용 비밀값으로 공유하는 것을 제안). 프로젝트 기간 동안 바꾸지 않습니다. 키가 없어도 앱은 뜹니다(가명처리 빈만 안 만들어짐).
- 테스트는 두 가지입니다: `./gradlew test`(인프라 불필요, CI) / `./gradlew infraTest`(`@Tag("infra")`, `docker compose up -d` 필요). 인프라가 필요한 테스트에는 `@Tag("infra")`를 붙여 주세요.
- 한글 테스트 이름이 들어 있어서, 로케일이 UTF-8이 아닌 리눅스 환경에서는 Gradle이 HTML 리포트를 만들다 실패할 수 있습니다 (`LC_ALL=C.UTF-8`). CI(ubuntu)는 영향 없음.

    - **Redis 재시작 대응**: 재동기화는 앱 시작 직후와 10분마다 돌고, 별도로 표시 키를 **30초마다** 확인해 없으면 바로 재동기화합니다. 제가 걱정한 "최대 10분간 모든 진입이 Oracle 조회"가 **최대 30초 + 재동기화 소요 시간**으로 줄었습니다.
  - **아직 남은 것 (둘 다 선택 사항, 급하지 않음)**
    - [ ] (발표 뒤로 미룸) 표시 키가 없는 그 짧은 구간에도 진입마다 Oracle 쿼리가 나갑니다. 오픈 폭주 중 Redis가 재시작되면 한꺼번에 몰릴 수 있어서, 제 쪽 `RiskPenaltyService`에 **Oracle 동시 조회 수 제한**(넘으면 100점이 아니라 잠깐 대기 또는 캐시)을 넣을 수 있습니다. 필요한지 팀이 정해 주세요.
    - [x] 표시 키가 **오래된 경우**(재동기화가 계속 실패): 대기열이 표시 키 값(완료 시각)을 읽어 `jejari.queue.risk-sync-stale-after`(기본 30분 = 재동기화 주기 10분의 3배)를 넘으면 **경고 로그**를 남깁니다 (10초에 한 번). 점수는 캐시 값을 그대로 씁니다 (캐시가 비었다는 증거가 아니라서 막지 않고 알리기만 함). 시각이 아닌 값(개발용 `dev`)이나 미래 시각은 무시합니다. 다인 님 쪽 변경은 없습니다.
