# 비회원 예매 — 스키마(ERD) 변경안과 확인 요청

> 작성 김성원 · 2026-11-23 (같은 날 강동균 님 답장 반영해 개정) · 브랜치 `SeongWon` · 제안이며 합의된 것이 아닙니다.
> "로그인 없이 열차 찾고 예매" 요청을 검토한 결과입니다. 열차 **찾기**는 이미 로그인 없이 됩니다(`GET /stations`, `/runs`, `/runs/{id}`는 `permitAll`). 막힌 것은 **예매**입니다.
> CLAUDE.md 규칙상 ERD 패치는 강동균 님만 쓰므로, 이 문서는 "무엇을 바꿔야 하는지"만 적습니다. 코드는 만들지 않았습니다.
> 강동균 님 답장: `docs/강동균/김성원-답장-비회원-예매-20261123.md` (이 문서는 그 지적을 반영한 개정본. 처음 안과 달라진 곳은 맨 아래 표)

## 왜 그냥 로그인만 빼면 안 되나

예약·결제·취소표·알림이 전부 `member_id NOT NULL`로 `member`에 걸려 있고, 이 서비스의 방어가 **본인인증 CI**에 기대고 있습니다.

| 기능 | 기대는 것 | 비회원이 CI 없이 오면 |
|---|---|---|
| 매수 제한 | `purchase_counter` PK `(scope, scope_ref_id, ci_hash)` | CI가 없으면 한 사람이 한도 없이 삼 |
| 위험 점수 | `risk_score` `subject_type = CI` | 점수가 쌓일 주체가 없음 → 매크로가 비회원으로 우회 |
| 1인 1계정·재가입 세탁 방지 | `member.ci_hash` 유지 | 같은 사람이 매번 새 비회원으로 들어옴 |
| 예약 | `reservation.member_id`, `ci_hash` NOT NULL | 행을 만들 수 없음 |

그래서 **비회원 = 비밀번호 없는 회원**으로 만들고, **본인인증(CI)은 그대로 받는** 방식입니다 (큰 방향은 강동균 님도 동의). `member_credential`이 이미 `member`와 별도 테이블이라, 자격 행이 없는 `member`가 게스트가 됩니다.

## 개정안

### ERD에서 바뀌는 곳 (새 패치 예시)

| 표 | 바꿀 것 | 이유 |
|---|---|---|
| `member` | **`member_type VARCHAR2(10) NOT NULL DEFAULT 'MEMBER'`** 추가, `CHECK (member_type IN ('MEMBER', 'GUEST'))` | 게스트 구분 전용. **`status`는 건드리지 않는다** |
| `member` | `guest_expires_at TIMESTAMP` (NULL 허용) 추가 | 게스트 개인정보 삭제 시점 (아래 보관 기한 참고) |
| `member` | `email`은 `guest-{member_id}@guest.invalid` 같은 값으로 채움 (스키마 변경 없음) | NOT NULL·UNIQUE라 컬럼을 풀면 기존 코드가 깨짐 |
| `app_policy` | `guest.enabled`, `guest.retain_days_after_run`, 조회 시도 제한 값 | TTL·사용 여부를 코드에 박지 않는다는 규칙 |
| `reservation` | **변경 없음** (~~`guest_lookup_hash`~~ 취소) | 아래 "조회" 참고 |
| `auth_session` | **변경 없음, 하지만 게스트도 세션 행을 만든다** | 아래 "세션" 참고 |

`member_credential`, `identity_verification`, `purchase_counter`, `risk_score`, `waitlist`, `notification`은 구조 변경 없이 그대로 씁니다.

### 처음 안에서 고친 것 (강동균 님 지적, 코드로 확인함)

| 쟁점 | 처음 안 | 고친 안 | 이유 |
|---|---|---|---|
| 게스트 표시 | `member.status = 'GUEST'` | **`member_type` 컬럼을 따로** | `status`는 관리자 조치 칸이다. 이용 제한(`CaseActionService`)은 `ACTIVE`인 계정만 `RESTRICTED`로 바꾸므로 게스트에는 제한이 안 걸리고, 정지했다 풀면(`RESTRICTED→ACTIVE`) 게스트가 일반 회원이 된다. 대기열(`OracleMemberIdentityPort`)도 `ACTIVE·RESTRICTED·BANNED`만 받아 게스트는 예매 자체를 못 한다 |
| 예약 조회 | `reservation.guest_lookup_hash` + 인덱스 | **새 컬럼 없음** | `reservation`은 쓰기가 몰리는 테이블이라 인덱스가 모든 예매에 비용을 붙인다. **예약 번호로 찾고 회원의 `phone_hash`와 비교**하면 된다. 대신 예약 번호를 하나씩 넣어 보는 공격을 막으려 **조회 시도 제한 키**(예: `rate:guest-lookup:{ip}`)를 `redis_keys`에 추가 |
| 보관 기한 | `guest.ttl_hours` (시간 단위) | **마지막 운행일 + 며칠** (`guest.retain_days_after_run`) | 명절 표는 몇 주 전에 산다. 시간 단위로 지우면 타기 전에 조회·환불이 막힌다. 기한 = 그 회원의 예약 중 가장 늦은 `departure` + N일 (진행 중 예약이 있으면 삭제하지 않음) |
| 세션 | 게스트는 세션 행 없이 짧은 토큰만 | **게스트도 `auth_session` 행을 만든다** (리프레시 없이 짧은 만료는 가능) | 세션이 없으면 행동 로그·녹화가 빠진다 (11-20 개발 모드에서 행동 로그가 통째로 빠진 일). 봇이 게스트 경로로 몰리고 관리자 정지로 쫓아낼 수도 없다 |
| 같은 사람의 게스트 | (언급 없음) | **같은 CI는 게스트 행 하나를 다시 쓴다** | 위험 점수는 같은 CI에 달린 계정 수를 센다. 예매마다 행을 새로 만들면 정직하게 다시 온 사람이 다계정으로 잡힌다. 이미 일반 회원인 CI면 그 회원으로 로그인하도록 안내 |
| 게스트 전용 선점 시간 | `guest.hold_minutes` | **넣지 않는다** | 아래 답변 참고 |

### 앱 쪽에서 바뀌는 곳

- `POST /api/v1/auth/guest` 신설: `verify` 토큰을 받아 `member_type = 'GUEST'` 행 만들기(같은 CI면 재사용) + 짧은 액세스 토큰 + 세션 행.
- JWT에 `guest=true` 클레임. 취소표·내 정보·탈퇴·정보 변경은 막고, 예약·결제·예약 조회만 허용.
- 비회원 예약 조회: 예약 번호 + 휴대폰 → `phone_hash` 비교, 시도 제한 적용.
- 게스트 만료 배치: `guest_expires_at` 지난 게스트의 이름·연락처 삭제.
- 프론트: 예매하기 누르면 "로그인 / 회원가입 / 비회원으로 계속" 선택, 비회원이면 본인인증 후 같은 열차로 복귀.

## 답변: `guest.hold_minutes`가 꼭 필요한가

**필요하지 않습니다. 넣지 않는 것에 동의합니다.** 제가 넣으려던 이유는 "게스트는 선점 시간을 짧게 줘서 남용을 줄이자"였는데, 그건 매수 제한·위험 점수(CI 기준)가 이미 맡는 일이고, 게스트도 CI로 같은 한도를 받으므로 시간까지 다르게 줄 근거가 약합니다. 반대로 결제 마감 시각을 복사하는 다섯 곳(`reservation.pay_deadline_at` → `seat_inventory.hold_expires_at`, Redis `seat:hold` TTL, `saga_instance.timeout_at`, `waitlist.offer_deadline_at`)에 게스트 분기가 들어가면 어긋날 곳만 늘어납니다. 게스트도 회원과 **같은 마감 시각 규칙**을 씁니다.

## 확인이 필요한 것

- **강동균 님**: 위 개정 ERD가 맞는지(`member_type`, `guest_expires_at`, `redis_keys`의 조회 시도 제한 키), 새 패치로 반영할 수 있는지.
- **길동현 님(팀장)**: 비회원 예매를 이번 범위에 넣을지. 기능설계서 2장은 "열차 조회는 비회원도"까지만 적혀 있습니다.
- **강다인 님**: 게스트도 같은 CI 규칙으로 점수가 쌓이고 관리자 조치(`RESTRICT`, 정지)가 `member_type`과 무관하게 걸리는 것으로 정리해도 되는지. 같은 CI의 게스트 행을 재사용할 때 기기·IP 해시 연결은 어떻게 둘지.
- **본인인증 없는 비회원**(CI 없이 이름·전화만)은 **권하지 않습니다**: 위 표의 방어가 전부 무력해지고, `purchase_counter`의 PK가 성립하지 않습니다.
