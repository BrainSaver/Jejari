# 비회원 예매 — 스키마(ERD) 변경안과 확인 요청

> 작성 김성원 · 2026-11-23 · 브랜치 `SeongWon` · 제안이며 합의된 것이 아닙니다.
> "로그인 없이 열차 찾고 예매" 요청을 검토한 결과입니다. 열차 **찾기**는 이미 로그인 없이 됩니다(`GET /stations`, `/runs`, `/runs/{id}`는 `permitAll`). 막힌 것은 **예매**입니다.
> CLAUDE.md 규칙상 ERD 패치는 강동균 님만 쓰므로, 이 문서는 "무엇을 바꿔야 하는지"만 적습니다. 코드는 만들지 않았습니다.

## 왜 그냥 로그인만 빼면 안 되나

예약·결제·취소표·알림이 전부 `member_id NOT NULL`로 `member`에 걸려 있고, 이 서비스의 방어가 **본인인증 CI**에 기대고 있습니다.

| 기능 | 기대는 것 | 비회원이 CI 없이 오면 |
|---|---|---|
| 매수 제한 | `purchase_counter` PK `(scope, scope_ref_id, ci_hash)` | CI가 없으면 한 사람이 한도 없이 삼 |
| 위험 점수 | `risk_score` `subject_type = CI` | 점수가 쌓일 주체가 없음 → 매크로가 비회원으로 우회 |
| 1인 1계정·재가입 세탁 방지 | `member.ci_hash` 유지 | 같은 사람이 매번 새 비회원으로 들어옴 |
| 예약 | `reservation.member_id`, `ci_hash` NOT NULL | 행을 만들 수 없음 |

그래서 **비회원 = 비밀번호 없는 회원**으로 만들고, **본인인증(CI)은 그대로 받는** 방식을 제안합니다.

## 제안: 게스트 회원 (본인인증은 하고, 계정만 안 만든다)

`member_credential`(비밀번호)은 이미 `member`와 별도 테이블이라, **자격 행이 없는 `member` = 게스트**로 둘 수 있습니다. 가입 API의 `verify`(본인인증)까지만 쓰고 `signup`(비밀번호 설정)은 건너뜁니다.

### ERD에서 바뀌는 곳 (새 패치 `V9_OPS` 예시)

| 표 | 바꿀 것 | 이유 |
|---|---|---|
| `member` | `status`에 `GUEST` 추가 (`ck_member_status`: `ACTIVE / RESTRICTED / BANNED / GUEST`) | 게스트를 구분해 목록·통계·탈퇴 처리에서 따로 다룸 |
| `member` | `guest_expires_at TIMESTAMP` (NULL 허용) 추가 | 게스트 개인정보 보관 기한. 지나면 이름·연락처 삭제 (탈퇴와 같은 방식) |
| `member` | `email`은 NOT NULL·UNIQUE라 `guest-{member_id}@guest.invalid` 같은 값으로 채움 (스키마 변경 없음) | 컬럼을 NULL로 풀면 기존 코드·검사가 깨짐 |
| `reservation` | `guest_lookup_hash VARCHAR2(64)` (NULL 허용) + 인덱스 | 비회원 조회용. 예약 번호 + 휴대폰 HMAC으로 찾음 (로그인이 없어서 브라우저를 닫으면 예약을 못 찾는 문제) |
| `app_policy` | `guest.enabled`, `guest.hold_minutes`, `guest.ttl_hours` | TTL·사용 여부를 코드에 박지 않는다는 규칙 |
| `auth_session` | 변경 없음 | 게스트 토큰은 짧은 액세스 토큰만 발급하고 리프레시는 주지 않음 → 세션 행을 만들지 않음 |

`member_credential`, `identity_verification`, `purchase_counter`, `risk_score`, `waitlist`, `notification`은 **구조 변경 없이** 그대로 쓸 수 있습니다. (모두 `member_id`·`ci_hash` 기준이라 게스트 회원 행이 있으면 동작)

### 앱 쪽에서 바뀌는 곳

- `POST /api/v1/auth/guest` 신설: `verify` 토큰을 받아 `GUEST` 회원 행 + 짧은 액세스 토큰 발급. 같은 CI가 이미 회원이면 그 회원으로 로그인하도록 안내(중복 행 방지).
- JWT에 `guest=true` 클레임. 취소표·내 정보·탈퇴·정보 변경은 막고, 예약·결제·예약 조회만 허용.
- 게스트 만료 배치: `guest_expires_at` 지난 게스트의 이름·연락처 삭제 (진행 중 예약이 없을 때).
- 프론트: 예매하기 누르면 "로그인 / 회원가입 / 비회원으로 계속" 선택, 비회원이면 본인인증 후 같은 열차로 복귀.

## 확인이 필요한 것

- **강동균 님**: 위 ERD 변경안(특히 `GUEST` 상태와 `guest_lookup_hash`)이 맞는지, 새 패치로 반영 가능한지.
- **길동현 님(팀장)**: 비회원 예매를 이번 범위에 넣을지. 기능설계서 2장은 "열차 조회는 비회원도"까지만 적혀 있습니다.
- **강다인 님**: 위험 점수·기기 해시가 게스트도 같은 규칙(CI 기준)으로 쌓이면 되는지. 게스트가 늘면 `RESTRICTED` 판정을 기다리는 사람이 회원이 아닌 사람이 될 수 있습니다.
- **본인인증 없는 비회원**(CI 없이 이름·전화만)은 **권하지 않습니다**: 위 표의 방어가 전부 무력해지고, `purchase_counter`의 PK가 성립하지 않습니다.
