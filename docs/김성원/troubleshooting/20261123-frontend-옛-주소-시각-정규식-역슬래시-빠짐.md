# [frontend] 옛 주소의 time=10:48이 시 단위로 바뀌지 않고 버려짐

| 항목 | 내용 |
|---|---|
| 작성자 | 김성원 |
| 날짜 | 2026-11-23 |
| 상태 | 해결 |
| 관련 커밋·이슈 | 5635efb |

## 1. 문제

- 현상: `?time=10:48` 같은 옛 주소로 열면 시각이 `10:00`으로 맞춰지지 않고 기본값으로 돌아감
- 재현 조건: 시 단위 선택으로 바꾼 뒤 분이 들어 있는 옛 주소·저장된 값으로 검색 화면 열기
- 영향: 사용자가 정한 시각이 조용히 무시됨 (에러 없음)

## 2. 원인

- 코드 리뷰 중 발견. `toHour`의 정규식이 `/^d{2}:d{2}$/`로 `\`가 빠져 `d`라는 글자 두 개만 맞는 식이었음 → 어떤 시각도 통과하지 못해 항상 빈 문자열 반환
- 같은 곳에서 `submit`이 `form.time = hourNow()`로 state 객체를 직접 바꾸고 있었음 (리렌더가 보장되지 않음)

```js
const toHour = (t) => (t && /^d{2}:d{2}$/.test(t) ? `${t.slice(0, 2)}:00` : '');   // 잘못
const toHour = (t) => (t && /^\d{2}:\d{2}$/.test(t) ? `${t.slice(0, 2)}:00` : ''); // 고침
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 정규식 없이 `split(':')` | 오타 여지 적음 | 잘못된 값 검증 따로 필요 | |
| 정규식에 `\d` 복구 + state 직접 수정을 지역 변수로 | 변경 최소 | | ✓ |

- 바뀐 코드 위치: `frontend/src/user/Search.jsx` (`toHour`, `submit`)

## 4. 수치

없음 (기능 버그). 빌드 통과, 백엔드 단위 520개·infraTest 476개 통과 상태에서 수정.

## 5. 정리

- 면접용 한 줄 요약: "정규식에서 `\d`의 역슬래시가 빠져 옛 주소의 시각이 조용히 버려지던 것을 리뷰에서 찾아 고치고, state를 직접 바꾸던 부분도 지역 변수로 바꿨다."
- 다음에 비슷한 상황이면: 정규식은 `.test()`로 통과·실패 값을 하나씩 바로 확인한다. 문자열 안 정규식은 이스케이프가 사라지기 쉽다.
