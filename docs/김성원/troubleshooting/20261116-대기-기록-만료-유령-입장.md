# [queue] 대기 기록이 만료되면 줄에 남은 유령이 입장해 자리를 낭비

| 항목 | 내용 |
|---|---|
| 작성자 | 김성원 |
| 날짜 | 2026-11-16 |
| 상태 | 해결 |
| 관련 커밋·이슈 | (커밋 후 기입) |

## 1. 문제

- 현상: `queue:member:{id}`(대기 기록)는 `queue.entry_ttl_sec`(기본 3600초)에 사라지는데, 줄(`queue:{runId}` ZSET)에는 그 사람이 남아 있었습니다. 입장 처리가 그 유령을 꺼내 토큰을 발급했습니다.
- 재현 조건: `queue.entry_ttl_sec=1`로 진입 → 1.3초 대기 → `admit(RUN)`. 번호표 조회는 404인데 입장 인원은 1명으로 셉니다. (`QueueScenarioTest` 대기_기록_만료)
- 영향: 유령이 초당 입장 인원(N)의 자리를 차지해 실제 대기자가 밀립니다. 유령은 토큰을 받지만 누구도 쓰지 못하고, 토큰 TTL 동안 `queue:active`에 남습니다. 같은 회원이 만료 뒤 다시 줄을 서면 옛 항목이 앞에서 입장해 새 항목과 이중 입장이 될 수 있었습니다.

## 2. 원인

- 줄과 대기 기록이 서로 다른 키라 TTL이 따로 돕니다. 이탈 스크립트는 둘을 함께 지우지만, 만료는 `queue:member`만 지웁니다.
- 입장 스크립트(`admit.lua`)가 꺼낸 멤버의 대기 기록이 아직 있는지 확인하지 않았습니다.

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 입장 때 `queue:member`가 없거나 다른 번호표면 건너뜀 | 스크립트 한 곳만 고침, 만료·재진입 둘 다 해결 | 유령이 입장 때까지 줄에 남음 | ✓ |
| 만료 때 줄에서도 삭제 (keyspace 이벤트) | 줄이 항상 깨끗함 | 이벤트 유실 가능, 구성 복잡 | |

- 선택한 이유: 판단을 입장 시점의 Lua 안에서 원자적으로 하므로 유실·경합이 없습니다.
- 바뀐 코드: `src/main/resources/lua/queue/admit.lua` — 꺼낸 멤버의 `queue:member`에 적힌 번호표가 같을 때만 입장시키고, 건너뛴 자리는 뒤 대기자로 채웁니다.
- 테스트: `QueueScenarioTest` 대기_기록_만료 3건 (유령 미입장, 재진입 시 새 항목만 입장, 유령이 낸 자리를 실제 대기자로 채움).

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 만료 대기자 입장 | 입장 처리됨 | 0명 |
| 유령이 차지한 자리 | 입장 인원에서 소모 | 뒤 대기자로 채움 |

## 5. 배운 점

- 같은 사람을 나타내는 키가 둘 이상이면 TTL이 어긋날 수 있으니, 꺼내 쓸 때 서로 맞는지 다시 확인합니다.
- 남은 문제: 만료된 유령은 입장 처리 때야 줄에서 정리됩니다. 입장이 없는 운행에서는 줄 길이(`ZCARD`)가 실제보다 크게 보일 수 있습니다.
