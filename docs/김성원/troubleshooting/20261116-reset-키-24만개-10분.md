## 1. 문제

- 현상: 내 PC에서 PowerShell로 `.\reset.ps1`을 실행하자 아무 출력 없이 한참 멈춰 있었다.
- 재현 조건: `entry-burst.js`를 한 번 돌린 뒤(Redis에 대기열 키 약 24만 개가 남음) `reset.ps1`
- 영향: 부하 테스트를 반복할 때마다 초기화에 수 분이 들거나, 멈춘 줄 알고 중단하게 된다.

## 2. 원인

- 가설: 멈춘 게 아니라 느린 것 → 스크립트가 하는 일을 세어 봤다.
- 최종 원인: 키를 **200개씩** 모아 지우는데, 한 묶음마다 `docker exec`를 새로 실행했고 명령마다 `docker ps`로 컨테이너 확인도 했다. 24만 개는 약 1,200묶음이라 호출이 2,400번쯤이고, Windows에서 `docker exec` 한 번이 0.5초 안팎이라 10분이 넘는다 (실제 소요 시간은 측정하지 못했고 이 계산으로 추정).

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| A. 묶음 크기를 키움 | 간단 | 명령줄 길이 한계, 키 수에 비례해 여전히 느림 | |
| B. 키 목록을 가져오지 않고 Redis 안에서 `SCAN` + `UNLINK`을 한 번에 실행 (Lua) | 호출 1번, 데이터가 Redis 밖으로 안 나옴 | 스크립트가 한 번 실행되는 동안 Redis가 잠깐 쉼(개발용이라 무방) | ✓ |

- 선택한 이유: 병목은 호출 횟수였다. 지우는 일을 Redis 안으로 옮기면 호출이 키 수와 무관하게 한 번이다. 패턴(`queue:*`, `risk:*`)만 지우므로 다른 키는 그대로 남는다.
- 같이 한 것: `docker` 컨테이너 확인을 처음 한 번만 하도록 캐시.
- 바뀐 코드 위치: `k6/queue/reset.ps1`, `reset.sh`, `lib/redis.ps1`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 키 24만 개 삭제 | 10분 이상 (추정, Windows) | **0.35초** (측정, Linux `redis-cli`) |
| 다른 키(`keepme`) | - | 그대로 남음 확인 |

- 측정 환경: 클라우드 컨테이너, Redis 7.0 로컬 프로세스, 키 24만 개를 `redis-cli --pipe`로 만들어 시간 측정
- 측정 방법: `time redis-cli eval "$DELETE_BY_PATTERN" 0 'queue:*'`
- 한계: Windows에서의 새 소요 시간은 아직 재지 않았다.

## 5. 정리

- 면접용 한 줄 요약: "초기화 스크립트가 키 24만 개를 200개씩 컨테이너 명령으로 지워 멈춘 것처럼 보였는데, 병목이 호출 횟수라는 걸 세어 보고 Redis 안에서 스캔하며 한 번에 지우게 바꿔 0.35초로 줄였다."
- 다음에 비슷한 상황이면: 외부 프로세스(`docker exec`, 쉘)를 반복 호출하는 루프는 데이터를 밖으로 꺼내지 말고 서버 쪽에서 한 번에 처리할 수 있는지 먼저 본다.
