# [infra] 동시 접속 9천 명대에서 서버가 새 연결을 거절

| 날짜 | 2026-11-23 |

> 파일 이름: `docs/김성원/troubleshooting/20261123-tomcat-연결-한도-거절.md`

## 1. 문제

- 현상: k6 시나리오 1(오픈 폭주)을 VU 최대 1만으로 돌리면 요청 11,068건이 `connectex: No connection could be made because the target machine actively refused it`로 실패. 대기열 입장 성공 71.5%
- 재현 조건: 로컬 앱(개발 모드), 사용자 파일 1만 명, `PEAK_RATE=2000 HOLD_DURATION=60s PRE_VUS=3000 MAX_VUS=10000`
- 영향: 서버 오류 로그는 0건인데 사용자는 접속 자체가 안 됨

## 2. 원인

- 처음엔 계정이 1000개뿐이라 VU끼리 같은 회원 ID를 써서 404가 나던 것(테스트 문제)을 먼저 걸러냈다. 사용자 파일을 1만 개로 늘리자 404는 사라지고 상태 0(연결 실패)만 남았다.
- 최종 원인(설정을 읽고 한 추정): Tomcat 기본 동시 연결 한도(max-connections 8192 + 대기열 100)를 VU 약 9,200개가 넘었다.

```
level=warning msg="Request Failed" error="Post \"http://localhost:8080/api/v1/runs/9001/queue\": dial tcp 127.0.0.1:8080: connectex: ... actively refused it."
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 한도 그대로, 부하를 낮춤 | 설정 변경 없음 | 문제를 덮음 | |
| `max-connections 20000`, `accept-count 2000` | 거절이 사라짐 | 연결이 느는 만큼 메모리 사용 | ✓ |
| 요청 스레드(200)를 늘림 | | 병목이 DB 대기라 효과 없음 | |

- 바뀐 코드 위치: `src/main/resources/application.yml` (`server.tomcat`)

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 연결 거절(실패 요청) | 11,068건 | 0건 |
| 대기열 입장 성공 | 71.5% | 100% |
| 입장 요청 p95 | 7.1초 | 8.3초 (여전히 느림) |

- 측정 환경: 로컬 PC 한 대에 앱·Oracle·Redis·Kafka·Mongo·k6 동거. 부하 생성기가 CPU를 나눠 써서 절대 수치는 운영과 무관
- 측정 방법: `loadtest/run.sh 1 -e PEAK_RATE=2000 -e HOLD_DURATION=60s -e PRE_VUS=3000 -e MAX_VUS=10000 -e USERS_FILE=<1만 명 파일>` (`loadtest/tools/gen_users.py --count 10000`)
- 앱 인자로 `--server.tomcat.max-connections=20000 --server.tomcat.accept-count=2000`을 줘서 먼저 검증한 뒤 yml에 반영

## 5. 정리

- 면접용 한 줄 요약: "동접 9천 명대에서 서버 오류 로그 없이 연결이 거절되는 걸 Tomcat 기본 연결 한도로 좁혀, 한도를 올려 거절 11,068건을 0건으로 줄였다."
- 다음에 비슷한 상황이면: 실패 응답의 **상태 코드를 먼저 집계**한다(404=테스트 데이터 겹침, 상태 0=연결 거절). 지연이 남는 건 이 PC 한계이므로 DB 접근 횟수(요청당 2.36회)와 로그인(Argon2)을 따로 본다.
