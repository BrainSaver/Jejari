# [seat] 좌석 선점 요청의 seats 배열에 null이 있으면 500 (NullPointerException)

| 항목 | 내용 |
|---|---|
| 작성자 | 김성원 |
| 날짜 | 2026-11-25 |
| 상태 | 해결 |
| 관련 커밋·이슈 | 이 문서와 같은 커밋 (보안 점검 2026-11-25 §2.4) |

## 1. 문제

- 현상: `POST /api/v1/reservations`에 `{"runId":9001,"seats":[null]}`를 보내면 **500 INTERNAL_ERROR** (NullPointerException).
- 재현 조건: 로그인한 회원 토큰만 있으면 된다. 입장 토큰도 필요 없다(검사 전에 터짐).
- 영향: 잘못된 입력 하나로 500과 에러 로그를 만들 수 있다. 데이터 피해는 없다.

## 2. 원인

- 최종 원인: 서비스(`SeatHoldService.hold`)에는 좌석 목록 검증이 있지만, 그보다 먼저 컨트롤러가 **행동 로그 메타데이터**를 만들려고 `body.seats().stream().map(SeatRequest::seatId)`를 돌리다가 `null` 원소에서 터졌다.

```
ReservationController.hold : List<Long> seatIds = body.seats().stream().map(SeatRequest::seatId).toList();  -- null → NPE
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 스트림에서 `null`을 걸러 내고 서비스에 맡김 | 한 줄 | 로그에는 걸러진 목록이 남아 실제 요청과 달라진다 | |
| 컨트롤러 맨 앞에서 `null` 원소가 있으면 400, 서비스 검증에도 같은 조건 | 요청 모양이 틀리면 바로 거절. 다른 경로로 서비스를 불러도 막힌다 | 두 곳에 같은 조건 | ✓ |

- 바뀐 코드: `seat/web/ReservationController.java`, `seat/SeatHoldService.java` (`anyMatch(Objects::isNull)`)

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| `seats:[null]` 요청 | 500 | 400 INVALID_REQUEST |

- 측정 방법: `SecurityAuditInfraTest.좌석_선점_목록에_null이_있으면_500이_아니라_400`, 로컬 서버 실제 요청

## 5. 정리

- 면접용 한 줄 요약: "검증은 서비스에 있었지만 컨트롤러가 로그용으로 입력을 먼저 만져 null 하나에 500이 났다. 입력 모양 검사를 컨트롤러 맨 앞으로 옮겨 400으로 바꿨다."
- 다음에 비슷한 상황이면: 검증 전에 입력을 읽는 코드(로그·메트릭)가 있으면, 그 코드가 잘못된 입력에도 안전한지 본다. JSON 배열 원소는 `null`일 수 있다.
