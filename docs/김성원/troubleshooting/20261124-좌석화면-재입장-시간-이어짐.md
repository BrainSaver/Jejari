# [queue] 좌석 화면을 나갔다 다시 예매하면 줄 없이 들어오고 남은 시간이 이어짐

## 1. 문제

- 현상: 좌석 선택 화면에서 다른 메뉴로 나갔다가 같은 열차를 다시 예매하면, 줄을 서지 않고 곧바로 좌석 화면에 들어왔다. "좌석을 고를 수 있는 시간"도 새로 시작하지 않고 나가기 전 시간이 그대로 이어졌다.
- 재현 조건: 로그인 → 열차 [예매하기] → 입장 → 좌석 화면(4:58) → 12초 뒤(4:46) 아래 [검색] 탭으로 나감 → 같은 열차 [예매하기] → 4:4x부터 이어짐
- 영향: 사용자는 "다시 들어왔으니 시간을 새로 받는다"고 기대하는데 시간이 이미 줄어 있다. 나갔다 와도 줄을 서지 않으니 "나가면 뒤로 밀린다"는 기대와도 다르다.

## 2. 원인

- 가설: 화면이 타이머를 잘못 보여 준다 → `pass.js`는 서버가 준 만료 시각을 그대로 쓰고 있어 화면 문제는 아니었다.
- 확인: `enter.lua`는 같은 운행에 이미 기록(`queue:member`)이 있으면 새 번호표 없이 기존 상태를 돌려준다(status 1). 입장한 회원은 기록이 토큰 유효 시간만큼 살아 있다(`admit.lua`의 `PEXPIRE mkey`). 좌석 화면에는 나갈 때 대기열을 비우는 처리가 없었다.
- 최종 원인: 좌석 화면을 떠나도 입장 토큰이 살아 있어서 다시 들어오면 같은 토큰, 즉 같은 마감 시각을 받았다.
- 같이 찾은 버그: 대기열 이탈(`leave.lua`)이 연장 표시 `queue:passext:{운행}:{회원}`를 지우지 않았다. 이탈한 뒤 다시 줄을 서서 새로 입장해도 남은 표시 때문에 [5분 더 쓰기]가 `QUEUE_EXTEND_USED`로 막혔다.

```
enter.lua  : if run == ARGV[1] then return {1, qm, ...}   -- 이미 있음 → 기존 상태
status.lua : token 있으면 {2, qm, PTTL(passKey), token}   -- 같은 토큰·같은 남은 시간
leave.lua  : DEL queue:pass:…  (queue:passext:… 는 안 지움)
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 다시 들어오면 서버가 시간을 새로 준다 | 구현이 단순하다 | 나갔다 들어오기만 반복하면 좌석 고르는 시간이 끝없이 늘어난다. "연장 1회" 제한이 의미 없어진다 | |
| 지금 동작을 두고 안내 문구만 단다 | 공정성을 유지한다 | 사용자 기대("나가면 뒤로 밀리고 새 시간")와 다르다 | |
| 좌석 화면을 나가면 대기열에서 뺀다. 다시 예매하면 맨 뒤에 새로 줄을 서고, 차례가 오면 새 시간을 받는다 | 사용자 기대와 맞다. 새 시간을 받으려면 다시 줄을 서야 해서 공정하다 | 실수로 다른 탭을 누르면 입장을 잃는다 → 타이머 아래에 안내 문구를 둔다 | ✓ |

- 선택한 이유: 시간을 새로 받는 대가로 줄을 다시 서게 하면 악용할 이득이 없다. 클라이언트가 이탈 요청을 안 보내도 예전처럼 시간이 이어질 뿐이라, 새로 생기는 우회로는 없다.
- 바뀐 코드
  - `frontend/src/user/Seats.jsx`: 화면이 내려갈 때(언마운트) `DELETE /api/v1/runs/{id}/queue/me`를 호출한다.
    - 좌석을 잡고 결제로 넘어가는 경우와 새로고침(언마운트 없음)은 나간 것으로 치지 않는다.
    - 개발 모드의 StrictMode는 붙였다 떼었다 다시 붙이므로, 이탈을 한 틱 미루고 바로 다시 붙으면 취소한다.
  - `src/main/resources/lua/queue/leave.lua`: 이탈 때 `queue:passext:{운행}:{회원}`도 지운다.
  - `QueueServiceTest`: 연장 → 이탈 → 다시 진입(WAITING) → 입장 순서로 확인한다. 새 토큰, 기본 시간, 연장 재허용을 본다.

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 나갔다 다시 예매했을 때 남은 시간 (12초 머문 뒤) | 4:4x (이어짐) | 4:58 (새로 받음) |
| 다시 예매했을 때 줄 서기 | 안 섬 (바로 입장) | 맨 뒤에 다시 섬 |
| 이탈 후 새 입장에서 [5분 더 쓰기] | 막힘 (`QUEUE_EXTEND_USED`) | 가능 |
| 대기열 통합 테스트 | 새 테스트 실패 (`leave.lua` 수정 전) | 204개 통과 |

- 측정 환경: 로컬 Docker Compose(Oracle·Redis·Kafka·Mongo), 앱 jar, 헤드리스 Chrome 390×844
- 측정 방법: 가짜 계정으로 가입·로그인 → 운행 100008 [예매하기] → 좌석 화면 타이머 기록 → 12초 대기 → [검색] 탭 → 다시 [예매하기] → 타이머 기록. 통합 테스트는 `./gradlew infraTest --tests 'com.jejari.queue.*'`

## 5. 정리

- 면접용 한 줄 요약: "좌석 화면을 떠나도 입장 토큰이 살아 있어 다시 들어오면 남은 시간이 이어졌는데, 시간을 그냥 새로 주면 나갔다 들어오기로 무한 연장이 되므로, 화면을 떠나면 대기열에서 빼고 다시 줄을 서야 새 시간을 받게 해 사용자 기대와 공정성을 함께 맞췄다."
- 다음에 비슷한 상황이면: "시간·횟수 제한"을 초기화하는 경로가 있으면 그 경로를 반복해 제한을 우회할 수 있는지 먼저 본다. 초기화에는 줄 다시 서기 같은 대가가 따라야 한다. 상태를 지우는 스크립트(이탈)는 그 상태에 딸린 키(연장 표시 등)까지 다 지우는지 확인한다.
