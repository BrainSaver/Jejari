# [hmac] 전화번호에 글자가 섞여도 조용히 버려져 다른 입력이 같은 해시가 됨

## 1. 문제

- 현상: 식별정보 가명처리 모듈의 전화번호 정규화가 숫자가 아닌 글자를 **전부 버리고** 남은 숫자로 해시를 만들었다. `010-9999-8888x`처럼 오타가 섞인 입력도 오류 없이 `01099998888`의 해시가 나왔다.
- 재현 조건: `Pseudonymizer.phone("010-9999-8888x")`
- 영향: 서로 다른 입력이 같은 해시가 될 수 있다. 이 해시는 "같은 사람인지"를 가르는 묶음 키(다계정·매수 제한 합산)라, 틀린 입력이 남의 번호와 묶이거나 오류 없이 지나가 버린다.

## 2. 원인

- 가설: 정규화가 너무 관대하다 → 단위 테스트에서 "잘못된 입력은 거부한다" 항목을 쓰다가 `010-9999-8888x`가 예외 없이 통과하는 것으로 발견했다.
- 최종 원인: 정규화가 `replaceAll("[^0-9]", "")`로 숫자 외 모든 문자를 제거한 뒤 형식만 검사했다. 허용하지 않는 문자가 섞였는지는 보지 않았다.

```
assertThatThrownBy(() -> p.phone("010-9999-8888x"))   // 기대: 예외, 실제: 해시가 나옴
Expecting code to raise a throwable.
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| A. 지금처럼 숫자만 남김 | 입력에 관대 | 오타·남의 번호가 조용히 통과 | |
| B. 허용 문자(숫자·공백·하이픈·괄호·`+`)가 아니면 거부 | 오타를 바로 알림, 같은 해시는 같은 번호일 때만 | 호출하는 쪽에서 오류를 처리해야 함 | ✓ |

- 선택한 이유: 이 해시는 되돌릴 수 없고 틀리면 나중에 찾기 어렵다. 입력 단계에서 막는 편이 안전하다. 오류 메시지에는 입력 원문을 넣지 않는다(개인정보).
- 바뀐 코드 위치: `src/main/java/com/jejari/common/hmac/Pseudonymizer.java` (`PHONE_CHARS`, `normalizePhone`)

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| `010-9999-8888x`, `abc010-1234-5678` 같은 입력 | 해시가 나옴 | `IllegalArgumentException` |
| 표기만 다른 같은 번호(`+82 10-1234-5678` 등) | 같은 해시 | 같은 해시 (유지) |
| 단위 테스트 | 1개 실패 | 19개 모두 통과 |

- 측정 방법: `./gradlew test --tests '*PseudonymizerTest'`

## 5. 정리

- 면접용 한 줄 요약: "전화번호 정규화가 글자를 조용히 버려서 오타 입력이 오류 없이 해시가 되는 걸 '잘못된 입력은 거부한다' 테스트를 쓰다가 발견해, 허용 문자만 받도록 바꿨다."
- 다음에 비슷한 상황이면: 값을 정규화할 때 "무엇을 버릴까"가 아니라 "무엇을 허용할까"로 시작한다. 되돌릴 수 없는 값(해시)은 입력 검증이 마지막 방어선이다.
