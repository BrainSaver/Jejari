## 1. `train_run.status`가 이제 `DEPARTED`까지 갑니다 (ERD v23)

**전**: `DEPARTED`로 바꾸는 코드가 없어서 운행이 영원히 `CLOSED`에 머물렀습니다.
값은 ERD CHECK 제약에만 있고 **읽는 코드도 없었습니다.**

**후**: 판매 오픈 스케줄러가 바꿉니다.

```
SCHEDULED --(sale_open_at)--> ON_SALE --(sale_close_at)--> CLOSED --(열차가 떠남)--> DEPARTED
```

- 기준은 **기점 출발 시각** (`MIN(train_stop.departure_time)`)
- **`DEPARTED`가 아닌 모든 상태에서 바로 갑니다.** 시드의 `sale_close_at`이 운행일 다음 날이라
  열차가 떠난 뒤에도 한동안 `ON_SALE`로 남기 때문입니다. 출발은 판매 일정과 무관한 사실이라
  다른 전이보다 세게 봤습니다
- 정차 정보가 없는 운행은 출발 시각을 몰라 그대로 둡니다

### 영향받는 분

| 누구 | 무엇 |
|---|---|
| **전원** | 운행을 상태로 거르는 코드가 있으면 `DEPARTED`도 생각해 주세요. 지금까지는 안 나오던 값입니다 |
| **김성원(A)** | `OnSaleRunProvider`는 `status = 'ON_SALE'`만 보므로 **영향 없습니다.** 떠난 운행이 자동으로 빠지니 오히려 정확해집니다 |
| **강다인(D)** | 취소 수수료는 상태가 아니라 출발 시각으로 판단하므로 **영향 없습니다** (확인했습니다) |
| **길동현(C)** | §8.3 재판매 여부 집계 배치를 나중에 붙일 때 "출발한 운행"의 기준으로 쓸 수 있습니다 |

### 각자 DB에 적용

스키마 자체는 안 바뀌었습니다 (컬럼·제약 그대로, **설명만** 바뀜). **다시 적용할 것 없습니다.**

## 2. ADM-03 실시간 현황에 "만료"가 생겼습니다

**전**: 분당 수치가 예약·결제·**취소** 셋이었습니다. 그런데 "취소"는 `cancellation` 행 기준이라
**결제 기한 초과 만료가 빠져 있었습니다** (만료는 돈이 오가지 않아 `cancellation`을 안 만듭니다).

예약 100건·결제 40건이면 나머지 60건이 취소인지 만료인지 알 수 없었습니다.

**후**: 네 번째 수치 `expires`가 생겼습니다.

### API 응답이 바뀝니다 (필드 추가)

```jsonc
// GET /api/v1/admin/dashboard/runs/{runId}
"rates": { "reservations": 12, "payments": 5, "cancels": 1, "expires": 6 }
//                                                           ^^^^^^^^^^ 추가

// GET /api/v1/admin/dashboard/runs/{runId}/minutes
"minutes": [ { "minute": "...", "reservations": 3, "payments": 1, "cancels": 0, "expires": 2 } ]
//                                                                             ^^^^^^^^^^ 추가
```

**필드가 늘어난 것뿐이라 기존 화면·클라이언트는 그대로 돕니다.**

### 무엇을 세나

`reservation_history`의 **`HOLD → EXPIRED`** 를 셉니다. 동시성 §7.1에서 `EXPIRED`로 끝나는
길이 셋인데, 이렇게 갈랐습니다.

| 경로 | from → to | 만료로 세나 |
|---|---|---|
| §6.1 기한 초과 (TIMEOUT) | HOLD → EXPIRED | **O** |
| §3 재선점 (PREEMPTED) | HOLD → EXPIRED | **O** |
| §5.2 결제 실패 (PAY_FAILED) | PAYMENT_PENDING → EXPIRED | **X** |

- **결제 실패를 뺀 이유**: 카드 거절은 결제를 시도한 것이라 "결제로 안 이어짐"과 뜻이 다릅니다
- **기한 초과와 재선점을 합친 이유**: 둘 다 `HOLD → EXPIRED`라 `from_status`로 구분되지 않습니다.
  가르려면 outbox payload의 `reason`이 필요한데 발행 뒤 24시간이면 지워집니다
  (`outbox.retention_hours`). 재선점도 결국 기한이 지난 선점이라 합쳐 세는 쪽이 뜻에 맞습니다

### 강다인 님께

취소 쪽 지표와 겹칠 수 있어 한 번 봐 주세요. 지금은 이렇게 나눠 셉니다.

- **취소** = `cancellation` 행 (사용자·운영 취소, 돈이 오감)
- **만료** = `reservation_history`의 `HOLD → EXPIRED` (돈이 안 오감)

하나로 묶는 편이 낫다고 보시면 바꾸겠습니다.

## 덧 — 그래프 색에 대해 (길동현)

만료 막대를 넣으면서 색 대비를 재 봤는데, **결제(초록 `--go`)와 취소(빨강 `--stop`)가
적록색약에서 구분되지 않습니다** (색차 ΔE 4.2, 권장 8 이상).

제가 넣은 파랑이 만든 문제가 아니라 **원래 있던 것**이고, 막대 순서가 고정이며 범례·툴팁에
이름이 붙어 있어 읽을 수는 있습니다. 다만 한지 테마 팔레트를 손대는 건 팀장 영역이라
그대로 뒀습니다. 고칠지 알려 주세요.

(만료는 오방색 토큰 `--saek`에 있는 파랑 `#1D4ED8`을 썼습니다. 기존 3색보다 나빠지지 않습니다.)
