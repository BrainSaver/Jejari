## 어떻게 했나

```
할당석 = seat_inventory에 예약 없는 행(BLOCKED) + Redis seat:hold = GROUP (반납 시각 TTL)
일반 선점: hold.lua가 GROUP에 짐 → 키가 먼저 사라져도 SeatHoldTx가 BLOCKED를 보고 거절
단체 승인(동현 님): BLOCKED → HOLD(R) → 이후 결제·만료·취소는 일반 예약과 같음, 카운터만 건너뜀
```

## 왜 이렇게 했나

- **할당석을 "예약 없는 행"으로 미리 만듦**: 선점 코드를 단체용으로 따로 만들지 않아도 PK와 Redis 키가 막아 준다. 고친 건 BLOCKED를 만료 HOLD로 착각하지 않게 하는 한 줄
- **만들기를 꺼 둠**: 단체 승인 API 없이 켜면 좌석 5%가 출발 30일 전까지 아무도 못 사는 좌석이 된다. 2차 대회(11-26) 좌석 수도 그대로 둬야 했다. 반납은 늘 돌게 해서 켰다 끈 뒤에도 남지 않게
- **팀원 JSON을 그대로 넣지 않음**: 검사 통과 ≠ 실행 가능. DDL 예시 INSERT처럼 검사 스크립트가 보지 않는 곳이 있다

## 배운 점

- **검사 스크립트가 보는 범위를 알아야 한다.** `check-erd`는 NOT NULL 예시 값은 보지만, FK 대상 예시 행이 있는지, 시각 형식이 맞는지는 안 본다
- **"한 번 쓰는 값"보다 "실제로 된 결과"를 다시 읽는다.** 할당석 키 버그는 "고른 좌석 = 만든 좌석"이라고 가정해서 생겼다
- **새 상태값 하나(BLOCKED)는 그 표를 읽는 모든 곳에 퍼진다.** 선점·배치도뿐 아니라 운행 삭제·가상 데이터 삭제·관리자 현황까지 `status`를 다시 봐야 했다
- 남의 설계에 반대 의견을 냈어도(대기열 우회) 팀장 결정이면 따르고, 그 안에서 피해를 줄이는 장치(오픈 직후 미루기)를 넣는다
