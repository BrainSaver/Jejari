## 왜 이렇게 했나

- **관리자 화면에서 대회를 "열지" 않고 결과만 "읽게" 했다**
  - 웹에서 봇·서버 명령을 실행하면 관리자 페이지가 임의 코드 실행 구멍이 된다
  - 공용 서버(CPU 4개)에서 봇을 돌리면 봇과 앱이 CPU를 다퉈 결과가 흐려진다
  - 대회는 진행자 PC의 진행 화면, 결과 보기는 관리자 화면으로 나눴다
- **eval.txt를 읽지 않고 DB를 다시 계산**: 결과 파일은 진행자 PC에만 있다. 같은 규칙으로 DB에서 다시 세면 어느 PC·서버에서도 같은 숫자가 나온다. synthetic_label 기록 같은 쓰기는 하지 않는다
- **깃에 없는 봇 경고**: 2차 대회는 1차와 "같은 봇"이어야 비교가 된다. 커밋 번호가 그 증거다. 막지는 않고 한 번 묻는다 (급할 때 진행은 해야 하니까)
- **락 수치를 최종 값으로**: 측정 방법을 고칠 때마다 해석이 바뀌었다 (C가 10배 → B에 짐 → 차이 없음). 발표에서는 최종 값만 말하고, 바뀐 과정은 이력으로 남긴다. "C가 더 빠르다"는 말은 하지 않는다

## 막힌 점과 해결

- **테스트 컴파일이 "MD5 해시를 만들 수 없음"으로 멈춤**: 이 작업 환경의 문자 인코딩이 UTF-8이 아니어서 한글 메서드 이름의 클래스 파일을 못 읽었다. `LC_ALL=C.UTF-8`로 돌리고 테스트 빌드 결과를 지워 해결 (저장소 문제 아님)
- **휴대폰 폭에서 KPI 4칸이 세로로 쌓임**: 화면에 칸 수를 직접 적으면(인라인 스타일) 좁은 화면 규칙이 안 먹는다 → `kpis k4` 클래스로 바꾸고 좁으면 2칸
