## 어떻게 했나 (v27)

```
전: 시드·스케줄러   700000 + (운행일 - 2026-01-01) * 10 + train_id
    시간표 적재      400000 + 연중일 * 1000 + 열차번호      ← 두 산식이 같은 번호를 낼 수 있음 (예: 703103)
후: train_run_seq (START 100000, MAXVALUE 399999) + 중복 판정은 자연키 (train_id, run_date)
```

- `MAXVALUE`로 할당 범위를 강제: 다 쓰면 남의 대역으로 조용히 넘어가지 않고 `ORA-08004`로 멈춘다
- 고정 번호가 필요한 것은 그대로: 명절 1001~2004, 시연 9001~9003, 테스트 9101~9999, 합성 880000~, 관리자 1000000~

## 왜 이렇게 했나

- v27: 지금 안 깨지는 건 실제 열차번호가 1~128이라서일 뿐이다. KTX-산천(4xx)이 들어오면 PK가 겹친다. **우연에 기대지 않으려고** 산식을 버렸다
- v28: MongoDB 시계열 컬렉션은 유니크 인덱스를 못 만든다. Kafka 재전달로 같은 조각이 두 번 들어오는 것을 막는 유니크가 저장 효율보다 중요하다
- 번호를 계산식으로 만드는 건 좌석 ID에는 맞았지만(시드를 다시 넣어도 같은 ID, 결정 1) **여러 사람이 각자 만드는 운행**에는 맞지 않았다
