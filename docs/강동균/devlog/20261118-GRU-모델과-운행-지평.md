## 한 일

- **GRU 모델 추가**: 행동 로그를 계정별 **이벤트 순서**로 읽는 딥러닝 모델. 부스팅 + Isolation Forest에 큰 GRU 5개 평균을 더해 세 점수 중 큰 값을 씀
- **운행 지평 스케줄러** (`RunHorizonScheduler`, 기본 꺼짐): 예매 가능 기간(2개월) 전체에 매일 운행을 채움
- **시연 운행이 3일 뒤 출발해 DEPARTED로 막히던 것** 수정 (출발 +45일, 시드를 다시 돌리면 날짜도 갱신)
- **첫 화면 검색** 3건: 날짜를 바꾸면 시각이 "검색한 순간"으로 남아 0건, 첫 화면이 빈 채로 시작, 자동 검색이 사람 검색처럼 행동 로그에 남음

## 어떻게 했나

- GRU: `seq.py`가 계정별 이벤트를 한 칸에 숫자 22개로 → `deep.py`로 GRU·하이브리드·여러 개 평균·큰 GRU 비교 → `train.py`가 `gru.pt` 저장, `score.py`가 함께 점수
  - torch나 `events.jsonl`이 없으면 부스팅 + IF만으로 돈다 (서버·팀원 PC 어디서나)
- 비교 방법은 어제와 같게 "봇 계열 하나를 통째로 빼고 학습 → 그 계열로 시험"(처음 보는 수법), 사람 오탐 5% 문턱

| 4세트 비교 | 부스팅 + IF | + 큰 GRU 5개 평균 |
|---|---|---|
| 처음 보는 계열 탐지 | 61.6% | **69.7%** |
| 사람 오탐 | 7.0% | **6.0%** |
| 좌석 묶어 두기 봇 | 46~63% | **100%** |

- 운행 지평: 10분마다 `ADD_MONTHS(오늘, 2) + 1일`까지 빠진 날짜를 채움. 정차 시각은 기존 운행에서 **기준일로부터의 간격**으로 베껴 자정 넘김을 지킴
- 자동 검색은 `X-Search-Auto: 1` 헤더 → `VIEW_TRAIN` meta에 `auto=true` → `tools/ml/features.py`가 빼고 특징 계산

## 왜 이렇게 했나

- GRU 단독은 44%로 지금 모델(65%)보다 약했다. 그래도 **순서**를 봐야 잡히는 봇(좌석 묶어 두기)이 있어서 대체가 아니라 **더하기**로 넣었다. 하나만 쓰면 결과가 들쭉날쭉해 5개 평균으로
- 운행 지평은 기본 꺼짐: 공용 서버·통합 테스트에 갑자기 운행 수천 건이 생기면 다른 사람 시험이 흔들린다
- 자동 검색을 빼지 않으면 모든 사람이 "열자마자 검색"한 것처럼 보여 봇 특징(빠른 조회)이 흐려진다
