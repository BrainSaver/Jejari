## 왜 이렇게 했나

- **모델 하나 대신 검사 + 변호인**: 모델 하나로 모든 함정을 맞추면 한쪽을 고칠 때 다른 쪽이 나빠진다(4차). 약한 그룹만 따로 보는 작은 모델을 붙이고, "봇을 몇 %까지 풀어 주나"를 숫자로 묶었다. "하나라도 봇이면 봇"으로 합치지 않음 — 오탐이 쌓인다
- **변호인이 문을 열면 그 문을 노리는 봇을 같이 만든다**: 기기 공유 예외를 만들면서 `b_shift_device`를 넣지 않았다면 그 그룹에 봇이 0명이라 문턱을 정할 수도, 새는지 볼 수도 없었다
- **라운드를 멈추고 여러 시드로**: 한 세트에서 사람 종류 하나는 30~110명이라 1명 = 1~3%p. 같은 r8이 시험 세트만 바뀌어도 33.0 ↔ 28.4%. "고치면 다른 쪽이 나빠진다"의 일부는 우연이었을 수 있음
- **더 학습하지 않기로**: 남은 가족 대량 구매(22%)는 행동 기록상 봇과 같아 모델을 바꿔도 못 푼다. 점수는 보조 의견이라 관리자 검토로 넘기고, 실제 판정 기록이 쌓이면 그때 실제 데이터로
- **`data/ml/model`을 덮어쓰지 않고 새 버전으로 등록**: 서버는 버전을 `model_run`에 두고 A-09에서 비교해 켠다. 덮어쓰면 기존 버전 점수가 몰래 바뀐다
