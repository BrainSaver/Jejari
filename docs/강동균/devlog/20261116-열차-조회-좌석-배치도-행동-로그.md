## 어떻게 했나

```
배치도·남은 좌석 → seatmap:{runId} 있으면 그대로
                    없으면 seat:hold 키 525개 MGET + DB SOLD 행 → 상태 계산 → 1초 저장
상태: R·REOFFER:R → HELD,  SOLD:R·DB SOLD → SOLD,  키 없음 → EMPTY
선점·해제가 성공하면 그 운행 캐시를 지워 내 화면엔 바로 반영
```

- 열차 편성·좌석 목록은 기준 데이터라 열차별로 앱 메모리에 한 번만 읽는다.
- 행동 로그는 예외 전에 먼저 `mark()`하고, 성공하면 예약 ID를, 실패하면 errorCode를 붙여 다시 `mark()` (마지막 호출만 남음).

## 왜 이렇게 했나

- **좌석 상태를 DB HOLD 행이 아니라 Redis 키로**: 경쟁에서 진 요청은 DB에 안 쓰는 구조라 실시간 원천이 Redis 키다.
- **1초 캐시**: 오픈 순간 새로고침 폭주를 Redis MGET 한 번으로 줄인다. 늦게 보여도 최종 판정은 선점 때라 중복 판매는 없다.
- **대기자 몫(REOFFER) 좌석은 "선점됨"으로**: 일반 사용자는 잡을 수 없으니 빈 좌석처럼 보이면 헛클릭만 늘어난다.
- **공용 OutboxRecorder로**: 같은 SQL(§11.1)을 두 벌 두면 샤드 계산을 한쪽만 고치는 사고가 난다. 그쪽은 트랜잭션 밖 호출을 막는 MANDATORY 보호도 있다.
- 감수한 단점: 캐시가 끝나는 순간 요청이 몰리면 여러 요청이 동시에 다시 만든다(값은 같음). 부하 테스트에서 문제면 한 대만 만들게 바꾼다.

## 막힌 점과 해결

- 강다인 씨 행동 로그 통합 테스트 3개가 실패 → 내 코드가 아니라 **로컬에 Kafka가 없어서**였다. Kafka(KRaft)를 띄우고 토픽을 만든 뒤 통과. 덕분에 내 로그가 Kafka → MongoDB까지 실제로 쌓이는 것도 직접 확인했다.
- 작업 중 main에 길동현 씨 `event` 패키지가 들어와 합친 뒤 전체 테스트를 다시 돌림 (단위 388, 통합 281 통과).

## 배운 점

- "실패 요청도 남긴다"는 말로만 확인하지 말고 저장된 문서를 봐야 한다. 403 선점 시도가 `errorCode: QUEUE_TOKEN_REQUIRED`로 실제 MongoDB에 있었다.
- 통합 테스트 실패는 먼저 환경(Kafka·Redis AOF·시간대)부터 의심한다. 이번 실패는 코드가 아니라 브로커가 없어서였다.
