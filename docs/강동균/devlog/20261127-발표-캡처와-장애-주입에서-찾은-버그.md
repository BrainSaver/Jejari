## 어떻게 했나

```
공용 서버 PG 시험: 서버 셸이 없음 → 서버 일은 조영준 님께 블록으로, k6·확인은 내 PC
  → 가입 제한은 관리자 API(내 IP만 2시간)로 풀고 pg1 계정 100개 → 기준·장애 두 번 → 결과 모름 0 확인 뒤 되돌리기
섞는 시험: 연습 봇 실행기에 사람 5종을 더함(새 도구 대신) → 소규모로 동작 확인 → 큰 시험은 메모리로 멈춤
캡처: A-06은 공용 서버(읽기만), A-11은 2차 대회 데이터가 있는 로컬, A-10은 로컬 장애 주입
  → A-11에서 500 → 원인 고치고 다시 찍음
  → A-10이 복구 뒤 초록으로 안 돌아옴 → "격리 보관 47건" → seat-release가 Redis 연결 끊김을 바로 보관함으로 → 고치고 같은 장애로 확인
```

## 왜 이렇게 했나

- **서버 되돌리기는 두 단계로 나눔**: 처음 보낸 블록은 "가짜 PG 다시 답하게"와 "mock으로 되돌리기"가 한 번에 돌았다. 그대로면 결과 모름 100건이
  `PG_NOT_RECEIVED`로 실패 처리돼 좌석이 풀린다. 붙이기 전에 알아채 "다시 답하게 → 0 확인 → 되돌리기"로 나눔
- **섞는 시험은 연습 봇 실행기에 더함**: 봇 49종·사람 변형 11종·이메일 라벨 채점이 이미 있었다. 같은 라벨 규칙을 쓰면 `eval_contest.sh`가 새 사람도 오탐까지 채점한다
- **seat-release는 "연결 장애만" 다시 시도**: 모든 예외를 다시 시도하면 버그(Lua 오류 등)가 파티션을 영원히 막는다. 연결 장애는 기다리면 풀리고, Redis가 없으면 어차피 처리할 수 없다
- **목록 SQL을 클래스 상수로**: 틀이 깨지면 첫 클릭이 아니라 앱 시작에서 바로 드러난다

## 막힌 점과 해결

| 막힌 것 | 원인 | 해결 |
|---|---|---|
| 공용 서버에서 앱을 http 모드로 못 바꿈 | 이 PC에 서버 접근(gcloud·SSH 키) 없음, PG 모드는 재시작해야 바뀜 | 조영준 님이 블록을 붙이고 측정은 내 PC |
| `perf1` 계정 로그인 401 | 확인 명령이 옛 경로 `/api/auth/login`을 씀 | 새 `pg1` 계정. `perf1`은 아마 살아 있음 |
| 결과 모름이 몇 분째 그대로 | 스캐너는 결제 마감(선점 + 10분) 뒤에만 PG에 묻는다 | 마감 시각을 예약 API로 보고 그 뒤 30초마다 확인 |
| 로컬 앱·큰 시험이 꺼짐 | Docker 가상 머신이 PC 메모리 절반(약 7.7GB). 대표 터미널에서 직접 돌려도 멈춤 | 소규모 결과로 정리, 앱은 jar(`-Xmx1g`)로 짧게만 |
| 단체가 5분 동안 승인 안 됨 | 일반 좌석은 대기열이 빈 뒤에만(§18.3a). 시험 운행은 바로 판매를 열어 할당석이 없음 | 설계대로. 기다림을 15분으로 |
| 첫 A-10 빨강이 장애 전 | 이 PC가 부하만으로 p95 3.6초 → 빨강 문턱(3초) | 부하를 10명으로 낮추고 "5xx"가 이유일 때만 찍음 |

## 배운 점

- 장애 주입은 "그 순간 버티나"만이 아니라 **끝난 뒤 저절로 돌아오나**까지 본다. 정합성 점검은 통과했는데 관제 화면이 알려 줬다
- 격리 보관함은 "다시 해도 안 되는 것"을 치우는 곳이다. 잠깐의 장애까지 넣으면 장애가 끝나도 일이 멈춘다
- 남이 붙이는 서버 명령은 **중간 확인 지점을 블록 경계로** 만든다
