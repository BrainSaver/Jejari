```
오전: 9001·9002를 "돌린 날 +45일"로 옮김
오후: 예매 가능한 모든 날에 열차 2편씩 깔기 (생성 운행 100000~)
  → 날짜가 지나자 9001이 옮겨 갈 2027-01-07을 생성 운행 100100이 이미 가짐 → UNIQUE(train_id, run_date) 위반

- 옮겨 갈 날짜의 생성 운행을 먼저 비운다. 생성 운행 번호는 `train_run_seq`가 줘서 번호 자체에 뜻이 없다(v27). 비워진 옛 날짜는 뒤쪽 MERGE가 다시 채운다
- 예약·좌석·대기자가 달린 운행은 건드리지 않는다. 그때는 9001을 옮기지 않고 그대로 둔다
- 검증 23번(지평 밖 운행이 안 열림)과 18번(관리자 화면이 만든 행사 정책까지 셈)도 함께 고쳤다

**대회 진행 화면**

```
브라우저(127.0.0.1:8098) ─ SSE ─ server.js (Node 기본 모듈만)

- "사람 흐름 확인"은 사람을 초대하기 직전에 한 번 돈다: 가입 → 로그인 → 대기열 → 좌석 → 결제 → 취소. 점검 계정은 `lt{태그}p.probe…`라서 평가(`lt{태그}.`만 셈)에 들어가지 않는다

## 왜 이렇게 했나

- **계정을 측정마다 만들지 않고 다시 쓴다**: 공용 서버는 Caddy가 X-Forwarded-For를 다시 쓰기 때문에, 모든 요청이 내 IP 하나로 잡힌다.
  - 가입 제한은 최대 시간당 100회이고 계정 하나에 2회(본인인증·가입)가 든다. 그래서 **한 시간에 50명이 한도**다
  - 측정 직전에 가입하면 Argon2 해시가 서버 CPU를 써서 측정값도 흐려진다
  - 대신 같은 `RUN_TAG`로 조영준 님 오후 측정도 같은 계정을 쓴다. 회원당 하루 20장 제한이라 몇 번 재도 괜찮다
- **진행 화면을 셸 스크립트 하나가 아니라 웹 화면으로**: 사람 참가자에게 접속 주소와 남은 시간을 크게 보여 줘야 하고, "사람 시간 지금 끝내기"·"중지"를 중간에 눌러야 한다. 락 비교 때 만든 `bench/web/server.js`와 같은 방식이라 설치할 것이 없다
- **사람 흐름 확인을 넣은 이유**: 1차 대회(11-19)에서 사람 참가자가 결제에서 막혀 사람 기록이 0명이었다. 원인은 Redis에 남은 리허설 기록이었는데, 어느 키였는지는 기록에 남지 않았다.
  - 그래서 "무엇을 지울지"를 추측하는 대신, IP별 시도 카운터처럼 지워도 안전한 것만 지운다
  - 대신 **사람이 하는 일을 직접 한 번 해 보고**, 막히면 사람을 부르기 전에 멈춘다
- **봇을 `bot.json`으로 꽂는다**: 봇이 늘 때마다 진행 화면 코드를 고치면, 대회 직전에 화면이 깨질 수 있다.
  - 화면은 봇 이름과 결과만 보여 주고 코드는 보여 주지 않는다 (블라인드 규칙)
  - 화면으로 넣은 봇만 지울 수 있고, 깃에 있는 봇은 지우지 않는다
- **Playwright를 `NODE_PATH`로 같이 쓴다**: 카톡으로 받은 봇 파일 하나를 올렸을 때 폴더마다 `npm i`를 다시 하지 않게 하려고
- 감수한 단점:
  - 화면으로 올린 봇은 깃에 없는 파일로 남는다. 2차 대회에 같은 봇을 쓰려면 제작자가 커밋해야 한다
  - 화면이 켠 앱은 화면을 끄면 같이 꺼진다

## 막힌 점과 해결

- **시드 04와 테스트 정리 구문은 둘 다 "만든 직후엔 멀쩡하다"가 원인이었다**:
  - 시드 04는 날짜가 지나야, 테스트 정리 구문은 관리자 화면으로 운행을 하나 만든 뒤에야 깨졌다 (11-19 대회 운행 1000000, 좌석 48석 SOLD)
  - 더 나쁜 쪽은 테스트 정리 구문이다. FK가 없는 테이블에서는 남의 데이터를 **조용히** 지웠을 것이다
- **결제 재확인 스캐너 누락은 전체 실행에서만 깨졌다**: 단독으로 돌리면 통과해서 다른 테스트의 간섭처럼 보였다. 실제로는 기본으로 켜지는 스캐너(`matchIfMissing=true`)가 조회보다 먼저 행을 집어 간 것이었다
- **진행 화면을 실제 앱으로는 아직 못 돌렸다**: 이 작업 환경에 Docker가 없어 가짜 앱·가짜 docker·가짜 봇으로만 시험했다.
  - 처음부터 끝까지 진행, 틀린 비밀번호, 중지 뒤 정리, 같은 태그 거절, 봇 추가·빼기, 경로 공격 거절, 휴대폰 폭(390px)까지 확인했다
  - 시험하면서 고친 것: 중지했는데 "평가 실패"로 표시되던 것, 늦게 연 화면에 로그가 비어 있던 것

## 배운 점

- 테스트 정리 구문은 "내가 만든 것만" 지워야 한다. 번호 대역처럼 **뜻이 없는 값**으로 범위를 잡으면, 정상 사용(관리자 화면으로 운행 만들기)과 바로 부딪힌다
- 원인을 모르는 실패를 막을 때는 "의심 가는 것을 지우기"보다 **"성공하는지 직접 해 보기"**가 확실하다
- 측정 조건을 바꾸지 않으려면 측정 도구가 운영 제약(IP당 제한)을 알아야 한다. 이번에 조건을 그대로 둔 채 계정 준비만 앞으로 뺐다
