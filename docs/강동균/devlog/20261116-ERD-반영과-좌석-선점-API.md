## 어떻게 했나

- ERD 반영: 요청 확인 → 그 팀원 코드에서 실제 키 이름·값 대조 → 새 패치 `V{n}_OPS` → `check-erd.js` FAIL 0 → DDL·종합 문서 재생성 → 설계 문서 맞춤
- 좌석 선점 흐름

  ```
  입장 토큰 → 예약 ID 발급 → idem SET NX → 한도 1차(limit_incr.lua) → 좌석 경쟁(hold.lua)
    ├ 짐: 한도·idem 되돌리고 409 (DB 쓰기 0건)
    └ 이김: DB 트랜잭션 [재선점 §3 → reservation → seat_inventory → reservation_seat
                        → purchase_counter → outbox SEAT_HELD → 이력 → Saga]
  ```

- 검증은 실제 컨테이너로: Oracle(gvenzl/oracle-free) + Redis(AOF) + MongoDB를 띄우고 `SeatHoldInfraTest` 10개 작성

## 왜 이렇게 했나

- **배포된 패치는 안 고치고 새 버전으로**: v13을 main에 올린 직후 강다인 씨가 패널티 값을 확정했다. v13 블록을 고치면 이미 편집기를 연 팀원과 새로 연 팀원의 스키마가 달라지므로 v14로 따로 냈다.
- **`event_id` 인덱스를 부분 인덱스로**: 그냥 유니크를 걸면 `event_id`가 없는 기존 로그끼리(null) 충돌해 두 번째 로그부터 저장이 막힌다. Mongo를 실제로 띄워 보다가 발견했다.
- **SQL은 JPA 대신 JdbcTemplate**: `concurrency.md`의 조건부 UPDATE·`FOR UPDATE`·`ORA_HASH(TO_CHAR(:pkey), 15)`를 문서 그대로 옮기려고. 팀의 위험 점수 코드도 같은 방식.
- **카운터는 모아서 정렬 후 갱신**: 재선점은 내 증가 + 남의 감소가 한 트랜잭션에 섞인다. `(scope, ref, ci)` 순서를 고정해 데드락을 막음 (§10.3).
- **개발 모드에선 판매 중 운행 대용품 유지**: 실제 구현과 대용품이 같이 있으면 어느 쪽을 쓸지 모호해져서, 실제 구현은 `dev-mode=false`일 때만 만든다.
- 감수한 단점: 어린이·경로 할인은 아직 없음 [가정]. 재선점된 예약의 Redis 정리 보장 경로(`seat-release`)는 다른 파트 몫이라 지금은 앱이 커밋 직후 한 번만 한다.

## 막힌 점과 해결

- **T1(같은 좌석 100명 동시)에서 커넥션 풀이 30초 멈춤**: 운행 조회 RowMapper 안에서 정차역을 다시 조회해 커넥션을 2개씩 쥐려 했음 → 조회를 둘로 나눔.
  → [troubleshooting/20261116-커넥션-풀-중첩-조회-멈춤.md](../troubleshooting/20261116-커넥션-풀-중첩-조회-멈춤.md)
- **산출물 페이지 탭을 누르면 iframe 안에 사이트가 또 뜸(로그인도 풀린 채)**: 사이트는 HTML 문서를 `srcdoc` iframe에 넣는데, 그 안의 `href="#ERD"`가 부모 주소 `jejari.pages.dev/#ERD`로 풀렸다 → 탭 클릭을 가로채 페이지 안에서만 전환. 브라우저로 수정 전 재현·수정 후 정상 확인.
- 로컬 테스트 준비: Redis를 AOF 없이 띄웠더니 앱의 설정 점검(`RedisConfigVerifier`)이 기동을 막음 → `appendonly yes`로. 한글 테스트 이름 때문에 Gradle은 `LC_ALL=C.UTF-8`, 시간대 점검 때문에 `TZ=Asia/Seoul` 필요.

## 배운 점

- RowMapper 안에서 DB를 다시 부르면 안 된다. 단건 테스트로는 안 보이고 동시 요청에서만 터진다 → 동시성 테스트를 일찍 돌린 게 이득.
- `srcdoc` iframe 안의 상대 링크는 부모 문서 주소 기준으로 풀린다.
- 스키마 요청은 말로만 받지 말고 그 팀원 코드의 상수·키 이름과 대조해야 한다 (오타 하나면 런타임에 "시퀀스 없음").
