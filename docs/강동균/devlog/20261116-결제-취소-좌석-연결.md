# 2026-11-16 · 결제·확정 취소가 부르는 좌석 단계

> 작성: 강동균 · 관련: PAY-01·02(길동현), CNL-02(강다인), concurrency.md §4·§5.1·§8

## 한 일

- **결제 시작 좌석 연장** `SeatPaymentService.extendHoldInCurrentTx(R, 새 마감)`: 좌석 마감을 예약의 새 마감으로 복사, 커밋 뒤 Redis 키도 연장 (§4.1-3, §4.2-1)
- **결제 승인 좌석 확정** `SeatPaymentService.confirmSeatsInCurrentTx(R)`: HOLD → SOLD, 커밋 뒤 Redis 키 `SOLD:R`(출발까지) (§5.1-4·10)
- **확정 취소 좌석 반환** `SeatReleaseService.returnSoldSeatsInCurrentTx(R)`: SOLD 행 삭제 + 카운터 감소, 커밋 뒤 좌석 키 `REOFFER:R`·한도 감소 (§8.1-2·3, §8.2)
- `SeatReleaseTx`에서 예약 읽기·카운터 감소·이벤트 내용 만들기를 공용 함수로 빼서 해제와 확정 취소가 같은 코드를 씀
- 통합 테스트 `SeatPaymentInfraTest` 11개, 기능 문서 `features/좌석-결제취소-연결.md`

## 왜 했나

Redis 스크립트 `extend`·`sold`는 만들어 두기만 하고 아무도 부르지 않았다. 결제(길동현)와 확정 취소(강다인)는 좌석을 건드려야 하는데 그 입구가 없어서, 두 파트가 각자 seat_inventory SQL을 짜거나 기다려야 했다. 좌석 재고·카운터·Redis 좌석 키는 한 곳(좌석 모듈)에서만 바꾸도록 입구를 먼저 만들었다.

## 어떻게 했나

```
결제·취소 쪽 트랜잭션: reservation 상태 변경(락) → [좌석 단계] → payment·cancellation·이력·outbox → COMMIT
                                                     └ 커밋 뒤에만 Redis (afterCommit)
```

- 세 메서드 모두 **호출하는 쪽 트랜잭션 안에서** 돈다. 결제 기록과 좌석 확정이 같이 커밋되거나 같이 롤백된다.
- 영향 행 수가 K(= 매수)와 다르면 **false**를 돌려준다. 결제 쪽이 "결제 시작 거절"(§4)인지 "확정 실패 → 늦은 승인 환불"(§5.1)인지 직접 고른다.
- 확정 취소는 예약이 이미 CANCELED일 때만 동작하고(순서가 틀리면 예외), 지울 SOLD 행이 없으면 null을 돌려줘 두 번 불러도 카운터가 한 번만 준다.

## 막힌 점과 해결

- Gradle 의존성을 받다가 Maven Central이 429(요청 과다)를 돌려줌 → 재시도로 해결.
- 테스트 컴파일이 `bad filename …$회피.class`로 실패 → 셸 로케일이 UTF-8이 아니었다. `LC_ALL=C.UTF-8`로 해결 (김성원 씨 트러블슈팅 "한글 인코딩"과 같은 원인).
- 좌석 통합 테스트 31개가 전부 컨텍스트 로딩 실패 → 기동 점검이 `JVM=Z(UTC)`를 잡아 거부한 것. `TZ=Asia/Seoul`로 실행해 해결. 코드 문제가 아니라 §0.7 점검이 제대로 동작한 것이다.
