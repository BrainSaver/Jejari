# 2026-11-17 · 관리자 기준 데이터·운행 관리 API

> 작성: 강동균 · 관련: ADM-01, ADM-02, 화면 A-02·A-03

## 한 일

- **`MasterDataService`·`MasterDataAdminController`**: 역·노선·차량 유형·열차 조회·등록·수정. 열차를 만들면 좌석 자동 생성
- **`RunAdminService`·`RunAdminController`**: 명절 행사(+ 전용 매수 제한), 운행 일괄 생성(정차 시각 포함), 시각 수정, 삭제, 지금 판매 열기
- `TrainLayoutReader`에 캐시 비우기(`evict`, `evictAll`) 추가
- `SaleOpenSchedulerInfraTest` 정리 범위를 테스트 대역(9101~999999)으로 좁힘 — 관리자 운행(1000000~)까지 지우면 정차 시각 FK에 걸림
- 통합 테스트 `TrainAdminInfraTest` 11개 (실제 Oracle). 열차 쪽 통합 테스트 29개 모두 통과
- 스키마 변경 없음 (ERD 패치 없음)

## 왜 했나

ADM-01·02는 P2라 1차는 시드와 판매 오픈 스케줄러로 대신했다. 시드만 있으면 운행을 추가할 때마다 SQL을 고쳐야 하고,
시연 중에 "새 명절 행사를 만들고 판매를 연다"를 보여 줄 수 없다. 화면 시안(A-02·A-03)이 부르는 API를 먼저 만들었다.

## 생각이 바뀐 곳

- **행사만 만들면 명절 한도가 안 걸린다.** 처음엔 행사 행만 넣었는데, §10.6을 다시 읽으니 행사 전용 정책이 없으면
  상시 정책으로 떨어져 PER_HOLIDAY가 사라진다. 그래서 행사 등록 때 정책 4개를 같은 트랜잭션에 넣었다.
- **오픈 시각을 Java로 계산하면 시드와 어긋난다.** `minusMonths(2)`는 2/28 → 12/28, Oracle `ADD_MONTHS`는 말일이면 말일(12/31).
  계산을 SQL로 옮겼다.
- **NULL 바인드를 `NVL(?, …)` 안에 넣으면 Oracle이 타입을 못 정한다** (SaleOpenSchedulerInfraTest 주석과 같은 이유).
  행사 유무로 문장을 나눴다.
- **`SELECT COUNT(*) … FOR UPDATE`는 Oracle에서 안 된다** (집계 + 잠금). 삭제 전 확인은 `SELECT status … FOR UPDATE`로.
