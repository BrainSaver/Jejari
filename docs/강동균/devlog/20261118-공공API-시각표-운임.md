## 한 일

## 왜 했나

역·노선·거리·차량유형은 파일데이터(CSV)로 받아 쓰고 있었다. 그런데 **정차 시각과 운임은
공공데이터가 아니라 내 계산식**이었다.

```
소요 시간 = 거리 ÷ 2.7km/분 + 정차 2분
운임     = 2,800원 + 125원/km   (특실 ×1.4)
```

발표에서 "구조만 공공데이터고 시각·운임은 계산했다"고 설명해야 하는 상태였다.
API가 실제 값을 주므로 그 두 칸을 메웠다.

## 바뀐 값

| | 전 (계산식) | 후 (API) |
|---|---|---|
| 열차 번호 | 101 · 102 (지어낸 값) | **00103 · 00026** |
| 서울~부산 | 2시간 52분 | **3시간 7분** (09:28 → 12:35) |
| 서울~부산 일반실 | 55,000원 | **54,400원** |
| 서울~광명 일반실 | 5,600원 | **7,500원** |

내 계산식이 꽤 근접했지만(부산 1.1% 차이) 가까운 구간은 많이 틀렸다 — 광명은 34% 낮았다.
거리에 비례한다고 본 것이 실제 요금 체계와 다르다.

## 어떻게 했나

```
API → db/seed/data/tago-train-info.json → load-public-data.js → 시드 SQL의 @generated 블록
     (fetch-train-api.js)                 (CSV와 같은 생성기)
```

받은 응답을 CSV와 같은 자리에 그대로 저장한다. 빌드마다 외부를 부르면 느리고 포털이 멈추면
빌드도 멈춘다. 한 번 받아 두면 CI는 네트워크 없이 그 파일만 보고 검사한다.

### 고른 기준

- **열차**: 5역에 모두 서는 순수 KTX 중 09시 이후 첫 편. 새벽 편(05시대)은 시연에 안 맞는다
- **시각**: API가 **중간역 시각을 주지 않는다** (출발역·도착역 둘뿐). 역 쌍을 돌며 모은다 —
  어떤 역의 도착은 (기점 → 그 역), 출발은 (그 역 → 종점) 조회에서 나온다. 조회 25번
- **날짜**: 시·분만 쓰고 날짜는 각 운행의 `run_date`에서 붙인다. 운행일이 적재일 기준
  상대값이라 조회 날짜를 그대로 쓰면 맞지 않는다
- **운임**: 같은 구간에 여러 편이 있으면 최빈값 (특별열차 운임에 끌려가지 않게).
  **특실은 API가 주지 않아** 일반실 ×1.4로 우리가 정한다

## 막힌 점과 해결

### 오퍼레이션 이름이 대문자로 시작한다

`getCtyCodeList`로 부르니 `NO_OPENAPI_SERVICE_ERROR(12) 해당 오픈API 서비스가 없거나 폐기됨`이
나왔다. 메시지가 키 문제처럼 읽혀서 키를 두 번 바꿔 가며 헤맸다.

**엉터리 키로도 같은 에러가 나는 것**을 보고 경로 문제임을 알았다. 진짜 키 문제는
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR(30)`으로 따로 나온다. 확실히 있는 다른 경로(버스도착정보)로
키만 따로 시험해 갈랐다.

정답은 `GetCtyCodeList` — **첫 글자가 대문자**다.

### 묵은 Oracle 볼륨이 통합 테스트를 깨뜨렸다

통합 테스트 455개 중 `RiskScoreBatchInfraTest` 2개가 `expected: 1 but was: 0`으로 실패했다.
내 변경과 무관해 보여 단독으로 돌려 보니 역시 실패 — 테스트 간 간섭도 아니었다.

원인은 실행 중인 Oracle의 `case_marker.rule_code` CHECK에 `REGULAR_INTERVAL`이 없던 것이다.
ERD v24로 추가됐지만 **DDL은 볼륨을 처음 만들 때만 돈다.** 테이블은 44개 다 있어 겉으로는
멀쩡해 보인다. `db/patch/v24.sql`을 적용하니 둘 다 통과했다.

11-17에도 같은 함정을 겪었다 (그때는 시퀀스 5개가 없었다). 테스트 메시지만 봐서는 알 수
없어서 `db/seed/README.md`에 적어 뒀다.

## 배운 점

- **에러 메시지를 믿기 전에 갈라서 확인한다.** "서비스가 없거나 폐기됨"을 키 문제로 읽고
  시간을 썼다. 엉터리 값으로 같은 에러가 나는지 보면 한 번에 갈린다
- **계산식이 근접해도 실제 값과 다르다.** 먼 구간은 1% 차이였지만 가까운 구간은 34% 틀렸다
