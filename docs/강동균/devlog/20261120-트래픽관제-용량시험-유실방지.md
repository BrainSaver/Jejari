- **격리 보관함(DLQ) · 다시 넣기** + 행동 로그 보내기 재시도 ([기능 문서](../features/격리-보관함-DLQ.md), [점검표](../features/데이터-유실-점검.md))

- [통합 테스트 돌리는 법](../features/통합테스트-돌리는-법.md) 정리

## 어떻게 했나

- 매번 **실제 앱 + k6 + 장애 주입**(Redis·Kafka·MongoDB 정지, DB 제약으로 저장 실패, 깨진 메시지)으로 확인하고, 숫자가 이상하면 원인부터 찾음
- 비교는 같은 조건으로: DB·Redis를 새로 만들고 1.5분 데운 뒤 같은 몰림

## 왜 이렇게 했나

- 사람이 몰릴 때 문제는 세 가지 — 공정(봇), 정확(돈·좌석), 버티기(서버). 관제 화면은 셋이 지금 괜찮은지 보는 눈이고, 용량 시험·유실 점검은 버티기·정확을 확인하는 것
