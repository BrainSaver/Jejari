# 길동현 님께 — 결제 코드에 넣은 것 알림 (2026-11-27)

> 작성: 강동균 · 결제(PAY)는 길동현 님 담당인데 제가 시험·보강하면서 결제 코드를 몇 군데 고쳤습니다.
> **기본값은 전부 예전과 같아서** 따로 켜지 않으면 동작이 바뀌지 않습니다 (화면 두 가지만 예외, 아래 4번).
> 바로 붙여 보낼 짧은 글은 맨 아래에 있습니다.
>
> **답 (11-27, 길동현): "다 허가 한다."** → 1-2 단계 위치·결과 모름 처리 그대로, 기능설계서 9장에 오류 코드 2줄과 PAY-01 예외 목록 추가함

## 1. 카드 명의 상한 (11-24, ERD v37)

- 새 카드를 회원에게 처음 붙일 때만, 그 카드에 이미 붙은 **서로 다른 명의(CI) 수**를 세어 상한 이상이면 422 `PAYMENT_CARD_LINK_LIMIT`.
  예약은 HOLD 그대로라 다른 카드로 바로 다시 결제할 수 있습니다
- 동시에 여러 계정이 처음 보는 카드로 결제를 시작해도 모두 "0명"으로 세고 통과하지 않게, 카드 해시마다 `card_lock` 한 행을 잠근 **뒤에** 셉니다
  (잠금 순서 concurrency.md §0.4-8, 트랜잭션 맨 끝 한 행이라 데드락 없음)
- 꺼져 있으면(0) 잠금도 만들지 않아 결제 시작에 비용이 없습니다
- 공용 서버에서 켤 예정입니다 (관리자 화면 정책에서 3). 같은 카드를 쓰던 시연·k6·대회 번호는 4번에서 사람마다 다르게 바꿨습니다.
  **통합 테스트들이 같은 카드(`4111…1111`)로 결제해서 로컬·테스트 기본값은 0으로 둡니다**
- 테스트: `CardLinkLimitInfraTest` (동시 10명 → 정확히 3명만 성공 포함)

## 2. `HttpPgClient` — PG를 네트워크로

- `jejari.payment.pg.mode`로 고릅니다. `mock`(기본)은 예전과 같은 `MockPgClient`(앱 안, 0초 응답), `http`는 `base-url`의 PG를 HTTP로 부릅니다
- 지금 `http`로 붙는 건 가짜 PG 서버(`loadtest/mock-pg/server.js`, compose `pg` 프로필)뿐입니다. 느린 PG·몰림·응답 없음을 만들어 부하 시험에 씁니다.
  실제 PG 테스트 모드를 붙인다면 이 자리입니다
- 연결 1초·응답 3초 한도. **시간 초과·연결 실패·5xx는 "결과 모름"** 으로 돌려서 기존 §6.2 스캐너(`PaymentRecheckScanner`)가 마감에 조회합니다 —
  모르는 걸 실패로 처리하면 돈은 빠졌는데 좌석이 풀리는 일이 생겨서입니다
- 카드번호가 본문에 들어가므로 이 기기 밖 주소는 https만 받습니다 (127.0.0.1·localhost만 http)
- 테스트: `HttpPgClientTest` 6개

## 3. `PgBulkhead` — PG 동시 승인 상한 (`PaymentService` 1-2 단계)

- 결제 단계 차단(1-1, 조영준 님) 바로 뒤, **결제 행을 만들기 전에** 자리를 잡습니다. 못 잡으면:
  멱등 키를 지우고 503 `PAYMENT_BUSY` + `Retry-After` 3초. DB에 아무것도 안 남고 예약은 HOLD 그대로라 **같은 멱등 키로 다시 보내면 처음처럼** 처리됩니다
- 기존 흐름은 `startWithSlot(...)`으로 옮겼을 뿐 내용은 그대로입니다 (2단계 DB 트랜잭션부터)
- 503이지만 예상된 거절이라 `RetryAfterException`이면 ERROR 로그·스택트레이스를 남기지 않게 `GlobalExceptionHandler`에 한 줄 (시험 한 번에 1,451개가 쌓였었음)
- 기본은 끔입니다. 응답 한도 3초만으로도 PG가 멈췄을 때 스레드가 68개에서 멈춰서(30초면 200/200), 상한은 한도를 길게 잡아야 하는 PG를 붙일 때의 두 번째 방어입니다
- 테스트: `PgBulkheadTest` 3개, `PaymentInfraTest`에 "상한이 찼을 때" 1개 (503 + Retry-After, 결제 행 0, HOLD 그대로, PG 안 감 → 자리가 나면 같은 키로 승인).
  PC에서 `PaymentInfraTest` 24/24
- 측정·이유: [PG-지연-시험](features/PG-지연-시험.md), concurrency.md §4.4

## 4. 결제 화면 (`Pay.jsx`)

- **시험 카드 버튼 번호가 회원마다 다릅니다**: `4111` + 회원 ID 11자리 + 끝자리(1 승인 · 8 늦은 승인 · 9 결과 모름 · 0 거절).
  모두 `4111 1111 1111 1111`을 쓰면 1번 상한을 켰을 때 네 번째 사람부터 막히고, 그 카드 하나에 위험 점수가 쌓였습니다 (서버에서 45점까지)
- **`PAYMENT_BUSY`면 자동 재시도**: `Retry-After`만큼(±20%) 기다렸다 같은 멱등 키로 다시. 최대 10번, 결제 기한이 10초 넘게 남을 때만, 화면을 떠나면 멈춤.
  기다리는 동안 버튼에 "몰려서 N초 뒤 자동으로 다시 (k/10)". 3번이 꺼져 있으면 이 응답이 오지 않으니 지금은 동작 변화가 없습니다
- `PAYMENT_CARD_LINK_LIMIT`·`PAYMENT_BUSY` 안내 문구를 `MESSAGES`에 추가

## 확인 부탁드릴 것

1. `PaymentService`에 1-2 단계를 끼운 위치(결제 단계 차단 뒤, DB 트랜잭션 앞)가 괜찮은지
2. "결과 모름"으로 돌리는 경우(시간 초과·연결 실패·5xx)가 기능설계서의 PAY 실패 처리와 맞는지
3. 기능설계서 9장 오류 코드 표에 `PAYMENT_CARD_LINK_LIMIT`(422)·`PAYMENT_BUSY`(503) 두 줄 — 팀장님 문서라 같이 여쭤보려 합니다
4. 실제 PG 테스트 모드를 붙일 계획이 있으면 `HttpPgClient`의 요청·응답 모양(`POST v1/payments/approve`, `GET v1/payments/{주문번호}`, `POST …/block`, `POST v1/refunds`)을 거기 맞춰 바꾸면 됩니다. `PgClient` 경계는 그대로라 결제 흐름은 안 바뀝니다

## 바로 붙여 보낼 글

> 동현 님, 결제 코드에 제가 넣은 게 있어서 알려 드려요. **기본값은 전부 예전 그대로**라 켜지 않으면 동작은 안 바뀝니다.
>
> 1. **카드 명의 상한** (`PaymentStartTx.checkCardLink`, ERD v37): 새 카드를 붙일 때 그 카드에 이미 붙은 명의 수가 상한 이상이면 422. `card_lock` 행을 잠근 뒤 세서 동시 요청에도 지켜요. 기본 0 = 끔, 공용 서버만 3으로 켤 예정
> 2. **`HttpPgClient`**: `JEJARI_PG_MODE=http`면 PG를 네트워크로 불러요(지금은 가짜 PG 서버로 부하 시험용). 응답 3초 한도, 시간 초과·5xx는 결과 모름 → 기존 스캐너가 처리
> 3. **`PgBulkhead`** (`PaymentService` 1-2 단계, 결제 단계 차단 뒤·DB 트랜잭션 앞): PG 동시 승인 상한. 넘치면 결제 행 만들기 전에 멱등 키 지우고 503 `PAYMENT_BUSY` + Retry-After. 기존 흐름은 `startWithSlot`으로 옮기기만 했어요. 기본 끔
> 4. **결제 화면**: 시험 카드 번호를 회원마다 다르게(`4111`+회원 ID), `PAYMENT_BUSY`면 자동 재시도
>
