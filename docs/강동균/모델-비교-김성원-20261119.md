# 위험 점수 모델 비교 · 강동균 `tools/ml` vs 김성원 `tools/dl-defense`

> 작성 강동균 · 2026-11-19 · 관련: [`tools/ml/README.md`](../../tools/ml/README.md) · 김성원 `tools/dl-defense/README.md` (`SeongWon` 브랜치, main에는 아직 없음)

## 한 줄 요약

**어느 모델이든 학습한 생성기와 같은 세계에서만 맞히고, 다른 세계로 가면 사람을 대부분 봇으로 본다.** 같은 구조(우리 모델)라도 학습 데이터만 바꾸면 결과가 정반대로 뒤집힌다. 실제 앱 로그(리허설)에서 봇을 잡은 건 우리 데이터로 학습한 우리 모델뿐이었지만, 리허설도 우리가 만든 봇·사람 흐름이라 **결정은 1차 대회(11-23) 실제 데이터로 한다.**

## 무엇을 비교했나

| | 강동균 `tools/ml` | 김성원 `tools/dl-defense` |
|---|---|---|
| 구조 | 계정 특징 28개 → 그래디언트 부스팅 + Isolation Forest, 이벤트 순서 → GRU 5개 평균. 셋 중 큰 백분위 | 이벤트 순서(종류·간격·응답) → CNN + 양방향 GRU + 어텐션. 기기 공유·같은 타이밍 세션 수를 따로 붙임. 주 모델 + fast 전용 모델 단계형 |
| 학습 데이터 | 우리 생성기 `generate.py` (서버 API 로그 모양, 수법 38가지, 오탐 함정) | 공격 생성기 v3 CSV(화면 클릭 단위) + fast 가속 봇 + 합성 사람 |
| 문턱 | 검증 사람 오탐 5% | 강한 단계 오탐 1.5% · 약한 단계 5% |

두 모델 모두 `behavior_log` 한 줄씩(`events.jsonl`)을 읽으므로, 같은 파일을 넣어 같은 정답(`members.jsonl`)으로 쟀다.

## 읽는 법

1. **구조보다 학습 데이터가 결과를 정한다.** ②와 ③은 같은 코드인데 데이터만 바꾸면 "자기 세계 오탐 6%, 남의 세계 오탐 90~99%"가 그대로 자리를 바꾼다. 생성 데이터 숫자는 발표에 쓰지 않는다
2. **같은 데이터로 학습하면(② vs ④)** 우리 구조가 봇 수로는 더 잡는다(96.6 vs 82.6%, 오탐은 비슷). 그런데 그 차이는 대부분 **천천히·사람처럼 움직이는 봇**이고, 이런 봇은 잡을 필요가 적다 (2026-11-19 강동균 판단)
   - 명절 예매는 몇 분 안에 매진된다. 느린 봇은 사람처럼 늦게 와서 남은 자리만 가져간다
   - 매수 제한이 명의(CI) 기준이라, 명의가 다른 여러 계정이 사람 속도로 움직이면 사람 여러 명과 같다 (진짜 명의 여러 개는 본인인증의 문제 — 강다인 보강 후보 7)
   - 결제 없이 묶어 두기는 결제 기한(기본 10분 + 결제 중 연장 최대 4분) 뒤 풀리고, 결제 실패·취소로 풀린 좌석은 대기자에게 먼저 간다
   - **잡아야 하는 건 "특정 순간에 빠른 봇"이다** — 판매 오픈 순간의 대기열 진입, 입장 직후 선점, 선점 만료로 풀린 좌석 잡기. 리허설 botc는 전체 속도가 사람 같았는데도 오픈 순간 바로 줄을 서서 6계정 모두 좌석을 샀다
   - 그래서 판정은 봇 수가 아니라 **좌석을 가져간 봇이 가져간 좌석 중 막은 비율**로 한다 (아래 "어떻게 고를지" 2)

   김성원 구조는 대신 **처음 보는 세계에서 오탐이 덜 무너진다**(김성원 시험 세트 36% vs 90%). 우리 구조는 계정·운행 특징(오픈 뒤 첫 선점까지 시간, 결제 안 한 선점 비율)에 기대는데, 이 값의 뜻이 세계마다 다르다
3. **실제 로그에서 botc를 잡은 건 우리 데이터로 학습한 우리 모델뿐**(12/12)이다. botc는 사람 속도(2~17초 간격)로 움직이고 이벤트가 4개뿐이라, 순서만 보는 모델에는 사람처럼 보인다. 우리 모델이 잡은 근거는 "운행을 둘러보지 않음 + 이벤트 수 적음"이다. 다만 botc와 우리 생성기를 같은 사람이 만들어 이 숫자를 믿으면 안 된다 (`tools/ml/README.md` 리허설 절)
4. **두 모델은 서로 다른 봇을 잡는다.** 같은 타이밍 템플릿을 나눠 쓰는 매크로(`pool`)는 김성원 모델, 둘러보지 않고 바로 줄 서기(botc)·가속 매크로(`fast`)는 우리 모델이 잡았다. OR로 합치면 탐지는 오르지만 오탐도 더해져, 지금 생성 데이터로는 합치는 효과를 잴 수 없다

## 김성원 님 모델에서 찾은 것 (대회 로그에 쓰기 전에 고쳐야 함)

- **실제 화면의 자동 검색(`meta.auto = true`)을 빼지 않는다.** 첫 화면은 자동 검색을 하고 바로 한 번 더 검색해, 조회 두 개가 12~81ms 간격으로 찍힌다. `realdata.py`가 이걸 "200ms 미만 = 봇 속도"로 읽어 리허설 사람 12명이 모두 강한 단계가 됐다. 자동 이벤트를 빼면 2/12로 내려간다
- 우리 모델은 `features.py`에서 이미 빼고 있다 (`d179ca6`)

## 이 비교의 한계

- **형식 변환이 근사다.** 김성원 님 CSV(화면 클릭 단위)를 행동 로그로 바꿀 때 김성원 님 매핑(`botcsv.CSV_TO_TYPE`)을 그대로 썼다. 그래서 좌석 "클릭"이 서버 "선점"이 된다. 행마다 바뀌는 `ua_hash`는 기기로 쓸 수 없어 세션마다 기기 하나로 두었고, 시드·열차마다 운행을 따로 나눴다. 우리 모델이 김성원 세계에서 무너진 데는 이 차이도 섞여 있다
- 리허설은 24명뿐이고, 봇·사람 흐름 모두 우리가 만들었다
- ⑤는 다시 학습하지 않은 배포 모델 그대로다. ③에는 GRU가 없다
- 김성원 님 생성기·학습 CSV는 김성원 님이 저장소에 올리지 않은 파일이라 **이 문서와 저장소에 넣지 않았다.** 변환·평가 스크립트도 그 파일에 기대므로 올리지 않았다 (다시 하려면 김성원 님께 파일을 받아야 함)

## 어떻게 고를지 (결과를 보기 전에 정함, 2026-11-19)

김성원 님은 지금 다른 일을 해야 해서, 대회 뒤 비교·선택은 **강동균이 혼자** 한다. 그래서 김성원 님 코드는 고치지도 main에 합치지도 않고, 비교 스크립트(`tools/ml/compare_dl.py`)가 실행할 때만 `SeongWon` 브랜치에서 꺼내 쓴다.

| 순서 | 기준 | 이유 |
|---|---|---|
| 1 | **대회 실제 사람 오탐 5% 이하**인 모델만 후보. 사람이 30명보다 적으면 판정을 미루고 2차 대회 데이터를 더함 | 보조 의견이라도 사람을 봇으로 보이게 하면 안 됨. 몇 명뿐이면 한 명이 오탐률을 크게 흔듦 |
| 2 | 후보 중 **좌석을 가져간 남의 블라인드 봇**이 가져간 좌석을 더 많이 막는 쪽 (막은 좌석 비율). 블라인드 봇 = bota(김성원)·botb(길동현), 그 모델을 만든 사람의 봇은 뺌 | 자기가 만든 봇은 수법을 알고 만든 모델이라 잘 잡는 게 당연함 (tools/ml → botc·botx 제외, dl-defense → bota 제외). 좌석을 못 가져간 봇은 피해가 없어 세지 않음 — 봇 수로 세면 아무것도 못 산 느린 봇과 좌석 20장을 쓸어 간 봇이 같은 무게가 된다 |
| 3 | 두 모델을 OR로 합쳐도 사람 오탐 5% 이하이고 2번 막은 좌석 비율이 더 높으면 **합친 쪽** | 두 모델이 서로 다른 봇을 잡음 (위 "읽는 법" 4). 합치면 김성원 모델은 보조 점수, ERD `model_score.by`에 `DL` 추가 |
| 4 | 동률이면 `tools/ml` | ERD v25·적재 설계가 이미 준비돼 있음 |
| 5 | 김성원 모델은 **s0**으로 판정, s1·s2는 참고 | 결과를 보고 좋은 시드를 고르지 않음 |

이 기준은 `compare_dl.py`의 `JUDGE`에 그대로 들어 있고, 스크립트가 표와 함께 판정을 출력한다. 기준을 바꾸려면 **대회 데이터를 보기 전에** 이 표와 스크립트를 같이 고친다.
