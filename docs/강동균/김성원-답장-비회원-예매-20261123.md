# 김성원 님께 · 비회원 예매 ERD 변경안 검토 (강동균, ERD 담당)

> 작성 2026-11-23 · 대상: [`docs/김성원/팀-확인-요청-비회원-예매.md`](../김성원/팀-확인-요청-비회원-예매.md)
> 결론 먼저: **"본인인증은 받고 계정만 안 만드는 게스트 회원"이라는 큰 방향에 찬성합니다.**
> 다만 표 6줄 중 3줄은 바꿔야 합니다. 그대로 넣으면 **게스트가 관리자 이용 제한을 피해 갑니다.**
> 범위에 넣을지는 길동현 님(팀장)이 정하실 일이라, 결정이 나면 v33 패치로 반영하겠습니다.

## 그대로 좋은 것

- 본인인증(CI)을 받는 것. 매수 제한(`purchase_counter`)·위험 점수·예약의 `ci_hash`가 모두 그대로 동작합니다. CI 없는 비회원을 권하지 않는다는 판단에도 동의합니다
- `member_credential` 행이 없는 `member` = 비밀번호 없는 회원이라는 구조. 스키마를 거의 안 건드립니다
- `email`에 `guest-{member_id}@guest.invalid`를 채우는 것 (NULL로 풀면 기존 코드·검사가 깨진다는 판단에 동의)
- 취소표·내 정보·탈퇴는 막고 예약·결제·조회만 여는 것

## 바꿔야 할 것

### 1. `member.status`에 `GUEST`를 넣지 말고 `member_type` 컬럼을 따로

`status`는 이미 **관리자 조치** 칸입니다. 여기에 "계정 종류"를 섞으면 두 값이 서로 덮어씁니다. 지금 코드로 확인한 것은 셋입니다.

| 코드 | 지금 동작 | `status = 'GUEST'`이면 |
|---|---|---|
| `CaseActionService.memberStatus` (이용 제한) | `UPDATE member SET status = 'RESTRICTED' WHERE status = 'ACTIVE' …` | **게스트는 `ACTIVE`가 아니라 제한이 안 걸림** → 매크로가 게스트로 들어오면 제한을 피함 |
| `CaseActionService.ban` (정지) | `status <> 'BANNED'`면 `BANNED`로 | 게스트 표시가 사라짐. 정지를 풀면 `ACTIVE`로 돌아가 일반 회원이 됨 |
| `OracleMemberIdentityPort` (대기열 진입 때 회원 상태 확인) | 허용값 `ACTIVE · RESTRICTED · BANNED`만 | 게스트가 대기열에서 막힘 (예매 자체가 안 됨) |

→ **`member_type VARCHAR2(10) NN` (`MEMBER / GUEST`)** 를 새 컬럼으로 둡니다.
- `status`는 지금처럼 `ACTIVE / RESTRICTED / BANNED` 그대로 둡니다. 게스트도 `ACTIVE`로 시작해, 제한·정지가 회원과 똑같이 걸립니다
- 기존 행은 `DEFAULT 'MEMBER'`로 채웁니다

### 2. `reservation.guest_lookup_hash`는 빼고, 예약 번호(PK) + `member.phone_hash`로 찾기

- `reservation`은 쓰기가 몰리는 테이블이라, 인덱스 하나가 모든 예매의 INSERT 비용에 붙습니다. 그래서 인덱스를 v6 54개에서 42개로 줄여 왔습니다 (CLAUDE.md "인덱스" 규칙)
- 비회원 조회는 **예약 번호로 PK 조회 1건 → 그 예약의 회원 `phone_hash`와 입력한 번호의 HMAC 비교**로 됩니다. 새 컬럼·인덱스가 필요 없습니다
- 게스트는 본인인증 때 휴대폰을 받으니 `phone_enc`·`phone_hash`를 반드시 채웁니다 (회원은 NULL 허용 그대로)
- 예약 번호가 순번이라 하나씩 넣어 보는 공격이 됩니다. 조회 시도를 IP당 제한해야 하므로 Redis 키 `rate:guest_lookup:{ipHash}`를 `redis_keys`에 추가합니다. 이건 해시 컬럼을 둬도 똑같이 필요합니다

### 3. 게스트 보관 기한은 "시간"이 아니라 "마지막 운행일 + 며칠"

- 명절 표는 몇 주 전에 삽니다. `guest.ttl_hours`로 지우면 **타기 전에 예약 조회·취소·환불이 안 됩니다**
- `guest_expires_at` = 그 게스트의 마지막 예약 **운행일 + `guest.retention_days`**. 새로 예매할 때마다 뒤로 밉니다
- 지울 때 `name`은 NN이라 마스킹 값으로 덮고, `phone_enc`·`phone_hash`는 NULL, `withdrawn_at`을 채웁니다 (탈퇴와 같은 경로)
- 비고에 `CHECK(member_type = 'GUEST' OR guest_expires_at IS NULL)`

## 덧붙일 것

### 4. 게스트도 `auth_session` 행을 만들어야 합니다

`session_id`는 CCTV 녹화 단위이고 행동 로그의 연결 키입니다. 세션이 없거나 UUID가 아니면 **행동 로그가 통째로 빠집니다.**
11-20에 개발 모드 세션이 `"dev-session"`이라 적재기가 전부 건너뛴 일이 실제로 있었습니다 (`eef5877`).

- 그대로 두면 게스트 경로가 **녹화·봇 탐지의 사각지대**가 되고, 봇이 그쪽으로 몰립니다
- 관리자 정지(`ban`)는 `auth_session`을 폐기해 쫓아내는데, 행이 없으면 게스트는 쫓아낼 수 없습니다
- 스키마 변경은 없습니다 (`refresh_token_hash`가 NN이라 짧은 리프레시도 같이 발급하는 쪽이 가장 단순합니다). 앱 쪽 설명만 "세션 행을 만들지 않음" → "짧은 세션 행을 만듦"으로 바꾸면 됩니다

### 5. 같은 CI의 게스트는 행 하나를 다시 쓰기

- 위험 점수는 같은 CI에 달린 회원 행 수(`LINKED_ACCOUNTS`)와 가장 오래된 계정의 나이(`NEW_ACCOUNT`)를 봅니다 (`RiskInputReader.accounts`)
- 비회원 예매마다 행을 새로 만들면, 정직하게 다시 온 사람이 **다계정처럼 보여 오탐**이 납니다
- 그래서 본인인증 결과 그 CI의 `GUEST` 행이 있으면 그 행을 씁니다 (`ix_member_ci_hash`가 이미 있음)
- 반대로 게스트가 나중에 같은 CI로 가입하면 **그 행을 회원으로 바꾸는 것**(이메일 설정, `member_credential` 추가, `member_type = MEMBER`)이 이력을 지킵니다

### 6. `guest.hold_minutes`는 이유가 있으면 알려 주세요

- 좌석 선점 마감은 `reservation.pay_deadline_at` 하나가 원천이고, `seat_inventory.hold_expires_at`·Redis TTL·saga·취소표 마감이 이 값을 복사합니다 (CLAUDE.md "마감 시각")
- 게스트만 다른 길이로 하면 이 다섯 곳이 회원 종류를 알아야 합니다
- 본인인증은 대기열 전에 끝나니 선점 시간이 따로 필요한 이유가 안 보입니다. 이유가 없으면 빼고 `guest.enabled`·`guest.retention_days` 둘만 두겠습니다

## 정리: v33 패치 초안 (범위 결정 뒤 반영)

> 문서의 `V9_OPS`는 옛 번호입니다. 지금 ERD는 v32라 다음은 **v33**입니다.

| 표 | 변경 | op |
|---|---|---|
| `member` | `member_type VARCHAR2(10)` NN, `MEMBER / GUEST` (CHECK 자동) | `add` + `nn` |
| `member` | `guest_expires_at TIMESTAMP` (NULL), 비고에 CHECK | `add` + `notes+` |
| `app_policy` | `guest.enabled` (N), `guest.retention_days` (예시값) | `samples+` |
| `redis_keys` | `rate:guest_lookup:{ipHash}` | `samples+` |
| 기존 DB | `db/patch/v33.sql`: `ALTER TABLE member ADD member_type DEFAULT 'MEMBER' NOT NULL` + CHECK, `guest_expires_at` | |

`reservation`·`auth_session`·`status` 허용값은 **바꾸지 않습니다.**

## 다른 분께

- **길동현 님**: 범위 결정. 기능설계서 2장 역할 표("비회원: 열차 조회만")와 AUTH 기능 목록을 같이 고쳐야 합니다
- **강다인 님**: 게스트에게 `NEW_ACCOUNT`(신규 계정 기본 점수)를 그대로 줄지. 게스트는 늘 "새 계정"이라, 같은 규칙이면 비회원이 대기열에서 조금씩 밀립니다. 의도한 것이면 그대로 두면 됩니다
