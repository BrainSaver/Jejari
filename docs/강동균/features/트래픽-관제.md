## 한 줄 요약

서비스 전체에 **지금 얼마나 몰리고, 어디가 느리거나 깨지고, 데이터를 흘리는지**를 관리자 화면 하나로 본다 (관리자 메뉴 운영 → 트래픽 관제).

## 어떻게 동작하나

```
앱 (Micrometer 지표) → Prometheus (5초마다 수집) → 서버 TrafficService가 고정 쿼리로 읽음 → 화면 (흐름도 2초 · 나머지 10초)
```

- **실시간 흐름도**: 요청을 동그란 점으로, 사용자 → 업무 영역 6개 → 앱 → Redis·Oracle·MongoDB·Kafka로 흘린다. 점 수 = 실제 초당 값 (점 1개 = N건). 파랑 정상 · 빨강 5xx · 노랑 429 · 회색 4xx
- **상태 띠**: 정상·주의·위험 + 이유 (5xx 1%↑, p95 1초↑, DB 풀 80%↑ …). "지금" 값은 최근 30초
- **데이터 놓침·밀림**: 행동 로그 수집·적재·버림·형식 오류, Kafka 소비 그룹 밀림, outbox 미발행, 격리 보관함(DLQ) 건수
- KPI·자원 막대(로그인 대기실 포함)·그래프 7개·많이 불린 API

## 왜 이렇게 했나

- Grafana는 서버 안에서만 열려 있어 관리자 로그인만으로 볼 화면이 필요했다. 화면에서 PromQL을 받지 않고 서버에 쿼리를 고정 → 관리자 화면이 아무 쿼리나 보내는 통로가 되지 않음
- 실제 앱 + k6 + 장애 주입(Redis·Kafka·MongoDB 정지)으로 숫자가 맞는지 확인하며 고쳤다 (트러블슈팅 2건: 흐름도 이름표 멈춤, 회복 뒤 위험이 1분 남음)

## 주의할 점

- Prometheus가 꺼져 있으면 "확인 불가"만 뜨고 앱 나머지는 영향 없음
- 이 화면 자신의 폴링과 actuator는 요청 수에서 뺀다
- Kafka 소비 밀림·outbox는 `PipelineMetrics`가 15초마다 잰다 (테스트에서는 꺼짐)
