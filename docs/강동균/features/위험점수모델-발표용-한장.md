# 위험 점수 모델 — 발표용 한 장

## 한 문장

"규칙이 놓친 처음 보는 봇을 잡으려고 모델을 붙였고, 모델 하나가 함정 사람을 서로 맞바꾸는 문제를 **검사 + 변호인** 구조로 풀었습니다.
같은 시험 2만 명에서 사람 오탐 6.3 → **3.8%**, 봇 탐지 92.6 → **98.4%**. 점수는 자동 차단이 아니라 관리자에게 보여 주는 **보조 의견**입니다."

## 구조

```
행동 로그 (조회·대기열·선점·결제 시각, 기기·카드 연결)
      │  계정마다 특징 40칸 — 속도·간격, 단계 시간, 운행마다 따로 본 속도, 연결 계정, 한 번에 잡은 좌석
      ▼
 ┌──────────── 검사 3명 (주 판정) ────────────┐
 │ 부스팅        "학습한 봇과 닮았나"            │
 │ Isolation Forest "사람들과 동떨어졌나"        │   → 사람 기준 백분위 중 가장 높은 값 = 봇 의심 점수
 │ GRU × 5       "행동 순서가 봇 같나"           │
 └──────────────────────────────────────┘
      │ 의심해도
      ▼
 ┌──────────── 변호인 3명 (해명 모델) ─────────┐
 │ 취소 그룹      → "사자마자 마음 바꾼 사람"      │   그 그룹 안의 사람 vs 봇만 배운 작은 모델.
 │ 대량 구매 그룹  → "가족 몫까지 산 사람"         │   확신하면 점수 50으로 (풀어 줌)
 │ 기기 공유 그룹  → "기기 하나를 시간 나눠 쓰는 가족" │
 └──────────────────────────────────────┘
   안전장치: 그룹 봇은 2%까지만 풀리게 문턱을 정함 · 카드 공유는 누구도 못 풂 · 몇 초 차로 도는 기기 공유도 못 풂
      ▼
 문턱 96.2점 (사람 오탐 5% 지점) → 관리자 케이스 화면 "모델 보조 의견" (점수 + 근거 3개 + 닮은 봇 유형)
 ※ 대기열 순번 · 이용 제한 · 케이스 열기에는 쓰지 않음 (그건 규칙 엔진)
```

## 왜 이 구조인가 (발표에서 말할 순서)

1. **규칙만으로는 출제자가 푼 시험** — 우리가 만든 봇은 100% 잡았지만 규칙을 모르는 사람이 만든 봇은 1차 대회에서 0/12
2. **모델 하나는 함정을 맞바꾼다** — 오픈 직후 사는 사람 오탐을 31 → 5%로 고쳤더니 사자마자 취소하는 사람이 7 → 24%로 나빠짐(4차)
3. **약한 그룹만 따로 보는 변호인** — 사자마자 취소 24 → 0%, 기기 공유 가족 28 → 8%
4. **문을 열면 그 문을 노리는 봇을 같이 만든다** — 기기 공유 예외를 노리는 봇을 넣어 96% 잡는지 확인, 첫 선점만 보던 구멍도 이 과정에서 찾아 막음
5. **비교는 같은 데이터 여러 세트로** — 한 세트에서 1명 = 1~3%p라, 같은 모델도 세트만 바꾸면 33 ↔ 28%. 5세트 2만 명으로 최종 선택

## 한계 (먼저 말할 것)

- **가족 몫 대량 구매는 약 22%가 봇처럼 보인다** — 조회 없이 한 번에 4석을 사는 행동은 기록상 봇과 같다. 모델을 바꿔도 못 푼다 → 자동 차단이 아니라 **관리자 검토**로 보내는 이유
- **학습은 생성 데이터** — 실제 사람 행동 모양(대회 데이터)으로 둘레를 맞췄지만, 실제 표본은 봇 36·사람 33계정뿐. "0/33"은 "문제없음"이 아니라 "이 표본에서는 안 걸림"(95% 구간 약 0~10%)
- **사람과 아주 비슷한 봇은 일부 놓친다** — 사람 흉내 봇 약 87%, 천천히 사는 봇 약 91%
- **다음 단계는 실제 정답** — 관리자가 케이스를 "봇 맞음/아님"으로 처리한 기록이 쌓이면 그걸로 다시 학습 (지금은 생성 데이터로 더 맞추면 생성기에 과적합)
