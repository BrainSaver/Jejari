# 로그인 대기실 (로그인 폭주 대비)

작성자: 강동균 · 코드 위치: `src/main/java/com/jejari/member/login/LoginGate.java` · 화면 `frontend/src/user/Login.jsx`

## 한 줄 요약

로그인이 한꺼번에 몰려도 **대기열·좌석 조회 같은 다른 API가 멈추지 않게**, 로그인을 따로 줄 세워 처리한다.

## 어떻게 동작하나

```
POST /login → 대기실 줄에 넣고 요청 스레드는 바로 반납 → 전용 일꾼 4명(= 해시 자리)이 차례로 비밀번호 확인
            → 줄(200칸)이 가득 차거나 8초 넘게 기다리면 429 AUTH_LOGIN_BUSY + Retry-After(예상 대기 초)
            → 로그인 화면이 "N초 뒤 자동으로 다시 시도해요" 카운트다운 후 자동 재전송
```

## 왜 이렇게 했나

- 비밀번호 확인(Argon2id)은 일부러 느리고 서버는 동시에 4개만 계산한다. 예전에는 자리를 기다리는 로그인이 **Tomcat 요청 스레드를 3초씩 쥐고** 있어, 200명만 동시에 로그인해도 스레드 200개가 다 차서 대기열 폴링까지 멈췄다
- 해시 4개 · 전원 동시 로그인 실측: 200명에서 무너지던 것(초당 10건, 5xx 24%) → **800명까지 버팀** (초당 740건, 로그인 뺀 p95 322ms, 5xx 0%)
- 자리를 줄이거나 바로 503을 주는 방법은 오히려 나빠지거나 사용자가 계속 다시 눌러야 해서 버림

## 주의할 점

- 몰리면 로그인 자체는 늦어진다 (200명 평균 6.5초, 800명 39초). 실패하지 않을 뿐 → **오픈 전 미리 로그인**(로그인 유지) 안내가 가장 싼 대비
- 관리자 로그인·가입은 지나가지 않는다
- 컨트롤러가 `CompletableFuture`를 돌려준다 (서블릿 비동기). MockMvc 테스트는 `asyncDispatch`로 결과를 받아야 함
- 지표 `jejari_login_queue_size`·`jejari_login_busy_total` → A-10 "로그인 대기실"
- 트러블슈팅: [로그인 폭주에 서비스 전체가 멈춤](../troubleshooting/20261120-로그인-폭주에-서비스-전체가-멈춤.md)
