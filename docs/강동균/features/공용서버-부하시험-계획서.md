# 공용 서버 부하 시험 계획서 (k6)

> 작성: 강동균 · 2026-11-25 · 함께: 조영준(서버) · 발표 2026-12-05
> 관련: 외부 평가 ① "규모를 증명하지 못함 — 숫자가 모두 localhost 한 대", 기획서 성과 목표 "TPS·응답 시간 개선 전후"
> 도구: `loadtest/tools/server_perf.sh`(시나리오 11) · `loadtest/scenarios/13_capacity.js`(용량) · `loadtest/tools/check_booking.sh`(정합성)

## 1. 왜 하나

지금 발표에 쓰는 "400명까지 버팀", "300명 몰림 300/300"은 **전부 강동균 PC(4코어, localhost)**에서 잰 값입니다.
공용 서버에서는 11-19에 조영준 님이 **200명 한 번**(앱 1대 vs 2대)만 쟀습니다. 개선(커넥션 풀 20, 로그인 대기실, outbox 유휴 감소,
행동 로그 조회) 뒤의 값과, 이 서버가 몇 명까지 버티는지는 아직 없습니다.

## 2. 무엇을 보여 줄 수 있고, 무엇은 못 하나

| 보여 줄 수 있는 것 | 못 하는 것 (발표에서 먼저 말할 것) |
|---|---|
| 같은 조건(200명/20초)의 **개선 전후** | 명절 실제 규모(수만 명) — 서버가 **vCPU 4개 VM 한 대**(앱·Oracle·Redis·Kafka·Mongo 함께) |
| **이 서버가 버티는 동시 사용자 수**와 그때의 초당 요청·p95 | 여러 지역·여러 IP에서 오는 부하 — k6는 **PC 한 대(IP 하나)** |
| 한계를 넘겨도 **무너지지 않고(5xx ≈ 0) 틀리지 않음(정합성 FAIL 0)** | 앱 2대의 수평 확장 효과 — 같은 CPU 4개를 나눠 써서 11-19에 오히려 느렸음 |

**발표 문장 목표**: "CPU 4개 서버 한 대에서 동시 N명까지 p95 X초로 버티고, 그 위로 몰려도 대기열·로그인 대기실이 받아 서버 오류 0%,
잘못 팔린 표 0건입니다. 같은 조건에서 개선 전 예매 p95 4.9초 → 개선 후 Y초입니다."

## 3. 시험 세 가지

| # | 이름 | 도구·설정 | 보는 것 | 합격 |
|---|---|---|---|---|
| A | **개선 전후** | `server_perf.sh run` (시나리오 11), **200명이 20초 안에**, 한 명이 예매 한 번 (로그인 → 조회 → 대기열 → 배치도 → 선점 → 결제). **2번** (운행을 바꿔) | 예매 전체·로그인·선점·결제·배치도 p95, 성공 수, DB 커넥션 대기, VM CPU | 측정값 기록 (기준 비교: 11-19 1대·해시 4 = 예매 p95 4.9초, 선점 0.55초) |
| B | **용량** | `13_capacity.js`, 단계 **50 → 100 → 200 → 400 → 800명**, 단계마다 90초, 로그인 흩뜨림 30초, 선점 없음(조회·대기열·배치도 반복) | 단계별 초당 요청·p95·5xx·대기열 입장 시간 → **"버틴 최대 단계"** | 버틴 단계 = p95 < 1초 **그리고** 5xx < 1% (스크립트 기본) |
| C | **한계 넘김 + 정합성** | B의 위 단계 그대로 관찰 + 끝난 뒤 `check_booking.sh` | 한계 위에서 5xx가 폭증하는지, 로그인 대기실·대기열이 받는지 / 돈·좌석·이벤트·알림이 맞는지 | 5xx 급증 없음, **정합성 10항목 FAIL 0** |

- B의 안전장치: 어느 단계든 5xx가 20%를 넘거나 p95가 5초를 넘으면 20초 지켜본 뒤 **자동으로 멈춤**. 멈춘 단계 바로 아래가 한계
- B는 선점을 하지 않으므로 좌석을 쓰지 않음 (같은 계정이 잡고 취소를 반복하면 매수 제한·취소 남용 규칙에 걸려 결과가 흐려짐)
- C의 정합성은 **A에서 실제로 결제한 운행**과 **최근 1시간 전체**를 둘 다 봄

## 4. 역할

| 사람 | 하는 일 |
|---|---|
| 강동균 (k6 PC) | 계정 준비, 빈 운행 고르기, A·B 실행, 결과 표 |
| 조영준 (서버) | 시험 시간 확보·공지, 자동 배포 끄기, `vmstat` 기록, Grafana 값 읽기, 정합성 점검, 되돌리기 확인 |
| 팀 채널 | 시험 시간 동안 공용 서버를 쓰지 않음 (시작·끝 공지) |

## 5. 준비 (시험 전날까지)

- [x] 결과 표 칸을 미리 만든 결과 문서 → [공용서버-부하시험-결과](공용서버-부하시험-결과.md)

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| 공용 서버가 멈춤 | B 안전장치(5xx 20%·p95 5초면 멈춤) + 멈추는 기준. 서버 재시작 절차는 조영준 님 (`deploy/README.md`) |

| k6 PC가 먼저 막힘 (회선·CPU) | k6 요약의 `dropped_iterations`·PC CPU를 같이 봄. 막히면 그 단계는 "PC 한계"로 표시하고 서버 한계로 쓰지 않음 |
| 시험 중 배포가 끼어듦 | 자동 배포 끔, 수동 배포 금지 공지 |
| CI 잠김 | 이 시험과 무관 (k6는 PC에서 서버로 직접) |
