# RSV-03 만료 스캐너 · RSV-05 결제 전 취소

작성자: 강동균 · 코드 `com.jejari.seat` (`HoldExpiryScanner`, `SeatReleaseService`, `SeatReleaseTx`) · 절차 원천 `docs/concurrency.md` §6.1·§7

## 한 줄 요약

결제 기한이 지난 좌석은 스캐너가 자동으로 돌려주고, 결제 전에는 사용자가 수수료 없이 취소할 수 있다. 두 경우, 그리고 결제 실패까지 **좌석 해제는 한 곳**(`SeatReleaseService`)을 지난다.

## 어떻게 동작하나

```
[RSV-03] 5초마다: 기한 지난 HOLD 최대 500건 조회 (ix_resv_hold_due와 같은 CASE 식)
           → 건마다 별도 트랜잭션으로 해제 (HOLD → EXPIRED)
[RSV-05] POST /api/v1/reservations/{id}/cancel → 해제 (HOLD → CANCELED)
[PAY-03] 결제 실패: Saga가 자기 트랜잭션 안에서 releaseInCurrentTx(R, PAY_FAILED) (PAYMENT_PENDING → EXPIRED)

해제 = DB 트랜잭션 (§7.1):  예약 상태 조건부 UPDATE → HOLD 행 삭제 → 카운터 감소 → Saga 보상 완료 → 이력 → outbox
       커밋 후 (§7.2):      좌석 키 → REOFFER:R (대기자 먼저, 60초) · 한도 감소 (예약당 한 번)
```

| 이유 | 상태 | 이벤트 | 좌석 키 |
|---|---|---|---|
| 기한 초과 TIMEOUT | HOLD → EXPIRED | `RESERVATION_EXPIRED` | 이미 TTL로 사라짐 → 모두에게 바로 열림 |
| 결제 전 취소 USER_BEFORE_PAY | HOLD → CANCELED | `RESERVATION_CANCELED` | `REOFFER:R` 60초 → 대기자에게 먼저 |
| 결제 실패 PAY_FAILED | PAYMENT_PENDING → EXPIRED | `RESERVATION_EXPIRED` | `REOFFER:R` |

## 왜 이렇게 했나

- **첫 문장이 조건부 UPDATE** (`WHERE status = 'HOLD'`): 1행일 때만 이어서 하므로, 취소와 만료가 동시에 와도, 앱 여러 대의 스캐너가 같은 예약을 잡아도 **한 번만** 처리되고 카운터도 한 번만 줄어든다 (T10). 락을 따로 걸 필요가 없다.
- **스캐너는 결제 확인과 쿼리를 나눔**: PG 결과를 모르는 결제가 쌓여도 HOLD 만료가 밀리지 않게 (§6, T27). 결제 확인 스캐너는 C 길동현 몫.
- **Saga용 메서드는 "호출한 트랜잭션 안에서"**: 결제 실패 기록과 좌석 해제가 같이 커밋되거나 같이 롤백돼야 한다. Redis 보상은 `afterCommit`에 걸어서 롤백되면 아무것도 안 한다.
- **주기·건수·보류 시간은 app_policy**에서 (`scanner.hold_interval_sec`, `scanner.batch_size`, `waitlist.reoffer_hold_sec`). 바꾸면 재기동 없이 반영.

## 주의할 점

- 확정 예약 취소(CNL-02)는 강다인 파트. 같은 `/cancel` 경로를 쓰기로 돼 있어서, 지금은 CONFIRMED면 409 `RESERVATION_NOT_HOLD`. 그쪽 서비스가 생기면 컨트롤러에서 상태별로 나눠 부르면 된다.
- 커밋 후 Redis 보상이 앱 종료로 유실되면 `seat-release` 소비자(보장 경로)가 같은 이벤트로 다시 해야 한다 — 소비자는 아직 없음 (C·D).
- 스캐너를 끄려면 `jejari.seat.expiry-scanner-enabled=false` (통합 테스트에서 직접 호출할 때).

## 테스트 (`SeatReleaseInfraTest`, 10개)

| 확인 | 결과 |
|---|---|
| 기한 지난 HOLD 만료 | EXPIRED, 좌석 행 0, 카운터 0, 이력·Saga·outbox(TIMEOUT), Redis 한도 0, 다른 사람이 바로 선점 가능 |
| 기한 초과 반환율 | 20건 중 20건 (좌석 행·카운터 전부 반환) |

| 결제 전 취소 | CANCELED, cancellation 없음, 좌석 키 `REOFFER:R`, 일반 사용자 선점 거절 (T30 앞부분) |
| 취소 두 번 / 남의 예약 / 결제 중 | 같은 결과 / 404 / 409 `PAYMENT_IN_PROGRESS` |
| T10 취소·만료 동시 | 한쪽만 처리, 카운터 한 번 감소 |
| 결제 실패 해제 | 같은 트랜잭션에서 EXPIRED, 두 번째 호출은 false, 롤백되면 DB·Redis 그대로 |
