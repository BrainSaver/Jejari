## 1. 결과 — 1차와 비교

| | 1차 (c1119, 11-19) | **2차 (c1124d, 11-24)** |
|---|---|---|
| botb (브라우저 봇) | 규칙 케이스 0 | **6/6 케이스** — HEADLESS_HOLD · LINEAR_MOUSE, 매수 제한, 순번 75초 |
| botc | 규칙 케이스 0 | 0/6 (순번 15초만) |
| 사람 | 참가 0명 (결제에서 막힘) | **27계정, 30건 모두 결제 · 규칙 오탐 0** (최고 45점, 케이스 없음) |
| 모델 (tools/ml) | botb 6/6 | 봇 12/12, **사람 오탐 14.8% (4/27)** → 기준(5%) 초과, 판정 보류 |

- **규칙 보강이 효과가 있었다**: 1차 0/12 → 2차 botb 6/6, 사람 오탐 0
- 읽을 때 주의: LINEAR_MOUSE 기준값은 botb를 보고 정해서(11-23) botb가 그 규칙에 걸린 것은 처음 보는 시험이 아님. HEADLESS_HOLD(녹화를 꾸민 선점 포함, `fa0b3ac`)는 연습 봇으로 만든 규칙
- **botc는 규칙으로 못 잡음** — 모델(tools/ml)은 botc 6/6을 잡음. 규칙과 모델이 서로 다른 봇을 잡는다
- 모델은 사람 4명을 봇으로 봐서 아직 보조 의견으로만

## 2. 진짜 사람으로 잰 기준값 (2차 뒤 보기로 한 것)

행동 로그에서 "응답을 받은 뒤부터 다음 요청까지" (INHUMAN_STEP이 재는 방식과 같게, `elapsed_ms` 반영)

| 역할 | 좌석표 → 선점 (최소 / 중앙) | 선점 → 결제 (최소 / 중앙) |
|---|---|---|
| 1 최대한 빨리 | 3.28 / 3.46초 | 3.32 / 5.54초 |
| 2 선점 버튼 두 번 | 3.11 / 7.54초 | 6.52 / 9.82초 |
| 3 한 컴퓨터로 가족 3명 | 5.65 / 8.39초 | 2.74 / 6.23초 |
| 4 휴대폰 | 2.81 / 3.22초 | 3.34 / 8.96초 |
| 5 천천히 | 3.15 / 4.81초 | 8.27 / 12.54초 |

- **진짜 사람 중 가장 빠른 단계 2.74초** (62번 중 0.5초 미만 0번). "최대한 빨리" 역할도 3초대
- → **INHUMAN_STEP 0.5초는 여유가 5배 넘게 있다.** 1.0~1.5초로 올리면 2단계 연습 봇(단계 사이 0.6~1초)도 잡힘. 다만 5명이라 한 번에 크게 올리지 말고 **1.0초**부터 (`risk.rule.inhuman_step_ms`)

**역할 3 (한 컴퓨터로 가족 3명): 계정을 바꾼 간격 31.7 · 61.4 · 89.6 · 100.4 · 429.4초**

- 가장 빠른 전환도 **31.7초** (로그아웃 → 다시 로그인 → 검색). 지금 기준 3초와 거리가 멂
- → **`risk.rule.account_switch_sec`을 15초로** 올려도 가족은 안 걸리고, 계정마다 3~14초 쉬는 다계정 봇은 다시 잡힘 (11-24 가상 데이터 15초 실험: 다계정 3/3, 정상 오탐 0)
- 역할 2(두 번 클릭)도 오탐 없음 — 강다인 님 수정(같은 좌석 두 번째 선점 빼기)이 진짜 손에서도 맞음
