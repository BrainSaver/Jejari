| 역할 | 좌석표 → 선점 (최소 / 중앙) | 선점 → 결제 (최소 / 중앙) |
|---|---|---|
| 1 최대한 빨리 | 3.28 / 3.46초 | 3.32 / 5.54초 |
| 2 선점 버튼 두 번 | 3.11 / 7.54초 | 6.52 / 9.82초 |
| 3 한 컴퓨터로 가족 3명 | 5.65 / 8.39초 | 2.74 / 6.23초 |
| 4 휴대폰 | 2.81 / 3.22초 | 3.34 / 8.96초 |
| 5 천천히 | 3.15 / 4.81초 | 8.27 / 12.54초 |

- **진짜 사람 중 가장 빠른 단계 2.74초** (62번 중 0.5초 미만 0번). "최대한 빨리" 역할도 3초대
- → **INHUMAN_STEP 0.5초는 여유가 5배 넘게 있다.** 1.0~1.5초로 올리면 2단계 연습 봇(단계 사이 0.6~1초)도 잡힘. 다만 5명이라 한 번에 크게 올리지 말고 **1.0초**부터 (`risk.rule.inhuman_step_ms`)

**역할 3 (한 컴퓨터로 가족 3명): 계정을 바꾼 간격 31.7 · 61.4 · 89.6 · 100.4 · 429.4초**

- → **`risk.rule.account_switch_sec`을 15초로** 올려도 가족은 안 걸리고, 계정마다 3~14초 쉬는 다계정 봇은 다시 잡힘 (11-24 가상 데이터 15초 실험: 다계정 3/3, 정상 오탐 0)
- 역할 2(두 번 클릭)도 오탐 없음 — 강다인 님 수정(같은 좌석 두 번째 선점 빼기)이 진짜 손에서도 맞음

## 4. botc는 규칙을 어떻게 피했나 (2차가 끝나 코드·로그를 봄)

botc = **진짜 브라우저(Playwright) + 사람처럼 느리게 + 필요한 것만** 하는 봇. 수법과 2차 로그를 맞춰 보면:

| 규칙 | botc가 피한 방법 | 2차 로그 (botc / 사람) |
|---|---|---|
| HEADLESS_HOLD (화면 없이 선점) | 진짜 브라우저라 녹화가 그대로 남음 | — |
| LINEAR_MOUSE (기계적 마우스) | 중간점 두 개를 지나는 **베지어 곡선 + 가속 → 감속**, 누르기 전 0.06~0.22초 멈춤 | — |
| INHUMAN_STEP (사람 손으로 불가능한 속도) | 생각 시간을 지수분포로 0.3~8초 | 좌석표 → 선점 **14초**, 선점 → 결제 **8초** (사람 최소 2.7초보다 느림) |
| FAST_CLICK · SAME_SEAT_RETRY | 요청을 **딱 한 번씩**만 (조회·선점·결제 각 1번) | 선점 시도 1번 (botb는 5~10번) |
| 매수 제한 | 명의 6 × 4석 = 24석, 한도 바닥에 맞춤 | 제한 거절 **0** (botb 24) |
| MULTI_ACCOUNT_SYNC (다계정 동시) | 6계정이 **10분에 걸쳐** 따로 들어옴, 계정마다 다른 브라우저(기기) | 기기 공유 없음 |

**남은 흔적 하나: 조회 없이 대기열로 바로 (NO_SEARCH_ENTRY)**

- botc는 검색 화면을 연 뒤 대기열 주소로 바로 감 → **6계정 모두 첫 행동이 대기열 진입** (열차 조회 0번)
- **사람 27계정은 전부 첫 행동이 열차 조회** (0/27)
- 그런데 이 규칙은 점수만 10점(LOW)이라, 신규 계정 5점과 합쳐 **15점에서 멈춤** (케이스 문턱 80) → 순번 15초만 밀림
- 모델(tools/ml)이 botc 6/6을 잡은 것도 아마 이것(조회 없음·이벤트 수가 적음) 때문

**막는 방법 (제안)**

1. **NO_SEARCH_ENTRY 점수를 올리기** (`risk.rule.no_search_entry_points` 10 → 30~40, 관리자 화면 정책) — 2차에서 사람 0/27이라 근거가 있음. 다만 실제 서비스엔 링크·취소표 "예매하기"로 조회 없이 줄 서는 정상 경로가 있어(11-23 사람 변형 humanlink) **케이스로 바로 올리지는 않음**
2. **조회 없이 진입 + 다른 약한 신호가 겹칠 때만 케이스**: 같은 IP에서 짧은 시간에 여러 명의가 조회 없이 진입 (botc는 6명의가 한 IP에서). 하나씩은 약하지만 겹치면 강함
3. **화면 쪽에서 막기**: 대기열 진입 API가 "검색 결과에서 왔다"는 표시(검색 응답에 담은 짧은 토큰)를 요구 → 주소로 바로 가면 줄을 못 섬. 정상 링크 경로(취소표 "예매하기")는 그 화면이 토큰을 같이 줌. 규칙보다 확실하지만 화면·API를 고쳐야 함
4. **녹화 모델**: botc의 마우스는 0.07~0.64초 만에 18~40점을 지나는 **매끈한 곡선(손떨림 없음)**. 2차 녹화를 꺼내 사람과 비교하면 손떨림·이동 시간으로 가를 수 있는지 볼 수 있음

**주의 — 2차 데이터로 판단하면 안 되는 것**

- **같은 IP·같은 기기에 여러 명의**: 2차에서는 사람도 한 사람이 6계정을 한 기기로 만들어 IP·기기마다 명의 5~6개 (대회 진행 방식 때문). 실제 사람의 모습이 아니라 이 신호의 오탐은 2차 데이터로 잴 수 없음
- 사람 한 명과 botb가 같은 카드 번호를 씀 (안내문의 예시 번호를 그대로 쓴 것으로 보임) — 카드 공유 신호도 2차 데이터로는 판단 불가

## 5. 4단계 연습 봇: botc에서 한 걸음 더 (11-24, 태그 `px1124`, 운행 100100, v40 기준값)

진짜 브라우저 봇 4종 × 명의 2 × 2석 (`loadtest/contest/practice/browser.cjs`). **4종 모두 결제, 모두 5점(신규 계정 기본)뿐 — 규칙으로 하나도 못 잡음**

| 봇 | 첫 행동 | 좌석표 → 선점 / 선점 → 결제 | 결과 |
|---|---|---|---|
| botwsearch (검색 거침) | **열차 조회** | 7.6~9.1초 / 7.0~7.7초 | 5점 — "조회 없이 대기열" 흔적이 사라짐 |
| botwtremor (손떨림) | 열차 조회 | 9.5~12.3초 / 6.7~7.9초 | 5점 |
| botwspread (명의마다 IP) | 열차 조회 | 8.7~9.3초 / 7.2~9.6초 | 5점 |
| botwfast (최대한 빨리) | 열차 조회 | **3.8~4.1초 / 1.5~1.6초** | 5점 — 1초 기준 위 |

- **검색 한 번이면 botc의 유일한 흔적이 지워진다.** NO_SEARCH_ENTRY를 30점으로 올린 것(v40)은 botc 같은 "주소로 바로 가는" 봇에만 듣는다
- **진짜 마우스로 누르면 1.5초 아래로 내려가기 어렵다**: 좌석 2개 + 잡기 버튼을 손처럼 움직여 누르면 이동만 1초가 넘는다. 사람 최소 2.74초와 봇 최소 1.5초 사이가 좁아, INHUMAN_STEP을 더 올리면(예: 2초) botwfast의 선점 → 결제는 잡히지만 사람 여유가 0.7초뿐이라 권하지 않음

**녹화 모델에 중요한 발견 — 평소 녹화(SAMPLED)로는 손 모양이 안 보인다**

| 봇 | 곧음 (현/호) | 손떨림 | 이동당 점 수 |
|---|---|---|---|
| botwsearch (매끈한 곡선) | 0.99 | 0.05 | 5.3 |
| botwtremor (떨림 1~3px) | 0.99 | 0.04 | 4.0 |

- 녹화기는 평소(SAMPLED) **0.15초마다** 마우스 위치를 찍어 이동 하나에 점이 4~5개뿐 → 곡선도 직선처럼, 떨림도 안 보임. 매끈한 봇과 떨리는 봇이 **같아 보인다**
- 촘촘한 녹화(FULL, 0.05초)는 세션의 10%(`replay.full_record_ratio`)와 점수 70점 이상(`replay.full_record_score`)만인데, 이런 봇은 5점이라 **대부분 SAMPLED로 녹화됨**
- → 녹화 모델이 손 모양을 보려면 **판매 오픈 몰림 시간에는 FULL 비율을 올리거나**(저장량 증가), 평소 녹화의 마우스 간격을 0.15초 → 0.05초로 (점이 3배, 묶음당 점 수 상한도 같이). 2차 사람 녹화로 학습하기 **전에** 정할 것 — 지금 사람 녹화도 대부분 SAMPLED일 것
- 손 모양 말고 녹화에서 볼 수 있는 것: 클릭 수·화면 이동 순서·머문 시간(PAGE_VIEW 간격)·스크롤 — 이건 SAMPLED에도 다 있음

**정리**: botc 계열(사람 속도 + 진짜 브라우저 + 검색 거침)은 행동 규칙의 한계다. 피해는 명의당 4매·대기열 한 자리·순번 패널티라는 **구조**가 묶는다. 남은 수단은 ① FULL 녹화로 손 모양 보기 ② 명의를 늘리기 어렵게(카드 한 장의 명의 수 상한 v37, 기본 꺼짐)
