# 결제·확정 취소가 부르는 좌석 단계

작성자: 강동균 · 코드 `com.jejari.seat` (`SeatPaymentService`, `SeatReleaseService.returnSoldSeatsInCurrentTx`) · 절차 원천 `docs/concurrency.md` §4·§5.1·§8

> 흐름 재생(애니메이션)과 표로 보는 안내: [좌석-결제취소-연결.html](좌석-결제취소-연결.html)

## 한 줄 요약

결제(PAY-01·02, 길동현)와 확정 취소(CNL-02, 강다인)가 **자기 트랜잭션 안에서 한 줄씩** 부르면 좌석 재고와 Redis 좌석 키가 맞춰진다.

## 나눠 맡는 기준

| 누가 | 무엇을 바꾸나 |
|---|---|
| 결제·취소 쪽 | reservation 상태, payment, cancellation, saga, 이력, outbox |
| 좌석 쪽 (이 문서) | `seat_inventory`, `purchase_counter`, Redis `seat:hold:*`·`limit:*` |

부르기 전에 그 예약의 reservation 행 락을 먼저 잡습니다 (reservation UPDATE 또는 `SELECT … FOR UPDATE`, §0.4-1).

## 어떻게 부르나

```
§4 결제 시작 (길동현)
  UPDATE reservation HOLD → PAYMENT_PENDING, pay_deadline_at = GREATEST(…) RETURNING :d
  if (!seatPay.extendHoldInCurrentTx(R, d)) → 롤백, 결제 시작 거절   ← 좌석 마감 = :d
  saga PAYING · payment REQUESTED · 이력 · outbox → COMMIT          → 커밋 뒤 Redis 키도 :d로 연장

§5.1 승인 (길동현)
  SELECT … FROM reservation WHERE reservation_id = R FOR UPDATE
  if (!seatPay.confirmSeatsInCurrentTx(R)) → 롤백, "확정 실패" 경로 (별도 트랜잭션: payment APPROVED + 늦은 승인 환불 §7.3)
  payment APPROVED · reservation CONFIRMED · saga DONE · 이력 · outbox → COMMIT   → 커밋 뒤 Redis 키 = SOLD:R (출발까지)

§8 확정 취소 (강다인)
  UPDATE reservation CONFIRMED → CANCELED (1행일 때만 계속)
  ReturnedSeats seats = release.returnSoldSeatsInCurrentTx(R)   ← SOLD 행 삭제 + 카운터 감소
  cancellation INSERT · 이력 · outbox RESERVATION_CANCELED (내용 = seats.eventPayload() + reason·cancelFee·refundAmount) → COMMIT
                                                                → 커밋 뒤 좌석 키 = REOFFER:R (60초 대기자 먼저) · 한도 감소

§5.2 결제 실패 (길동현, 이미 있음)
  payment FAILED 기록과 같은 트랜잭션에서 release.releaseInCurrentTx(R, ReleaseReason.PAY_FAILED)
```

## 왜 이렇게 했나

- **같은 트랜잭션 안에서**: 결제 기록과 좌석 확정이 같이 커밋되거나 같이 롤백돼야 "돈은 냈는데 좌석이 HOLD" 같은 반쪽 상태가 안 생긴다.
- **Redis는 커밋 뒤에만**: 롤백됐는데 Redis만 SOLD가 되면 아무도 그 좌석을 못 산다. 그래서 `afterCommit`에 걸어 둔다.
- **false = 좌석을 잃음**: 영향 행 수가 K(= 매수, 구간 재고 OFF)와 다르면 그 사이 좌석이 풀린 것이다. 예외 대신 boolean을 돌려줘서 결제 쪽이 "거절"(§4)과 "확정 실패 경로"(§5.1)를 직접 고를 수 있게 했다.
- **확정 취소는 좌석 부분만**: 수수료·환불·cancellation은 CNL 쪽 규칙이라 강다인 파트에 둔다. 좌석·카운터·Redis는 해제(§7)와 같은 코드를 써서 한 번만 줄고, 같은 모양의 이벤트 내용을 만든다.

## 주의할 점

- 세 메서드 모두 트랜잭션 밖에서 부르면 `IllegalStateException`.
- `returnSoldSeatsInCurrentTx`는 예약이 이미 CANCELED여야 한다 (순서가 틀리면 `IllegalStateException`). 두 번 부르면 두 번째는 null이고 카운터는 그대로.
- `extendHoldInCurrentTx`는 TTL로 이미 사라진 Redis 키를 되살리지 않는다 (남에게 넘어갔을 수 있음). DB가 최종 판정이라 결제는 계속된다.
- `confirmSeatsInCurrentTx`는 Redis 키가 무엇이든 SOLD:R로 덮어쓴다 (DB가 확정했으므로).
- 커밋 뒤 Redis 작업이 실패해도 예외를 던지지 않는다 (로그만). 해제·취소 쪽은 `seat-release` 소비자(보장 경로, 아직 없음)가 다시 해야 한다.

| 공통 | 트랜잭션 밖 호출 거부 |
