> 정리: 강동균 · 2026-11-17 · 담당: 조영준 씨(E)

## 요약

**구글 클라우드에서 컴퓨터 1대를 빌려서, 그 안에 지금 `compose.yaml`을 그대로 올린다.**

Oracle·MongoDB·Redis·Kafka 전부 그 컴퓨터 안의 **도커 컨테이너**다. 지금 각자 PC에서
`docker compose up -d` 하면 뜨는 그 7개가, 똑같이 구글 컴퓨터 안에서 뜬다.
구글은 **빈 컴퓨터만 빌려주고** DB는 우리가 띄운다 (Cloud SQL에 Oracle이 없다).

- **각자 로컬은 그대로 쓴다.** 서버는 시연·연동 확인용으로 한 벌 더 두는 것이다
- 사양 `e2-standard-4`(4 vCPU/16GB) + 50GB · **월 $138**(서울) · $300 체험 크레딧 안
- Oracle은 **무료**다 (23ai Free, FUTC). 한도는 데이터 12GB · DB RAM 2GB · 2코어

```
구글 데이터센터 ┌─ VM 1대 ─────────────────┐
                │ 컨테이너 7개 + 앱(jar)    │ ──:8080──> 팀원·발표장 브라우저
                └──────────────────────────┘
```

## 방법

```bash
# 1. 프로젝트·결제 연결 + 예산 알림부터
gcloud projects create jejari-demo && gcloud config set project jejari-demo
gcloud services enable compute.googleapis.com

# 2. VM
gcloud compute instances create jejari --zone=asia-northeast3-a \
  --machine-type=e2-standard-4 \
  --image-family=ubuntu-2404-lts-amd64 --image-project=ubuntu-os-cloud \
  --boot-disk-size=50GB --tags=jejari-web

# 3. 방화벽 — 8080만. DB 포트는 열지 않는다
gcloud compute firewall-rules create jejari-web \
  --allow=tcp:8080 --target-tags=jejari-web --source-ranges=0.0.0.0/0

# 4. 서버 준비 (접속 후)
gcloud compute ssh jejari --zone=asia-northeast3-a
sudo apt-get update && sudo apt-get install -y \
  docker.io docker-compose-v2 openjdk-21-jdk-headless git
sudo usermod -aG docker $USER && exit      # 재접속해야 적용된다

# 5. 코드 + 비밀값 (.env는 레포에 없다)
git clone https://github.com/BrainSaver/Jejari.git
gcloud compute scp .env jejari:~/Jejari/.env --zone=asia-northeast3-a   # 내 PC에서
chmod 600 ~/Jejari/.env

# 6. 인프라 — Oracle이 healthy 될 때까지 약 5분
docker compose up -d
until [ "$(docker inspect -f '{{.State.Health.Status}}' jejari-oracle-1)" = healthy ]; do sleep 10; done

# 7. 앱
LC_ALL=C.UTF-8 TZ=Asia/Seoul ./gradlew bootJar
#   systemd 등록 (긴 문서 3-6절). Environment=TZ=Asia/Seoul 필수

# 8. 확인
curl http://<IP>:8080/actuator/health
```

단계별 확인·막혔을 때 표는 긴 문서 8절에 있다.

## 핵심

**틀리면 안 되는 것 다섯 가지.**

1. **`TZ=Asia/Seoul`** — 없으면 앱이 아예 안 뜬다. 기동 점검이 거부한다.
   `journalctl -u jejari | grep "시간대 점검 통과"` 가 떠야 정상
2. **DB 포트를 열지 마라** — `compose.yaml`이 이미 `127.0.0.1`에 묶어 뒀다. 그 바인딩만 안 풀면 된다.
   확인: `nc -zv <IP> 1521` 이 **반드시 실패**해야 한다. 성공하면 Oracle이 인터넷에 노출된 것
3. **SSH 22번이 기본으로 전 세계에 열려 있다** — 기본 VPC의 `default-allow-ssh` 때문이다.
   팀원 IP로 좁히거나 IAP로 바꾼다. **IAP로 갈 땐 권한을 먼저 주고** 기존 규칙을 지운다 (순서 틀리면 아무도 못 들어간다)
4. **시드 날짜가 적재일 기준 상대값이다** — 서버를 5일 넘게 켜 두면 `9001`이 판매 중이 아니게 돼
   **시연이 막힌다.** 시연 전날 Oracle 볼륨을 다시 만든다
5. **`JEJARI_HMAC_KEY`는 팀 공용 값 그대로** — 서버에서 새로 만들면 `ci_hash`가 달라져
   매수 제한·위험 점수가 로컬과 안 맞는다

**팀에 알릴 것**: 로컬 통합 테스트를 이 서버 DB로 돌리면 안 된다. 서버 앱의 스케줄러가
테스트의 HOLD를 먼저 만료시키고 outbox를 가져간다.

**먼저 정할 것**: 리전(서울 $138 / 아이오와 $106) · 결제 계정 · SSH 범위 · 공용 DB 비밀번호 ·
안 쓸 때 끌지 (`gcloud compute instances stop jejari` — 끄면 디스크 값만 나간다)
