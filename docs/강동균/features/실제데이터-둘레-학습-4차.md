# 실제 데이터 둘레 학습 4차 (r6·r7)

## 무엇을 바꿨나
3차(r4)는 총무(h_organizer) 오탐을 36%→3%로 줄였지만, 오픈 직후 바로 사는 사람(h_open_rusher)이 10%→31%, 마음 바꿔 바로 취소하는 사람(h_quick_regret)이 7%→21%로 늘었습니다. 명절 예매에서 "오픈하자마자 사는 것"은 가장 흔한 사람 행동이라 그대로 쓸 수 없습니다.

- **r6**: IF(이상 탐지)에 "전체 양" 대신 **운행당 양**(이벤트·조회·홀드·결제 수 ÷ 운행 수)을 줍니다. 총무는 운행이 많아도 운행당 양은 보통이라 안 걸립니다. 거기에 오픈 직후 사람·바로 취소 사람 학습 예시를 2배로 늘렸습니다.
- **r7**: r4 설정(양 빼기) 그대로에 오픈 직후 사람·바로 취소 사람 2배만 더했습니다. "예시만 늘려도 되는가"를 보는 대조군입니다.

## 기준 충족 여부
- **r6**: 한 가지만 미달 — h_quick_regret 24.1%(기준 ≤10%). 나머지 기준은 모두 충족.
- **r7**: 두 가지 미달 — 실제 c1124c 원본 사람 오탐 2/6, 실제 c1124d 원본 오탐 19/27(참고). h_quick_regret는 6.9%로 충족.

## 해석
- 운행당 양(r6)을 IF에 주면 오픈 직후 사람(31%→5%)과 총무(3%)를 동시에 해결하고 실제 원본 데이터 오탐도 가장 적습니다.
- 예시만 늘린 r7은 합성 수치는 비슷해도 실제 원본 사람 오탐(c1124d 19/27)이 많아 믿기 어렵습니다. 속도만 보는 IF의 한계가 그대로입니다.
- r6의 남은 약점은 "마음 바꾼 뒤 바로 취소하는 사람"입니다(24.1%). h_family_bulk도 18.7%로 r2보다 높아졌습니다.
