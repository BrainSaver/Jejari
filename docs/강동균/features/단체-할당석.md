# 단체 할당석 (좌석 쪽)

작성자: 강동균 · 코드 위치: `seat/GroupQuotaScheduler.java`, `seat/SeatHoldTx.java`, `seat/SeatReleaseTx.java`, `seat/SeatReleaseService.java`, `seat/SeatMapService.java` · 절차: `docs/concurrency.md` §18 · ERD v36

## 한 줄 요약

여행사 단체 예매를 위해 운행마다 일반실 좌석의 5%를 미리 묶어 두고(BLOCKED), 출발 30일 전까지 안 쓰이면 일반 판매로 돌린다. 단체 신청·승인 API는 길동현 님 담당이고, 여기는 좌석 쪽 준비다.

## 어떻게 동작하나

```
판매 오픈 10분 전 ── GroupQuotaScheduler(1분마다) ──> seat_inventory에 BLOCKED 행(예약 없음) + Redis seat:hold = GROUP (반납 시각 TTL)
        │
        ├─ 일반 선점: hold.lua가 GROUP 값에 짐 → 실패. 키가 먼저 사라져도 DB에서 BLOCKED를 보고 거절 (SeatHoldTx)
        ├─ 단체 승인(길동현): BLOCKED → HOLD(단체 예약 R)로 바꿈 → 그 뒤는 일반 예약과 같은 결제·만료·취소
        └─ 출발 30일 전 ── 같은 스케줄러 ──> 남은 BLOCKED 행 삭제 + 값이 GROUP인 키만 삭제 → 일반 판매
```

- **좌석 고르기**: 일반실만, 객차 순서대로, 객차 안에서는 뒤쪽 좌석부터 고른다. 같은 객차 안에서 붙은 좌석이 된다.
- **개수**: 운행 전체 좌석 × `group.quota_rate`(0.05). 명절 행사는 `sale_event.group_quota_rate`가 우선이고, 0이면 만들지 않는다.
- **단체 예약은 개인 매수 카운터를 쓰지 않는다**: 올린 적이 없으므로 만료·결제 전 취소·확정 취소·재선점 때도 줄이지 않는다(§18.5). 줄이면 대표자 개인 한도가 최대 200매만큼 잘못 줄어든다.
- **좌석 배치도**: BLOCKED는 "선택 불가"(HELD)로 보인다.

## 왜 이렇게 했나

- **"예약 없는 행"으로 미리 묶음**: 선점 코드를 단체용으로 따로 고치지 않아도 할당석이 일반 판매에서 빠진다. 이미 있는 PK·Redis 키가 막아 준다. 바꾼 건 BLOCKED를 만료된 HOLD로 착각하지 않게 거절하는 한 줄뿐이다.
- **Redis 키에 반납 시각 TTL**: 스캐너가 늦어도 Redis 쪽은 제때 풀린다. 그 사이의 일반 선점은 DB가 막는다(DB가 최종, §0.1).
- **반납 DELETE는 `status = 'BLOCKED'` 조건**: 단체 승인과 동시에 돌아도 이미 배정된 좌석은 지우지 않는다.

## 주의할 점

- **만들기는 기본으로 꺼져 있다** (`jejari.seat.group-quota.create-enabled`, 환경변수 `JEJARI_GROUP_QUOTA_ENABLED`). 단체 API 없이 켜면 좌석 5%를 아무도 못 사게 된다. 반납은 늘 돈다.
- 이미 ON_SALE인 운행에는 소급해서 만들지 않는다. SCHEDULED 상태에서 오픈 10분 전부터 만든다.
- 할당석이 모자라면 일반 좌석에서 선착순으로 이어 배정한다(§18.3a). 이건 단체 승인 쪽(길동현) 코드다.
- 테스트: `GroupQuotaInfraTest`(G1·G2·G6·G7·G8, 만들기·반납). `./gradlew test -PincludeTags=infra --tests '*GroupQuota*'` 방식으로 Oracle·Redis가 떠 있을 때 돈다.
