# 결제 거절 반복 신호 DECLINED_CARDS (카드 대입)

> 2026-11-27 · 추천안 강동균 · 결정 강다인 (규칙 담당) · 구현 강동균 (강다인 님 부탁) · ERD v41

## 한 줄

명의(CI)가 **최근 1시간에 서로 다른 카드 3장 이상**으로 결제를 거절당하면 위험 점수 **30점**. 점수만 (케이스는 안 엶).

## 왜

훔친 카드 목록을 가진 사람은 "어느 카드가 살아 있나"를 아무 결제로나 시험해 본다 (카드 대입). 지금까지 결제 실패는
위험 신호에서 아예 빠져 있었다 — 취소를 셀 때 "본인 행동이 아닌 실패"를 빼려던 것이 이것까지 가렸다.

## 핵심 원리

| 정한 것 | 이유 |
|---|---|
| **서로 다른 카드**를 센다 (`payment_method.method_hash`) | 같은 카드가 여러 번 거절되는 건 사람이다 (잔액 부족·한도 초과 뒤 재시도). 카드를 바꿔 가며 거절되는 게 대입이다. `method_id`는 회원마다 따로라 해시로 센다 |
| **`PG_`로 시작하는 사유는 뺀다** | `PG_FAILED`·`PG_ERROR`·`PG_TIMEOUT`·`PG_NOT_RECEIVED`는 PG가 아픈 것이다. 그때는 정상 사용자도 실패가 쌓인다 (강다인 님 지적 — 처음 추천안은 `PG_NOT_RECEIVED` 하나만 뺐다) |
| 대상은 **명의(CI)** 만 | 계정을 바꿔 가며 시도해도 명의로 모인다. 카드 쪽(한 카드에 여러 명의)은 카드 명의 상한(`payment.max_ci_per_card`)이 맡는다 |
| 창 **1시간** (고정) | 대입은 짧은 시간에 몰아서 한다. 정책 키는 문턱·점수 2개만 (팀 결정) |
| **3장 → 30점, 점수만** | 사람은 오타·한도로 1~2장. 30점 = 경고 등급이라 단독으로는 결제 단계 차단(80)에 닿지 않고, 다른 신호와 합쳐야 막힌다 → 오탐 비용이 작다 |
| 결제 실패도 재계산을 깨운다 | 재계산은 예약 확정·취소 이벤트에만 반응했다. 결제 실패는 예약 만료(`RESERVATION_EXPIRED`, 사유 `PAY_FAILED`)로 나와서, 그것도 받게 했다 (시간 만료는 그대로 무시) |

우리 결제는 거절되면 좌석이 풀린다 (Saga 보상). 대입하려면 매번 다시 선점해야 해서 선점 속도 제한·매수 한도가 이미 속도를 늦춘다.
이 신호는 첫 관문이 아니라 **그 사이를 뚫은 대입을 점수로 남기는 것**이다.
