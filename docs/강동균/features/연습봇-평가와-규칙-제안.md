## 3-1. 모델(보조 의견)로 채점해 보니 (재학습 없이, 2026-11-23)

같은 데이터를 지금 모델·next·김성원 님 모델로 채점 (`compare_dl.py`, 결과는 로컬 `data/ml/practice-pc1123/compare.md`).

- 이유 (추정): 이 데이터의 계정은 모두 **오늘 만든 새 계정 + 짧고 목적이 분명한 세션**(조회 1~3번 → 줄 서기 → 선점 → 결제)이다. 모델이 배운 생성 데이터의 사람은 더 오래 둘러본다. **명절 판매 오픈의 진짜 사람도 바로 이런 모습**(새로 가입하고 곧장 예매)이라, 오픈 날 실제 사람을 대부분 봇으로 볼 위험이 크다 — 11-19 모델 비교 문서의 "다른 세계로 가면 사람을 대부분 봇으로 본다"와 같은 현상
- 합성 사람은 내가 만든 스크립트라 근거가 약하지만, 위험 쪽으로 읽는 게 맞다: **지금 모델을 순번·제한에 쓰면 안 된다** (지금처럼 보조 의견만)

## 3-2. 2단계 봇: 제안 규칙을 알고 피하면 (2026-11-23, 태그 `pd1123`, 운행 100098)

규칙을 넣으면 매크로도 바뀝니다. 그래서 **3절 제안 규칙을 알고 피하는 봇 9종**(`GEN=2`)을 만들어 돌렸습니다.
제안 규칙은 아직 코드가 아니라서 `simulate_rules.py`로 꺼낸 로그에 적용해 모의 채점했습니다.

| botsearchfast | 조회 한 번 하고 진입 (NO_SEARCH_ENTRY 피함) |

**결과: 9종 모두 좌석을 정상 구매. 지금 규칙 최고 5점·케이스 0, 제안 규칙(모의)도 케이스 0/9.** 합성 사람 케이스 0/12.
점수 규칙 SHARED_IP만 6종에 조금 붙었고, botresi·botghost·botghostsync는 아무것도 안 걸렸습니다.

| 종류 | 좌석표 → 선점 | 선점 → 결제 | 처음 → 결제 (중앙) |
|---|---|---|---|
| 2단계 봇 9종 | 0.67~3.2초 | 0.83~2.84초 | 2.7~10.7초 |
| 합성 사람 | 1.97~5.95초 | 0.86~8.8초 | 12.7초 |

- **단순 문턱 규칙은 한 번 알려지면 쉽게 피해진다.** 0.5초 → 0.6초로 바꾸는 데 코드 한 줄이면 됩니다. 문턱을 1~2초로 올리면 진짜 사람(특히 빠른 사람)이 걸릴 위험이 큽니다
- 그래도 1단계 규칙은 넣을 가치가 있습니다: **피하려면 봇이 느려져야 하고**, 느려지면 매진 전 좌석 경쟁에서 불리합니다 (이 운행은 경쟁이 없어 다 샀지만 오픈 직후에는 다름)
- 위 표에서 2단계 봇이 사람보다 빠른 곳(처음 → 결제)이 보이지만, **합성 사람은 내 스크립트라 이 차이로 규칙을 만들면 안 됩니다.** 진짜 사람 분포는 2차에서 잽니다
- 남은 방어 몫 (단순 문턱이 아닌 신호):
  1. **마우스·터치 궤적** (LINEAR_MOUSE, 아직 없음) — API만 부르는 봇은 궤적 자체가 없음. 화면에서 이벤트를 보내야 해 지금 9종 전부 해당
  2. **점수 높은 계정에만 확인 단계**(CAPTCHA 등) — 오탐 비용을 사람 한 번의 클릭으로 낮춤
  3. **2차 진짜 사람 데이터로 모델 재학습** — "오픈 날 사람"을 배운 뒤 3-1의 AUC를 다시 잼
- 다시 재기: `GEN=2 RUN_ID=<운행> TAG=<태그> node loadtest/contest/practice/run.mjs` → `tools/ml/export_live.sh` → `python3 -I loadtest/contest/practice/simulate_rules.py data/ml/practice-<태그> [--step 0.5 --times 2]`

## 3-3. 새 빌드로 다시 재기 (2026-11-23 오후, 태그 `pe1123`, 운행 100098)

1~3-2절은 **오전 빌드**로 잰 것이라 강다인 님이 오후에 넣은 규칙(HEADLESS_HOLD·NO_SEARCH_ENTRY·LINEAR_MOUSE)이 빠져 있었습니다.
새 빌드로 39종(1단계 30 + 2단계 9) × 명의 3 + 합성 사람 12명을 다시 돌렸습니다. **합성 사람은 이제 화면 녹화(클릭·곡선 궤적)를 보냅니다** —
그래야 "다른 세션 녹화가 하나도 없으면 세지 않음"(녹화 장애 보호)이 풀려 대회와 같은 조건이 됩니다.

| 결과 | 봇 | 최고 점수 |
|---|---|---|
| **케이스 (지금과 같음)** | bothammer · botshareddev · botsniper | 65~100 |
| **HEADLESS_HOLD + NO_SEARCH_ENTRY** | botdirect · botnosearch · botsameci | 45 (순번 45초) |
| **HEADLESS_HOLD** | 나머지 33종 (2단계 9종 전부 포함) | 35 (순번 35초) |
| 합성 사람 12명 | 녹화 있음 → HEADLESS_HOLD 0, LINEAR_MOUSE 0 | 5 (오탐 0) |

- **39종 전부가 HEADLESS_HOLD에 걸렸습니다** (API만 부르는 봇은 녹화가 없음). 2단계에서 0/9였던 봇들도 여기서는 잡힘
- 하지만 HEADLESS_HOLD는 **점수만**(세션 1개 30점, 3개 45점)이고 케이스 문턱이 80이라 **케이스는 여전히 3종**
- → **HEADLESS_HOLD를 케이스(marker)로 바꾸면 39종 전부 케이스, 합성 사람 0** — 가장 큰 개선 한 가지. ERD v34(`case_marker.rule_code`)가 먼저 필요 (강동균)
- 이 규칙은 녹화를 **아무거나 하나** 보내면 피해집니다 → [마우스 궤적 보강 제안](마우스-궤적-보강-제안.md) 2번(클릭 없는 선점)이 짝. 다음 3단계 연습 봇이 이걸 노립니다
