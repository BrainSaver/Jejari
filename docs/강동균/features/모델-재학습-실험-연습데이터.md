# 탐지 모델 재학습 실험: 연습 봇 데이터를 더하면? (2026-11-23)

> 작성: 강동균 · 스크립트 [`tools/ml/practice_exp.py`](../../../tools/ml/practice_exp.py) · 데이터는 로컬 `data/ml/practice-*` (git에 안 올라감)
> **결론: 숫자는 좋아졌지만 모델은 바꾸지 않습니다.** 모델이 배운 것이 "사람"이 아니라 "내 사람 스크립트"였기 때문입니다.

## 무엇을 했나

| | 학습 | 시험 (학습에 안 쓴 것) |
|---|---|---|
| A | 생성 데이터 g7·g8·g9 (18,000계정) — 지금 방식 | 3단계 봇 9종(녹화 꾸미기) + 사람 변형 10종 + 기본 사람 |
| B | A + 연습 데이터 270계정 (1·2단계 봇 39종 + 기본 사람 36명) | 같음 |

모델은 지금 쓰는 짝(그래디언트 부스팅 + Isolation Forest, 비교만 하려고 GRU는 뺌), 문턱은 검증 사람의 95백분위(오탐 5% 목표).

```bash
python3 -I tools/ml/practice_exp.py --gen data/ml/g7 data/ml/g8 data/ml/g9 \
  --train data/ml/practice-pc1123 data/ml/practice-pd1123 data/ml/practice-pe1123 \
  --test data/ml/practice-pf1123 data/ml/practice-ph1123
```

## 결과

| | 구별력 AUC | 봇 탐지 (27계정) | 기본 사람 오탐 (24) | **사람 변형 오탐 (31, 처음 봄)** |
|---|---|---|---|---|
| A 생성만 | 0.49 | 100% | 100% | 81% |
| B 생성 + 연습 | **0.90** | 100% (botrecreal 포함) | 8% | **35%** |

- A는 모두를 봇으로 봅니다 (11-23 오전 3-1절과 같은 현상: 새 계정 + 짧은 세션)
- B는 구별력이 크게 올랐고, 규칙으로는 못 잡던 **botrecreal(사람과 같은 녹화)까지** 잡았습니다

## 그런데 왜 안 쓰나 — 모델이 무엇을 봤나

시험 데이터에서 특징을 하나씩 섞어 보니(순열 중요도) 거의 하나로 가릅니다:

| 특징 | 봇 (3단계) | 기본 사람 | humanfast (손 빠른 사람) |
|---|---|---|---|
| **요청 간격 중 1초 미만 비율** `frac_int_lt_1s` | 0.40~0.60 | **0.00** | 0.25 → 오탐 |
| 간격 10백분위 `int_p10_s` | 0.18~0.37초 | 1.01초 | 0.62초 → 오탐 |

- 내 합성 사람 스크립트는 생각 시간이 늘 1초 이상이라 "1초 미만 간격"이 **0**입니다. 모델은 "1초 미만 간격이 있으면 봇"을 배웠습니다
- 진짜 브라우저는 화면 하나를 열 때 요청을 여러 개 연달아 보내고, 손 빠른 사람도 있어서 **진짜 사람도 1초 미만 간격이 생깁니다**. 그래서 사람 변형 중 손 빠른 사람·조회 없이 링크·결제 뒤 취소가 오탐 (3/3씩)
- 즉 B의 0.90은 "봇 vs 사람"이 아니라 **"봇 vs 내 스크립트"** 점수입니다. 오탐 35%는 목표 5%의 7배

## 배운 것

- **사람 데이터가 가짜면 모델도 가짜를 배운다.** 봇은 스크립트로 얼마든지 만들 수 있지만, 사람은 진짜가 있어야 한다
- 다만 방향은 보였다: "전체 흐름의 속도"(간격 분포)는 강한 신호다. 문제는 **진짜 사람의 분포를 모른다**는 것
- 그래서 순서는: **2차 대회(11-26)에 진짜 사람 30명 이상** → 그 사람 데이터 + 연습 봇으로 B를 다시 → 사람 오탐이 5% 이하일 때만 후보 (A-09에 꺼진 채 등록)
- 2차 뒤 같은 명령에서 `--train`에 2차 사람 데이터를 더하고, `--test`는 **2차 사람 중 학습에 안 쓴 절반**으로

## 새로 학습하면? (재학습 대신 모델을 하나 더, 같은 날)

| | 구별력 AUC | 봇 탐지 | 기본 사람 오탐 | 사람 변형 오탐 |
|---|---|---|---|---|
| C 연습 데이터만으로 새 모델 | 0.84 | 100% | 13% | **48%** (15/31) |
| D 새 모델, 속도 특징(간격·첫 선점 시각 등 8개) 빼고 | 0.53 | 100% | 100% | 90% |

- C는 B(생성 + 연습)보다 나쁩니다: 검증 사람이 7명뿐이라 문턱이 흔들리고, 생성 데이터가 주던 "다양한 사람"이 없어 사람 변형을 더 많이 잡음
- D가 핵심: 속도 특징을 빼면 **아무것도 못 가름**. 행동 로그 특징에서 연습 봇과 합성 사람의 차이는 **속도 하나뿐**이고, 그 속도가 바로 스크립트 티
- 그래서 "모델을 하나 더"는 좋은 방향이지만, **같은 행동 로그 특징으로 하나 더 만드는 것은 의미가 없음**. 새 모델은 **새 정보**를 봐야 함 → 화면 녹화(마우스 궤적·클릭·입력 장치)는 지금 모델(`features.py`)이 전혀 안 씀
- 2차 대회 참가자는 진짜 브라우저를 쓰므로 **진짜 사람의 녹화**가 처음 생김. 그 데이터로 "녹화 모델"을 새로 학습하는 것이 다음 단계
