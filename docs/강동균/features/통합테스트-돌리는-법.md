# 통합 테스트 돌리는 법 (천천히, 한 단계씩)

> 대상: 내 PC (Windows + Git Bash, `F:\jejari\jejari`). mac·Linux도 명령은 같습니다.
> 걸리는 시간: 처음 15~25분 (Oracle 기동 + 컴파일), 그다음부터 5~10분.

## 0. 먼저 알아 둘 것 — 테스트는 두 종류

| 명령 | 무엇을 돌리나 | 인프라(Docker) |
|---|---|---|
| `./gradlew test` | **단위 테스트만**. `@Tag("infra")`가 붙은 테스트는 **빼고** 돈다 | 필요 없음 |
| `./gradlew infraTest` | **통합 테스트만** (`@FullStackInfraTest`, 이름이 `…InfraTest`인 39개 정도) | Oracle·Redis·MongoDB·Kafka 필요 |

> ⚠️ **정정**: 전에 "`./gradlew test --tests '*ModelAdminInfraTest'`로 돌려 보라"고 안내했는데 **틀렸습니다.**
> `test`는 infra 태그를 빼므로 그 명령은 테스트 0개로 "성공"처럼 끝납니다.
> 통합 테스트는 항상 **`./gradlew infraTest`** 로 돌립니다.

통합 테스트는 앱 전체(스프링)를 실제 Oracle·Redis·MongoDB에 붙여서 띄우고, 예매·취소·대기열·관리자 API를
진짜로 호출해 봅니다. 그래서 아래 준비가 다 맞아야 합니다.

---

## 1. 터미널 열고 저장소로 이동

Git Bash를 열고:

```bash
cd /f/jejari/jejari
```

```bash
git pull
```

- 확인: `git log -1 --oneline`이 GitHub의 최신 커밋과 같으면 됩니다.

## 2. 앱(bootRun)이 떠 있으면 끄기

다른 터미널에서 `./gradlew bootRun`을 켜 두었다면 그 창에서 **Ctrl + C**.

왜: 앱과 테스트가 같은 Oracle·Redis·Kafka를 봅니다. 앱이 떠 있으면 앱의 만료 스캐너가 테스트가 잡은 좌석을
먼저 풀고, outbox 릴레이가 테스트 이벤트를 먼저 가져가서 **실행할 때마다 다른 테스트가 깨집니다.**
그래서 테스트는 시작하자마자 8080 포트를 보고, 앱이 떠 있으면 이렇게 멈춥니다:

```
 앱이 8080 포트에 떠 있습니다. 통합 테스트를 그대로 돌리면 조용히 깨집니다.
 …
 bootRun 창에서 Ctrl+C로 앱을 끄고 다시 돌리세요.
```

이 메시지가 나오면 앱을 끄고 다시 돌리면 됩니다.

## 3. 인프라 켜기

```bash
docker compose up -d
```

```bash
docker compose ps
```

- 확인: `oracle` 줄이 **`(healthy)`** 가 될 때까지 기다립니다. 처음엔 2~5분 걸립니다.
  `(health: starting)`이면 30초 뒤 `docker compose ps`를 다시.
- Docker Desktop이 꺼져 있으면 `error during connect …`가 나옵니다 → Docker Desktop을 먼저 실행.

## 4. DB가 최신 스키마인지 확인 (볼륨이 오래됐을 때만)

Oracle 데이터는 Docker 볼륨에 남아 있어서, **볼륨을 만든 뒤에 ERD가 바뀌었으면** 새 테이블·칸·시퀀스가 없습니다.
그러면 통합 테스트가 무더기로 `ORA-00942`(테이블 없음)·`ORA-02289`(시퀀스 없음)·`ORA-00904`(칸 없음)으로 깨집니다.

둘 중 하나를 고릅니다.

### 4-A. 간단한 방법: 볼륨을 새로 만들기 (내 PC의 테스트 데이터가 지워져도 될 때)

```bash
docker compose rm -sf oracle
```

```bash
docker volume rm jejari_oracle-data
```

```bash
docker compose up -d oracle
```

최신 DDL·시드로 다시 만들어집니다. 3번처럼 `(healthy)`까지 기다리세요 (처음과 같이 몇 분).

> 볼륨 이름이 다르다고 나오면 `docker volume ls | grep oracle`로 이름을 확인합니다.

### 4-B. 데이터를 지키고 싶을 때: 빠진 패치만 실행

`db/patch/v{번호}.sql`이 ERD 버전별 델타입니다. 볼륨을 만든 뒤에 생긴 번호만, **낮은 번호부터** 실행합니다.
(이번 주에 생긴 것: v25 ~ v32. v32처럼 "DB 변경 없음"이라고 적힌 것은 건너뛰어도 됩니다.)

```bash
docker compose exec -T -e NLS_LANG=AMERICAN_AMERICA.AL32UTF8 oracle bash -c 'sqlplus -S -L "$APP_USER/$APP_USER_PASSWORD@localhost:1521/FREEPDB1"' < db/patch/v29.sql
```

- 확인: 끝에 `ORA-`로 시작하는 오류가 없으면 됩니다. 패치는 두 번 돌려도 안전하게 짜여 있습니다
  (이미 있는 칸이면 "이미 있음"으로 넘어감).
- 번호만 바꿔 v30, v31 … 차례로.

## 5. 암호화 키를 환경변수로 내보내기

`.env`는 docker compose만 읽고 **Gradle은 읽지 않습니다.** 앱이 쓰는 암호화·HMAC 키를 터미널에 직접 넣어 줍니다.
**이 터미널 창에서만** 유효하니, 창을 새로 열면 다시 해야 합니다.

```bash
set -a && . <(grep -E "^JEJARI_(ENC|PEPPER|HMAC)" .env) && set +a
```

- 확인: `echo ${JEJARI_HMAC_KEY:+있음}` → `있음`이 나오면 됩니다 (값 자체는 화면에 찍지 마세요).
- 빠뜨리면: 회원 관련 통합 테스트가 `PiiCipher` 빈이 없다며 실패합니다.

## 6. 통합 테스트 돌리기

### 전부 돌리기 (10분 안팎)

```bash
LC_ALL=C.UTF-8 TZ=Asia/Seoul ./gradlew infraTest
```

### 하나만 돌리기 (내가 고친 부분만 빨리 볼 때)

```bash
LC_ALL=C.UTF-8 TZ=Asia/Seoul ./gradlew infraTest --tests '*ModelAdminInfraTest'
```

여러 개는 `--tests`를 반복합니다:

```bash
LC_ALL=C.UTF-8 TZ=Asia/Seoul ./gradlew infraTest --tests '*ModelAdminInfraTest' --tests '*ModelOpinionInfraTest'
```

앞에 붙은 두 개가 꼭 필요한 이유:

- `LC_ALL=C.UTF-8` — 없으면 한글 테스트 이름이 `bad filename …$회피.class`로 컴파일부터 실패
- `TZ=Asia/Seoul` — 없으면 기동 점검이 JVM 시간대를 UTC로 보고 앱을 거부해 **모든** 통합 테스트가 멈춤

### 결과 읽기

- 마지막 줄이 `BUILD SUCCESSFUL` → 전부 통과
- `BUILD FAILED`와 `N tests completed, M failed` → 아래 7번 보고서를 엽니다

## 7. 실패했을 때 보고서 보기

```bash
start build/reports/tests/infraTest/index.html
```

(mac은 `open`, Linux는 `xdg-open`.) 브라우저에서 빨간 테스트를 누르면 **어느 줄에서 무엇을 기대했고 무엇이 왔는지**가 나옵니다.
"Standard output" 탭에는 그 테스트 동안 앱이 남긴 로그가 있습니다.

## 8. 자주 나오는 실패

| 증상 | 원인 | 해결 |
|---|---|---|
| `앱이 8080 포트에 떠 있습니다` | 앱이 떠 있음 | 2번 (Ctrl+C). 일부러 띄운 채 돌려야 하면 `-Djejari.test.allow-running-app=true` |
| `bad filename … .class` / 컴파일이 이상하게 깨짐 | `LC_ALL` 빠짐, 또는 예전에 깨진 컴파일 결과가 남음 | `LC_ALL=C.UTF-8`을 붙이고 `rm -rf build/classes/java/test` 후 다시 |
| 모든 테스트가 기동 단계에서 실패, 로그에 시간대(UTC) | `TZ` 빠짐 | `TZ=Asia/Seoul` |
| `PiiCipher` / `JEJARI_ENC_KEYS` 관련 빈 생성 실패 | 5번 안 함 (새 창을 열었을 때 흔함) | 5번 다시 |
| `ORA-00942`, `ORA-02289`, `ORA-00904` 여러 개 | 볼륨이 오래됨 | 4번 |
| `Connection refused` (1521·6379·27017·9092) | 인프라가 아직 안 뜸 | `docker compose ps`에서 `healthy` 확인 후 다시 |
| 처음 한두 테스트만 시간 초과 | Oracle이 막 healthy가 돼 아직 느림, 또는 PC 메모리 부족 | 한 번 더 돌림. 계속이면 Docker Desktop 메모리를 6GB 이상으로 |
| 테스트 0개로 바로 `BUILD SUCCESSFUL` | `test`로 돌림 (infra 제외) | `infraTest`로 |
| `--tests`가 `No tests found` | 이름 오타, 또는 `test` 작업에 붙임 | 클래스 이름 확인 (`ls src/test/java -R \| grep InfraTest`), `infraTest`에 붙이기 |

## 9. 끝나고

- 테스트는 Redis **15번 DB**만 쓰고 시작할 때 비웁니다. 앱이 쓰는 0번 DB는 건드리지 않습니다.
- 테스트가 만든 회원·예약은 각 테스트가 지웁니다. 중간에 Ctrl+C로 끊었으면 일부 남을 수 있지만
  다음 실행에는 영향이 없게 짜여 있습니다 (회원 번호·전화번호를 매번 새로 만듦).
- 다시 앱을 켜려면 평소처럼 `./gradlew bootRun …`.
