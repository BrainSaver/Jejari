# 봇 대회 하는 법 (팀원 누구나)

> 작성: 강동균 · 2026-11-23 · 자세한 화면 설명: [`loadtest/contest/진행-화면-사용법.md`](../../../loadtest/contest/진행-화면-사용법.md) · 봇 규칙: [`loadtest/contest/README.md`](../../../loadtest/contest/README.md)

## 한 줄 요약

**각자 PC에서 `node loadtest/contest/web/server.js` → 브라우저 `localhost:8098` → 봇 체크 → [대회 시작].**
운행 만들기, 봇 명의 만들기, 사람 참가 받기, 예매, 평가, 정리까지 화면이 차례로 합니다. 결과는 `loadtest/contest/results/{태그}/`에 남습니다.

1차 대회(11-19, 태그 `c1119`)가 끝나서 **봇 코드와 1차 원본 데이터를 모두 저장소에 둡니다.** 누구나 같은 봇으로 자기 PC에서 다시 돌려 보고, 규칙을 고친 전후를 비교할 수 있습니다.

## 1. 처음 한 번만 (15분)

1. **Docker Desktop** 켜기, 저장소 루트에 `.env` (없으면 `.env.example`을 보고 팀 채널에서 받기)
2. **Node 18 이상**, Windows는 **Git Bash**에서
3. 최신 코드 받기
```bash
git pull origin main
```
4. 브라우저 봇용 Playwright를 **봇 폴더 하나에만** 설치 (모든 봇이 같이 씀)
```bash
cd loadtest/contest/botb && npm i playwright && npx playwright install chromium && cd ../../..
```
5. (선택) 모델 비교까지 보려면 Python 3.9 이상 + `pip install torch scikit-learn numpy` — 없으면 그 단계만 건너뜀

## 2. 대회 돌리기

```bash
node loadtest/contest/web/server.js
```
브라우저로 **http://localhost:8098** (이 PC에서만 열림)

1. **관리자 ID·비밀번호** (로컬 DB의 SUPERVISOR. `.env`의 `JEJARI_ADMIN_BOOTSTRAP_ID` / `..._PASSWORD`. 비밀번호에 `!`가 있어도 화면에 넣으면 됨)
2. **태그**: 영문 소문자·숫자 7자 이내, **매번 새로** (예: `d1124a`). 같은 태그는 다시 못 씀
3. **봇 체크**: 나갈 봇만
4. **사람 시간**: 사람 없이 봇만 돌리면 짧게 (1~2분)
5. **[대회 시작]** → 끝나면 화면 아래 결과표

**앱은 꺼 둔 채로 시작하세요.** 화면이 최신 화면을 빌드해서 켭니다(`buildFrontend bootRun`, 처음 3~5분).
이미 켜 둔 앱이 있으면 그 앱을 그대로 쓰는데, 예전에 빌드한 화면이면 봇이 멈춥니다 — 2026-11-23 실제로 botb가 옛 검색 화면에서 "예매하기 버튼 기다리는 중"만 반복하다 10분 뒤 시간 초과. 직접 켜야 한다면 `./gradlew buildFrontend bootRun`으로.

> 확인 (2026-11-23, 로컬): botb·botc 둘 다 명의 6개 → 예매 → 평가까지 끝까지 돎 (botb 60석 · botc 24석, 규칙 케이스 0 — 1차와 같음)

## 3. 결과 읽기

| 파일 (`loadtest/contest/results/{태그}/`) | 보는 것 |
|---|---|
| `eval.txt` | **규칙 엔진**: 봇마다 가져간 좌석, 최고 점수, 케이스, 순번이 밀린 시간, 사람 오탐 |
| `compare.md` | **모델 3개** 비교 표와 판정 |
| `log.txt` · `summary.json` | 진행 로그, 단계별 결과 |

1차 결과 (c1119): 규칙 엔진 0/12 · 막은 건 매수 제한(명의당 4석)뿐 · 모델은 블라인드 봇 botb 6/6.
원본: `data/ml/contest-c1119/` (전부 해시값, 그 폴더 README)

## 4. 내 봇 넣기

1. 폴더 `loadtest/contest/bot{영문 소문자}/` (예: `bote`) — **이름 = 계정 이메일의 종류 이름**이어야 평가에 잡힘
2. `bot.json` 한 장
```json
{ "name": "bote", "owner": "내 이름", "blind": false, "run": ["node", "bot.js"], "needs": ["playwright"], "env": {} }
```
3. 봇이 받는 값: `BASE_URL` · `RUN_ID` · `TAG` · `MODE`(`signup` = 명의만 만들기, `buy` = 예매)
4. **계정 이메일 형식 (필수)**: `lt{태그}.{봇이름}.g{묶음}.{번호}@loadtest.example.com`. 다르면 결과에서 통째로 빠짐
5. **명의(본인인증)는 봇 하나당 최대 6개** — 무한히 만들면 매수 제한이 의미 없음
6. 화면의 **+ 봇 추가 → 파일 올리기**로 넣어도 같은 폴더·`bot.json`이 만들어짐. 그다음 git에 올리기:
```bash
git add loadtest/contest/bote && git commit -m "test(contest): bote 봇" && git push origin 내브랜치
```
`node_modules/`와 실행 파일(`.exe`)은 올리지 않습니다 (`.gitignore`).

## 5. 지킬 것

- **2차 대회(11-26) 전까지 이미 있는 봇(botb·botc)은 고치지 않습니다.** 1차와 같은 봇이어야 규칙 보강 전후를 비교할 수 있습니다. 새 수법은 새 봇 이름으로
- 사람 참가자가 있을 때는 **시작 전에 Redis를 비운 깨끗한 상태**로 (1차는 남아 있던 리허설 기록 때문에 사람이 결제에서 막혔음). 화면의 "지난 기록 정리"는 IP 카운터만 비우므로, 사람을 부를 땐 **앱을 끈 상태에서** 아래를 한 번 (Redis는 디스크에 저장해서 재시작만으로는 안 비워짐. 캐시·대기열·좌석 표시만 지워지고 원본은 Oracle에 있음)
```bash
docker compose exec redis redis-cli FLUSHALL
```
- 결과를 팀에 공유할 때는 `eval.txt`·`compare.md`만. 사람 참가자 기록이 있는 `data/ml/contest-{태그}`는 해시값이라도 집계자가 판단해 올림
