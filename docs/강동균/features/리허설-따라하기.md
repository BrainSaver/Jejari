# 2차 대회 리허설 따라하기 (차근차근)

> 작성: 강동균 · 2026-11-24 · 2차 대회(11-26) 전에 진행 화면이 처음부터 끝까지 도는지 확인
> 같은 순서로 2차 당일에도 하면 됩니다 (당일은 3단계에서 사람 시간을 25~30분으로)

리허설은 두 번 합니다.
- **1회차: 봇만** — 화면의 모든 단계가 끝까지 넘어가는지
- **2회차: 내가 사람 1명** — 휴대폰으로 접속이 되는지, 사람이 오탐 없이 예매하는지

모든 명령은 **Git Bash**에서, **저장소 맨 위 폴더(`Jejari`)**에서 칩니다.
지금 어디 있는지 모르겠으면 `pwd`를 치고, `Jejari`로 끝나지 않으면 `cd` 로 그 폴더로 갑니다.

---

## 0단계. 준비물 확인 (처음 한 번)

| 확인 | 어떻게 | 정상이면 |
|---|---|---|
| Docker Desktop | 작업 표시줄에 고래 아이콘, 열어서 "Engine running" | 초록색 |
| Node | `node -v` | `v18` 이상 |
| `.env` 파일 | `ls .env` | `.env`가 보임 |
| 관리자 계정 | `.env`를 메모장으로 열어 `JEJARI_ADMIN_BOOTSTRAP_ID=`, `JEJARI_ADMIN_BOOTSTRAP_PASSWORD=` 줄에 값이 있는지 | 둘 다 값 있음 (화면이 이 값을 씀) |

## 1단계. 준비 — 진행 화면이 합니다 (2026-11-24부터)

예전에는 명령어로 하던 준비(최신 코드·도커·DB 패치·켜 둔 앱 끄기·Redis 비우기·봇 브라우저 설치)를 **[대회 시작]을 누르면 화면이 차례로** 합니다.
내가 할 것은 두 가지뿐입니다.

1. **Docker Desktop**이 설치돼 있기 (꺼져 있으면 화면이 켬, Windows 기본 위치일 때)
2. **main 브랜치**에 있기 — 다른 브랜치거나 고친 파일이 있으면 화면이 최신 코드를 받지 않고 그대로 진행합니다
```bash
git checkout main
```

화면의 "준비" 단계 로그에서 확인할 것:
- `코드: 최신입니다` 또는 `코드: N개 새로 받음`
- `DB 패치 14개 적용` — 그 아래 `참고 (뒤 패치가 다시 맞춤): v24.sql …`은 정상 (옛 패치가 옛 규칙 목록을 넣으려다 실패하고, 뒤 패치가 최신으로 다시 만듦)
- `Redis를 비웠습니다`
- "최신 코드에 진행 화면이 바뀌었습니다"로 멈추면: 이 창에서 `Ctrl + C`, `node loadtest/contest/web/server.js` 다시, [대회 시작] 다시

## 2단계. 리허설 1회차 — 봇만 (15~20분)

### 2-1. 진행 화면 켜기

```bash
node loadtest/contest/web/server.js
```
`http://localhost:8098` 같은 줄이 나오면 켜진 것. **이 Git Bash 창은 닫지 말고 그대로 둡니다** (닫으면 화면이 꺼짐).

### 2-2. 브라우저로 열기

크롬에서 **http://localhost:8098** 을 엽니다.

### 2-3. 입력하기

| 칸 | 넣을 것 |
|---|---|
| 관리자 ID·비밀번호 | **비워 둠** (화면이 `.env`의 처음 관리자 계정을 씀) |
| 최신 코드 받기 · Redis 비우기 | 체크된 그대로 |
| 태그 | **`r1124a`** (영문 소문자·숫자 7자 이내. 한 번 쓴 태그는 다시 못 씀) |
| 봇 | **botb**, **botc** 체크 (다른 봇은 체크 해제) |
| 사람 시간 | **1분** (이번엔 사람 없음) |

### 2-4. [대회 시작] 누르기

화면에 단계가 차례로 진행됩니다. 처음엔 앱 빌드 때문에 **3~5분** 걸립니다.

| 단계 | 정상이면 | 멈추면 |
|---|---|---|
| 점검 | 몇 초 (봇 브라우저를 처음 설치하면 2~5분) | Docker Desktop 설치 확인 |
| 준비 | 몇 초~몇 분 | 로그 마지막 줄을 알려 주세요 |
| 앱 켜기 | 3~5분 뒤 넘어감 | `loadtest/contest/results/app.log` 끝부분 |
| 대회 운행 만들기 | 몇 초 | 화면 로그 마지막 줄을 알려 주세요 |
| 봇 명의 만들기 | 1~5분 | 실패한 봇만 빠지고 계속됨. 둘 다 실패면 알려 주세요 |
| **사람 흐름 확인** | 몇 초 | **가장 중요.** 여기서 멈추면 2차 날 사람이 막힘 → 멈춘 이유(오류 코드)를 알려 주세요 |
| 사람·봇 예매 | 봇이 끝날 때까지 (5~10분) | |
| 평가 | 2~6분 | Python이 없으면 모델 비교만 건너뜀 (괜찮음) |
| 정리 | 몇 초 | |

### 2-5. 결과 보기

화면 아래에 결과표가 뜹니다. 파일로도 남습니다:
```bash
cat loadtest/contest/results/r1124a/eval.txt
```

**볼 것**
- botb·botc 줄의 **탐지 계정**이 0보다 큰지, 오른쪽에 **"규칙(케이스)"**가 있는지 — 1차(11-19)는 둘 다 케이스 0이었음
- 아래 "걸린 규칙" 표에 **HEADLESS_HOLD · INHUMAN_STEP · LINEAR_MOUSE** 중 무엇이 보이는지
- 이 파일을 통째로 복사해 보내 주시면 1차와 비교해 드립니다

## 3단계. 리허설 2회차 — 내가 사람 1명 (15분)

### 3-1. 다시 시작

진행 화면은 그대로 두고, 브라우저에서 새로 고친 뒤:

| 칸 | 넣을 것 |
|---|---|
| 태그 | **`r1124b`** (새 태그) |
| 봇 | botb·botc 체크 (사람과 같이 돌아야 실제와 같음) |
| 사람 시간 | **10분** |

[대회 시작].

### 3-2. 접속 주소 받기

"사람·봇 예매" 단계가 되면 화면에 크게 **접속 주소**(예: `http://192.168.0.12:8080`), **이메일 형식**, **운행일**, **남은 시간**이 뜹니다. 사진을 찍어 두세요.

### 3-3. 휴대폰으로 예매 (첫 번째 사람)

1. 휴대폰을 **PC와 같은 와이파이**에 연결
2. 휴대폰 브라우저에 접속 주소 입력
   - 안 열리면: PC의 Windows 보안 → 방화벽 → "앱 허용"에서 **Java**를 개인 네트워크에 허용하고 다시
3. 가입
   - 이메일: **`ltr1124b.human.g1.1@loadtest.example.com`** (lt + 태그 + .human.g1.1)
   - 이름·휴대폰: 아무 가짜 값 (휴대폰 끝 네 자리 0000은 피하기)
   - 비밀번호: 10자 이상, 쉬운 것·연속 숫자 안 됨
4. 서울 → 부산, 화면에 뜬 운행일 → 검색 → 예매하기 → 줄 서기 → 좌석 1~2석 → 결제
   - 카드번호: **끝자리가 1인 아무 16자리** (예: `4111222233334441`)
5. "예매 완료"가 보이면 성공

### 3-4. 노트북(또는 PC 다른 브라우저)으로 한 번 더 — 두 번 클릭 시험

1. 크롬 **시크릿 창**(Ctrl + Shift + N)에서 같은 접속 주소
2. 새로 가입: 이메일 **`ltr1124b.human.g1.2@loadtest.example.com`**, 이름·휴대폰은 **아까와 다른** 가짜 값
3. 예매하다가 좌석을 고른 뒤 **선점 버튼을 두 번 빠르게** 누름 (더블클릭하듯)
4. 결제까지 끝냄

### 3-5. 끝내기

둘 다 끝났으면 화면의 **[사람 시간 지금 끝내기]**를 누릅니다. 평가까지 자동으로 갑니다.

### 3-6. 결과 보기

```bash
cat loadtest/contest/results/r1124b/eval.txt
```

**볼 것**
- **`human` 줄이 "오탐 없음"**인지
  - "오탐 1명"이면, 걸린 규칙 표에서 `human` 줄의 규칙 이름을 봅니다. `INHUMAN_STEP`이면 두 번 클릭 오탐이 진짜로 재현된 것 → 강다인 님께 전달
- botb·botc는 1회차와 비슷한지

## 자주 막히는 곳

| 증상 | 해결 |
|---|---|
| `docker: command not found` · `Cannot connect to the Docker daemon` | Docker Desktop을 켜고 "Engine running"이 될 때까지 기다림 |
| 준비에서 "Oracle 접속 실패" | Oracle이 처음 켜지는 중일 수 있음. 1분 뒤 새 태그로 다시 |
| "앱 켜기"에서 관리자 로그인 실패 | `.env`의 `JEJARI_ADMIN_BOOTSTRAP_ID`·`_PASSWORD` 값 확인, 또는 화면에 직접 입력 |
| botb가 "예매하기 버튼 기다리는 중"만 반복 | "Redis 비우기"를 꺼서 옛 앱을 썼음 → 켜고 새 태그로 다시 |
| 휴대폰에서 주소가 안 열림 | 같은 와이파이인지, 방화벽에서 Java 허용 (3-3) |
| "가입 429" | 같은 IP에서 가입을 많이 해서. 진행 화면이 대회 중엔 한도를 올려 두지만, 그래도 나면 알려 주세요 |
