# [deploy] 매시간 모델 점수가 등록된 버전 중 하나만 매김

| 항목 | 내용 |

| 날짜 | 2026-11-25 |

| 관련 커밋·이슈 | `f019ffc` (main `41208ea`) |

## 1. 문제

- 현상: 공용 서버에서 `jejari-model`(매시간 모델 점수)을 세 번 돌렸는데 매번 **`ens-2026.11-03` 한 줄만** 나왔다. 등록된 버전은 01·02·03 셋
- 재현 조건: `model_run`에 ENSEMBLE 버전이 2개 이상일 때 `deploy/model-refresh.sh`
- 영향:
  - 맨 앞 버전만 점수가 쌓여 A-09에서 버전끼리 비교할 수 없음
  - 켜진 버전이 없을 때 첫 버전(`-01`)을 켜는 부분까지 반복이 가지 못해 **아무 버전도 켜지지 않음** → A-06 "모델 보조 의견" 카드가 빔

## 2. 원인

- 조영준 님 진단: 반복문 `while read … done <<<"$VERSIONS"` 안에서 부르는 `tools/ml/load_scores.sh`의 `docker compose exec -T mongo mongosh --eval …`이 표준 입력을 막지 않아 **남은 버전 목록을 먹어 버림**
- `-T`는 터미널(tty)을 안 붙일 뿐, 표준 입력은 그대로 컨테이너로 넘긴다. 그래서 반복문의 입력(버전 목록)이 mongosh로 흘러 들어가고, 다음 `read`는 빈 입력을 받아 반복이 끝난다

```
# 같은 모양을 로컬에서 재현 (cat = 표준 입력을 읽는 명령)
old: while read -r x; do echo $x; cat >/dev/null; done <<<"a b c"(줄마다)      → a
new: while read -r -u 3 x; do echo $x; cat >/dev/null; done 3<<<"a b c"(줄마다) → a b c
```

- 최종 원인: 반복문이 읽는 목록과 반복문 안 명령의 표준 입력이 같은 통로였다

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 그 mongosh 줄에만 `< /dev/null` | 한 줄 | 안에서 표준 입력을 읽는 다른 명령이 생기면 또 남 | ✓ (함께) |
| **반복문이 목록을 fd 3으로 읽음** (`read -u 3` · `done 3<<<`) | 안에서 무엇을 불러도 목록이 안전 | 줄 두 개 | ✓ |

- 선택한 이유: 둘 다 했다. fd 3이 근본 해결이고, `/dev/null`은 `load_scores.sh`를 다른 반복문에서 불러도 안전하게
- 바뀐 코드 위치: `deploy/model-refresh.sh` (반복문), `tools/ml/load_scores.sh` (mongosh `< /dev/null`)

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 한 번 실행에 매긴 버전 | 1 / 3 | 3 / 3 (로컬 재현: 목록 3줄 중 1 → 3) |
| 켜진 버전이 없을 때 첫 버전 자동 켜기 | 안 됨 | 됨 (반복이 끝까지 감) |

- 측정 환경: 로컬 Git Bash 재현 (위 코드), 서버 확인은 배포 뒤 `journalctl -u jejari-model -n 20`에 세 줄
- 측정 방법: 위 재현 명령 · 서버 `sudo systemctl start jejari-model`

## 5. 정리

- 면접용 한 줄 요약: "매시간 모델 점수가 버전 하나만 매기던 것을, 반복문 안의 `docker compose exec`가 반복문의 입력을 먹는 것으로 찾아 목록을 다른 파일 기술자로 읽게 바꿔 세 버전 모두 매기게 했다."
- 다음에 비슷한 상황이면: `while read` 안에서 `docker exec`·`ssh`·`ffmpeg`처럼 표준 입력을 읽는 명령을 부르면 목록을 fd 3으로 읽는다. 서버 스크립트는 "몇 개를 처리했나"를 로그에 남겨야 이런 게 보인다 (이번에도 "한 줄만 나온다"로 찾음)
