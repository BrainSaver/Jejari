# Kafka 토픽이 없으면 대기열 입장이 30초 넘게 밀린다

> 작성: 강동균 · 2026-11-17 · 관련: QUE-03 입장 스케줄러, 행동 로그 Kafka 전송, `compose.yaml` kafka-init

## 증상

로컬에서 앱을 띄우고 화면으로 줄을 서면 순번 1번, 앞사람 0명인데 **입장이 안 된다**. 30초쯤 지나야 입장된다.
번호표 조회(`GET /queue/me`)는 계속 200 WAITING. 로그에는 이런 줄이 반복된다.

```
Topic jejari.behavior not present in metadata after 2000 ms.
```

## 원인

`docker compose up -d oracle redis mongo kafka`처럼 **서비스를 골라 띄우면 `kafka-init`(토픽을 만드는 일회성 컨테이너)이 빠진다.**
토픽이 없으니 Kafka로 보내는 작업이 매번 메타데이터를 기다리며 막히고, 그동안 같은 스케줄러 스레드에서 1초마다 돌아야 하는
대기열 입장(`QueueAdmitScheduler`)이 밀렸다. Redis를 보면 대기열 점수는 이미 지금 시각보다 앞인데 꺼내지지 않았다.

## 해결

```bash
docker compose up kafka-init
```

앱을 다시 띄우면 바로 입장된다. 처음부터 `docker compose up -d`(서비스 이름 없이)로 띄우면 생기지 않는다.

## 배운 것

- 입장 같은 핵심 스케줄러가 Kafka 같은 외부 의존과 같은 스레드를 쓰면, 외부가 느려질 때 같이 느려진다.
  스케줄러 스레드 풀을 나누거나 Kafka 전송을 비동기·짧은 대기(`max.block.ms`)로 두는 것을 팀에 제안할 만하다 (김성원·길동현)
- 화면만 보면 "화면이 안 넘어간다"로 보이지만, 요청 기록(상태 200)과 Redis 키를 같이 보면 서버 쪽 문제로 바로 좁혀진다
