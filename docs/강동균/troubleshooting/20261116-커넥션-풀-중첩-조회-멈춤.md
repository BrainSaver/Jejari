# 좌석 동시 선점 테스트에서 커넥션 풀이 30초 멈춤

작성자: 강동균 · 날짜: 2026-11-16 · 관련: RSV-02, `TrainRunReader`, 동시성 T1

## 문제

같은 좌석에 100명이 동시에 선점하는 테스트(T1)가 성공 1건이 아니라 `CannotGetJdbcConnectionException`으로 실패했다.

```
HikariPool-1 - Connection is not available, request timed out after 30000ms (total=10, active=10, idle=0, waiting=28)
```

DB 락을 기다린 게 아니라, 커넥션 10개가 모두 "사용 중"인 채로 아무 일도 하지 않았다.

## 원인

운행 정보를 읽는 `TrainRunReader.find()`가 **RowMapper 안에서 정차역 목록을 다시 조회**했다.

```java
jdbc.query(RUN, (rs, i) -> new RunInfo(..., stops(runId)), runId);   // stops()가 또 jdbc.query
```

바깥 조회가 끝나기 전이라 커넥션 1개를 쥔 채로 1개를 더 빌린다. 혼자 돌 때는 풀에 여유가 있어 문제가 없지만,
32개 스레드가 동시에 들어오면 10개가 각자 첫 커넥션을 쥐고 두 번째를 기다린다. 아무도 반납하지 않으니
모두 30초 뒤 타임아웃이 난다 (풀 데드락).

## 해결

첫 조회를 끝낸 뒤 정차역을 따로 읽도록 나눴다. 한 요청이 동시에 쥐는 커넥션은 항상 1개다.

```java
List<RunInfo> rows = jdbc.query(RUN, (rs, i) -> new RunInfo(..., Map.of()), runId);
return rows.stream().findFirst().map(r -> /* 여기서 stops(runId) */);
```

## 수치

| | 결과 |
|---|---|
| 수정 전 | T1 실패 (30초 대기 후 커넥션 타임아웃) |
| 수정 후 | T1 통과: 100건 중 성공 1, 거절 99, DB 예약 행 1개 |

## 배운 점

- RowMapper·RowCallbackHandler 안에서는 DB를 다시 부르지 않는다. 결과를 다 받은 다음에 부른다.
- 단건 테스트로는 안 보이고 **동시 요청**에서만 드러난다. 동시성 테스트를 일찍 돌린 덕에 부하 테스트 전에 찾았다.
