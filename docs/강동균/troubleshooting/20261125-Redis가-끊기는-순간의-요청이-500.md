# [common] Redis가 끊기는 순간 처리 중이던 요청이 503이 아니라 500

| 항목 | 내용 |
|---|---|
| 작성자 | 강동균 |
| 날짜 | 2026-11-25 |
| 상태 | 해결 |
| 관련 커밋·이슈 | `798dec8` (main `ac5591c`) |

## 1. 문제

- 현상: Redis를 죽인 순간 처리 중이던 **10건이 500 `INTERNAL_ERROR`**. 나머지 장애 동안 요청은 정상적으로 503
- 재현 조건: 부하 중 `docker compose kill redis` (`loadtest/tools/fault_demo.sh redis`). 죽이는 그 순간(같은 1ms 안)에 Redis에 명령을 보내 둔 요청만
- 영향: 사용자는 "잠시 후 다시"(503, 재시도 안내) 대신 "서버 오류"를 봄. 서버 오류 경보(5xx 비율)가 장애가 아닌 버그처럼 울림

## 2. 원인

- 가설: 예외 처리기(`RedisExceptionHandler`)가 연결 문제를 못 알아봄 → 맞음
- 앱 로그의 원인 예외를 모아 보니 두 가지. 처리기는 앞의 것만 503으로 봤다

```
Caused by: io.lettuce.core.RedisException: Currently not connected. Commands are rejected.   ← 끊긴 뒤 보낸 명령 (503 처리됨)
Caused by: io.lettuce.core.RedisException: Connection disconnected                            ← 끊기는 순간 이미 보낸 명령 (500)
```

- 최종 원인: 끊기는 순간 응답을 기다리던 명령은 "Connection disconnected"를 받는데, `isUnavailable`이 메시지 "Currently not connected"만 검사했다

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 모든 `RedisSystemException`을 503으로 | 단순 | 스크립트 오류 같은 진짜 버그도 503으로 숨겨짐 | |
| 연결이 끊긴 메시지("Connection disconnected/closed")를 503 목록에 더함 | 버그는 계속 500으로 드러남 | 드라이버 메시지에 기댐 | ✓ |

- 바뀐 코드 위치: `src/main/java/com/jejari/common/error/RedisExceptionHandler.java` (`isUnavailable`) · 시험 `RedisExceptionHandlerTest.끊기는_순간_처리_중이던_명령도_503`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| Redis를 죽인 순간의 500 | 10건 | **0건** |
| 503 응답 p95 | 19ms | 10ms (요청을 붙잡지 않음) |

- 측정 방법: `loadtest/tools/fault_demo.sh redis` → report.md "구간별" 표의 "다른 5xx" 칸. 원인 예외는 앱 로그에서 `Caused by` 줄을 모아 셈

## 5. 정리

- 면접용 한 줄 요약: "장애 주입으로 'Redis가 끊기는 바로 그 순간'의 요청만 500이 나는 것을 찾았고, 끊김 예외를 503으로 분류해 순간 오류 10건을 0건으로 만들었다."
- 다음에 비슷한 상황이면: 장애 처리 시험은 "끊긴 뒤"뿐 아니라 "끊기는 순간"(처리 중이던 요청)도 본다. 예외 분류에 쓴 메시지는 실제 로그에서 모은다
