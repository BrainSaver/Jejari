## 1. 문제

- 현상: 결제가 몰려 서버가 503 `PAYMENT_BUSY` + `Retry-After: 3`을 주면 화면이 3초 뒤 같은 멱등 키로 자동 재시도해야 하는데,
  버튼이 **"결제하는 중…"에서 영원히 멈춤**. 안내 띠도 안 뜨고 다시 보내지도 않음. 서버에는 503 한 번만 찍히고 예약은 HOLD 그대로
- 재현 조건: `npx vite`(개발 서버)로 띄운 화면 + 실제 앱(`JEJARI_PG_MODE=http`, `JEJARI_PG_MAX_CONCURRENT=1`) + 가짜 PG 2.5초.
  회원 A의 결제가 PG 자리 1칸을 잡은 동안 회원 B가 화면에서 결제하기
- 영향: 개발 모드에서만. 배포 빌드(`npm run build`, 공용 서버)는 StrictMode의 두 번 붙이기가 없어 정상. 다만 같은 원인으로
  **결제가 성공해도 결과 화면으로 안 넘어가는** 경로도 있어, 개발 중 시연·시험이 막힐 수 있었다

## 2. 원인

- 처음 가설: 프론트 API 클라이언트가 503을 특별 취급하거나 `Retry-After`를 못 읽는다 → `client.js`의 `send()`는 모든 오류에서
  `Retry-After`를 읽어 `ApiError.retryAfter`로 넘김. 아님
- 확인 방법: Playwright로 브라우저 요청·응답을 모두 찍음 → 503을 받은 뒤 아무 요청도 없고, `setError`도 `setBusy(false)`도 안 불림
  → 코드에서 둘 다 건너뛰는 조건은 `alive.current === false`뿐
- 최종 원인: "화면을 떠나면 재시도를 멈춘다"용 `alive` 표시를 **떼는 쪽(cleanup)에서만 false로** 바꾸고 붙는 쪽에서 true로 되돌리지 않았다.
  React 개발 모드(StrictMode)는 효과를 붙였다 → 떼고 → 다시 붙인다. 그래서 첫 렌더 직후 `alive`가 false로 남았다

```js
// 전
useEffect(() => () => { alive.current = false; }, []);
// 후
useEffect(() => {
  alive.current = true;
  return () => { alive.current = false; };
}, []);
```

- 가짜 응답 시험(오전)에서 못 잡은 이유: 그 시험은 **배포 빌드(dist)** 를 띄웠다. StrictMode의 두 번 붙이기는 개발 빌드에만 있다

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| `alive` 표시를 효과 안에서 true로 켜고 cleanup에서 끔 | 한 줄, StrictMode·실제 언마운트 둘 다 맞음 | — | ✓ |
| `AbortController`로 진행 중인 요청과 대기를 취소 | 대기 타이머까지 정확히 끊음 | 클라이언트 `send()`가 signal을 받게 바꿔야 함 (공용 코드) | |
| StrictMode 끄기 | — | 다른 화면의 같은 종류 버그를 숨김 | |

- 선택한 이유: 효과의 정석(붙을 때 켜고 뗄 때 끔)이고, 공용 API 클라이언트를 건드리지 않는다
- 바뀐 코드 위치: `frontend/src/user/Pay.jsx`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 503 뒤 자동 재시도 | 0번 (멈춤) | 3초 뒤 1번 → 201 승인 |
| B 예약 상태 | HOLD (화면은 "결제하는 중…") | CONFIRMED, 결과 화면 "표가 확정됐어요" |
| B 결제 요청 흐름 | 503 (+0.37초) | 503 `Retry-After 3` (+0.37초) → 201 (+5.9초 = 대기 3초 + PG 2.5초) |

- 측정 환경: 작업 환경 Docker(Oracle·Redis·Kafka·Mongo), `./gradlew bootRun` + `JEJARI_PG_MODE=http JEJARI_PG_MAX_CONCURRENT=1`,
  가짜 PG `PG_LATENCY=2500-2500 node loadtest/mock-pg/server.js`, 화면은 `npx vite`, 폭 390px
- 측정 방법: Playwright 스크립트 — 회원 A·B 가입 → 대기열 → 좌석 선점(API) → B는 화면 로그인 후 결제 화면 →
  A 결제(API) 0.3초 뒤 B가 [결제하기] → 요청·응답·화면 문구·예약 상태 확인

## 5. 정리

- 면접용 한 줄 요약: "화면을 떠나면 재시도를 멈추려던 표시를 cleanup에서만 꺼서, StrictMode의 다시 붙이기 뒤 503 자동 재시도가 멈췄고,
  효과 안에서 켜고 cleanup에서 끄게 바꿔 실제 앱에서 503 → 3초 뒤 재시도 → 승인까지 확인했다."
- 다음에 비슷한 상황이면: 화면 시험은 **개발 서버(StrictMode)로 한 번, 배포 빌드로 한 번** 둘 다 돌린다. `useRef` 표시를
  cleanup에서 바꾸면 같은 효과의 본문에서 되돌리는지 본다
