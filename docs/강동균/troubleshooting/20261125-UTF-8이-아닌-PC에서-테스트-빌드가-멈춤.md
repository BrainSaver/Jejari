# [build] UTF-8이 아닌 PC·서버에서 테스트 빌드가 "bad filename"으로 멈춤

| 항목 | 내용 |
|---|---|
| 작성자 | 강동균 |
| 날짜 | 2026-11-25 |
| 상태 | 해결 |
| 관련 커밋·이슈 | 이 문서와 같은 커밋 (외부 평가에서 지적) |

## 1. 문제

- 현상: `./gradlew test`가 테스트를 돌리기도 전에 멈춤
  ```
  SignalCollectorTest.java:121: error: error while writing SignalCollectorTest.회피:
    bad filename RelativeFile[com/jejari/risk/SignalCollectorTest$회피.class]
  ```
  고친 뒤에도 한 번 더: 테스트는 다 통과했는데 HTML 보고서를 만들다 실패
  ```
  Malformed input or input contains unmappable characters: .../sudo가_실패하면_알린다().html
  ```
- 재현 조건: 로케일이 UTF-8이 아닌 리눅스 (`LANG` 비어 있음 = POSIX). 이때 Java의 파일 이름 인코딩(`sun.jnu.encoding`)이 ASCII
- 영향: CI(ubuntu, UTF-8)와 Windows(CP949)에서는 안 나서 아무도 몰랐다. 새 서버·컨테이너·팀원 리눅스에서 빌드가 막힘

## 2. 원인

- 한글 이름의 **중첩 테스트 클래스**(`@Nested class 회피`)는 `.class` **파일 이름**이 된다. ASCII 파일 이름 인코딩으로는 그 파일을 못 쓴다 (6개 파일 31개)
- 한글 **메서드** 이름은 `.class` 파일이 되지 않아 컴파일은 괜찮지만, Gradle HTML 테스트 보고서가 메서드마다 파일을 만들어 같은 문제가 난다
- `-Dsun.jnu.encoding=UTF-8`로 바꿀 수 없음을 확인 (Java가 로케일에서만 정함)

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 모두 `LC_ALL=C.UTF-8`로 실행하라고 안내 | 코드 변경 없음 | 사람이 기억해야 함. 서버·CI 이미지가 바뀌면 또 남 | |
| 중첩 클래스 이름을 영문 + `@DisplayName("원래 한글")` | 근본 해결. 보고서에 보이는 이름은 그대로 | 다른 팀원 테스트 6개 파일을 건드림 (이름만) | ✅ |
| 빌드 검사: 한글 클래스 이름이 들어오면 이유와 함께 멈춤 | 다시 생기지 않음 (CI에서도 잡힘) | 없음 | ✅ |
| 파일 이름 인코딩이 UTF-8이 아니면 HTML 보고서만 끔 | 메서드 수백 개를 안 바꿈. XML 결과는 그대로 | 그 환경에서는 HTML 보고서가 없음 (경고로 알림) | ✅ |

## 4. 결과

| 환경 | 전 | 후 |
|---|---|---|
| POSIX 로케일 | 컴파일 실패 | **644개 통과** (HTML 보고서만 꺼짐) |
| UTF-8 로케일 | 644개 통과 | 644개 통과, HTML 보고서 그대로 |
| 한글 클래스를 새로 넣으면 | 그 PC에서만 실패 | 어디서나 "클래스 이름은 영문으로 … @DisplayName" 안내와 함께 멈춤 |

## 5. 배운 점

- "내 PC에서는 된다"의 범위는 로케일까지다. 한글 식별자는 **파일 이름이 되는 곳**(클래스, 보고서)에서만 문제가 된다
- 사람에게 기억시키는 대신 빌드가 막게 한다
