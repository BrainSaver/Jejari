# [frontend] 새로 연 페이지의 첫 요청이 토큰 없이 나가, 로그인한 사람의 검색이 "비회원"으로 기록됨

| 항목 | 내용 |
|---|---|
| 작성자 | 강동균 |
| 날짜 | 2026-11-18 |
| 상태 | 해결 |
| 관련 커밋 | `ea6d1b1` fix(frontend): 새로 연 페이지의 첫 요청이 비회원으로 기록되던 문제 |

## 1. 문제

- **현상**: 로그인한 사람이 운행을 날짜로 검색해도, 그 검색(`VIEW_TRAIN`)이 그 회원의 행동 로그에 남지 않았다.
  사람처럼 화면을 쓰는 스크립트로 3명을 예매시키자 셋 다 "이벤트 4개 · 조회 1번 · 검색 0번"으로 나왔다
- **재현 조건**: 로그인 → 주소창으로 검색 화면을 열거나 새로 고침 → 검색. (화면 안에서 링크로만 이동하면 안 생김)
- **영향**
  - 회원 행동 로그에서 "둘러보기" 신호가 통째로 빠졌다. 위험 점수 모델 리허설에서 봇을 잡은 근거가 "검색 없이 바로 대기열"이었는데,
    사람도 검색 기록이 없으니 **사람과 봇을 가르는 신호가 실제 데이터에서 사라질 뻔했다**
  - 학습 데이터 생성기는 "사람은 검색을 여러 번 한다"고 가정했는데, 실제 로그에는 그 신호가 없었다 — 학습과 실제가 어긋남

## 2. 원인

- 가설 1: 서버가 검색을 로그에 안 남긴다 → `TrainController.search`는 `BehaviorLog.mark(VIEW_TRAIN, …)`를 부른다. 남기고는 있다
- 확인: Mongo에서 `VIEW_TRAIN`을 회원 유무로 나눠 세니 화면에서 한 검색은 **`member_id`가 비어** 있었다

```
db.behavior_log.aggregate([{$match:{event_type:"VIEW_TRAIN"}}, {$group:{_id: member_id 유무, n:{$sum:1}}}])
→ 회원 없음 11 · 회원 있음 190 (회원 있음은 k6처럼 처음부터 토큰을 붙인 요청)
```

- **최종 원인**: 액세스 토큰은 XSS를 막으려고 **메모리에만** 둔다. 페이지를 새로 열면 토큰이 없어서 리프레시 쿠키로 다시 받아야 하는데,
  검색 화면은 열리자마자 `/api/v1/runs`(공개 API)를 부른다. 공개 API라 토큰 없이도 200이 나오니 401 → 재발급 흐름도 타지 않는다.
  서버는 그 요청을 비회원 검색으로 기록한다

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 토큰을 `localStorage`에 둔다 | 새로 열어도 바로 있음 | XSS 한 번에 토큰이 털림 (지금 설계가 피한 것) | |
| 검색 화면만 로그인 확인 뒤 검색 | 고칠 곳이 적음 | 다른 공개 API(운행 상세 등)에 같은 문제가 남음 | |
| **첫 API 요청 전에 리프레시를 한 번 기다림** (`api()`에서) | 모든 화면·API에 한 번에 적용. 토큰 보관 방식 그대로 | 첫 요청이 리프레시 한 번만큼 늦음. 로그인 안 한 사람은 리프레시가 바로 실패하고 진행 | ✓ |

- 선택한 이유: 원인이 "화면 하나"가 아니라 "새로 연 페이지의 첫 요청"이라, 요청을 보내는 한 곳(`api()`)에서 막는 게 맞다.
  리프레시는 페이지당 한 번만 기다린다 (`booted` 프로미스를 같이 씀)
- 바뀐 코드: `frontend/src/api/client.js` `api()`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 사람 흐름 3명의 회원 행동 로그 이벤트 수 | 4개씩 (검색 0) | 5개씩 (검색 1) |
| 화면 검색 중 회원으로 기록된 비율 | 0% | 100% |

- 측정 환경: 로컬 Docker Compose, 운행 1000005, Playwright로 "로그인 → 날짜로 검색 → 예매하기 → 좌석 → 결제"를 사람 속도로
- 측정 방법: 사람 흐름 스크립트로 예매 → `tools/ml/export_live.sh <태그> <폴더>` → `features.py`의 `n_events`·`browse_before_hold`

## 5. 정리

- 면접용 한 줄 요약: "토큰을 메모리에만 두는 설계에서, 새로 연 페이지의 첫 공개 API 요청이 토큰 재발급보다 먼저 나가 로그인한 사람의
  행동이 비회원으로 기록됐다. 첫 요청 전에 재발급을 한 번 기다리게 해 회원 행동 기록률을 0%에서 100%로 바꿨다."
- 다음에 비슷한 상황이면: **공개 API는 401이 안 나서 재발급 흐름을 안 탄다.** "로그인한 사람의 요청인데 비회원으로 보인다"면
  토큰이 준비되기 전에 나간 요청부터 의심한다. 행동 로그처럼 "누가 했나"가 중요한 데이터는 실제 브라우저로 한 번 돌려 확인한다
