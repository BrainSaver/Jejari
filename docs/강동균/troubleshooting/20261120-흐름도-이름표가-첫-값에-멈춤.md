## 1. 문제

- 현상: A-10 트래픽 관제의 실시간 흐름도에서 **점(요청)은 새 값대로 움직이는데, 노드 옆 숫자(`대기열 162/초 · 평균 1.9ms`)와 테두리 색은 화면을 연 순간의 값에서 바뀌지 않았다.**
  Redis를 끊어 대기열 요청의 70%가 5xx가 됐는데도 대기열 노드가 빨강(위험)이 아니라 노랑(주의)이었다. 장애 전·중·후 스크린숏의 숫자가 셋 다 `162/초 · 57/초 · 4.8/초`로 똑같았다.
- 재현 조건: 값이 계속 바뀌는 실제 트래픽에서 화면을 켜 두기. **가짜 데이터(늘 같은 값)로 찍은 스크린숏에서는 드러나지 않는다.**
- 영향: 관제 화면이 장애를 "정상"처럼 보여 준다. 위에 있는 범례의 "지금 217건/초 · 오류 72%"와 그림이 서로 달라 화면을 믿을 수 없게 된다.

## 2. 원인

- 가설 1: 서버(`/api/v1/admin/traffic/flow`)가 캐시된 옛 값을 준다 → 아님. 같은 시각 API 응답과 범례 숫자는 바뀌고 있었다
- 가설 2: 그리기 루프가 옛 값을 쓴다 → **맞음**

`FlowMap.jsx`의 그리기 루프(`requestAnimationFrame`)는 `useEffect` 안에서 **한 번 만들어지고** 매 프레임 돈다.
점을 낳는 쪽은 매 렌더마다 갱신되는 `target.current`(ref)를 읽었지만, 노드를 그리는 쪽은 effect를 만들 때 붙잡은 `groups`·`stores` 변수를 썼다.
effect의 의존성은 `[groups.length, stores.length]`라 영역 수가 그대로면 effect가 다시 만들어지지 않고, 루프는 **첫 응답의 groups를 영원히** 본다 (React의 "오래된 클로저" 문제).

```js
useEffect(() => {
  const frame = () => {
    const f = target.current;              // ✓ 매번 새 값 (ref)
    ... 점 낳기: e.rate(f) ...
    drawNodes(ctx, L, f, groups, stores);  // ✗ effect를 만들 때의 groups (첫 값)
  };
}, [groups.length, stores.length]);
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| effect 의존성에 `groups`를 넣기 | 간단 | 2초마다 루프·점 상태가 통째로 다시 만들어져 점이 끊김 | |
| 루프 안에서 ref(`target.current`)의 값으로 그리기 | 루프는 그대로, 값만 새것 | 없음 | ✓ |

- 선택한 이유: 점의 위치·누적값은 루프가 계속 들고 있어야 부드럽다. 바뀌는 데이터는 ref로만 읽는다는 규칙을 하나로 맞췄다
- 바뀐 코드: `frontend/src/admin/FlowMap.jsx` — `drawNodes(ctx, L, f, f?.groups ?? [], f?.stores ?? [])`

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| Redis 끊김 중 대기열 노드 색 | 노랑 (첫 값 기준) | 빨강 + 번지는 고리 |
| 노드 숫자 (장애 전 → 중) | 162/초 → 162/초 (안 바뀜) | 170/초 → 142/초, Redis 211 → 1.9 명령/초 |

- 측정 환경: 로컬 docker compose (Oracle·Redis·MongoDB·Kafka·Prometheus) + 앱 1대 (`--jejari.dev-mode=true`)
- 측정 방법: k6로 대기열 줄 서기 20/초 · 상태 조회 150/초 · 좌석 60/초 · 틀린 로그인 5/초를 보내며, 중간에 `docker compose stop redis` 40초 → 다시 `start`. Playwright로 관리자 로그인 후 A-10을 장애 전·중·후 스크린숏

## 5. 정리

- 면접용 한 줄 요약: "애니메이션 루프가 effect 생성 시점의 데이터를 붙잡는 오래된 클로저 때문에 관제 화면이 장애를 정상으로 보였고, 바뀌는 값을 ref로만 읽게 바꿔 실측 장애 재현에서 노드가 즉시 위험으로 바뀌게 했다."
- 다음에 비슷한 상황이면:
  - `requestAnimationFrame`·`setInterval`처럼 **한 번 만들어 오래 도는 함수**는 props·state를 직접 쓰지 말고 ref에서 읽는다
  - 화면 검증은 **값이 바뀌는 데이터**로 한다. 고정 가짜 데이터 스크린숏은 "그려지는가"만 확인해 준다
