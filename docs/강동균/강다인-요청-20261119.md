## 대회 전 (~11-22)

### 1. 블라인드 누출 주석 지우기 — 5분

`src/main/java/com/jejari/seat/web/ReservationController.java:63` 주석에 규칙 이름이 있습니다.

```java
// 행동 로그: 실패(409 등)도 남아야 같은 좌석 반복 실패(SAME_SEAT_RETRY)를 잡는다. 예외 전에 먼저 표시
```

블라인드 공격자(김성원·길동현)가 **읽어도 되는 파일**(이용자 API 컨트롤러)이라, 이 줄로 "같은 좌석을 반복하면 잡힌다"가 샙니다.
규칙 이름을 빼고 `// 행동 로그: 실패(409 등)도 남게 예외 전에 먼저 표시` 정도로 바꿔 주세요. **두 공격자가 봇을 만들기 전(11-20)에** 하면 좋습니다.

### 2. 1차 대회 동안 규칙·정책 고정

- `com.jejari.risk` 코드와 `app_policy`의 `risk.*` 값은 **1차 대회(11-23)가 끝날 때까지 바꾸지 않습니다** (2026-11-18 결정 "수비 고정")
- 버그 수정은 예외입니다 — "규칙을 고정"하는 것이지 버그를 남겨 두는 것이 아닙니다. 고치면 저에게 알려 주세요 (결과표에 적음)

## 1차 대회 뒤 (11-23~25)

### 3. 규칙 보강 — [`방어자-지시문.md`](../../loadtest/contest/방어자-지시문.md)

1차가 끝나면 제가 **결과표**(`eval_contest.sh` 출력)와 **공격자 수법 요약 4개**, 태그·운행 ID를 드립니다.
그걸 받은 뒤 새 Claude 세션에 지시문을 붙여 넣고 진행하시면 됩니다. 요점만:

- 뚫린 봇마다 "사람과 다른 **성질**"을 찾아 규칙으로 (봇 하나의 값·이메일 라벨을 외우지 않기)
- 매수 제한은 그대로, 문턱만 낮춰 탐지율 올리기 금지, **사람 오탐이 늘면 실패**
- 1차 데이터로 다시 매겨 보고, `docs/강다인/features/`에 보강 전 → 후 표
- 새 `rule_code`가 필요하면 저에게 말해 주세요 → ERD 패치(`case_marker.rule_code` CHECK)는 제가
- **마감 11-25** (11-26 2차 대회 — 같은 봇을 그대로 다시 돌려 개선 전후 비교)

> 참고 (11-18 리허설): 규칙 엔진은 botc(규칙을 아는 브라우저 봇) 6명의를 **하나도 못 잡았고**, 매수 제한만 일했습니다.
> 모델은 같은 봇 6/6, 사람 오탐 0/6. 잡힌 근거는 "조회 1 · 이벤트 4 — 검색 없이 바로 대기열"이었습니다.

## 11-27~ : 모델 점수를 시스템에 붙이기

지금 모델(`tools/ml/`)은 **파이썬으로 따로 돌고 결과가 CSV**(`scores.csv`)로만 나옵니다.
계정마다 `score`(0~100) · `flag` · `by`(부스팅 / IF / GRU 중 가장 높게 본 모델) · 근거 3개입니다.
관리자에게 보이려면 아래를 정해야 합니다.

### 4. 정할 것 — 모델 점수를 어디에 둘지

| 정할 것 | 선택지 | 제 의견 |
|---|---|---|
| **a. 언제 매기나** | ① 배치: 파이썬이 주기적으로 매겨 DB에 씀 · ② 서버가 요청마다 모델 호출 | **①** — 모델이 파이썬(scikit-learn·PyTorch)이라 서버(Java)에서 부르려면 별도 서비스가 필요. 보조 의견이라 실시간일 필요 없음 |
| **b. 누구 단위로** | 모델은 **계정(member)** 단위 · `risk_score`는 **CI·결제수단·기기** 단위 | 계정 → CI로 묶어 CI 행에 최댓값. 결제수단·기기 행은 비움 |
| **c. 어느 칸에** | `risk_score.iforest_score` 재사용 · 새 컬럼(`model_score`) | 새 컬럼 권장 — 지금은 Isolation Forest만이 아니라 부스팅·GRU를 합친 점수라 이름이 틀림. 근거는 `reasons` JSON에 `source: "model"`로 |
| **d. 모델 버전** | `model_run.algorithm` CHECK가 `RULE / IFOREST`뿐 | `ENSEMBLE` 같은 값 추가, `model_version` 예: `ens-2026.11-01` |
| **e. 점수가 하는 일** | 보조 의견만 · 순번 조정에도 반영 | **보조 의견만** (제안서 결정). 순번 조정·제한은 지금처럼 규칙 점수와 사람 판정으로 |

b·c·d가 정해지면 **ERD 패치는 제가** 씁니다 (ERD 반영 담당). 정해 주실 것: a~e에 대한 결정 한 줄씩.

### 5. 관리자 화면에 보조 의견 (A-05 위험 사용자 목록 · A-06 케이스 상세)

- 규칙 점수 옆에 **"모델 의견: 99점 · 근거 3개"** 를 작게. 판정 버튼은 그대로 규칙·사람 판정 기준
- `by`가 GRU면 근거 맨 앞에 "행동 순서가 학습한 봇과 닮음" — 특징 숫자로는 이유가 안 보이는 경우라서, 이때는 의심 구간 타임라인(CCTV 재생)으로 보게 안내
- 화면은 강다인 님 담당(A-05·A-06), API에서 4번에서 정한 칸을 읽으면 됩니다

### 6. 정할 것 — 가상 데이터 생성기가 둘

| | `com.jejari.synthetic` (DATA-02, 강다인) | `tools/ml/generate.py` (강동균) |
|---|---|---|
| 용도 | 화면·시연용 DB 데이터 | 모델 학습용 파일 (수법 38가지, 오탐 함정 포함) |
| 출력 | Oracle·Mongo에 직접 | `events.jsonl` (행동 로그와 같은 모양) |

제안서에는 "형식을 강다인 님과 먼저 맞춘다"고 적었는데 아직 못 맞췄습니다. **각자 용도가 달라 둘 다 두는 것**을 제안합니다.
다만 행동 로그 필드(이벤트 종류·meta 키)를 바꾸시면 `tools/ml/features.py`·`seq.py`도 같이 바뀌어야 하니 저에게 알려 주세요.

> 새로 생긴 행동 로그 규칙: 화면이 사람 조작 없이 스스로 부른 조회는 `meta.auto = true`
> (첫 화면 자동 검색 `VIEW_TRAIN`, 좌석을 뺏긴 직후 좌석표 재조회 `VIEW_SEAT`. 헤더 `X-Search-Auto: 1`).
> 규칙 엔진에서 조회 횟수·간격을 셀 때도 이 이벤트는 빼는 게 맞습니다 — 안 빼면 봇과 경쟁하다 좌석을 놓친 사람이 봇처럼 보입니다.

## 발표 전

### 7. 비교표 — 규칙 · Isolation Forest · 딥러닝 (제안서 "평가 2", 강다인 님 판단)

- 대회 봇 4개를 **돌려 가며 하나씩 빼고** 학습 → 뺀 봇으로 시험 (4회 평균 = 처음 보는 봇을 잡는 실력)
- 같은 표에 규칙 엔진 결과(`eval_contest.sh`)와 사람 오탐을 같이
- 모델 쪽 숫자는 제가 `tools/ml/`로 뽑아 드립니다. 표에 넣을 규칙 쪽 숫자와 해석(왜 이 규칙이 놓쳤나)을 부탁드립니다
- 지금까지 생성 데이터로 잰 값(모델 약 70%)은 **발표 숫자로 쓰지 않습니다** — 우리 생성기로 잰 값이라

## 모델을 직접 돌려 보려면

```bash
pip install torch scikit-learn numpy      # Windows·Mac은 이대로 CPU판
python3 -I tools/ml/generate.py --members 6000 --seed 7 --out data/ml/g7 && python3 -I tools/ml/features.py data/ml/g7
python3 tools/ml/train.py data/ml/model data/ml/g7/features.csv          # 학습 (GRU 포함 5~15분)
tools/ml/export_live.sh <태그> data/ml/contest-<태그>                     # 대회 데이터 꺼내기
python3 -I tools/ml/features.py data/ml/contest-<태그>
python3 tools/ml/score.py data/ml/model/model.pkl data/ml/contest-<태그>/features.csv   # → scores.csv
```
