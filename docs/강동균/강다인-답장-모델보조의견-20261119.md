# 강다인 님께 · 모델 보조 의견 설계안 답장

> 작성 강동균 · 2026-11-19 · 답하는 문서: [강다인 · 모델-보조의견-설계](../강다인/모델-보조의견-설계.md) · 이전 요청: [강다인-요청-20261119](강다인-요청-20261119.md) 4번

설계안 그대로 갑니다: **오프라인으로 점수 매기기 → Mongo `model_score` → 관리자 화면**.
제 요청서 4-c(`risk_score`에 `model_score` 컬럼 추가)는 **철회**합니다. `risk_score`는 대기열이 순번을 정할 때 읽는 값(`RiskScoreFallbackPort`)이라, 같은 표에 두면 언젠가 모델 점수가 순번에 섞입니다. 강다인 님 안이 맞습니다.

아래 세 가지만 다듬어 주세요.

## 다듬을 것 3가지

1. **`model_score`에서 `ci_hash`를 빼 주세요.**
   계정 → CI는 서버가 조회할 때 Oracle에서 찾으면 됩니다. 식별 해시 사본을 하나 줄이고, Oracle 값과 어긋날 일도 없어집니다.
2. **"계정마다 1건" 대신 `UNIQUE(member_id, model_version)`**
   같은 버전을 다시 적재하면 덮어쓰고(upsert), 버전끼리 비교도 됩니다. 화면에는 `model_run.is_active = 'Y'`인 버전만 보여 줍니다.
3. **`model_run`의 "is_active = Y는 한 번에 하나" → "`algorithm`별로 하나"**
   지금 문구대로면 규칙(`RULE`)과 `ENSEMBLE`을 동시에 켤 수 없습니다. 비고는 ERD 패치에서 제가 고칩니다.

## 질문에 대한 답

1. **방식**: 설계안 방식으로 갑니다 (위).
2. **ERD 변경 ①②③**: 모두 제가 패치합니다.
   - ① Mongo `model_score`: `member_id`, `score`, `by`, `scores`{부스팅·IF·GRU}, `reasons`[3], `model_version`, `scored_at`, `source`(대회 태그) · `UNIQUE(member_id, model_version)`
   - ② `model_run.algorithm`에 `ENSEMBLE` + is_active 비고 수정
   - ③ `risk_score.iforest_score`는 **지웁니다** — 코드 어디에서도 쓰지 않습니다
3. **`scores.csv` 컬럼**: 지금 컬럼을 고정으로 약속합니다 — `member_id, label, strategy, score, flag, by, score_{모델}…, reasons`(근거는 ` · `로 구분).
   다만 나중에 컬럼이 늘 수 있으니 적재 스크립트는 **순서가 아니라 헤더 이름으로** 읽어 주세요. `label`·`strategy`(정답)를 적재하지 않는 건 말씀대로입니다.
