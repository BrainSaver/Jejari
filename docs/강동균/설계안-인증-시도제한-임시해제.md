# 설계안 · 인증 시도 제한 임시 해제 (자동 복구)

> 작성 2026-11-24 · 강동균 · 상태: **제안** (회원 인증 담당 강다인 님, 보안 조영준 님과 정한 뒤 구현)
> 관련 코드: `member/AuthPolicy.java`, `member/signup/SignupService.java`, `member/login/LoginService.java`, `member/guest/GuestService.java`, `auth/admin/AdminLoginService.java`, `member/web/ClientIpResolver.java`

## 1. 왜 필요한가

공용 서버에 k6로 데이터를 쌓거나 성능을 잴 때, 한 PC(한 IP)에서 계정을 수백 개 만들고 로그인합니다. 지금 제한은 이렇습니다.

| 정책 키 | 기본 | 관리자 화면 허용 범위 | 문제 |
|---|---|---|---|
| `auth.signup_rate_per_hour` (본인인증·가입) | 10 | 1~100 | 최대로 올려도 시간당 100개 |
| `auth.login_rate_per_min` (회원·관리자 로그인) | 20 | 1~600 | 분당 600이면 대체로 충분 |
| `guest.lookup_rate_per_hour` (비회원 예약 조회) | 10 | 1~1000 | 시험에 거의 안 씀 |

지금 쓸 수 있는 우회는 두 가지인데 둘 다 위험합니다.

- **값을 손으로 올렸다 내리기**: 1차 봇 대회 때 100으로 올렸다가 되돌리는 걸 **4일간 잊었습니다** (11-19 ~ 11-23). 사람이 기억해야 하는 방식은 언젠가 빠집니다.
- **IP 바꿔 보내기(`X-Forwarded-For` + 신뢰 프록시)**: 앱이 헤더의 IP를 믿게 하는 설정이라, 켜 두면 누구나 헤더만 바꿔 제한을 우회합니다. 공용 서버에는 넣으면 안 됩니다 (loadtest README).

그래서 **"정해진 IP만, 정해진 시각까지만" 풀리고 시각이 지나면 저절로 원래대로 돌아가는** 방법을 제안합니다.

## 2. 한 줄 요약

관리자가 "k6를 돌리는 IP"와 "언제까지"를 정하면, 그 IP의 인증 시도 제한만 그 시각까지 높은 값으로 바뀌고, 시각이 지나면 **아무도 안 건드려도** 원래 값으로 돌아간다.

## 3. 동작

```
요청 → ClientIpResolver(연결 주소, 신뢰 프록시 규칙 그대로) → ip_hash
     → 제한 확인: AuthPolicy.limitFor(키, ip_hash)
          ├─ 지금 < auth.rate_relax_until  그리고  ip_hash ∈ auth.rate_relax_ip_hashes  → 해제 값
          └─ 그 밖                                                                  → 평소 값 (지금과 같음)
```

- **자동 복구는 "읽을 때 비교"로 합니다.** 스케줄러가 값을 되돌리는 방식이 아니라, 읽을 때마다 `지금 < 종료 시각`을 봅니다. 앱이 죽어 있거나 스케줄러가 멈춰도 시각이 지나면 그 순간부터 평소 값입니다. 되돌리기를 빠뜨릴 수가 없습니다.
- **IP를 지정한 곳만 풉니다.** 전체를 풀면 그 사이 봇 대회 참가 봇이나 외부 봇이 가입 폭주를 할 수 있습니다. k6를 돌리는 PC의 IP만 지정합니다.
- **IP 판정은 지금과 같은 `ClientIpResolver`를 씁니다.** 신뢰 프록시 설정은 건드리지 않으므로 `X-Forwarded-For` 위조로 해제 IP인 척할 수 없습니다.
- **원본 IP는 저장하지 않습니다.** 이미 제한 키에 쓰는 것과 같은 `ip_hash`(HMAC)만 저장합니다. 관리자 화면은 IP를 받아 서버에서 해시로 바꿉니다.

## 4. 정책 값 (app_policy, ERD 패치 1개 — 새 표 없음)

| 키 | 예 | 뜻 |
|---|---|---|
| `auth.rate_relax_until` | `2026-11-27 18:00` (빈 값 = 해제 안 함) | 이 시각까지만 해제. **지금 + 24시간을 넘게 저장하면 거절** |
| `auth.rate_relax_ip_hashes` | `a1b2…,c3d4…` | 해제할 IP의 `ip_hash` 목록. 최대 5개 |
| `auth.rate_relax_signup_per_hour` | `2000` | 해제 동안 가입 한도 (허용 범위 1~5000) |
| `auth.rate_relax_login_per_min` | `3000` | 해제 동안 로그인 한도 (허용 범위 1~10000) |

- 비회원 조회는 해제 대상에서 뺍니다. 시험에 안 쓰고, 예약 번호 + 휴대폰 맞히기 공격을 막는 제한이라 풀 이유가 없습니다.
- **관리자 로그인도 해제 대상에서 뺍니다.** 관리자 비밀번호 대입은 시험과 무관하고 피해가 큽니다.

## 5. 관리자 화면 (ADM-08 정책 화면에 칸 하나)

- **"인증 제한 임시 해제"**: IP, 시간(1·3·6·12·24시간 중 고르기), 사유(5자 이상)
- 저장하면 `admin_action`에 누가·언제·사유·IP 해시·종료 시각이 남습니다. 정책 이력(`app_policy_history`)에도 남습니다.
- 해제 중에는 관리자 화면 위에 **"인증 제한 해제 중 — 18:00까지 (남은 2시간 10분)"** 띠를 띄웁니다. 띠에 "지금 끝내기" 버튼을 둡니다(두 단계 버튼).
- 연장하려면 다시 저장합니다. 이때도 지금 + 24시간 상한은 그대로입니다.

## 6. 코드 변경 (작게)

1. `AuthPolicy`: `limitFor(String key, String ipHash)` 추가. 해제 조건이 맞으면 해제 값, 아니면 지금의 `number(key)`. 1초 캐시는 그대로 씁니다.
2. `SignupService.checkSignupRate`, `LoginService`의 로그인 시도 확인: `number(…)` → `limitFor(…, ipHash)` (두 줄)
3. 관리자 정책 저장 검사(`PolicyBounds`): `rate_relax_until`이 과거이거나 지금 + 24시간을 넘으면 거절, IP 해시 목록 최대 5개
4. 해제 중 지표 `jejari_auth_rate_relax_active`(0/1) → Grafana 패널, 24시간 넘게 1이면 경보 (상한 검사가 뚫렸을 때 대비)

## 7. 하지 않는 것

- 신뢰 프록시(`jejari.auth.trusted-proxies`)를 공용 서버에 넣지 않습니다.
- 제한을 "0 = 무제한"으로 만들지 않습니다. 해제 중에도 상한은 있습니다(가입 5000/시간).
- 위험 점수 규칙은 그대로 둡니다. k6 계정도 점수·케이스가 생깁니다. 끝나면 실행 태그(`RUN_TAG`)로 지웁니다.

## 8. 테스트

| # | 시나리오 | 기대 |
|---|---|---|
| R1 | 해제 IP에서 종료 시각 전 가입 11번 | 전부 성공 (평소엔 11번째 429) |
| R2 | 해제 IP가 아닌 곳에서 같은 시험 | 11번째 429 (평소대로) |
| R3 | 종료 시각이 지난 뒤 해제 IP에서 가입 | 평소 한도 (자동 복구, 아무도 안 건드림) |
| R4 | `X-Forwarded-For`에 해제 IP를 넣고 다른 곳에서 요청 | 평소 한도 (위조로 못 품) |
| R5 | 종료 시각을 지금 + 25시간으로 저장 | 관리자 화면이 거절 |
| R6 | 관리자 로그인·비회원 조회 | 해제 중에도 평소 한도 |

## 9. 정해 주세요

- 담당: 회원 인증(강다인 님) 또는 보안·인프라(조영준 님). `AuthPolicy`는 두 분 다 건드린 코드입니다.
- 24시간 상한이 적당한지 (k6 성능 측정은 보통 몇 시간이면 끝남)
- 2차 봇 대회(11-26) 날에는 해제를 쓰지 않기로 정할지. 대회 중 해제가 켜져 있으면 공격자 봇이 같은 와이파이(같은 IP)일 때 같이 풀립니다.
