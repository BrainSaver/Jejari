# 멀티 인스턴스 대비 코딩 규칙 (초안)

작성자: 조영준 · 2026-11-16 · 상태: 초안 (팀 확인 전)

> 지금은 각자 PC에서 앱 1대 + 로컬 DB로 개발합니다. 2주차부터는 공용 서버에서 **앱을 여러 대** 띄워 통합 확인과 부하 테스트(T17·T18·T20)를 합니다.
> 혼자 돌릴 때는 잘 되다가 여러 대에서만 깨지는 코드를 미리 피하려는 규칙입니다. 다섯 개만 지키면 서버로 옮길 때 코드는 고치지 않고 `.env` 값만 바꾸면 됩니다.

## 한눈에

| # | 규칙 | 어기면 |
|---|---|---|
| 1 | 주소·포트·비밀번호·TTL을 코드에 쓰지 않는다 | 서버로 옮길 때 코드를 고쳐야 함 |
| 2 | 서버 메모리에 공유 상태를 두지 않는다 | 앱 A에 저장한 걸 앱 B가 모름 |
| 3 | 주기 작업은 두 대가 동시에 돌아도 안전하게 | 같은 만료·발행을 두 번 처리 |
| 4 | 데이터는 손으로 넣지 말고 스크립트로 남긴다 | 공용 서버에서 같은 데이터를 못 만듦 |
| 5 | 현재 시각은 `LocalDateTime.now(clock)` | 서버 시간대·테스트에서 시간이 어긋남 |

## 1. 환경마다 다른 값은 설정으로

```java
// ✗
String url = "jdbc:oracle:thin:@//localhost:1521/FREEPDB1";
redis.expire(key, Duration.ofMinutes(10));

// ✓ 접속 정보는 application.yml(${ENV}) → .env
// ✓ TTL·임계값은 app_policy에서 읽기 (CLAUDE.md "Redis")
redis.expire(key, policy.duration("reservation.pay_deadline_min"));
```

- 접속 정보는 이미 전부 `application.yml`의 `${ORACLE_HOST}` 같은 환경 변수입니다. 새 외부 연결을 추가할 때도 같은 방식으로.
- 비밀값은 `.env`에만 두고, 키 이름만 `.env.example`에 추가합니다.

## 2. 공유 상태는 Redis·DB에

```java
// ✗ 앱마다 따로 있는 메모리 → 앱 2대면 값이 둘
private static final Map<Long, Integer> holdCount = new ConcurrentHashMap<>();

// ✓ 모든 앱이 같이 보는 곳
redis.opsForValue().increment("limit:" + runId + ":" + ciHash);
```

- 금지 예: `static` 컬렉션 캐시, HTTP 세션(`HttpSession`), 앱 메모리의 대기열·카운터·락(`synchronized`, `ReentrantLock`으로 좌석 보호)
- `synchronized`는 **같은 앱 안에서만** 막습니다. 좌석·한도 같은 동시성은 `concurrency.md`대로 Redis Lua + DB 조건부 UPDATE로 막습니다.
- 바뀌지 않는 기준 데이터(역 목록 등)를 메모리에 캐시하는 건 괜찮습니다. 바뀌는 값이면 TTL을 짧게 하거나 Redis에 둡니다.
- 인증은 JWT라 서버에 세션이 없어서 이미 안전합니다.

## 3. 주기 작업(`@Scheduled`)은 중복 실행에 안전하게

앱이 2대면 `@Scheduled`도 2대에서 동시에 돕니다. 아래 셋 중 하나로 만듭니다.

| 방법 | 언제 | 예 |
|---|---|---|
| 조건부 UPDATE (중복돼도 한 번만 성공) | 상태 전이 | 만료 스캐너: `WHERE status = 'HOLD'` → 영향 행 1이면 내가 처리 (concurrency.md §6, §7.1) |
| `FOR UPDATE SKIP LOCKED` | 여러 대가 나눠서 처리 | 취소표 제안 (concurrency.md §9) |
| 리스 (Redis 키로 담당자 정하기) | 순서가 중요해 한 대만 해야 할 때 | outbox 릴레이 `relay:shard:{n}` (concurrency.md §11.2) |

```java
// ✗ 읽고 → 확인하고 → 저장 (두 대가 같은 행을 동시에 읽으면 둘 다 처리)
Reservation r = repo.findById(id);
if (r.isHold()) { r.expire(); }

// ✓ 판정과 변경을 한 문장으로
int updated = repo.expireIfHold(id);   // UPDATE ... WHERE id = :id AND status = 'HOLD'
if (updated == 1) { /* 내가 처리한 것 */ }
```

- Kafka 컨슈머도 같은 이벤트를 두 번 받을 수 있습니다. `processed_event`로 거릅니다 (concurrency.md §12).

## 4. 데이터는 스크립트로

- 기준 데이터: `db/seed/*.sql` (강동균 님 방식처럼 다시 실행해도 결과가 같게 `MERGE`)
- 테스트·부하용 데이터: SQL이나 생성 스크립트를 저장소에 커밋 (DATA-02·03)
- SQL Developer·IntelliJ로 손으로 넣은 데이터는 내 PC에만 있습니다. 공용 서버나 다른 팀원 PC에서는 없습니다.

## 5. 시각은 앱 시계로

```java
// ✗
LocalDateTime now = LocalDateTime.now();

// ✓ Clock 빈 주입 (common.config.ClockConfig, Asia/Seoul)
LocalDateTime now = LocalDateTime.now(clock);
```

- 서버 OS 시간대와 상관없이 같은 값이 나오고, 테스트에서 시간을 고정·이동할 수 있습니다 (`MutableClock`, `src/test/java/com/jejari/support`).
- DB의 "이미 지났는가" 비교는 `SYSTIMESTAMP`, 마감 시각 계산은 앱 시계 (concurrency.md §0.7).
