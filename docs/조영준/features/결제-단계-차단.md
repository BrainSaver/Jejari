# 결제 단계 차단 (봇 대회 보강 7번)

> 11-23 봇 대회 결과 회의에서 나온 보강 7개 중 7번. 담당 조영준. 절차 원천: `docs/concurrency.md` §7.5

## 한 줄 요약

위험 점수가 **케이스가 열리는 기준(80점) 이상**인 사람은 **결제를 시작하지 못하고**, 잡아 둔 좌석은 바로 다른 사람에게 돌아갑니다.

## 왜 필요한가

- 지금까지 위험 점수는 **대기열에서 늦게 들여보내는 데만** 썼습니다 (80점 = 80초 늦게).
- 봇은 기다렸다 들어와서 좌석 선점부터 결제까지 그대로 할 수 있었습니다.
- 결제는 표를 실제로 가져가는 마지막 관문이라, 여기서 한 번 더 막습니다.

## 흐름

```
결제 요청 → 멱등 키 처음? ──아니오(재요청)──→ 지금 결제 상태만 돌려줌 (막지 않음)
              │ 예
              ▼
        위험 점수 확인 (CI·카드·기기 중 최댓값, 이용 제한 계정 100)
              ├─ 기준 미만 / 점수 모름 → 평소대로 결제 (DB 트랜잭션 → PG)
              └─ 기준 이상 → 멱등 키 삭제 → HOLD 좌석 즉시 해제 → 403 PAYMENT_RISK_BLOCKED
```

## 설계 결정

| 결정 | 이유 |
|---|---|
| PG 부르기 **전**에 막음 | 돈이 나가기 전이라 환불·정산 문제가 없음 |
| 기준은 `risk.rule.case_threshold` 재사용 | 관리자가 A-07에서 기준을 바꾸면 케이스·결제 차단이 같이 움직임. 새 설정 키는 ERD 변경이 필요 |
| 막으면 좌석 **바로 해제** | 결제 마감까지 좌석이 묶이지 않게, 다른 사람이 바로 살 수 있게 |
| 해제는 actor `SYSTEM` | 사용자 취소로 세면 위험 점수가 또 오름 (이중 처벌 방지) |
| 점수를 **모르면 통과** | 대기열은 모르면 막지만(100점), 결제까지 그러면 Redis 장애 한 번에 모든 결제가 멈춤. 대기열에서 이미 한 번 걸렀음 |
| 같은 키 재요청은 막지 않음 | 이미 PG까지 간 결제를 중간에 끊으면 돈과 표가 어긋날 수 있음 |
| 기준값 30초 캐시 | 결제마다 app_policy를 읽지 않게 |

## 코드 위치

| 파일 | 하는 일 |
|---|---|
| `payment/PaymentRiskGuard.java` | 판정 (점수·기준·스위치·지표) |
| `payment/PaymentService.java` `start()` | 멱등 키 처음 잡은 직후에 판정을 부름 |
| `queue/domain/RiskPenaltyService.knownScore()` | 대기열과 같은 점수 규칙. 못 읽으면 빈 값 |
| `seat/SeatReleaseService.releaseForRiskBlock()` · `ReleaseReason.RISK_BLOCKED` | 본인 HOLD만 즉시 해제 (§7.1) |
| `payment/PaymentErrorCode.PAYMENT_RISK_BLOCKED` · `frontend/src/user/Pay.jsx` | 403과 화면 안내 |

## 운영

- **끄기:** 앱 설정 `jejari.payment.risk-block=false` (기본 켜짐)
- **지표:** `jejari_payment_risk_check_total{result="passed|blocked|unknown|off"}`. `unknown`이 늘면 Redis·Oracle 점수 조회 장애
- **로그:** `결제 단계 차단 member=… reservation=… 점수 … ≥ 기준 …`
