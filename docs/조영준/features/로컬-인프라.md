# 로컬 인프라 · 기동 점검 · CI

작성자: 조영준 · 코드 위치: `compose.yaml`, `docker/`, `.env.example`, `src/main/resources/application.yml`, `common/config/TimeZoneVerifier`, `common/config/RedisConfigVerifier`, `.github/workflows/ci.yml`

> 실행 명령은 저장소의 `docker/README.md`에 있습니다. 이 문서는 "무엇을, 왜 이렇게 했나"를 설명합니다.

## 한 줄 요약

`docker compose up -d` 한 번으로 모든 팀원이 같은 Oracle·MongoDB·Redis·Kafka·Prometheus·Grafana를 띄우고, 설정이 설계와 다르면 앱이 아예 뜨지 않게 한다.

## 어떻게 동작하나

```
.env (각자, 커밋 안 함) ──┬─→ docker compose ─→ Oracle · Mongo · Redis · Kafka · Prometheus · Grafana
                          └─→ Spring Boot (spring.config.import) ─→ 기동 점검 ─→ 실행
```

| 서비스 | 설정 | 첫 기동 때 자동으로 |
|---|---|---|
| Oracle 23ai Free | `TZ=Asia/Seoul` | ERD DDL(`docs/erd/jejari-erd.ddl.sql`) → 기준 데이터 시드(`db/seed`, 강동균) |
| MongoDB 8 | 앱 계정은 jejari DB 읽기·쓰기만 | behavior_log·queue_log·login_attempt 인덱스·TTL (`docker/mongo/mongo-init.js`) |
| Redis 7.4 | `noeviction` + `maxmemory 512mb`, AOF `everysec`, 비밀번호 | - |
| Kafka 4.1 (KRaft) | 보관 7일, 자동 토픽 생성 끔 | 토픽 4개 (`docker/kafka/create-topics.sh`) |
| Prometheus · Grafana | 5초 수집 | 데이터소스·대시보드 폴더 프로비저닝 |

- 모든 포트는 `127.0.0.1`에만 열어 같은 네트워크의 다른 PC에서 DB에 붙지 못합니다.
- **기동 점검**: 앱이 뜰 때 확인하고, 다르면 시작을 멈춥니다.
  - `TimeZoneVerifier`: JVM · DB 세션 · Oracle OS 시간대가 모두 `+09:00` (concurrency.md §0.7, T34)
  - `RedisConfigVerifier`: `maxmemory-policy=noeviction`, `appendonly=yes`, `appendfsync=everysec` (§14.5)
- **CI** (GitHub Actions): `./gradlew build`(인프라 없이 도는 테스트) + `check-erd.js`(ERD FAIL 0) + 공공데이터 시드 검사

## 왜 이렇게 했나

- **설정 실수를 "경고"가 아니라 "기동 실패"로**: 시간대가 하나만 어긋나도 결제 마감이 9시간 틀어지고, Redis가 기본 정책이면 메모리가 찰 때 `seat:hold` 키가 조용히 사라져 같은 좌석이 두 번 팔립니다. 둘 다 평소엔 티가 안 나서 로그 경고는 놓칩니다. compose에만 맡기면 compose 없이 띄운 서버에서 기본값으로 돌 수 있어 앱이 직접 확인합니다.
- **`noeviction`에 `maxmemory`를 같이**: 한도가 없으면 noeviction이 쓰기 오류로 드러나지 않고 메모리가 끝까지 차서 프로세스가 죽습니다.
- **`.env` 하나를 compose와 Spring이 같이 읽음**: 비밀번호를 두 곳에 따로 적다 어긋나는 일을 없애고, 비밀값은 저장소에 두지 않습니다 (`.env.example`에는 키 이름만).
- **Kafka 자동 토픽 생성 끔**: 토픽 이름 오타가 조용히 새 토픽을 만들어 메시지가 사라지는 것을 막습니다.
- **DB 서버 위치는 `.env` 값**: 지금은 각자 로컬 DB로 개발하고, 2주차 공용 서버로 옮길 때도 코드는 바꾸지 않습니다 ([멀티 인스턴스 대비 코딩 규칙](멀티인스턴스-코딩-규칙.md)).

## 검증한 것 (2026-11-16)

- 시드 23개 검증 항목 OK

## 주의할 점

- **초기화 스크립트는 빈 볼륨에서 한 번만** 돕니다. ERD가 바뀌면 Oracle 볼륨을 지우고 다시 띄웁니다 (데이터 삭제, `docker/README.md`).
- 지금 Oracle은 무료판이라 **CPU 2스레드·메모리 2GB** 제한이 있습니다. 부하 테스트 결과를 해석할 때 고려합니다.
- 관리형 Redis처럼 `CONFIG` 명령이 막힌 곳에서는 `jejari.redis.verify-config=false`로 끄고 콘솔에서 직접 확인합니다.
- 2026-11-16 기준 GitHub Actions는 조직 결제 잠금으로 실행되지 않습니다. 같은 검사를 로컬에서 돌려 확인합니다.
