# 운영 설정 (ADM-08, 화면 A-07)

작성자: 조영준 · 코드 위치: `admin/policy/PolicyAdminService`, `admin/policy/web/PolicyAdminController`, `frontend/src/admin/Settings.jsx`

> 처음 구현은 강동균 님이 대신 만들어 줌 (2026-11-17). 담당자로서 검토하고 2곳을 고침 (2026-11-18).

## 한 줄 요약

관리자가 `app_policy` 값(결제 기한, 대기열 입장 속도, 위험 점수 문턱 등)을 화면에서 바꾸면, **DB → 이력 → Redis 캐시** 순으로 반영되어 1초 안에 앱 모든 대가 새 값을 쓴다. 보기는 VIEWER, 바꾸기는 SUPERVISOR.

## 어떻게 동작하나

```
PUT /api/v1/admin/policies/{key} {value, version}   (SUPERVISOR)
  트랜잭션: UPDATE … SET version = version + 1 WHERE version = ?   ← 0행이면 409 (다른 관리자가 먼저 바꿈)
            INSERT app_policy_history (이전 값 → 새 값)
  커밋 뒤:  Redis policy:cache[key] = 커밋된 DB 값
앱들: 메모리(1초) → Redis policy:cache → (AppPolicy만) Oracle → 기본값
```

- 목록 화면은 DB 값과 Redis 캐시 값이 다르면 "캐시 …" 표시를 붙임 (어긋난 걸 눈으로 볼 수 있게)

## 검토에서 고친 것 (2026-11-18)

| 문제 | 고친 방법 | 테스트 |

## 왜 "캐시 키를 지우는" 방식이 아닌가

흔한 방법은 커밋 뒤 캐시를 지워 다음 읽기가 DB를 보게 하는 것이다. 하지만 이 프로젝트의 읽는 쪽이 제각각이다.

| 읽는 쪽 | Redis에 없으면 |
|---|---|
| `AppPolicy` (결제 기한 등) | Oracle → 기본값 |
| `AuthPolicy`, `BehaviorPolicy` | **기본값** (Oracle을 안 봄) |

그래서 지우면 일부 기능이 DB 값이 아니라 기본값으로 돌아간다 → 반드시 넣어야 하고, 넣기 실패는 알려야 한다.

## 주의할 점

- **SQL로 `app_policy`를 직접 고치면** Redis에 그 키가 있을 때 앱은 옛 값을 계속 씀 (AuthPolicy·BehaviorPolicy는 Redis에 없어도 DB를 안 봄). 값은 이 화면(API)으로 바꾼다
- **범위를 알려 주는 모듈은 아직 두 곳** (`AuthPolicy` 인증 7개 키, `BehaviorPolicy` 행동 로그 2개 키). 대기열(`queue.*`, 입장 속도 0이면 입장 멈춤)·결제 기한 등 `AppPolicy`·위험 점수는 범위가 없거나 구조가 달라 형식·음수만 막음. 범위가 생기면 그 모듈이 `PolicyBounds`를 구현하면 됨 (각 기능 담당과). 키 50개 점검표와 제안 범위: [정책-범위-점검](정책-범위-점검.md)
- 문자열 정책(`auth.argon2_params` 등)의 하한은 읽는 쪽만 검사함
- 테스트: `./gradlew test --tests 'com.jejari.admin.policy.*'` (단위 10개), `./gradlew infraTest --tests 'com.jejari.admin.policy.*'` (실제 Oracle·Redis 3개)
