# [deploy] 직접 배포한 뒤에도 자동 배포 상태가 옛 "CI 기다림"으로 남음

> 파일 이름: `docs/조영준/troubleshooting/20261119-자동배포-상태가-옛-판단으로-남음.md`

## 1. 문제

- 현상: 관리자 화면 "배포" 버튼(A-08)을 만들고 서버에서 직접 배포(`deploy.sh`)한 뒤 버튼을 눌렀는데, 배포 장치는 돌고 끝났지만 화면의 "마지막 판단"이 **그 전의 `WAITING_CI`(11:49)** 그대로
- 재현 조건: 서버가 이미 main 최신일 때 자동 배포 장치(`auto-deploy.sh`)가 돎 (직접 배포 직후, 또는 새 커밋이 없을 때)
- 영향: 화면이 틀린 상태를 보여 줌. Grafana 경보 "CI 대기가 1시간 넘게 이어짐"은 상태 파일을 보고 판단해서 **CI 문제가 없는데도 울릴 수 있었음**

## 2. 원인

- 가설: 버튼이 장치를 못 돌림 → `systemctl is-active`가 activating → inactive로 바뀌고 journal에 실행 기록이 있어 아님
- 최종 원인: `auto-deploy.sh`가 **main과 같으면 상태를 쓰지 않고 바로 끝남**. 상태 파일은 "마지막으로 뭔가 결정한 때"에 멈춰 있었고, 직접 배포(`deploy.sh`)는 상태 파일을 쓰지 않음

```bash
[[ "$HEAD_MAIN" == "$CUR" ]] && exit 0      # 기록 없이 종료
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| `deploy.sh`도 상태를 쓰게 | 직접 배포 직후 정확 | 상태를 쓰는 곳이 둘 | |
| **최신이어도 `OK <커밋> 최신 (main과 같음)`을 기록** | 장치가 돌 때마다 지금 상태가 남음, 한 곳에서만 씀 | 20분마다 기록 한 줄 (무시할 수준) | ✓ |

- 선택한 이유: 상태 파일은 "지금 서버가 어떤가"를 보여 주는 곳이라 돌 때마다 맞춰 주는 게 맞음. `auto-deploy.sh`는 BLOCKED 대상이 아니라 다음 배포로 바로 반영
- 바뀐 코드 위치: `deploy/auto-deploy.sh`

## 4. 수치

| 지표 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 직접 배포 뒤 상태 | `WAITING_CI cbb536a …` (옛 판단) | `OK 988a49b 최신 (main과 같음)` |
| 잘못된 "CI 대기" 경보 가능성 | 있음 (1시간 뒤) | 없음 |

- 측정 환경: 공용 서버, 버튼 API로 이 수정을 직접 배포해 확인

## 5. 정리

- 면접용 한 줄 요약: "배포 장치가 '할 일이 없을 때' 상태를 기록하지 않아 직접 배포 뒤 화면과 경보가 옛 판단을 보던 것을, 돌 때마다 현재 상태를 기록하게 바꿔 잘못된 경보를 없앴다."
- 다음에 비슷한 상황이면: 상태를 보여 주는 파일·지표는 **아무 일도 없을 때도** 갱신되는지 본다 (조기 종료 경로가 빠지기 쉬움)
