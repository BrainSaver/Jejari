> 파일 이름: `docs/조영준/troubleshooting/20261119-정책값이-저장돼도-조용히-무시됨.md`

## 1. 문제

- 현상: PERF-01 측정 전에 가입 제한 `auth.signup_rate_per_hour`를 관리자 API로 10000으로 올렸는데, 응답은 성공(버전 +1, 캐시 10000)이었지만 **가입 5번째에 여전히 429**
- 재현 조건: 범위(1~100)를 벗어난 값을 운영 설정(A-07)·`PUT /api/v1/admin/policies/{key}`로 저장
- 영향: 관리자는 바뀐 줄 알지만 앱은 옛 기본값을 씀. 더 나쁜 경우: 대기열 입장 속도에 `200.5`처럼 **소수**를 넣으면 입장 처리가 매초 예외로 실패해 **입장이 멈춤**

## 2. 원인

- 가설 1: 캐시가 늦게 반영됨 → API 응답의 `cachedValue`가 이미 10000이라 아님
- 가설 2: 앱이 값을 버림 → 앱 로그에 `인증 정책 auth.signup_rate_per_hour 값이 허용 범위(1~100) 밖이라 기본값 10을 씀`
- 최종 원인: **범위는 값을 읽는 모듈(`AuthPolicy`)에만 있고, 저장하는 관리자 API는 형식(숫자)·음수만 검사**. 두 곳의 기준이 달라 "저장 성공 → 실제로는 무시"가 생김. 같은 점검에서 대기열(`PolicyProvider`)·`AppPolicy`는 범위도 없고 `Long.parseLong`이라 소수면 예외

```
관리자 API check():  NUMBER = -?\d{1,15}(\.\d{1,6})?  → "10000", "200.5" 통과
AuthPolicy.number(): 1 ≤ v ≤ 100 아니면 기본값 + 경고
PolicyProvider.getLong(): Long.parseLong("200.5") → NumberFormatException (잡지 않음)
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 관리자 API에 키별 범위 표를 따로 적기 | 빠름 | 읽는 쪽과 두 군데라 또 어긋남 | |
| **읽는 모듈이 `PolicyBounds`로 범위를 알려 주고, 관리자 API가 저장 전에 그 범위로 거절** | 범위의 원본이 하나 (읽을 때 쓰는 상수 그대로) | 모듈마다 구현 필요 | ✓ |
| **"지금 값이 정수인 키에는 정수만"** (소수 차단) | 키 목록 없이 모든 키에 적용, 새 키도 자동 | 정수 키를 소수 키로 바꿀 땐 한 번 막힘 | ✓ |

- 선택한 이유: 기준이 두 곳이면 언젠가 다시 어긋남. 소수 문제는 범위가 정해지기 전에도 기능을 멈출 수 있어 키 목록 없이 먼저 막음
- 바뀐 코드 위치: `common/policy/PolicyBounds.java`, `admin/policy/PolicyAdminService.java` (`checkRange`·`checkKeepsInteger`), `member/AuthPolicy.java`·`behavior/sink/BehaviorPolicy.java` (범위 알려 주기만, 동작 그대로)

## 4. 수치

| 지표 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 범위 밖 값(10000) 저장 | 200 성공 → 앱은 기본값 | **400** "1~600 사이만" (서버 앱 2대 모두 확인) |
| 소수(20.5) 저장 | 200 성공 | **400** "정수만" |
| 범위 검사가 있는 키 | 0 / 50 (관리자 API 기준) | 9 / 50 (나머지는 담당 확정 중) |

- 측정 환경: 공용 서버, `PolicyAdminServiceTest` 10개
- 측정 방법: 서버에서 관리자 로그인 후 `PUT /api/v1/admin/policies/auth.login_rate_per_min` 에 10000·20.5

## 5. 정리

- 면접용 한 줄 요약: "운영 설정을 저장하는 쪽과 읽는 쪽의 검증 기준이 달라 '저장은 성공, 실제로는 무시'가 생겼고, 범위의 원본을 읽는 모듈 하나로 두고 관리자 API가 그 범위로 저장 전에 거절하게 바꿔 조용한 실패를 400 오류로 드러냈다."
- 다음에 비슷한 상황이면: 같은 값을 **쓰는 곳과 읽는 곳의 검증이 같은지** 먼저 본다. 읽는 쪽이 "조용히 기본값"으로 넘어가면 쓰는 쪽에서 반드시 막는다
