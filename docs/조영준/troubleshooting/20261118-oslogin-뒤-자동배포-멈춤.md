# [deploy] OS Login을 켠 뒤 자동 배포가 앱 재시작에서 멈춤

| 항목 | 내용 |
|---|---|
| 작성자 | 조영준 |
| 날짜 | 2026-11-18 |
| 상태 | 해결 |
| 관련 커밋·이슈 | `deploy/sudoers-jejari`, `deploy/setup-server.sh` |

> 파일 이름: `docs/조영준/troubleshooting/20261118-oslogin-뒤-자동배포-멈춤.md`

## 1. 문제

- 현상: 팀원이 14:12에 올린 화면 수정이 17분이 지나도 공용 서버에 안 보임. 자동 배포 상태는 `FAILED 70cd905 deploy.sh 실패`
- 재현 조건: VM에 OS Login(`enable-oslogin=TRUE`)을 켠 뒤 처음 도는 자동 배포
- 영향: 서비스는 정상(두 앱 모두 재시작 전에 멈춰 옛 버전으로 응답). 대신 자동 배포가 "실패한 커밋은 반복하지 않음" 설정 때문에 다음 커밋까지 멈춤 → 팀원 변경이 반영되지 않음

## 2. 원인

- 가설: 빌드 문제 → 로그를 보니 화면·jar 빌드는 끝났고 **앱 재시작에서** 실패

```
sudo: a password is required
dita_810 : user NOT in sudoers ; COMMAND=/usr/bin/systemctl restart jejari@8080
getent group google-sudoers  →  google-sudoers:x:1001:   (구성원 없음)
```

- 최종 원인: OS Login을 켜면 구글 게스트 에이전트가 **메타데이터 SSH 키로 만든 기존 계정(`dita_810`)을 `google-sudoers`에서 뺀다.** 자동 배포는 `dita_810`으로 돌고 `sudo systemctl restart`가 필요해서 막힘
- 놓친 이유: OS Login을 켠 직후 **내 계정의 sudo만** 확인하고, 배포를 실제로 돌리는 계정의 sudo는 확인하지 않음

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| `dita_810`을 다시 `google-sudoers`에 넣기 | 예전과 같음 | 에이전트가 다시 뺄 수 있음, sudo 전체라 넓음 | |
| OS Login 끄기 | 바로 됨 | 팀장님 접근을 계정 단위로 관리하는 이점이 사라짐 | |
| **`/etc/sudoers.d/jejari`로 제자리 서비스 명령만 허용** | 에이전트가 건드리지 않는 파일, **예전보다 좁은 권한** | 허용 명령을 늘릴 땐 파일 수정 | ✓ |

- 허용: `jejari@8080·8081` start·stop·restart, `jejari-autodeploy` 실행, 타이머 켜기·끄기. 그 밖의 sudo는 거부 (`cat /etc/shadow` 거부 확인)
- 설치: `visudo -cf`로 문법 검사 뒤에만 설치 (`setup-server.sh`에 넣음). 잘못된 sudoers는 sudo 전체를 망가뜨림
- 바뀐 코드 위치: `deploy/sudoers-jejari`(새), `deploy/setup-server.sh`

## 4. 수치

| 확인 | 전 | 후 |
|---|---|---|
| 자동 배포 | `FAILED 70cd905` (재시작에서 sudo 거부) | `OK 70cd905 자동 배포 완료` (앱 2대 UP) |
| 팀원 화면 수정 `e42566e` | 서버에 없음 | 반영 (화면 번들 `index-E0Wk…` → `index-pPth…`) |
| `dita_810`의 다른 sudo | 전체 허용 (OS Login 전) | 거부 |

- 측정 환경: GCP e2-standard-4, 앱 2대, OS Login 켜짐

## 5. 정리

- 면접용 한 줄 요약: "OS Login을 켜자 기존 서비스 계정의 sudo가 사라져 자동 배포가 앱 재시작에서 멈췄고, sudo 전체 대신 서비스 재시작 명령만 허용하는 sudoers로 바꿔 복구하면서 권한도 예전보다 좁혔다."
- 다음에 비슷한 상황이면: 접근 방식(로그인·권한)을 바꾼 뒤에는 **사람 계정이 아니라 자동화가 쓰는 계정으로** 한 번 끝까지 돌려 본다. 그리고 자동화가 실패하면 알림이 필요하다 (지금은 상태 파일뿐이라 팀원이 먼저 발견함)
