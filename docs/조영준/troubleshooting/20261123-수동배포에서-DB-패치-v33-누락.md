# [deploy] 수동 배포에서 DB 패치 v33이 빠져 ORA-00904 130건

| 항목 | 내용 |
|---|---|
| 작성자 | 조영준 |
| 날짜 | 2026-11-23 |
| 상태 | 해결 |
| 관련 커밋·이슈 | f1bcd5e(ERD v33), e96590f(비회원 예매 코드), 이 문서와 같은 커밋(deploy.sh 패치 확인) |

## 1. 문제

- **현상:** 14:08(KST)에 6617d81까지 수동 배포한 뒤 앱 로그에 `ORA-00904: "MEMBER_TYPE": invalid identifier`가 났다.
  - 14:21까지 130건이다 (게스트 정리 조회 114, 게스트 예매 16).
  - health는 200이라 겉으로는 정상이었다.
- **재현 조건:**
  - CI가 결제 잠김으로 멈춰 있어 수동 배포(`bash deploy/deploy.sh`)를 했다.
  - 배포 범위에 새 DB 패치(`db/patch/v33.sql`)와 그 컬럼을 쓰는 코드가 같이 있었다.
- **영향:**
  - 비회원 예매가 실패했다.
  - 같은 검사(`GuestGuard`)를 거치는 취소표 대기 등록과 내 정보 변경도 실패할 수 있었다.
  - 예매·로그인은 영향이 없었다.

## 2. 원인

- **처음 가설:** "재배포하면 DB도 자동으로 맞춰진다" → 확인해 보니 사실이 아니었다.
- **확인한 것:** `deploy.sh`에는 DB 패치를 넣는 단계가 없다.
  - 패치는 자동 배포가 BLOCKED로 멈췄을 때 A-08 [적용]으로만 들어간다 (`DeployApprovalService`).
- **최종 원인:**
  - 자동 배포는 CI 확인이 BLOCKED 판단보다 앞에 있다. CI가 잠기면 WAITING_CI에서 멈춰 BLOCKED·A-08 패치 화면이 나오지 않는다.
  - 그 상태에서 사람이 `deploy.sh`를 직접 돌리면 패치 없이 코드만 올라간다.

```
journalctl -u jejari@8080 | grep ORA-00904   → 130  (05:08~05:21 UTC)
dba_tab_columns MEMBER.MEMBER_TYPE           → 없음
db-patches.applied                           → v0.sql(11-19)만
```

## 3. 해결

| 선택지 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 운영 규칙으로만 ("수동 배포 전에 패치 확인") | 코드 변경 없음 | 사람이 또 잊음 (오늘 Grafana 재시작도 빠뜨림) | |
| deploy.sh가 패치를 항상 자동 적용 | 편함 | 모르는 사이 DB가 바뀜, 팀 규칙(DB 변경은 사람이 확인)과 어긋남 | |
| deploy.sh가 **빠진 패치를 찾아 멈추고**, 확인 후 `APPLY_PATCHES=1`로 적용 | 놓치지 않으면서 사람이 확인 | 한 번 더 실행해야 함 | ✓ |

- **즉시 조치:** v33.sql 적용 → ORA-00904 0건, health 200.
- **바뀐 코드:** `deploy/deploy.sh`
  - 지난 배포 이후 바뀐 `db/patch/vNN.sql` 중 `~/jejari-app/db-patches.applied`에 기록이 없는 것이 있으면 빌드 전에 멈춘다.
  - `APPLY_PATCHES=1`은 버전 순서대로 넣고 기록한다. ORA·SP2·PLS 오류가 있으면 중단한다.
  - `SKIP_PATCH_CHECK=1`은 이미 넣었을 때 쓴다.
  - 배포 뒤에는 Grafana·Caddy 재시작 같은 서버 할 일을 알려 준다.

## 4. 수치

| 지표 | 개선 전 | 개선 후 |
|---|---|---|
| 패치가 빠진 수동 배포 | 코드가 올라가고 오류 130건 | 빌드 전에 멈춤 (앱은 그대로) |
| ORA-00904 (v33 적용 뒤) | 130건 / 13분 | 0건 |

- **측정 방법:** 임시 git 저장소에서 7가지를 확인했다 (미적용 → 멈춤, 일부 기록, APPLY, 재실행, SKIP, ORA 오류 → 중단, 경보 변경 → 알림).

## 5. 정리

- **면접용 한 줄 요약:** "CI가 멈춰 수동 배포하던 중 DB 패치 없이 새 코드가 올라가 컬럼 없음 오류가 났고, 배포 스크립트가 적용 기록과 비교해 빠진 패치가 있으면 빌드 전에 멈추도록 바꿔 같은 실수를 막았다."
- **다음에 비슷한 상황이면:**
  - 자동화가 막힌 동안 우회 경로(수동 배포)가 자동화의 안전장치(BLOCKED)까지 건너뛰지 않는지 먼저 본다.
  - health 200만 보지 말고 배포 직후 앱 로그 오류 수를 같이 본다.
