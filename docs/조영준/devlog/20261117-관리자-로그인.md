## 어떻게 했나

- `AdminLoginService`가 강다인 님의 `PasswordHasher`·`AuthLimiter`·`AuthPolicy`·`LoginAttemptLog`를 그대로 사용
- 토큰 발급은 기존 `AuthTokenService.issue(ADMIN, adminId, …)`. `AdminRoleLookup`으로 현재 권한을 읽어 `adm`에 넣음
- 다른 팀원 파일은 추가만: `LoginAttemptLog.recordAdmin()`(강다인), `Purpose.ADMIN_LOGIN`·정규화 규칙·테스트 예시값(김성원), 테스트 도우미에서 관리자 토큰에 권한 넣기(김성원·내 테스트)

## 왜 이렇게 했나

- **pepper 고정**: admin_user에 `pepper_key_id`가 없음. 관리자는 몇 명뿐이라 ERD 변경 대신 현재 pepper로만 검증
- **첫 계정을 기동 때**: 해시가 각자의 pepper에 묶여 시드 SQL로 공유 불가
- **권한은 토큰에만 먼저**: 관리자 API가 아직 없어 `ADMIN` 하나로 막고, 나중에 `@PreAuthorize`만 붙이면 됨
- **adm 없는 관리자 토큰은 위조로 봄**: 관리자 토큰을 만드는 곳은 로그인 하나뿐이라 adm이 빠졌다면 정상 토큰이 아님

## 막힌 점과 해결

- `@EnableMethodSecurity`만 켜면 권한 거부 예외가 공통 처리기의 "예상 못한 오류"로 빠져 **500**이 됨 → `AccessDeniedException`을 403(관리자 경로는 ADMIN_FORBIDDEN)으로 처리하는 핸들러 추가, 테스트로 확인
- 관리자 토큰 형식이 바뀌어 기존 테스트 2개(권한 없는 관리자 토큰 사용) 실패 → 테스트 도우미가 관리자일 때 VIEWER를 넣도록 수정 (테스트 의도는 그대로)
- `Purpose`에 종류를 추가하자 `Pseudonymizer`·테스트의 `switch` 식이 컴파일 오류 → 각각 규칙·예시값 추가 (enum 끝에 추가만, 기존 해시 영향 없음)
- 로컬 Oracle이 v16 → 볼륨 재생성으로 v17
