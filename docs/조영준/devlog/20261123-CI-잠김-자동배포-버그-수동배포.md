# 2026-11-23 — CI 잠김, 자동 배포가 옛 커밋을 고른 버그, 수동 배포

## 상황

- 11-19 BLOCKED(47e7a14, ERD v30)는 팀이 관리자 화면 A-08 승인으로 풀었다 (11-19 17:11, 11-20 14:10). 서버는 11-20 17:58에 822ce67까지 배포됐다.
- 11-19에 만든 정책 범위 코드(7b77b79)도 이 배포에 들어갔다.
- jejari-model 타이머는 CPU 제한 없이 설치돼 있다. 제한을 넣을지는 아직 정하지 않았다.

## 1. CI 전부 실패 — GitHub 계정 결제 잠김

- 11-23 09:14부터 모든 CI 실행(ERD check, Gradle build)이 2~3초 만에 실패한다.
- check-run 주석에 남은 원인은 `The job was not started because your account is locked due to a billing issue.`이다. 코드 문제가 아니라 작업이 아예 시작되지 않는다.
- 자동 배포는 CI가 성공한 커밋만 배포하므로, 이 상태에서는 새 커밋을 배포하지 않는다 (WAITING_CI).

## 2. 자동 배포가 3일 전 커밋을 고른 버그

**현상:** 09:21 `BLOCKED 27f50db`. 막힌 파일 목록에 db/patch v0~v32와 시드가 보였다.

**원인:**

```
main:      ... ─ 822ce67 (배포된 것) ───────────┐
                                               ├─ a75dc75 (merge, main 최신)
SeongWon:  ... ─ 27f50db (11-20 00:50) ────────┘
                 ↑ 첫 번째 부모
```

- 김성원 님 브랜치에서 `main을 SeongWon에 합친` merge가 그대로 main에 올라갔다 (fast-forward). 그래서 main의 첫 번째 부모 줄이 SeongWon 쪽 옛 커밋으로 이어졌다.
- `auto-deploy.sh`는 `git rev-list --first-parent 배포된것..main`으로 최신부터 CI 성공 커밋을 찾는다. a75dc75는 CI가 실패해 건너뛰었고, 27f50db(11-20 CI 통과)를 골랐다.
- 27f50db는 822ce67의 후손이 아니다. 배포하면 3일치가 되돌아간다 (파일 420개, 5만 줄 삭제).

**왜 막혔나:** 되돌림 범위에 db 파일이 있어 BLOCKED가 걸렸을 뿐이다.
- 앱 코드만 되돌리는 경우였다면 승인 없이 자동으로 배포됐을 것이다.
- A-08에서 승인하면 되돌림 배포가 된다.

**CI가 정상이어도 생긴다:** CI가 도는 3~5분 동안은 최신 커밋이 "진행 중"이라 건너뛰기 때문이다.

**해결 (CI가 풀린 뒤):** 후보 커밋마다 `git merge-base --is-ancestor "$CUR" "$sha"`로 배포된 커밋의 후손인지 확인하고, 아니면 건너뛴다.

## 3. 수동 배포

- 서버에서 `sudo -iu dita_810; cd ~/Jejari; bash deploy/deploy.sh`로 main 최신 32d72d0을 배포했다. 앱은 active이고 health 확인은 200이다.
- `deployed-sha`가 바뀌어 27f50db BLOCKED가 풀렸다. Grafana "자동 배포 멈춤" 경보가 RESOLVED로 디스코드에 왔다.
- 직후 올라온 930c7ce는 CI 실패로 WAITING_CI다. 정상 동작이다.
- 윈도우 PowerShell은 실행 정책 때문에 `gcloud.ps1`을 막는다. `gcloud.cmd`를 쓰거나 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`로 푼다.

**운영 방식 (CI가 풀릴 때까지):** 팀원이 요청하면 조영준이 로컬 테스트 → 서버 `deploy.sh` → `systemctl start jejari-autodeploy` 순서로 수동 배포한다. "CI 대기 1시간" 경보는 원인을 알고 있으니 무시한다.

## 5. jejari-model CPU 제한 — 그리고 3일째 실패 중이던 것 발견

- 실행 시간을 보다가, 11-20 16:19부터 매시간 2초 만에 "꺼내기 실패"로 끝나고 있음을 찾았다.
  - **원인:** 최근 1일 행동 로그 0건(주말) → `grep` 0건 → `pipefail`로 말없이 종료.
  - **고침:** `tools/ml/export_live.sh` grep 두 곳에 `|| true`. 0건은 이제 "행동 로그 없음"으로 정상 종료된다.
- **CPU 제한:** 작업이 컨테이너 안에서 돌아 systemd `CPUQuota`·`Nice`가 닿지 않는다. 그래서 `docker run --cpus`로 걸었다.
  - 매시간 점수는 1개, 일요일 재학습은 2개.
  - 유닛 파일을 바꾸지 않아서 자동 배포 BLOCKED 대상이 아니다.
- 트러블슈팅: [모델 보조 의견 3일간 매시간 실패](../troubleshooting/20261123-모델-보조의견-3일간-매시간-실패.md)
- 서버 반영은 다음 수동 배포 때 한다.
