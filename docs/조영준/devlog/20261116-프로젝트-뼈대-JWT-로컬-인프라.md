## 어떻게 했나

- 인증: `Bearer 검증(서명·만료, DB 안 봄) → AuthPrincipal`, 재발급은 `UPDATE … WHERE 해시 = 옛 값 AND 폐기 안 됨 AND 만료 안 됨` 한 문장
- 인프라: `.env` 하나를 compose와 Spring이 같이 읽음. 포트는 127.0.0.1에만
- 검증 순서: 단위 테스트(DB 없이) → 실제 컨테이너로 기동 → 실제 DB에서 흐름 확인 → 일부러 설정을 틀리게 해서 막히는지 확인

## 왜 이렇게 했나

- **회전해도 session_id 유지**: session_id가 CCTV·행동 로그의 연결 키라 15분마다 바뀌면 안 됨. ERD를 바꾸지 않는 방법을 고름
- **401 코드 구분**: 만료(재발급하면 됨)와 위조(다시 로그인)를 프론트가 바로 구분
- **기동 실패로 막기**: 시간대·Redis 정책 오류는 평소엔 티가 안 나고 사고가 크다 (마감 9시간 어긋남, 좌석 이중 판매)
- **로컬 DB로 개발**: 공유하는 건 데이터가 아니라 코드·DDL·시드. 서버로 옮겨도 `.env`만 바뀜
- **감수한 단점**: 로그아웃 후 액세스 토큰 최대 15분 유효, 두 탭 동시 재발급 시 세션 폐기 가능

## 막힌 점과 해결

- 만료된 Bearer를 단 채 `/auth/refresh`를 부르면 필터가 먼저 401 → 재발급 불가. 인증 경로(로그아웃 제외)에서는 Bearer를 읽지 않게 수정, 회귀 테스트 추가
- 첫 기동 때 Mongo 종료 (`createIndexes`에 인덱스 명세를 넘김): `troubleshooting/20261116-mongo-init-인덱스-생성-실패.md`
- 로컬 Oracle이 v10 스키마로 남아 있었음 → 볼륨 재생성으로 최신 DDL 적용
- GitHub Actions가 전부 실패 → 코드가 아니라 조직 결제 잠금(job이 시작도 안 됨). 같은 검사를 로컬에서 돌려 확인
- Git Bash에서 `docker compose exec`에 넘긴 `/opt/...` 경로가 Windows 경로로 바뀜 → `MSYS_NO_PATHCONV=1`
- 회원가입·로그인 API가 404 → 강다인 님 코드는 비밀값 세 개(HMAC·암호화·pepper)가 모두 있어야 회원 기능을 켬(약한 대체값으로 돌지 않게). 키를 채워 해결
- 본인인증이 400 → Git Bash에서 한글을 curl로 그대로 보내면 UTF-8이 아닌 인코딩으로 가서 JSON을 못 읽음. `테` 같은 이스케이프로 보내면 정상 (서버 문제 아님, k6는 UTF-8이라 영향 없음)
- 시드 적재 때 `SP2-0158: unknown SET option "--"` 경고 → `02-seed.sh`의 `SET SQLBLANKLINES ON` 뒤 줄 끝 주석 때문 (SQL*Plus SET은 줄 끝 주석 불가). 데이터는 정상
