## 통합 테스트를 CI에 (강동균 님 요청, 보완할 일)

- 지금까지 통합 테스트(`@Tag("infra")`, 46개 파일)는 각자 PC에서 `docker compose up -d` 뒤 `./gradlew infraTest`로만 돌았다. CI(`ci.yml`)는 인프라 없이 `test`만
- 46개를 나눠 보니 **Oracle 없이 도는 건 대기열·Kafka 발행 쪽뿐**(대기열 `@QueueInfraTest` 묶음 + `QueueApiInfraTest`·`QueueWiringInfraTest`·`KafkaEventPublisherInfraTest`). 나머지는 앱 전체 컨텍스트라 Oracle이 필요하다. Oracle 없이 Mongo만 쓰는 테스트는 없어 push 작업엔 Mongo를 띄우지 않음
- 새 작업 `.github/workflows/infra-test.yml`:
  - **push·PR마다** "Infra test (Redis·Kafka)": Redis·Kafka(+토픽 만들기)만 띄우고 `./gradlew infraTest -PnoOracle` (`@Tag("no-oracle")`만)
  - **매일 02:00 KST** "Infra test (전체, Oracle 포함)": compose로 Oracle·Mongo·Redis·Kafka를 띄움(Oracle 첫 기동이 최신 DDL·시드를 넣음) → `./gradlew infraTest` 전부. Actions 화면에서 바로 돌릴 수도 있음(`workflow_dispatch`)
  - 비밀값은 저장소에 두지 않음: `.github/scripts/ci-env.sh`가 실행마다 임의 값으로 `.env`를 만들고 버림
- `build.gradle` `infraTest`에 `-PnoOracle`(태그 식 `infra & no-oracle`). 태그를 단 4곳: `QueueInfraTest`(메타 애너테이션)·`QueueApiInfraTest`·`QueueWiringInfraTest`·`KafkaEventPublisherInfraTest`. **새 통합 테스트는 태그가 없으면 밤에만 돈다** (Oracle이 필요하다고 보는 게 안전한 기본값)
- 내 PC에서 확인: 따로 띄운 Redis·Kafka(compose 프로젝트 `jejari-citest`, 끝나고 볼륨까지 지움)로 `infraTest -PnoOracle` → **18개 클래스 200개 통과**. 밤 작업(Oracle 포함)은 아직 Actions에서 한 번도 안 돌았음 → main에 합친 뒤 Actions에서 "Run workflow"로 한 번 확인
- 자동 배포와의 관계: 자동 배포는 그 커밋의 check-run이 **모두** 성공해야 배포한다 → push마다 Redis·Kafka 작업(약 3~5분)이 끝나야 배포됨. 밤 작업은 그 시각 main 최신 커밋에 결과가 붙으므로, 밤 작업이 실패하면 그 커밋이 아직 배포 전일 때 `CI_FAILED`로 멈춘다 (의도: 통합 테스트가 깨진 커밋은 올리지 않음)
