## 왜 이렇게 했나

- **팀원 접근은 세 층으로 나눔**: ① 서비스(https) 전원 ② 서버 운영(SSH) 두 명 ③ 클라우드(결제·방화벽) 주인만. 팀원이 서버를 "보는" 일은 Grafana로 해결
- **OS Login**: 구글 계정 단위라 권한을 빼면 즉시 차단, 접속 기록이 사람별로 남음. 메타데이터 SSH 키 방식은 VM 설정을 바꿀 수 있는 넓은 권한이 필요해 피함
- **Grafana는 익명 대신 공용 보기 전용 계정**: 익명이면 인터넷 전체에 지표가 보임. 팀원은 SSH 없이 보고, 바꾸는 건 못 함
- **자동 배포는 서버가 가져오는 방식**: GitHub에 GCP 접속 권한을 맡기지 않음. CI 결과도 공개 API로 봄
- **최신 커밋만 기다리지 않음**: 커밋이 CI보다 자주 오는 날엔 영영 배포를 못 함 → CI가 성공한 가장 최근 커밋
- **DB 변경은 자동으로 하지 않음**: 패치가 버전마다 형식이 달라 자동 적용이 위험. 멈추고 사람이 맞춘 뒤 직접 배포하면 풀림
- **Oracle만이 아니라 Mongo·Redis도 함께 비움**: 회원·예약 번호가 1부터 다시 시작해, 남은 매수 카운터·대기열·행동 로그를 새 회원이 물려받을 수 있음
- **재배포 규칙을 정함**: 커밋마다가 아니라 ERD 변경·통합 확인·시연 전에만. 코드 재배포와 DB 변경은 따로 따라가야 함
- **SSH는 IAP를 먼저 확인하고 기본 규칙 삭제**: 순서가 바뀌면 아무도 못 들어감. 3389(RDP)도 Linux VM엔 필요 없어 같이 닫음
- **공개 문서에 서버 IP를 적지 않음**: 사이트가 공개라 스캔 대상이 되지 않게. 주소는 팀 채널로
- **넘겨받기 전에 직접 재생성**: 남의 결과 숫자를 그대로 옮기지 않고, 어제 버그가 났던 바로 그 DB에서 다시 돌려 고쳐진 것을 확인. 노이즈도 수치가 아니라 행동 로그에 실제로 들어 있는지 Mongo에서 셈
- **강도를 이메일 `g{강도}`에 남기고 한 번에 섞어 실행**: 강도마다 따로 돌리면 실행마다 좌석·시각 조건이 달라져 비교가 흐려짐. 한 실행 안에서 비교하면 같은 조건
- **연타 뒤 1초 쉬고 대기열로**: 대기열 진입이 연타 직후 바로 오면 그 간격도 빠른 간격으로 세져 경계가 한 칸 밀림. 연타 수만 정확히 재려고
- **steady는 시작 시각을 t0 + i×간격에 맞춤**: "요청 → 응답 → sleep"이면 응답 시간 흔들림이 간격에 섞여 변동계수가 커짐. 서버는 요청을 받은 시각으로 간격을 잼
- **규칙을 내가 바꾸지 않음**: 문턱 아래 0점·일정 간격 15점은 강다인 님 설계 판단. 측정 결과와 후보만 공유
- **운영 설정 캐시는 지우지 않고 반드시 넣음**: AuthPolicy·BehaviorPolicy는 Redis에 없으면 DB가 아니라 기본값을 씀 → 지우면 그 기능들이 기본값으로 돌아감
