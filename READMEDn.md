# 강다인(D) 작업 정리

브랜치 `DaIn` · 담당: 행동 로그, 규칙 위험 점수, 의심 구간 타임라인, 취소·환불, 취소표 대기, 회원·모의 본인인증, 개인정보 암호화, 위험 사용자 관리자 화면

> 이 파일은 D 파트가 바꾼 내용을 한눈에 보기 위한 요약입니다. 자세한 내용은 각 링크의 문서를 보세요.

### 2. RESTRICTED 회원 규칙 보완

**문제**: 제한 회원은 대기열 패널티만 받았는데, 취소표 대기는 대기열 입장 토큰 없이 신청하고 순서도 위험 점수와 무관해서 패널티를 우회하는 길이 됐습니다.

**결정**: RESTRICTED = 예매 가능 + 대기열 패널티 100점 고정 + **취소표 대기 신청 불가**

| 파일 | 바뀐 곳 |
|---|---|
| `docs/기능설계서.md` | 2장 회원 상태 표, QUE-01(RESTRICTED면 100점으로 계산), WL-01 규칙·예외, 9장 에러 코드 `WAITLIST_RESTRICTED`(403), 11장 3번 해결 표시 |
| `docs/ui/U-10.md` | 오류 표시에 `WAITLIST_RESTRICTED` 문구 추가 |

스키마(ERD) 변경은 없습니다.

### 4. 팀 확인이 필요한 것

| 대상 | 내용 |
|---|---|
| 강동균 (ERD) | `behavior_log`에 `event_id` + 유니크 인덱스 추가 (Kafka 재전달 시 중복 저장 방지) |
| 강동균 (ERD) | `identity_verification.member_id` NULL 허용 여부 (인증 실패 이력 저장) |
| 팀 | `member.name` 평문 유지 여부와 "평문 개인정보 0건" 지표 대상 (제안: 휴대폰·CI·카드·IP) |
| A·B·C | 담당 API에 행동 로그 `mark()` 한 줄씩 넣기 |
| A | 대기열 진입 시 RESTRICTED면 100점으로 계산 |
| E | 가입·로그인이 같은 Argon2id `PasswordHasher` 사용 |
| 프런트 | 기기 지문 헤더 `X-Device-Id` 생성 방식 (제안: localStorage UUID) |
