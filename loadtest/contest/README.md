## 버튼 하나로 진행 (집계자, 2026-11-23~)

```bash
node loadtest/contest/web/server.js        # → http://localhost:8098 (이 PC에서만 열림)
```

**쓰는 법은 [`진행-화면-사용법.md`](진행-화면-사용법.md)** (화면 맨 위 "사용 방법"에도 그대로 보임).

관리자 ID·비밀번호·태그·사람 시간(기본 10분)을 넣고 봇을 고른 뒤 **대회 시작**을 누르면 아래를 차례로 합니다.
로그와 결과는 `loadtest/contest/results/<태그>/` (log.txt · eval.txt · compare.md · summary.json).

| 단계 | 하는 일 |
|---|---|
| 점검 | Node 18+, docker compose, bash, 봇마다 `needs` 패키지, 관리자 로그인 |
| 앱·인프라 | 앱이 꺼져 있으면 `docker compose up -d --wait` → `gradlew buildFrontend bootRun` (로그 `results/app.log`, 이 화면을 끄면 앱도 꺼짐). 이용자 화면이 있는지 확인 |
| 지난 기록 정리 | Redis의 IP별 가입·로그인 시도 카운터(`rate:signup:*`·`rate:login:*`)만 비움 |
| 대회 운행 만들기 | `day.sh start` (이 PC만 가입·로그인 한도 해제 — 4시간 뒤 저절로 끝남, 행사·운행 만들고 판매 열기) |
| 봇 명의 만들기 | 봇마다 `MODE=signup` (동시에). 실패한 봇은 빼고 계속 |
| 사람 흐름 확인 | 가입 → 로그인 → 대기열 → 좌석 → 결제 → 취소를 API로 한 번. **1차 대회처럼 사람이 결제에서 막히면 여기서 멈춤** (점검 계정은 `lt{태그}p.probe…`라 평가에 안 들어감) |
| 사람·봇 예매 | 접속 주소·이메일 형식·남은 시간을 크게 보여 줌. 봇 `MODE=buy`가 같이 출발. 사람 시간이 끝나고 봇이 다 끝나면 다음으로 |
| 평가 | `eval_contest.sh` → `export_live.sh` → `compare_dl.py --bots <blind 봇>` (Python이 없으면 모델 비교만 건너뜀) |
| 정리 | `day.sh restore` — **중간에 실패하거나 중지해도 항상** |

### 봇 꽂기 (`bot.json`)

봇 폴더(`loadtest/contest/bot{영문 소문자}/`)에 한 장 두면 화면에 나타납니다. 진행 화면 코드는 고치지 않습니다.
화면의 **+ 봇 추가**로도 넣을 수 있습니다: 받은 봇 파일을 올리면 이 폴더와 `bot.json`을 만들어 주고, 다른 폴더에 있는 봇은 경로만 등록합니다(`web/bots.local.json`, 이 PC에만).
Playwright는 봇 폴더 하나에만 설치하면 모든 봇이 같이 씁니다 (화면이 `NODE_PATH`로 묶음).

```json
{ "name": "botb", "owner": "길동현", "blind": true, "run": ["node", "bot.cjs"], "needs": ["playwright"], "env": {} }
```

`run`은 그 폴더 안에서 실행되고, 진행 화면이 `BASE_URL`·`RUN_ID`·`TAG`·`MODE`를 넣습니다. 평가는 `bot`으로 시작하는 모든 종류를 셉니다.

## 순서 (손으로 할 때)

```bash
# 0) 대회 날 집계자 PC: 이 PC만 한도를 풀고(자동 종료) → 대회 운행을 만들고 → 사람 참가자 접속 주소를 띄운다
ADMIN_ID=… ADMIN_PW=… loadtest/contest/day.sh start
#    끝나면: ADMIN_ID=… ADMIN_PW=… loadtest/contest/day.sh restore   (해제를 바로 끝냄. 잊어도 RELAX_HOURS 뒤 저절로)
#    사람 한 명이 기기 하나로 계정을 여러 개 만드는 시험이면 RAISE_GLOBAL=yes (전체 한도도 올림 — 이때는 restore 필수)
#    사람 참가자에게: loadtest/contest/사람-참가-안내.md

# 1) (day.sh가 대신 해 줌) 대회 운행만 따로 만들 때
ADMIN_ID=… ADMIN_PW=… loadtest/contest/setup.sh https://<서버>
#    → "대회 운행 ID = 1000123" 을 공격자 모두에게 알린다

# 2) 각자 봇 실행 (태그는 대회 날 집계자가 하나 정해 모두 같은 값을 쓴다)
#    봇마다 실행 방법은 그 폴더의 README 또는 파일 머리말

# 3) 평가 (서버의 저장소 폴더에서, docker compose가 떠 있는 곳)
loadtest/tools/eval_contest.sh <태그> <대회 운행 ID>          # 규칙 엔진: 막힌 층
tools/ml/export_live.sh <태그> data/ml/contest-<태그>           # 모델: 같은 데이터를 꺼내
python3 tools/ml/compare_dl.py data/ml/contest-<태그>           # 집계자만. 사용법은 그 파일 머리말
```

봇과 사람이 **같은 태그**를 쓰면 한 번에 평가됩니다 (사람 이메일 `lt{태그}.human.g{번호}.{번호}@…`).
모델 점수는 봇·사람을 **같은 폴더에서 같이** 매깁니다 — 판매 오픈 시각·연결 계정 같은 특징이 같은 기준으로 계산되게.

## 라벨 규칙 (모든 봇 공통)

계정 이메일에만 정답을 넣습니다. 서버는 라벨을 볼 길이 없습니다.

```
lt{태그}.{종류}.g{묶음}.{번호}@loadtest.example.com
   종류: bota · botb · botc · botd · botx · human (사람 참가자)
   묶음: 한 사람(봇)이 쓰는 계정끼리 같은 번호
```

- **봇 하나당 명의(본인인증)는 최대 6개.** 모의 본인인증은 가짜 명의를 끝없이 만들 수 있어서,
  상한이 없으면 매수 제한이 의미가 없어집니다. 실제로는 "명의를 빌린 사람 6명"에 해당합니다
- 대회는 **집계자(강동균) 한 명의 로컬 서버**에서 봇 네 개를 한꺼번에 돌립니다 (2026-11-18 결정)
- 봇은 환경 변수 `BASE_URL` · `RUN_ID` · `TAG`를 받고, 명의를 미리 만드는 단계가 있으면 `MODE=signup` / `MODE=buy`로 나눕니다.
  실행 명령과 필요한 것은 폴더 README 한 장에

## 평가 결과 읽기 (`eval_contest.sh`)

| 칸 | 뜻 |
|---|---|
| 명의 | 서로 다른 본인인증(CI) 수 |
| 결제한 좌석 · 잡고 안 낸 좌석 | 공격이 얼마나 성공했나 |
| 선점 시도 · 제한 거절 | 좌석 잡기 요청 수와, 그중 매수 제한(422 `LIMIT_*`)에 걸린 수 |
| 탐지 계정 | 연결된 CI·결제 수단·기기에 의심 케이스가 열린 계정 수 |
| 최고 점수 · 순번 -초 | 위험 점수, 그만큼 다음 판매에서 대기열에서 밀리는 시간 |
| 막힌 층 | 매수제한 · 규칙(케이스) · 순번조정 · 관리자판정 중 걸린 것. 하나도 없으면 **뚫림** |

사람(`human`)은 탐지되면 오탐입니다.

## 폴더

| 폴더 | 공격자 | 방향 | 부류 |
|---|---|---|---|
| `bota/` | 김성원 | B HTTP만으로 빠르게 | 블라인드 |
| `botb/` | 길동현 | A 단순 반복 매크로 | 블라인드 |
| `botc/` | 강동균 | C 사람처럼 보이는 브라우저 | 규칙을 아는 공격자 (제출됨) |
| `botd/` | 조영준 | D 조직이 명의 나눠 쓰기 | 규칙을 아는 공격자 |
| `botx/` (선택) | 강동균 새 세션 | A·B·D 중 다시 뽑기 | 약한 블라인드 |
| `bot…/` (추가) | 새로 만드는 사람 | `공격자-지시문.md`대로, `bot.json` 포함 | 만든 사람에 따라 |

공격자 모두 Claude로 만들었다는 점, 그래서 수법이 닮았을 수 있다는 점은 결과를 낼 때 같이 적습니다.
