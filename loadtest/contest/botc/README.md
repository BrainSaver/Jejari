# botc (강동균)

"규칙을 아는 공격자" 부류. **진짜 브라우저**를 띄우는 봇입니다 (Playwright + Chromium).

## 필요한 것

- Node 18 이상
- Playwright + Chromium: `npm i playwright && npx playwright install chromium`
  (이 폴더에서 `npm i playwright` 하면 됩니다. 저장소 쪽 `node_modules`는 19MB라 빼고 보냈습니다)
- 서버가 이용자 화면을 함께 내보내야 합니다 (브라우저로 동작). 로컬이면 `./gradlew buildFrontend bootRun`

## 실행

```bash
# 1) 명의 미리 만들기 — 가입은 IP당 1시간 제한이 있어 대회 전날 돌려 둡니다
TAG=<태그> MODE=signup node bot.js

# 2) 대회 날 구매
TAG=<태그> RUN_ID=<대회 운행 ID> MODE=buy node bot.js

# 한 번에 (가입 제한에 여유가 있을 때)
TAG=<태그> RUN_ID=<대회 운행 ID> node bot.js
```

| 환경 변수 | 기본값 | 뜻 |
|---|---|---|
| `MODE` | `all` | `all`(가입+구매) · `signup`(명의만) · `buy`(구매만) |
| `RUN_ID` | — | 대회 운행 ID (`setup.sh`가 출력). 구매할 때 필수 |
| `BASE_URL` | `http://localhost:8080` | 서버 주소 |
| `TAG` | 무작위 4자 | 실행 태그. 평가가 이메일에서 이 값을 읽습니다 |
| `ACCOUNTS` | `6` | 명의 수 (대회 상한 6) |
| `SEATS` | `4` | 명의당 좌석 (열차당 한도 4) |
| `SPREAD_MIN` | `10` | 계정들이 들어오는 시간 폭(분) |
| `FROM`, `TO` | 서울 `3900023` → 부산 `3900114` | 구간 |
| `HEADLESS` | — | `0`이면 창을 띄웁니다 (처음엔 이걸로 보세요) |
| `SHOT_DIR` | — | 실패한 화면을 저장할 폴더 |

평가: `loadtest/tools/eval_contest.sh <TAG> <RUN_ID>`

## 수법 (1차 대회 뒤 공개)

1. **진짜 브라우저로 화면을 거칩니다.** API를 직접 부르지 않아 "화면 없이 요청만 오는 패턴"에 안 걸립니다.
2. **마우스 궤적을 그립니다.** 이전 위치에서 목표까지 여러 점을 지나며 4~16ms씩 쉬고, 누른 뒤 40~120ms 뒤에 뗍니다.
3. **생각하는 시간이 지수분포입니다.** 균일 난수가 아니라 사람 분포에 가깝게 — 짧은 멈춤이 많고 가끔 길게 쉽니다.
4. **한도 안에서만 움직입니다.** 명의 6 × 좌석 4 = 24석으로 열차당 한도 바닥에 맞춰, **매수 제한을 한 번도 건드리지 않습니다.**
5. **계정이 10분에 걸쳐 들어오고**, 가입은 전날 미리 해 둡니다.

### 1차 대회(11-19) 결과

| | botc | botb |
|---|---|---|
| 결제한 좌석 | 24 | 24 |
| 선점 시도 | **6** | 72 |
| 매수 제한 거절 | **0** | 24 |
| 최고 위험 점수 | **5** | 35 |
| 규칙이 연 케이스 | **0** | **0** |

**두 봇 다 규칙에 안 걸렸습니다.** 점수만 올랐고 케이스는 열리지 않았습니다
(평가 출력의 "탐지 계정 1"은 집계 PC에서 통합 테스트를 돌리며 생긴 무작위 점검 표본이라 대회 탐지가 아닙니다).
botc가 5점에 그친 이유는 위 1~5번입니다 — 특히 4번 때문에 매수 제한 층을 아예 지나갑니다.
